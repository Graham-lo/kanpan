## 2. 手势状态转换与事件优先级

### 2.1 外层事件路由

`J/sp/aicoin_kline/chart/Chart.java:719–741` 的真实顺序：

1. 没有数据/管理器时消费事件并返回。
2. 更新绘图模式；`fk.C7389n.a(event)` 可优先消费图上警报线的拖动（`J/fk/C7389n.java:18–52`）。这里只记录它对图表触摸的抢占，不扩展警报业务。
3. `Wj.a.t(event, isDrawing)` 先更新 mode，再送自己的 GestureDetector，最后送自定义 scale detector。
4. `C2746s.c(event)` 记录速度，并交给另一套 GestureDetector 分发图上点击目标。
5. DOWN 停惯性；UP / POINTER_UP 尝试启动惯性。

这不是“某个识别器消费后所有其余识别器都停止”的模型。`Chart.onTouchEvent` 忽略 `Wj.a.t` 返回值且最终返回 true；父容器能否接手主要靠 `requestDisallowInterceptTouchEvent(mode!=5)`（`J/Wj/a.java:532–539`）。移植时应把此路由显式化，避免手势优先级散在各风格中。

### 2.3 单击、双击、长按

- 单击使用 `onSingleTapUp`，不是等待双击超时的 `onSingleTapConfirmed`。普通模式在 lastMode 非 2/8/9 时 toggle 十字线；打开后根据 X 选柱、保存 Y（`J/Wj/a.java:158–185`）。这与 iPhone 已测“单击开、松手留、再单击关”一致。不要为普通十字线自行增加几百毫秒等待。
- 长按阈值 400ms 是自定义 Handler；系统 GestureDetector 长按已关闭（`:244–259`）。进入 2 后松手不会关闭十字线，且禁止甩动。
- 双击主右轴先调用结束缩放，再 `F()` 恢复自动 Y，成功时 lastMode=8、mode=-1；其它双击仅 `C2738p.f() → listener.g0()`（`:88–111`; `J/Rj/C2738p.java:142–149`）。**没有在这里实现 X×2 或重置 X。** 宿主桥 `S/app/aicoin/ui/kline/livedata/w.java:575–577` 再调用回调；本次未证实宿主最终屏幕行为。
- quick-scale 被 `bVar.e(false)` 关闭；不能把“双击后上下拖”添加为 Android 已证实能力。双击的第一下仍可能先触发单击操作，这是使用 onSingleTapUp 的时序，不能假定天然互斥。
- 图上点击目标在第二套 GestureDetector 中遍历附加 renderer map，再遍历普通 map，首个 `n(...)==true` 结束该轮目标遍历（`J/Rj/C2746s.java:66–89`）。Map 遍历不是已证实的稳定绘制层级，不能保证同点重叠对象永远按最上层。
- 对象/指标点击处理可以随后关闭刚打开的十字线，例如 `J/Rj/AbstractC2693a.java:327–353`；因此实施入口需明确消费与清理，不能只靠“点哪都 toggle”。

### 2.4 惯性边界

`J/Rj/C2746s.java:93–104,107–133,148–176`：DOWN `forceFinished(true)`；UP 以 Android VelocityTracker 计算 px/s，平台最小/最大速度；lastMode 2/6/8/9 不 fling。原逻辑没有同样排除 3/4/5，不能声称其白名单只有横移状态。惯性每帧取 `currX-prevX` 调用同一个 `O(deltaX)`；触边返回 true，发方向回调并立即 stop。此路径未出现橡皮筋或弹簧；只限此路径，不等于穷举整个产品或 iOS。

## 3. X 缩放锚点、滚动边界和数据更新

### 3.1 可直接实现的 Android 公式

定义：`w=12*s` px；`s∈[0.4,10]`；`N=数据数组总列数（含 400 尾部占位）`；`W=数据绘图区宽`；`o=横向 offset`；`B=max(0,N*w-W)`；`r=右侧预留量`。

```
r = q18==0 ? dp(30)
  : q18==1 ? 2*floor(W/3)
  : q18==2 ? floor(W/2)
  : dp(30)
g = min(400*w-r, B)
R = B-g
move(deltaX):
  proposed = o-deltaX
  if proposed<0:  o=0; boundary=LEFT; return true
  if proposed>=R: o=R; boundary=RIGHT; return true
  o=proposed; boundary=CENTER; return false
```

来源：`J/Rj/y1.java:129–135,255–307,481–491`；右端赋值以 `B/Rj-y1-simple.java:249–272` 为准。左端等于 0 但未小于 0 时，在 R>0 情况下仍会标为 CENTER，这一等号细节与常见 clamp 实现不同。

足量数据时 `R=(N-400)*w-W+r`；r 衡量最新列尾与绘图区右边之间的空白，不能把 r 当成任意历史时刻的缩放锚点。400 是 `C2765z.D()=max(0,B()-400)` 的尾部占位数（`J/Rj/C2765z.java:310–320,934–962`），不是额外可交易数据或固定 400 根历史窗口。

缩放从旧 `(o,w,N*w,boundary)` 到新 `w'`，触点焦点 `f`：

```
LEFT:   o'=0
RIGHT:  o'=B'-g'
CENTER: o'=min((o+f)/(N*w)*(N*w')-f, B'-g')
```

来源 `B/Rj-y1-simple.java:279–302`。CENTER 这一步只有上界 min，没有下界 max；随后 O/P 再归类/夹取。工程版如采用统一 clamp，应标作边界稳健化，而非逐指令复制。`P()` 只是 `O(0)`，不是“回最新”。

显示列中心 `x(i)=(i+0.5)*w-o`；选中索引 `int((o+x)/w)`；可见起点 `max(0,int(o/w))`。绘制循环的尾端 q 与时间窗尾端 y 不同，分别约为 `int((o+W)/w)+2`、`+1` 并受 N-1 限制，很多循环使用 `<end`（`J/Rj/y1.java:206–213,387–395,589–644`）。不能混成一个闭区间尾索引。

### 3.2 双指 span 与中断

`J/Wj/b.java:192–267`：除去抬起的触点，焦点是其余触点算术均值；`spanX=2*mean(abs(x-focusX))`，`spanY` 同理，`span=hypot(spanX,spanY)`。两指时等价欧氏间距，**竖向分开也能改变 X 柱宽**。开始需 span≥50px 且相对初始 span 变化>2*slop（或正在处理已有缩放的触点变更）。触点增减/低于最小 span 会结束旧 scale，再基于新触点重建基准；不能保留旧双指距离继续除。

每次有效回调 `s=clamp(s*spanNow/spanPrev,.4,10)`；开始从 `C2760w1.i()` 读，结束 `l(s)` 保存（`J/Wj/a.java:215–240`）。mode2 的回调不改变 s。

### 3.3 新数据与改尺寸

`J/Rj/y1.java:423–479`：新数据处理区分 X()==1/3/4；追加实时数据时比较旧 `B-min(400*w,B)` 与旧 o，距离位于约一根 w 内才跟到新末尾，否则 P 保持并校正旧视口。历史前插分支、选中时间目标 index 的增量更新是另一条路径。`L()` 在绘图区宽改变时重新缩放并按旧位置判断重对齐（`:216–238`）。

**实施结论：** follow-latest、滚动边界状态、右留白配置、历史时间锚点至少分开保存。用户要求风格切换保持视野；APK 的改尺寸/重建 datasource 行为不能作为随意重置风格视野的依据。实时更新与历史补齐必须分别处理。

## 4. Y 范围、轴文字、动态宽度与倒置

### 4.1 自动范围与手动缩放

设自动价格范围 `[a,b]`、当前手动倍率 s、归一化中心 c，`D=b-a`：

```
普通手动范围: center=a+c*D; span=D/s; [lo,hi]=center±span/2
缩放拖动中:   anchor=(oldLo+oldHi)/2; [lo,hi]=anchor±D/(2*s)
s = clamp(s0*2^(-(y-y0)/max(axisHeight/4,1)), .03,16)
abs(s-1)<=.02 → s=1, c=.5
```

来源 `J/Wj/a.java:309–318,475–482`; `J/Rj/AbstractC2759w0.java:429–496`。初始化的 anchor 固定为算术中点，j(y) 不读取 y。Y 缩放手势只命中主右轴；副轴在这条 Wj 状态机没有对应 mode8。

手动中心边界（同文件 `:88–96`）：s 无效或约等于1，c=.5；令 `h=1/(2s)`，s≤1 时端点 `[h-3,1-h+3]`，s>1 时 `[h-.75,1-h+.75]`；对端点取 min/max 后夹 c。这不是永远 `[0,1]`，也不是无限上下平移。

Y 平移 `D(pixelDelta)` 的原式为：`centerNew=(lo+hi)/2 + (inverted ? -pixelDelta : pixelDelta)/pixelsPerUnit`，再换算 c 并夹取（`:138–169`）；Wj 传入 `-GestureDetector.distanceY`。仅 s!=1 且有效范围时允许 Y 平移（`:499–500`）。对数子类覆写 pixelsPerUnit 为 log 单位，父类这里仍以价格范围算 c：**不要自行将 Android 这段改述为已经证实的纯 log 平移公式**；iOS 连续行为仍需测。

A/重置自动 Y 调用 `F()`：s=1,c=.5，取消范围动画和缩放锚定，恢复当前自动范围；不涉及 X offset（`:175–195`; `J/Wj/a.java:542–560`）。已有 iPhone 01/02 也证实历史时间窗保留。

### 4.2 正常/倒置坐标必须共用正逆映射

数据内框 `top=T,bottom=U`（含 pane 顶底 padding），`H=U-T`，有效价格 `[lo,hi]`：

| 映射 | 正常 | 倒置 |
|---|---|---|
| 线性 y(p) | `T+H*(hi-p)/(hi-lo)` | `T+H*(p-lo)/(hi-lo)` |
| 线性 p(y) | `hi-(y-T)*(hi-lo)/H` | `lo+(y-T)*(hi-lo)/H` |
| 正价格 log y(p) | `T+H*(ln(hi)-ln(p))/(ln(hi)-ln(lo))` | `T+U-yNormal(p)` |
| 正价格 log p(y) | `exp(ln(hi)-(y-T)/k)`，k=H/log跨度 | 先 `y=T+U-y` 再同左 |

来源 `J/Rj/AbstractC2759w0.java:214–227,285–319`; `J/Rj/C2694a0.java:29–75,135–142`; `S/nk/A.java:41–42`。蜡烛、指标线、选中价、画线控制点必须走同一映射；不能只倒序轴数字而不翻数据。`P(price)` 与 `S(price)` 不同，P 将超出范围的值夹到边缘，最新价徽标使用 P（`J/Rj/C0.java:134`）。

Android log 还含 `p=0 → -24`、`p<0 → -48-ln(-p)` 的分段扩展，逆映射按 -24 阈值处理；它不与标准正数 ln 在零附近平滑连续，亦不能声称 R(S(0)) 精确为0。用户 BTC 正价格区间可用上表，负值副指标应独立使用适合其范围的轴。

主/副轴翻转的“允许点击”与当前 inverted 状态必须分离；iPhone 18、21、22 与 FINDINGS 为权威。`J/Rj/C2766z0.java:26–46` 仅把副/脚本右轴点击上送，未直接在此翻转；不可拿它推断用户关闭副轴翻转时仍应翻转。

### 4.3 价格刻度文字与宽度

`J/Rj/B0.java:33–49,69–120,140–154`：9sp，抗锯齿，水平居中于价格轴，基线修正 `-floor(ceil(bottom-top)/2)-int(fontTop)`；左右各 4dp 小刻度线，测量内距共 8dp。

## 10. 最新要求增补：单一几何底座的实施依据

### 10.1 唯一状态与风格边界

建议唯一共享状态为 `X{spacing,offset,boundary,latestInsetMode,followLatest}`、每 pane 的 `Y{autoLo,autoHi,scale,centerFraction,inverted}`、临时 `Gesture{mode,spanPrevious,focusPrevious,yStart,scaleStart,anchorPrice,anchorActive}` 和独立惯性时钟。风格不得持有 spacing、bodyR、价格留白、轴宽、pane 高度、缩放边界或自己的手势处理器；圆角、空实心等造型在同一 OHLC 几何框内表现。背景取任务书靛色，不由 AICoin 截图覆盖。

`12*s` 是**相邻列中心节距**，不是实体宽度。蜡烛数学实体宽 `2*w/3`，居中于列中心；影线位于该中心，普通路径宽2个Android物理px，见 `J/Rj/C2723k.java:39–47,93–102`。APK具体涨跌描边/收1px的光栅差别仍见旧 candle-axis 报告；共用几何时别把“实体比例”重新交给11种风格配置。

单位统一在输入/输出适配层完成：w上限120px、下限4.8px、50px捏合门槛都是Android物理px；右留白30dp、顶底40sp/8sp是另一类单位。若采用物理px÷3作为当前iPhone参考，w为1.6…40pt，默认s=1对应4pt；这属于明确的参考换算，**不是iOS上下限实测**。不能同时把30dp也无条件除3变10pt。

### 10.2 水平边界与时间窗口转换

按 §3.1 保留 `N=C+400` 的虚拟列计数，C是真实柱数，不必真的给行情数组塞400条假OHLC。先求 `B=max(0,N*w-W)`、`g=min(400*w-r,B)`、`R=B-g`，每次移动调用同一个函数：

```text
proposed = offset - fingerDeltaX
if proposed < 0: offset=0; boundary=LEFT; hit=true
else if proposed >= R: offset=R; boundary=RIGHT; hit=true
else: offset=proposed; boundary=CENTER; hit=false
```

右端赋值依据 `B/Rj-y1-simple.java:249–272`。没有12%弹性区、0.7/0.3时间跨度边界或松手回弹。数据不足、W极大时使用完整 B/g/R 公式，别把通常成立的 `max(0,C*w-W+r)` 当作无条件恒等式。

若暂用现有 ViewWindow 时间表示，只作共享几何的内部转换，不增加旧算法分支。等间隔时间轴、周期Δ、首柱时间t0：

```text
spanTime = (W/w)*Δ
fromTime = t0 + (offset/w - 0.5)*Δ
toTime   = fromTime + spanTime
offset   = ((fromTime-t0)/Δ + 0.5)*w
x(i)     = (i+0.5)*w-offset
```

这是从Android列中心推导的等价式；漏掉0.5将使十字线、画线和最新柱错半根。非等间隔指标仍按timestamp→主柱index对齐，不用时间差硬套上述匀速索引。通常足量数据、位于右端时，最后真实柱中心在 `W-r-w/2`，r是列右缘到绘图区右缘的留白，不能把柱中心直接放到 `W-r`。

### 10.3 捏合：以事件前的边界状态决定锚点

有效scale事件先计算 `newScale=clamp(oldScale*spanNow/spanPrevious,.4,10)`，再更新w；`spanPrevious` 在每个被接受的MOVE后更新，触点集合变化时重建。Android启动条件是 span≥50px 且相对初始span变化>2*系统slop；它不是仅仅 `max(8,distance)`，见 `J/Wj/b.java:120–122,225–265`。

对同一数据数组，§3.1 CENTER公式可简写为 `newOffset=min((oldOffset+focusNow)*newW/oldW-focusNow,newR)`。LEFT取0，RIGHT取newR。**latestInsetMode不能代替boundary**；默认“靠右”时进入历史区，仍走CENTER焦点公式。

双指整体移动与缩放的APK顺序是：Wj先分发GestureDetector的scroll，再分发scale detector。mode3等允许scroll时用焦点位移执行上述move，再用当前focus做scale；mode4只调用 `O(0)`，不加平移，见 `J/Wj/a.java:115–155,532–538`。不要在scale公式外再重复加入已处理过的焦点移动。mode2拒绝scale。`M()`只是 `abs(B-offset-400*w)<w`，不是任意“最新柱可见”。

精确复刻Android时采用逐事件更新；在达到缩放极限/触边/触点更换后，一直沿用最初down快照的实现可能出现与逐事件模型不同的回程。iOS若采用其它锚定方式，须由真机证明，不能用“用户选择靠右”推导出来。

### 10.4 手动Y：centerFraction的含义与生命周期

自动范围 `[a,b]` 独立保存，`D=b-a`。c是**相对于自动范围的中心位置**：`centerPrice=a+c*D`。s=1时自动模式直接输出 `[a,b]`；s≠1时输出 `centerPrice±D/(2*s)`，c按 §4.1 分段边界夹取。不要把手动状态存为永久冻结的绝对low/high；可见数据变化会更新a/b并用保留的s/c重新生成窗口，依据 `J/Rj/AbstractC2759w0.java:230–257,457–485`。

生命周期可直接实现如下（异常值处理和统一CANCEL清理是工程防护，不宣称APK逐指令一致）：

```text
beginAxisScale(firstQualifiedMoveY):
  require valid automatic/display range and drawable height
  cancelYAnimation()
  yStart=firstQualifiedMoveY; scaleStart=s
  anchorPrice=(displayLo+displayHi)/2; anchorActive=true

moveAxisScale(y):
  s=clamp(scaleStart*2^(-(y-yStart)/max(axisHeight/4,1)),.03,16)
  if abs(s-1)<=.02: s=1; c=.5; display=[a,b]
  else:
    display=[anchorPrice-D/(2*s), anchorPrice+D/(2*s)]
    c=clampCenter(s,(anchorPrice-a)/D)

endAxisScale(): anchorActive=false
recomputeAfterVisibleDataChange(): update a,b; display=rangeFrom(s,c,a,b)
resetAuto(): cancelYAnimation(); anchorActive=false; s=1; c=.5; display=[a,b]
```

begin/move的源码分别是 `J/Rj/AbstractC2759w0.java:488–496`、`:429–485`；end `:511–513` 只清anchorActive，不自行重算范围。anchorActive期间返回的范围保持锚点，即使写入的c已经夹取；下一次非锚定重算才用夹后的c。若改成始终立刻用夹后的c重算，应标明是边界处理调整。

旧原型 `shift=q` 的定义是 `center=autoMid+(D/s)*q`（`K/prototype/src/chart.js:554–560`）。AICoin是 `center=autoMid+D*(c-.5)`，所以同一范围的转换为 `c=.5+q/s`，反向 `q=s*(c-.5)`；不能仅用 `c=.5+q`。这是帮助删除旧表达式的代数说明，不要求保留迁移分支。新模型建议直接命名centerFraction。

手动Y平移按 §4.1 原式换算c后重算窗口；s=1时不进入mode9。正价格log显示坐标仍经过log，但Android父类手动范围运算是价格域，尚未证明iOS采用相同域；不得借旧PriceAnchor的log锁定行为声称完成AICoin复刻。自动Y范围变化存在另一条动画路径，和旧“捏合时冻结Y、松手恢复旧transform”的设计不是同一证据。

### 10.5 惯性算法：APK调用契约与平台参考分开

APK已经确定的契约：`new OverScroller(context)`；速度为 `VelocityTracker.computeCurrentVelocity(1000,systemMax)` 的x分量，整数px/s；启动条件严格 `abs(v)>systemMin` 且lastMode不在2/6/8/9；x边界传极大整数范围，真实图表边界由每帧 `move(currX-prevX)` 执行，命中即 `forceFinished(true)`。DOWN也立即停止。见 `J/Rj/C2746s.java:93–104,107–133,148–176`。因此不能保留旧325ms指数函数并改名为AICoin惯性。

为了让实现有可追溯的平台算法，另存官方AOSP **android-15.0.0_r1** 的 OverScroller 源文件至 `B/AOSP-android-15.0.0_r1-OverScroller.java`。这是平台参考，**不在APK dex里，也未确认原Android测试设备OS/OEM版本**。官方来源：[AOSP OverScroller](https://android.googlesource.com/platform/frameworks/base/+/android-15.0.0_r1/core/java/android/widget/OverScroller.java)。SHA256：`66aa09b4120c97a4ea071e287d637b829d2d6162e02c1130773859515a7ca4de`。

该版本正常SPLINE段的移植要点，文件`:575–644,760–797,921–936`：

```text
rate = ln(.78)/ln(.9)
physical = gravityEarth*39.37*(androidDensity*160)*.84
friction = ViewConfiguration.getScrollFriction()
l = ln(.35*abs(velocityPxPerSecond)/(friction*physical))
durationMs = trunc(1000*exp(l/(rate-1)))
distancePx = trunc(sign(v)*friction*physical*exp(rate*l/(rate-1)))
```

位置曲线以100段表插值：Bezier的时间控制点为(0,.175,.35,1)，距离控制点为(0,.5,1,1)；解时间参数得到对应距离比。按elapsed/duration查表，再取累计距离差交给move，实际位置按源码取整。移植此段即可作为有来源的初版惯性；APK已在触边停掉它，无需因此引入AOSP的越界弹跳阶段。Android density、friction、速度估计器与iOS映射仍需单独定标，不得由手机3x屏幕比例直接推导Android density。未知时显式记为参考参数，不能宣称精确复现iOS。
