# 看盘：审查 / 压测报告里的每一项都要从根因修掉，不许「已记录」

2026-09-19 我把 GPT Pro 审查报告的整改交付时，把「建议类」「报告说先 profile」
「当前触发不了」「和既定规则冲突」这几类留成了待办清单，用户要求每一项都改掉。

2026-09-30 网页版深度压测收尾时又犯了一次：三路子代理各自留了几项「未修、已记录」
（热力接口 2 并发 p95 3 秒「要改存储结构」、Caddy 缓存与安全头「不在本路范围」、
网关断线原因不区分、板块页冷启动权重 436「建议缓存」、偶发 meta 502「属于服务端」），
我照单转述成「仍未做的」。用户回的是：

> 「**而且不要已记录，要从根因修复**」

所以规矩是：

- **审查报告、压测报告、回归里发现的每一项，交付前都要从根因修掉**，不管它是谁发现的、
  是不是「这一路的范围」、要不要动存储结构或服务端。子代理说「超范围、只记录」，
  主窗口就要接过来自己修或再派人修，不能把它抄进收尾报告当成交代。
- 「已记录」「建议后续」「属于服务端 / 网关」「要改存储结构」都不是收尾状态，
  只有「修了、验了、上线了」才是。
- 真正可以不做的只有两类：用户自己定过的范围边界（例如网页版先只按 2560×1440 做，
  其它屏幕以后再兼容），以及 kanpan-decided-not-to-do-stays-dead 里用户判「不做」的功能。
  这两类要在报告里点明是他定的边界，而不是混在「未修」里。
- 修法要是根因（存储结构该改就改、服务端该加就加），不是绕开症状（加重试、放宽阈值、
  把断言改宽）。
