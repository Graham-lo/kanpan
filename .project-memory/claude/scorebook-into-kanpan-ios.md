# 复盘并入看盘：以看盘为准

用户明确要求把原来的复盘项目（Scorebook，TypeScript 前端 + Rust 后端的网页应用）
并入看盘（Kanpan，iOS K 线图表 app），并且**以看盘项目为准**：看盘是主体，复盘是
接进来的功能，不是并列的第二个产品。

这条是用户对我早先方案的纠正。我当时提的是「底栏五格一个都不动」，把复盘挂成浮动
按钮和顶栏入口，并且把长文复盘、统计、语义搜索留在 Mac 网页端、只把轻量记录放到
iOS 上。用户否掉了这两点：

- **入口布局和排列要整个重新设计**，而不是在现有 chrome 上另外加挂件。为了给复盘腾
  位置，可以重排甚至合并看盘已有的入口。
- **全部统一到 iOS 上**，不要做 iOS + Mac 网页的双端切分。用户的原话是「我现在是要
  接到 ios 上，统一起来」。

所以后续任何关于这两个项目的方案，默认前提是：单一 iOS app，看盘的交互语法（顶栏 /
周期条 / 底栏 / 图上浮钮 / 全屏盖 / 半屏抽屉）是唯一的语法，复盘的概念要翻译成这套
语法，而不是把网页端的信息架构搬过来。
