# kanpan-header-may-borrow-height-from-chart

**项目约定**：看盘行情页上部（头部价格/统计、周期条等）空间不够时，可以向图表区域借一点高度，不要靠压缩头部内容（缩字、截字、挤窄）来凑；但图表是主区域，不能过分压缩

2026-09-20 我验收行情页头部的费率倒计时时，一直坚持「头部高度一个像素不变、内容再挤也塞进两行」，
实现代理为此把四格统计块按屏宽做了 196 / 182 / 172 三档收窄，之前还把价格字压小过。用户看到汇报后说：

> 「如果行情页上部分空间不够，你可以压缩图表区域，图表区域的空间其实非常足，
> 但不能过分压缩，图表才是主区域。」

所以在看盘行情页上，版面的取舍顺序是：

- **上部空间不够时，优先向图表区域借高度**，而不是把头部内容缩字号、截字、压窄字距或砍掉信息。
  图表区域纵向余量很足，多给头部十来个 pt 不影响看图。
- **借的量要克制。** 图表仍然是主区域，头部只能多占「刚好放下」的那一点，不能因为这条规则
  就把头部越做越高、往里堆东西。kanpan-header-price-and-change（头部只放最新价和涨跌幅，
  其余一行小字）、kanpan-ui-restrained-element-scale（元素尺寸克制）仍然有效。
- 这条同样适用于周期条、读数行等图表上方的条：命中区放大到 44pt 之类的改动，如果确实需要
  多几个 pt 高度，可以从图表那里拿，不必为了「布局高度一像素不变」去做妥协。
- 反过来，图表以外的区域缺横向空间时，仍然不能往画布上浮控件（kanpan-no-floating-controls-over-chart）。
