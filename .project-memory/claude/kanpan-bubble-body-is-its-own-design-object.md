# kanpan-bubble-body-is-its-own-design-object

**项目约定**：看盘板块气泡页里，气泡本体（球的材质与光学）要当成一个独立的设计对象单独重点打磨，不能当作皮肤配色的副产品顺手画出来

2026-09-18 我把板块气泡图的四套原型（潮汐／星图／琉璃／版面）给用户看时，
气泡本体画的是「圆 + 一道白色高光弧 + 底部一弯反光」那种早年 Web2.0 玻璃糖果球
（实现上就是几层 `radial-gradient` 叠一个白弧）。用户连着否了三次：
「这个气泡能不能设计的好看一点」→「一点都不美观啊」→
**「你得弄好看啊，要极致的好看，气泡单独重点设计」**。

所以这一页有一条单独的要求：**气泡本体是一个独立的设计对象，要单独立项重点做**，
不是「把皮肤的主色填进一个圆里、再加一道高光」就算完事。这一页上真正被用户反复盯着看的
就是那几十个球，它们的材质、光学、边缘、内部层次决定了整页好不好看；
页面的排版、榜单、列表再精致也救不了一个难看的球。

判断标准跟着项目既有的两条走：`kanpan-visual-direction-beauty-first`（极致好看优先，
不要工程风）和 `kanpan-redesign-boldly-not-by-subtraction`（说「更好看」要的是更大胆的
色彩与材质，不是做减法）。具体到球上，"高光弧 + 渐变填充"是被点名否掉的做法；
要往真实的光学去做——边缘的菲涅尔亮边而不是中心的白点、光穿过球体在底部汇聚的焦散、
次表面的色彩纵深、背景在球缘的折射错位，以及材料本身的叙事（釉、玉、水墨、液态金属、
皂膜虹彩等），而不是一个统一的「玻璃球」滤镜。

做法上遵循 `kanpan-put-the-knob-in-the-prototype`：我改一版他否一版的时候，
正确动作不是再猜第四版，而是把气泡材质做成一张单独的材质实验页／抽屉里的选择器，
把同一份数据用多种材质并排画出来让他自己挑。
材质必须在最小半径（约 14px）和最大半径（约 64px）两端都成立，
在三套皮肤 × 深浅 × 红绿两色下都成立，并且球面上还要压得住名称和涨跌幅两行字。

## 陪衬球不做任何特殊处理——它就是一颗普通的球

这条我错了两次，用户纠了两次，最后落在「什么都不做」上。

第一版我写的是「陪衬去饱和、压低不透明度、不抢主角」，原型里做出来就是同一颗球叠一个
0.56 的透明度，看着不是"安静"，是"没画完"。用户否掉：
「所以重点是要把气泡设计的非常好看，极致的美学，**即使陪衬的也要好看啊**」。

第二版我改成「陪衬用另一种同样讲究的材料语言表达它的次要——主角通透发亮，陪衬哑光磨砂」。
用户又否掉，而且这次把道理讲穿了：
**「重要度是看大小和视觉位置，所以不需要陪衬专门搞这种」**。

他是对的，而且这就是这一页一以贯之的那条原则（见 `kanpan-sector-bubble-page-structure`
里「编码本身已经说明了重要性」）：**重要度已经由大小和位置编码完了**——陪衬的
|涨跌幅| 小，所以球本来就小；它排在中间，所以位置本来就不在两头。
再给它加一层"弱化"（不管是降透明度还是换一种哑光材质），都是在用第三个通道
重复说几何已经说过的话。这和同一天砍掉板块榜是同一个理由。

所以定稿是：**所有气泡用同一种材质、同一套光学、同一个质量标准画。**
陪衬不去饱和、不降透明度、不换材料、不加也不减任何处理。
它看起来次要，只因为它确实小、确实不在两头。

（"陪衬"这个词只描述它在选取逻辑里的角色——从中间挑 M 个填版面，纯美学参数，
见 BRIEF §3.5；它不描述任何渲染上的差别。）

## 可以有动效，但不能夸张

同一句里用户还点名要了：「可以搞点不夸张的动效什么的」。
所以气泡场不是一张静态图——允许极轻微的呼吸、漂移、光泽随时间缓慢流动、
切换口径时的重排过渡这类**几乎察觉不到但让画面活着**的运动。
边界是「不夸张」：不要弹跳、不要抖动、不要让球互相碰撞弹开、不要循环闪烁，
也不要让运动大到干扰读数字。默认开，并按项目惯例在调试抽屉里给一根速度/幅度滑杆
（见 `kanpan-put-the-knob-in-the-prototype`），让用户自己拧到满意。

## 「特效拉满」不等于可以糊掉可读性

2026-09-18 用户说完「极致好看精美，特效拉满这次」之后，我让一版原型把辉光放开做。
浅色皮肤下的结果是整屏被洗成一团青白雾：球没有边缘、球与球之间没有界线、
浅色球上的白字彻底看不见、强弱两头的红绿被光晕洗成同一个色。
他看了一眼就说：**「这光晕都看不清了啊」**。

所以这两条要一起记：**「拉满」指的是渲染的丰富度（材质的层次、真实的光学、
环境映像、溢出球缘的光），不是把参数往大里推。** 收敛是效果的一部分，不是对效果的削减：

- 辉光要有明确的半径上限并随球半径等比缩放，宁可紧贴球缘、亮而锐，
  也不要大范围的低频 bloom——雾会吃掉旁边的球和字。
- 每颗球都必须保留一条界（菲涅尔亮边／暗轮廓／球缘的环境压缩线），
  没有边缘的就不是球，是一团光斑。
- **自发光在浅色皮肤下不成立。** 浅色下要换形态——做成"被强光打亮的实体 + 明确的接触投影"，
  靠明暗和阴影立体；深色下才把辉光放开。只是把强度调低是不够的。
- 球心区要亮度稳、和字有足够对比，浅色球上就用深墨字，不要一律白字。

另外这一条也再次验证了 `kanpan-put-the-knob-in-the-prototype`：
辉光强度和半径这类参数应该一开始就是原型顶部的滑杆，默认取保守的一档。

## 好看要从色彩搭配和图标来，不是从特效来

紧接着上面那句「这光晕都看不清了啊」，用户把话说得更明确了：

> 「**我要的是好看不是廉价感**，你可以**从色彩搭配上入手**啊，
> 比如这些板块可以搞点**图标 icon 设计不同的颜色搭配**不就好看了吗」

这句话纠正了我对「特效拉满」的理解。我当时把它执行成了"把辉光、bloom、景深往大里推"，
做出来的结果在他眼里是**廉价**——模糊、发光、糊成一片，是廉价的做法，不是贵的做法。

所以这一页"好看"的来源按优先级重排：

1. **色彩搭配**——颜色之间的关系是第一位的，不是效果的强度。
2. **每个板块一枚自己的图标**，图标各有各的配色。板块因此有了身份，
   整屏的丰富度来自几十枚精心配色的记号，而不是来自一层雾。
   画法遵循项目既有的两条：`kanpan-icons-are-not-wireframes`（实心圆润、有色彩材质，
   不许单色细线线框）和 `kanpan-symbol-badges-must-be-real-marks`（一个板块一个记号，
   不能整类共用一个图形，也不能拿名字缩写兜底），配色按皮肤特调
   （`kanpan-badge-colors-match-the-skin`）。
3. 材质与光学排在后面，而且必须收敛（见上一节）。

**遗留的冲突要留意：** 这一页早先定过「球色只讲哪一头，全屏只有两种球色」
（见 `kanpan-sector-bubble-page-structure`）。"每个板块不同的颜色搭配"和它是冲突的。
我的处理是把两者分层——**球身仍然只有强端/弱端两个色，板块各自的配色落在那枚图标上**，
这样既有丰富的色彩，又不破坏"一眼看出最强最弱"。这一层关系如果用户另有说法，以他的为准。

他随即又补了一条边界：**「但是颜色也不能太多，不然视觉会疲劳」**。
所以"不同的颜色搭配"不等于一个板块一个自由取色——要先定一套**受控的小色板**
（数得过来的几个色相），几十枚图标都从这套色板里取色和配对，靠色相的**搭配关系**
和材质变化拉开区别，而不是靠色相的数量。这和项目里
`kanpan-badge-colors-match-the-skin`（徽章配色按皮肤特调、线条粗细统一，不能各画各的）
是同一条脉络。

## 不要生物感；cryptobubbles 那个形态他认可，吸收它

紧接着上面那两条，用户又补了两句，一起构成了球体形态的正面参照：

> 「另外**不要搞成生物的那种**」
> 「https://cryptobubbles.net/zh **你看看这个就很好看啊**」

**第一句**划掉一整类做法：细胞、细胞膜、变形虫、培养皿里的菌落、发光孢子、水母、
有机体那种会呼吸会蠕动的质感。球是**器物**（釉、玉、金属、漆、玻璃），不是活物。
辉光一放开、边缘一软化、再配上缓慢的呼吸缩放，做出来就正好是「显微镜下的细胞」，
这也是「廉价感」的一个具体来源。

**第二句**值得注意：BRIEF 最早写的是「参照 cryptobubbles 的信息密度，但视觉必须比它精致得多」，
用户现在直接指着它说好看。这不矛盾——他认可的是那个**形态**，我们要做的是同一个形态做得更精致。
它好看的机制拆开是：

- 球体本身是**近黑的暗盘**，不是发光团，也不是玻璃糖果球；盘面几乎是平的。
- 真正发亮的是**球缘那一圈环**。环只有一个色相（涨=绿），亮度和粗细随幅度变——
  **颜色只讲哪一头，强度讲多强**，和这一页早就定下的编码规则完全一致。
- 球内上半部一枚**真实的品牌 logo**，彩色、实心、各不相同；下面白色的名称和涨跌幅两行。
  **整屏的色彩丰富度全部来自那几十枚 logo，底子只有一个绿。**
  这正好印证了上一节那条「好看要从色彩搭配和图标来」，也顺手解决了那里记的冲突——
  球身两色和图标多色是分层的，不是对立的。
- 暗底 + 白字 + 彩色小图标，对比极高，每个球都读得清。
- 球挨得很紧，**密度本身就是画面**，不需要靠雾和光去填。
- 最小的那些球**只画图标不画字**，不硬塞两行字进去。

我们要比它精致的地方在：它的盘面是平的、环是简单的 CSS 发光。我们把「暗盘 + 亮环」
做成真材质（环是被环境照亮的一圈高光带，盘面有极微的纵深和环境映像），
图标换成我们自己设计的板块记号。

## 2026-09-18 定稿：釉珠通过了，这一页的球体形态不要再重开

前面那四次否决之后收敛出来的形态，用户在 2026-09-18 看过完整原型后一句话定了：
**「这版可以，直接做，我喜欢这个设计，底栏也照着改即可」**。

被定下来的就是「釉珠」这一套，具体是：近黑的深釉球胎（不自发光、边缘用一道暗轮廓收口）
+ 球缘一圈随方位变亮的环光（强端一个色相、弱端一个色相，亮度和粗细随 |涨跌幅| 变）
+ 球内上半一枚彩色实心的板块记号 + 下面白色的名称和涨跌幅两行；小球只画记号不塞字；
深色档才放辉光且半径硬封顶，浅色档换成「被左上强光打亮的实体 + 有方向的接触投影 +
偏心的明暗交界」，靠明暗立体而不是靠亮。

所以以后在这一页上：**不要再提第五种球体方案，也不要把它当成还在探索的方向**。
需要调的是参数（抽屉里的滑杆），不是形态。同一句里他还说了底栏要照着这套改，
也就是说这套视觉语言是跨页的基准，不只属于板块页。
