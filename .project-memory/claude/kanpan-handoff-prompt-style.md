# kanpan-handoff-prompt-style

**项目约定**：写给其他模型窗口（GPT、Opus 子代理等）的看盘交接 prompt 要直接指向远程仓库并附 file:line，不要内联大段代码；成品交付文件一律放到桌面

# 看盘交接 prompt 的写法

用户会把我产出的方案/审查结论再交给 GPT 做一轮独立复核，或者由我交给 Opus 子代理实施（Codex 已不参与）。第一次我按「对方看不到仓库」的假设，把九段关键实现原文全部内联进 prompt，做出来 23KB。用户纠正说：**对方可以读取远程仓库，把仓库地址放上去即可。**

所以以后写这类交接 prompt：

- 直接给 GitHub 远程地址（看盘是 `https://github.com/Graham-lo/kanpan.git`）、分支和具体 commit SHA，让对方自己去读源码。
- 结论用 `路径:行号` 引用，不要粘贴代码正文。这样 prompt 从 20KB 级降到几 KB，对方还能看到完整上下文而不是我摘出来的片段。
- 引用行号前先确认本地源码与 `origin/main` 一致（`git status --porcelain` 看目标文件有没有本地改动）；有未提交改动时，行号要以 `git show origin/main:<path>` 为准，否则对方照着行号找会对不上。

成品文件**一律放到桌面**（`~/Desktop`），不要留在临时目录或塞进仓库——用户要直接拿去粘贴或转给别人。这条不只适用于 prompt：审查结论、最终方案等任何要交出去的成品文档都一样，用户在第二次交付时又强调了一次「还是输出到桌面」。
