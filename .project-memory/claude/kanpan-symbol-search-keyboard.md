# kanpan-symbol-search-keyboard

**项目约定**：看盘搜品种的输入框一律锁 ASCII 英文键盘；浮层进来不自动弹键盘，键盘真起来时要让内容留在它上沿以内

2026-09-18 用户试横屏画线工作台里点品种名弹出来的那层换品种浮层，报了两件事：
「都还没点搜索框键盘就弹出来了，而且就算弹应该弹英文键盘啊，大部分品种都是英文」，
紧接着又追了一句「弹出来的键盘是不是占比太大了，这个可以优化一下体验吗」。

由此定下三条，适用于看盘里**所有**搜品种的输入框（画线换品种浮层、顶栏搜索页、
选品种面板）：

**一、键盘锁成 ASCII。** 品种代号全是 ASCII（BTCUSDT、TSLA、XAUUSD…）。不写
`.keyboardType(.asciiCapable)` 的话，用户上次用的是中文输入法，这里就弹一副中文键盘
出来，打 BTC 还得先切一次输入法。`.textInputAutocapitalization(.characters)` 只管大小写，
不管输入法语言，两个都要写。

**二、浮层进来不自动抢焦点。** 我原来在换品种浮层上写了 `.onAppear { focused = true }`，
注释的理由是「点品种名就是为了打字，多按一下输入框是白让他按的」——这个推断错了。
那块浮层的主体是底下那格「常看」，用户多数时候是来点一个常看品种的，键盘一上来
反而把它们盖住，还得先收键盘才能点。真要打字的人点一下搜索框就是了，那一下比
每次都先关一次键盘便宜得多。整页级的搜索页（用户是从「搜索」入口点进去的）不在此列，
那儿自动聚焦是对的。

**三、键盘占屏太大要主动让开，而不是让它盖住内容。** 横屏的键盘是半块屏
（iPhone 上约 209pt / 393pt）。两件事都要做：浮层所在的那一层不参与 SwiftUI 的整页
键盘避让（否则 K 线连同浮层一起被顶上去，而用户点品种名的时候还在看图），
以及浮层自己在键盘起来时把列表高度压到键盘上沿以内，让前几个匹配结果始终露着、
再多的照样滑。
