# kanpan-fix-root-cause-including-network

**项目约定**：看盘里遇到 bug 一律自己从根因修掉，不能因为「是网络/环境问题」或「是别的窗口引入的」就停下来等或者只做记录

2026-09-18 我在做 iPhone 15+ / 全 iPad / iOS 18 的兼容矩阵时撞上两个问题：模拟器里
K 线历史取不到（诊断快照显示 `bars: 1`，而实时报价、成交量、持仓量都正常到了），以及
`origin/main` 本身编译不过（有个提交只落了半边改动，另半边还在另一个 Claude 窗口的
工作树里没提交）。我把两件事都查清楚了，然后停下来——给对方窗口发了消息请它补提交，
并向用户报告「我在等它动作」，还把 `bars: 1` 归类成可能是「网络/环境问题」。

用户的回应是：「🈶️bug 直接改，无论是网络问题还是什么问题，要从根因上修复」。

所以在这个项目里，遇到 bug 的正确做法是**自己查到根因并修掉**，以下这些都不是停下来的理由：

- **「这是网络问题/环境问题，不是代码问题」**——不成立。取不到数据、连不上、超时、
  域名不可用，这些统统要追到根因再修，不能归档成「外部因素」就交差。
- **「这是别的窗口引入的，等它修」**——不成立。发消息知会对方是对的，但不能因此把自己
  的活挂起等着。
- **「这是存量问题，不是我这轮引入的」**——不成立，这一条在
  `kanpan-finish-features-completely` 里已经定过，这里再扩一次范围。

「根因」的标准是：能说清是哪一行/哪个配置导致的、为什么会那样，而不是绕开症状。
绕过去的临时办法（跳过用例、加重试、换个机型再跑）不算修复。

知会其他窗口和修复是并行的两件事，不是先后关系。
