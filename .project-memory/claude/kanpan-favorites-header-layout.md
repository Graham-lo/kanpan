# kanpan-favorites-header-layout

**项目约定**：看盘自选页头部的定稿排版（2026-09-25 起）：只有一行——左边分类胶囊条、右边放大镜圆片与「…」圆片；没有长搜索框、没有「N 个品种」、没有排序功能，列表永远按自选顺序

# 自选页头部：一行，空间让给列表（2026-09-25 定稿）

2026-09-25 用户看着自选页说：「上面搜索占了很大空间，只需要给个搜索 icon 即可，然后分类文件夹
挪到上面和搜索对齐，字体也不需要那么大，另外多少个品种和排序功能去掉，默认就是刚开始的排序，
想要排序用户自己去调整，因为基本上排序很固定很少用到这么多排序功能。空间多留给品种列表的展示，
尽量多展示几个。」随后补了一句「但是你要注意要满足设计规范」。这推翻了 2026-09-18 那版
「长搜索框一行 + 分类条一行 + 『N 个品种 · 排序』一行」（约 160pt）的头部。现行定稿：

- **只有一行，高 44，下方留 4**。从左到右：分类胶囊条（占满剩余宽度、可横滑，选中格实心渐变胶囊、
  字号 `TypeScale.control` / `controlOn` 即 13pt，格子可见 32、轨 36、命中区 44）→ 放大镜玻璃圆片
  （`favorites.add`，点开整张搜索页；可见 36、命中区 44）→「…」玻璃圆片（`favorites.more`）。
  调整顺序时放大镜换成「完成」胶囊（`favorites.editToggle`）。
- **胶囊分段器保留**：用户仍喜欢这种分类样式，只是缩小了；这一页的按钮与分类条仍全是圆的
  （圆片 / 胶囊），不混圆角矩形。
- **没有「N 个品种」，没有排序功能**。列表永远按自选顺序排，用户想换顺序走「…」→「调整顺序」
  （长按拖动）。涨跌那格固定显示涨跌幅，副文案固定「成交额 … · 振幅 …」。
  `Prefs.favoritesSort / favoritesAscending / favoritesAmount` 三个字段只为同步协议兼容保留，页面不读。
- **做减法时规范不能破**：字号只落在 TypeScale 阶梯上，命中区一律 ≥ 44，间距走 4pt 网格。
  用户要的是「省空间」，不是「变小变难点」。

历史：2026-09-18 他曾照推特定过「中间长搜索框、右边圆按钮、下面一行分类」，并两次说按钮太小
把圆片放大到 42；那一版已被本次推翻，不要再改回去，也不要在这一行上再加东西。

## 行的右侧：价格在前、涨跌幅在后（2026-09-25 同日定稿）

同一天用户又拿一张富途式的自选表截图当参照：「可以参考这两个，价格在前，涨幅在后吗。你看看布局
怎么搞展示的更优美好看」，并把行副文案里的「振幅」也去掉了。现行定稿：

- 行右侧是**横排**：价格（15 medium 等宽数字）靠右贴着涨跌药丸，药丸定宽 72 × 28、13 semibold，
  一列药丸左右缘对齐成一条竖线。不再是「价格在上、药丸在下」的竖排。
- **药丸的颜色必须是淡的**：底是涨跌色 14% 透明、0.5pt 30% 描边，字就是涨跌色本身。我第一版照
  参照图做成了实心饱和红绿底加反白字，用户当即否掉：「不用那么红和绿，之前的淡红淡绿其实就很好，
  以前的那种涨跌幅那种设计，我说的是包裹以及颜色」——他拿富途图当参照时要的只是「价格在前、
  涨跌幅包在一颗药丸里」这个排法，不是它的重色。以后列表里的涨跌色块一律淡底淡字，不做实心块。
- 副文案只写「成交额 …」，没有振幅。
- 这颗药丸（`ChangePill`）是自选页、板块内品种表、长按预览卡共用的，改一处三处一起变。
