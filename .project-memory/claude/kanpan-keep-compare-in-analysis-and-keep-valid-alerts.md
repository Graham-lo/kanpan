# kanpan-keep-compare-in-analysis-and-keep-valid-alerts

**项目约定**：看盘「分析」面板里的对比入口要保留（和顶栏「对比＋」并存，不许因为顶栏有了就砍掉）；提醒只要还没失效就必须留存，不许因为列表精简、日志滚动或别的清理把仍有效的提醒删掉；用户 2026-10-06 明说

2026-10-06 我交付「顶栏对比＋ / 顶栏铃铛提醒表」那一轮后，用户回了一句：
「**分析里的对比要留，提醒只要没失效也要留存**」。两条都是对我上一轮取舍的纠正：

1. **「分析」面板里的对比入口要保留。** 我做顶栏「对比＋」时按 kanpan-one-entry-per-action
   把「分析」面板里的对比移除了，用户不认——对比在「分析」里是和指标、画线并列的一个大类，
   顶栏的「对比＋」只是快捷入口，两处并存。以后收敛入口时，「分析」面板里的既有大类
   （指标 / 画线 / 对比）不许砍，只能加快捷方式。
2. **提醒只要没失效就要留存。** 「失效」指它已经没有意义了：已触发（提醒只响一次，见
   kanpan-alerts-fire-once-no-repeat）、所挂的画线被删、品种下架这类。除此之外的提醒
   ——还没触发、画线还在、品种还在——不论建了多久、不论在哪一端、不论列表怎么精简，
   都必须一直留着，服务端与本地都不许按时间或条数清掉它。清理 / 滚动删除只能作用于
   「提醒日志」（触发记录）这类历史，不能作用于仍在等触发的提醒本身。
