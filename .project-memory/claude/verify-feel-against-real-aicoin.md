# 手感问题：去实测 AICoin，别猜它的行为

看盘项目的交互与手感基准是 AICoin。当我为了复刻某个手感而需要知道「AICoin 到底怎么做的」
时，用户的要求是**去真的用一遍**，而不是凭常识推断。他的原话是：
**「我手机上有 aicoin，你可以看看，真实测试一下」**。

背景是双指缩放那次：我已经在心里给「AICoin 大概是冻结价格轴还是连续贴合」编了几种
可能，正准备挑一种实现。用户直接把实物指给我——这说明遇到这类问题，正确的第一步是
找到可对照的实物去看，而不是在几种猜想之间做选择题。

## 能怎么对照

- 这台 Mac 上装了 **`/Applications/AiCoin.app`**（macOS 客户端），用 computer-use
  打开就能直接操作，滚轮缩放这类在桌面端能做的手势可以自己验。
- 用户的 iPhone 通过 USB 连着（`xcrun devicectl list devices` 看得到），但我没有驱动
  真机触摸的工具，双指捏合这种只能在 Mac 客户端上验，或者请用户描述/录屏。

验完把观察到的事实写进对应里程碑的验收证据里，再照着改实现。

## 模拟器不算数，要用他本人的手机

我后来为了挖 AICoin 的细节，把安卓包反编译之后又装了个 Android 模拟器想跑起来看。用户
直接否了：**「不用安卓那个了，删掉，再过一会直接连接我的手机操作 aicoin 这样更有参考
意义」**。

所以这条对照基准还要再收紧一层：**参考价值的排序是「用户本人手机上的 AICoin」＞
「Mac 客户端」＞「模拟器里跑的安装包」＞「反编译推断」**。模拟器上的表现不能代表
用户日常看到的那个 app，花时间搭模拟器环境是白费。遇到手感问题，直接安排连他的手机
去操作真机上的 AICoin；静态反编译只用来拿那些实测看不出来的常量（比如缩放上下限、
高度分配公式），不要拿它代替实测。
