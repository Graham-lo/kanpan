# kanpan-route-choice-is-binding

**项目约定**：看盘设置里的「行情线路」只有直连 / 网关两档，出厂默认直连、没有任何自动切换；选了哪条就走哪条，选择只记在本机这台设备上、不再随账号同步（2026-09-19 按审查 B7 改）

看盘（Kanpan）设置面板里有一行「行情线路」：直连 / 网关（`MarketRoutePolicy`）。
2026-09-17 用户在我验收这条开关时连发几句话定下规则：「设置中的网络切换会正确切换到链路吗，
不是摆设吧」「如果用户选择网络是直连那么就是走币安的网络不是 OKX」「选了哪条就走哪条」，
之后又追加：「现在软件默认就是直连，不做任何智能切换，选择什么就怎么切换，并且用户登录了
要记住这个选择，后面直接用相同的网络即可」「用户没登录就本地记住这个网络选择」。

含义：

- **出厂默认直连，没有「自动」档。** 原来的自动探测偶发误判就把他的真机切到 OKX 兜底，
  用户明确不要任何智能切换：不要 OKX 兜底、不要网关对冲、不要恢复排期、不要落盘上次交易所。
- **直连 = 只走币安直连。** REST 和 WS 都只拨币安自己的域名，探不通就明说「点此重试」，
  任何切到 OKX 的分支都不允许存在。
- **网关 = 只走 VPS 网关**（供 OKX），跳过直连。
- **改了策略要立刻生效**，REST 和已经连着的 WebSocket 都要跟着换线，不能只改历史请求。
- **选择要记住，但只记在这台设备上**：存在 `Prefs.routePolicy`，字段归类是 `deviceOnly`，
  下次开机直接按记住的线路起步，不再探测。

  2026-09-17 最初定的是「登录了随账号同步」。2026-09-19 GPT Pro 第二轮审查 B7 指出这和字段计划里
  「网络属性留在本机」的判据矛盾：A 设备选网关并同步，B 设备本来直连且没动过，同步后被改成网关。
  我起初以「这是用户定的产品规则」为由没改，用户说「这些你直接改啊」，于是按报告改成本机字段：
  新客户端不再上传它、云端档案里的旧值不覆盖本机、迁移时原样保住当前选择；服务端为兼容旧客户端
  仍认这个字段。直连／网关两档、出厂直连、无自动切换、改了立刻生效这些都没变。

以后凡是动 `RoutedMarketFeed` / `MarketRESTTransport` / `SourceSocketFactory` 这类路由代码，
都要按「用户选的线路是硬约束、代码不自作主张」来改，并且用真机 `MarketRouteUITests`
验证直连下拿到的是币安的 K 线。
