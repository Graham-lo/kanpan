# kanpan-bottom-bar-has-no-surface-of-its-own

**项目约定**：看盘的底栏不许有自己的底——页面的材料要从它身后穿过去；釉面渐变刷在记号本身上，不再有选中方块

2026-09-18 重做看盘底栏时，同一件事我错了三回，一次比一次淡，但错的都是「给底栏配一块
自己的材料」：先是左右内缩、带发丝边和投影的悬浮釉面卡片，然后是卡片撤掉但留一道沉到
`raised2` 的渐变带，最后是平铺一块和页面同色的 `theme.app`。第三版在取色上已经和页面
一模一样了，用户看真机之后还是说「我觉得白色不太好，应该和整体风格融合太突兀了」
「其它地方全是融合的」。

**「和页面同色」不等于融合。** 看盘的页面底本来就不是一个纯色：自选页身下是
`AuroraBackdrop`——底色、几团漂移的光斑、一道越往下越浓的 wash、一层颗粒。底栏在那道
wash 最浓的地方盖一块纯色，等于把整页味道最足的收尾裁掉换成一块白板，拼缝就在那儿。
正确做法是**底栏一个 `background` 都不画**：用 `safeAreaInset(edge: .bottom)` 把它挂在页面上，
页面自己铺满整屏、材料原样从底栏身后流到 home 条。这是
`kanpan-no-seams-one-continuous-surface` 在「浮层 / 常驻栏」上的具体解法。

**底栏还必须说页面的那套视觉语言。** 用户接着说「针对这块重点设计」「提升整体的美感，
不能因为底栏破坏 ui 的完整性，不然显得格格不入，不好看了」。整个 app 的语言是
**釉面渐变方块 + 白色记号**（品种徽章 `CoinBadge`、分类药丸、勾选圆点都是这一套），
而底栏当时是「浅底上一个灰记号」，所以那一栏读起来像从别的 app 贴过来的。选中格换成同一枚釉
（`accentLift → accent` 斜向渐变、圆角 0.31、白记号、淡影）之后才成了一家人。
以后在这个项目里新加任何常驻控件，先去找页面上已经存在的材料照着用，不要另起一套。

**占比要小。** 记号从 20 一路推到 36 是为了治「太素」，结果整条栏占了 112 点，用户说
「而且显得占比那么大」「不仅浪费空间，而且下面会显得空很多」「我希望能往下移一点」。
治「素」的是材料不是尺寸：有了那枚釉，记号收回 26、整条栏落到 50（系统标签栏是 49）、
留白全给上沿、底下贴着 home 条，反而更好看。

## 2026-09-18 续：釉从方块挪到了记号本身

同一天晚些时候，用户指着另一个窗口的板块气泡原型（`vG.html`）的底栏说
「我觉得这个好看啊比之前的精致一些」，紧接着补了一句「颜色搭配也很好看」。
那条底栏没有任何选中方块：四个记号直接画成彩色渐变实心图形——一根带金点的走势线、
三根高低不一的柱、一颗金星、一枚花瓣状齿轮，选中的那格满不透明度，没选中的压到 52%，
每个记号自己带一点柔影。

## 2026-09-28 续：融合保留，但内容不许和记号重叠

我在体验评估里指出：底栏没有自己的底，列表滚到末尾时最后一行的文字和底栏图标直接叠在
一起（板块品种列表里 ZEN 那一行的星形记号压在「成交额 25.64M」上）。用户的答复是：
「底栏确实存在这样的问题，这是之前融合的做法，我希望保留整体融合，但不要重叠。」

所以规矩是两条同时成立：底栏仍然不画自己的材料、页面从它身后穿过去；**但记号所在的那一带
不能有可读内容压在下面**——靠底栏区域一道从透明到页面底色的渐变把身后的行压淡、并给
滚动内容留够底部内边距让最后一行能滚到底栏上方，而不是给底栏加一块底。判据是滚到最底时
最后一行完整可读、记号周围没有文字。

所以底栏的定稿改成：**颜色长在记号上，不再有釉面方块。** 上面「选中格换成同一枚釉」
那一段已经被这一版取代，但「底栏一个 `background` 都不画」和「占比要小」仍然成立。
釉面渐变（浅色→深色、`.topLeading` → `UnitPoint(x: 0.35, y: 1)`）还是全 app 那一套语言，
只是现在刷在图形上；配色全部走 `PaletteSeed` 令牌（`seed.accent` 及其提亮、`seed.amber`），
所以青苔 / 陶土 / 经典三套皮肤和深浅色都自动跟着变，不要在底栏里写死颜色。
