# 看盘：成批删功能前先打 tag，方便以后恢复

2026-09-28 收设置项那一轮删掉了二十多个自定义选项，用户说：「**现在自定义选项删除了很多，
最好记录一个 tag，因为可能后面需要恢复某些设置的自定义，方便直接找代码恢复**」。

所以以后在看盘里凡是**成批做减法**（删一组设置、砍掉一个功能模块、去掉一套 UI）之前：

- 在删除前的最后一个 main 提交上打一个**带说明的 tag**（例如 `settings-before-trim-2026-09-28`），
  说明里列出这次要删掉的东西，并 `git push origin <tag>` 推到远程。
- 每个删除提交的说明末尾写「恢复见 tag …」；`.project-memory/PROJECT.md` 里记一节：
  每项被删的东西对应的字段名、文件与 UI 位置、同步白名单字段，以及这个 tag。
- 目的不是留分支（用户不要长命分支），而是让以后想恢复某一项的人能从 tag 直接定位到
  那一项的完整实现（字段、面板、同步契约），而不用在历史里翻。
