# kanpan-ui-no-lecturing

**项目约定**：看盘的界面不要堆解释性文案，能自动做的事不要弹窗让用户选

# 看盘的界面：少说话，能自动就别问

用户对看盘界面的一贯要求是**克制**。两条具体的：

1. **不要在界面上堆解释性文字。** 我给账号系统做的登录页写了副标题、安全提示、
   两段脚注，他的回话是「登录这个页面太多文字描述了，没必要」。登录页就是账号、
   密码、按钮（账号是用户名，邮箱注册后来停掉了，见 `kanpan-account-username-not-email`）；
   该讲的道理放在文档里，不是放在用户每天都要过一遍的屏幕上。
2. **能自动完成的事，不要做成让用户选的面板。** 我原本给「登录后本机匿名数据与云端
   数据合并」设计了一张面板，列出本机多少条、云端多少条，让用户三选一。他否掉了：
   「融合数据不需要展示哪些具体的融合，直接系统自动融合即可」。合并规则由我们定对，
   静默合并，用户不需要知道发生过这件事。

推广一下：在这个项目里，界面上每多一句话、每多一次询问，都要能说出它为什么非在
那儿不可；说不出来就删掉。
