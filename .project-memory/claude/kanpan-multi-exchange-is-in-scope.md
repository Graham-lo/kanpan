# kanpan-multi-exchange-is-in-scope

**项目约定**：看盘 2026-09-22 起要接 Coinbase 现货，并把多交易所能力抽成一个独立模块（品种身份 / 行情提供者 / 线路三者正交），因为后面还要接别家；这推翻了之前「多交易所 / Coinbase 不做」的判定

2026-09-22 用户说：「再开一个 codex 线程，让它把 coinbase 接入，把多交易所功能抽出来，不要散落
代码，因为后续还需要接入其它。」此前 `docs/不做清单.md` 里「多交易所抽象 / Coinbase」是不做项
（2026-09-17 的方案一直标着「待用户确认」）。这句话把它翻成了要做，清单已同步移出。

所以在看盘里：

- **多交易所是正式范围**，Coinbase 现货是第一个新交易所，之后还会接别家。
- **用户在意的是「不散落」**：交易所相关代码必须收在一个模块里（`KanpanNetwork` 的 Provider 层 +
  每家所一个文件夹 + 一份注册表；服务端同样一处分发），其它层只认 `InstrumentID` 和
  `MarketProvider`。接第三家应当只是「新建一个文件夹 + 注册表加一行 + 服务端加一条透传」。
  这是这项功能的验收标准，比 Coinbase 本身能不能看图更重要。
- 仍然不做的：OKX 持仓量副图；OKX 不是用户可见的交易所，它只是币安永续在网关线路上的服务端替身。
- 这条和 kanpan-us-equity-data-is-binance-only 不冲突：美股行情仍只用币安自己的标的，
  Coinbase 接的是加密现货。
- 这类大功能用户要的是**第二条 Codex 线程并行做**，放在独立 git worktree（`kanpan-coinbase`、
  分支 `multi-exchange`）里按阶段 ff 合回 main，不和第一条线程抢同一个工作树。

## 三家交易所各自只用一种品种（2026-09-24 用户说明）

做「主力订单流」派活时我把范围写成「币安合约，非币安品种没有全簿就灰掉」，用户插话纠正：
「**目前已经接了 okx、币安和 coinbase，okx、币安一律只用 usdt 合约，coinbase 只用现货，以前的项目就是这么干的**。」

所以看盘的交易所范围是固定的三家、每家一种品种：
- **币安**：只用 USDT 本位永续合约（直连线路直接打币安；网关线路经 stream_hub 转发）。
- **OKX**：只用 USDT 永续（SWAP），只有网关这一条路（`Backend/kanpan-gateway/okx_hub.py` 把 OKX 频道翻成币安风格帧，网关线路下币安 / OKX 两路竞速）。
- **Coinbase**：只用现货。
- 不接 OKX / 币安现货、币本位合约、期权等；以前的订单流项目（send-tradfi 的 bit-orderbook-binance / -okx / -coinbase 三个 crate）也是同样的三家三种。
- 凡是要接簿、成交、行情的新功能，默认三家都要覆盖，不能只做币安、把另外两家灰掉。
