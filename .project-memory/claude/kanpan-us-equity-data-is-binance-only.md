# kanpan-us-equity-data-is-binance-only

**项目约定**：看盘的美股行情只用币安自己的标的，不接传统券商数据源；因为标的数量有限，美股板块不能像加密那样细分

2026-09-18 我在给看盘设计板块气泡图时，打算给美股自建一套 AI 产业链板块，并准备从
传统券商 / 第三方行情源补齐币安没有的标的。用户纠正了这个方向：

> 「其实 bian 美股合约很齐全了，不需要传统券商的数据，并且 bian 本身接了美股，也有
> bstock，这些数据是否可以拿到，因为本身价格都是差不多的，所以不要细分」

所以在这个项目里有两条连在一起的要求：

**美股行情只走币安自己的路。** 币安 USDT 永续里 `underlyingType` 为 `EQUITY` /
`HK_EQUITY` / `KR_EQUITY` / `CN_EQUITY` / `PREMARKET` 的那批合约就是美股（及港韩 A 股、
未上市公司）的数据来源，加上币安自己的股票类产品。不要为了补标的去接传统券商或第三方
行情源——币安的报价和券商差不多，多接一路只是给自己增加一条会坏的链路。
（这说的是**行情价格**。市值那类静态元数据仍按 `docs/市值口径与数据来源-2026-09-18.md`
走 stockanalysis，那是另一回事。）

**正因为标的只有这些，美股的板块就不能细分。** 币安的股票合约总共不到 200 个，其中
AI 相关的更少。分成十来个产业链细分段之后，每段只剩两三个标的，板块涨跌幅的中位数在
两个样本上没有任何统计意义，而且缺的标的还得靠假数据凑——2026-09-18 工作树里那份
`prototype/板块气泡-2026-09-18.html` 就是这么做的：它把美股切成 GPU / 定制 ASIC / HBM /
晶圆代工 / EDA / 先进封装等 13 段，里面 UMC、GFS、SNPS、CDNS、ASX、AMKR、FN、ANET、
ETN、NVT、CEG 币安根本没有，那份数据自己标了 `demo:true`。

加密不受这条限制：币安有 526 个 COIN 永续，细分板块是用户点名要的。**细分只对加密，
美股要粗。**

## 2026-09-18 补：不细分 ≠ 只分四段，产业链的关键环节一个都不能少

当天晚些时候用户连着补了两条，把上面「美股要粗」的尺度校准了：

> 「端侧 ai 相关的，机器人也要加上」
> 「还有云厂商，他们是 ai capex 来源」

所以「不细分」说的是**不要按 GPU / 定制 ASIC / HBM / 晶圆代工 / EDA / 先进封装那种
工艺环节去切**（那样每段只剩两三只，中位数没有统计意义，还得拿币安没有的标的凑），
**不是**说只留四个大段。产业链上有独立叙事、又能凑够标的的环节必须单独立段，
当天定下来的是 10 段：算力芯片、存储、设备与材料、光通信与网络、服务器与电力、
云厂商、算力租赁、端侧 AI、机器人与具身、模型与应用。

**这个段数一直在动，别拿这里的清单当现状。** 后来服务器与电力拆成了两段、加了「软件」、
「硬件」又并回「算力芯片」（`bddf51c`），现行是 12 段。真正的清单只看
`KanpanCore/Sources/KanpanCore/Sector/SectorCatalog.swift`。这一段记的是**立段的尺度**
（有独立叙事 + 凑得够标的才单独立段，不按工艺环节切，上面不盖粗段），不是段数本身。
改段数时注意两张简称表要一起改：`SectorCatalog.shortNames` 和
`Sector/SectorBubbleRenderer.swift` 里的 `SectorShortName`——这是这个项目的老坑。
另外 `SectorLayout.referenceCount` 固定是 13，那是量半径的尺子，不是板块数，**不要跟着段数改**：
它原本是拿球场面积反算的，颗数越少球越胖，改小了加密和美股两页的球会一起变胖，
用户抱怨过「美股气泡太大」就是这么来的。

**立段还有一条硬下限：一段至少要有 3 个当场取到报价的成员才上得了气泡场。**
`SectorAggregate.minEligibleMembers == 3`，`eligible` 数的是**真的算出涨跌幅的成员**
（`rets.count`）而不是名单长度，`SectorSelection.swift` 里 `!$0.isFallback && $0.eligible`
把不够的整段滤掉。所以一个刚好 3 人的段只要少一条报价，整颗气泡会**静悄悄消失**——
这很容易被误判成布局 bug，先查这条再查渲染。上面「凑得够标的才立段」因此有个数字：
名单 3 人是死线，要留余量。（`bddf51c` 被并掉的「硬件」当时正卡在 3 上；现在最小的
「算力租赁」是 5 个。）

**只有这一层，不要在它上面再盖粗段。** 我一度把这 10 段归并成「硅与制造 / 机房与互连 /
云与算力 / 终端与模型」4 个粗段，并为此在界面上加了一个粗细粒度切换。用户当场否掉：
「你直接细分就行了啊，为什么还要粗分呢」。板块气泡就两层——板块 → 成员品种，
多一层粒度只是把「看哪个粒度」这个选择推给用户，属于项目一直反对的那种多余开关。

其中云厂商与算力租赁是用户点名要拆开的：**云厂商是 AI capex 的出钱方、是整条链需求的
源头，neocloud 是收 capex 的一方**，两者方向相反，混在一段里中位数会互相抵消。
2026-09-18 的快照就是证据——合在一起是 +0.74%，拆开是云厂商 +0.98% / 算力租赁 −0.45%。

判一只股该不该进某段之前，先用 `/fapi/v1/constituents?symbol=<SYM>USDT` 反查它背后的
真实交易所代码，不要按代号猜（HYUNDAI 是现代汽车 A005380，它持有 Boston Dynamics，
所以进机器人段；HK1810 是小米，进端侧）。允许一只股跨段（高通同时在算力芯片和端侧），
每段各自取中位数。另外，像 MARA 这种「在把矿场改造成 HPC」的标的不要放进算力租赁——
它的股价还是比特币的 beta，会把板块中位数污染成币价。
