# 看盘：服务端存历史数据的预算是 20–40 GB，动态滚动

2026-09-24 做主力订单流的服务端历史时，我推算一只品种一天约 5 MB、7 天约 40 MB，
并按 7 天保留来设计。用户回复：

> 「可以的，服务器资源很空，完全可以存 20–40 GB，动态滚动即可」

所以在看盘里，服务端（kanpan-api 所在的 VPS，Postgres）存行情类历史——大单生命周期、
成交统计、以后可能的其它时序数据——的预算是 **20 到 40 GB**，做法是**按时间滚动**：
保留期尽量长（按数据量倒推，几十天到几个月），总量逼近预算时删最旧的，不要为了省空间
把保留期砍到几天。这条只针对服务端；手机端仍按 kanpan-persist-small-is-fine（几 MB 到几十 MB）
和 kanpan-device-resource-budget（存储加内存不超过约 2 GB）来。
