# kanpan-alerts-independent-of-drawings-and-hide-drawings-toggle

**项目约定**：看盘里画线与提醒互不依赖：删掉画线绝不能连带删掉挂在它上面的提醒（推翻 09 月定的「本机删线显式级联删提醒」）；竖屏要有一颗主动隐藏全部画线的按钮，隐藏画线不影响提醒；用户 2026-10-06 明说

2026-10-06 用户在我交付提醒 / 对比那一轮后说：

> 「画线要给一个主动隐藏的按钮，不然竖屏情况下我既想保留警报又不想看画线体验非常不好，
> 即使画线删除也应该保留预警信号啊。画线和警报是不冲突的，我删除画线也不应该删除警报才对。」

所以在看盘里这两条是长期规矩：

1. **提醒不依附于画线。** 画线提醒建立时就把几何（`lines`）抄进提醒自己身上，之后无论
   那条线被删、被隐藏、在别的设备上找不到、网页认不出工具，提醒都照常留着、照常评估、
   照常在图上留一道自己的提醒信号（提醒线 + 铃铛）。这推翻了 2026-09 定的
   `AlertArchive.reconcile`「本机删线 → 显式级联删提醒」和网页 `lineAlerts.ts` 的同款规则；
   「线被挪了 → 几何重算」这一条仍然成立（线还在时提醒跟着线走）。删提醒只有用户自己在
   提醒列表里删、或者提醒触发（触发即删，见 kanpan-alerts-fire-once-no-repeat）两条路。
2. **竖屏要有一颗「隐藏画线」的主动开关**，让用户在竖屏看盘时把所有画线收起来，但提醒
   继续生效、提醒信号照常可见。它是体验类状态，跟人走、全端同步
   （见 kanpan-preferences-follow-the-person-instantly），iOS、手机网页、电脑网页都要有。
3. 这两条合起来的原因：用户的典型用法是横屏画线、把提醒挂上去，然后回到竖屏只看行情和
   提醒，不想再看满屏的线；画线对他是「画提醒用的脚手架」，提醒才是要留下来的东西。
