# kanpan-sync-is-not-a-login-gate

**项目约定**：看盘里「跨设备同步」和「必须登录才能用」是两件事——体验类状态离线照常可用、云端只是同步通道；只有像复盘这种运算在后端的功能才真的要登录，那是权限验证

2026-09-19 用户在定完「云端宕机不能导致不可用」之后，把这条规则的**边界**也划清楚了：

> 「是的，**体验这块本来就是跨设备同步，不是权威**，只有某些功能必须要登录，那是**后台的权限验证**，
> 比如**复盘就是必须登录才可以用，因为这个功能由后端处理**。」

所以看盘里要把两类东西严格分开，不要混为一谈：

**一、体验类状态（偏好、图表布局、皮肤与深浅、自选与分类、画线、钉住的周期、行情线路……）**
云端对它们只是**跨设备同步的通道**，不是权威，也不是使用的前提。断网、服务器宕机、没登录，
这些功能都照常可用，且用的是这个人自己的值。本地永远留一份完整的、带账号标识的缓存
（见 kanpan-cloud-outage-must-not-break-the-app）。**绝不能因为「它会同步」就给它加登录门槛。**

**二、运算真的发生在后端的功能（复盘是典型）**
这类功能**必须登录**，因为数据和计算都在服务端，本地没有也算不出来。这里的登录是
**后台的权限验证**，不是同步机制。它该有明确的「请先登录」入口，而不是靠偏好同步那条链兜着。

判断一个功能属于哪一类，问一句：**断网时它还能不能给出正确结果？** 能，就是第一类，不许加登录门槛；
不能（因为结果只有服务端算得出来），才是第二类。

这条的意义在于防两个方向的错：把体验类状态做成「登录才生效」（用户离线就被打回出厂默认），
以及把后端功能做成「离线也假装能用」（给出算不出来的结果或空界面）。
