# kanpan-design-against-latest-working-tree

**项目约定**：看盘做原型、交接说明或验收之前，必须先重读当前工作树里的最新代码，不能沿用上一版原型或旧文档里的代码事实

2026-09-17 我做交互定板原型时，头部、周期条、设置面板都是照着更早的「陶土青苔」原型和
几小时前的代码印象画的。用户连着纠正了两次：「你要看看最新的代码」「你用的不是最新代码了」，
并补充「注意实现要在最新的代码上」「自选列表页面 opus 窗口正在改」。

看盘（Kanpan）项目里代码一直在被另一个 Opus 窗口高频改动，几小时前的印象就已经过时。
所以每一轮动手之前都要：

- 先 `git fetch` 并对比 origin/main 与本地，再看工作树里未提交的改动（`git status`、
  按修改时间列文件），把「最新代码」明确定义为当前工作树，而不是某个 commit 或旧原型。
- 原型里出现的每一个界面（头部、周期条、底栏、面板、设置、账号、复盘）都要对着现在的
  Swift 文件重读一遍再画，file:line 引用只能来自这次重读。
- 正在被另一个窗口改的文件（按 mtime 判断，最近几分钟内还在变的）视为禁区：不设计、不改、
  交接说明里明确排除。
- 交接给实现方时也要写明「以拉取时的工作树为基线」，并要求对方先 fetch。
