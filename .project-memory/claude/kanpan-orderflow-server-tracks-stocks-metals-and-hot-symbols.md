# 看盘主力订单流：服务端跟哪些品种，由用户定的优先级

2026-09-25 我准备直接改主力订单流的服务端（保留期、跟踪上限）时，用户叫停：
「你先给具体的方案，先把方案敲定下来。」随后给了跟踪范围的原则：

> 「如果预算不太够那么美股存储 soxl mrvl 几个重要品种要定的，然后就是金银，还有一些热门品种。
> 热门品种是动态，可以是涨幅比较高的，持仓有异动的等等，总之是容易吸引人眼球的。」

我给了一版「固定 8 只美股 + 金银 + 热门 15 只 + 总量 40」的方案，用户回：

> 「既然存储不是问题你多订一些啊，ai 产业链成交量大或者热门品种，还有一些山寨。」

所以在看盘里：

- **范围要宽，不要自己抠**。存储实测不是瓶颈（ETH 一天 2.9 MB）时，服务端常驻跟踪按「用户可能会点开的都提前跟上」来定：
  AI 产业链美股（芯片、存储、光模块、服务器、云、AI 应用、算力电力）在币安有合约的全部；金银、原油等大宗
  与 QQQ / SPY 这类指数；币安 U 本位成交额靠前的山寨；再加一组动态热门。三只主币本来就常驻。
  真正的约束是 VPS 的 CPU / 内存与交易所的连接、快照限频，扩范围时按这些分阶段上、量过再加。
- **固定美股层的名单是「AI 产业链全部」，不按成交额再剪。** 用户 2026-09-25 点名：存储三只
  闪迪（SNDK）、美光（MU）、海力士——海力士在币安有两个代号，正股 SKHYNIX 和 ADR SKHY，
  两个都要；INTC、ARM 也要加。他先说「固定中的英伟达不用」，随后改口「还是 ai 产业链全部吧」，
  所以 NVDA 也保留。只有币安根本没上合约的才跳过。
- **动态热门要真的动态**：信号是「容易吸引人眼球」的——24 小时涨跌幅大、持仓量异动、成交额突增；
  入榜就跟、掉榜后再停，不是写死一张表。
- **保留期仍是几天**（见 kanpan-orderflow-history-few-days-and-okx-tradfi），扩品种不改这条。
- **涉及服务端跟踪范围、预算取舍这类事，先把具体方案（哪几只、什么信号、多少只、多大开销）
  写清楚给用户敲定，再派活。** 这是 kanpan-plan-first 的一个明确实例：它不是「修 bug」，
  用户要先看到方案。
