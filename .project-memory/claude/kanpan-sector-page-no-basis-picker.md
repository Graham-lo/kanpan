# kanpan-sector-page-no-basis-picker

**项目约定**：看盘不把算法口径、统计方法这类选项摆给用户选（中位数/均值/成交额加权/市值加权都由我定一种）；一页上的模式最多两个常用的；用户要的是功能，不是自己去发现

2026-09-18 我给板块强弱写实施方案时，保留了板块页上现有的「中位数 / 均值 / 成交额加权」
三档口径切换，又打算把它退到「…」菜单里。用户直接否了：「现在我不需要这么多分类，比如按照
市值、按照成交额加权，用户搞这么多分类根本不知道怎么回事，这里需要为用户做决定，最多选择
两个常用的分类……无论你是使用什么算法，总之选择一个最合理最好用的即可」。我改了之后他又
补了一句更一般的原则：「不要展示太多东西给用户选择，用户要用的是功能而不是他自己去发现」。

所以在看盘里，这是一条全局原则，不只针对板块页：

- **算法口径、统计方法、参数这类用户看不懂的东西不暴露给用户选。** 中位数还是均值、
  成交额加权还是市值加权，是我该做的决定；连收进「…」菜单都不要，直接只留一种。
- **同一页上给用户的模式最多两个常用的**（比如板块页的「今日 / 5 日」）。多于两个就该拆成
  不同页面功能，而不是并排一串 chip 让用户去试。
- **功能要直接摆在用户面前能用，不是藏着让他自己发现。** 一个选项如果需要用户先理解
  它是什么才知道选哪个，那这个选项本身就不该存在。
- 用户的原话是「选择一个最合理最好用的即可」——他要的是我替他拍板，不是把选择权交回去。

这条和 kanpan-ui-no-lecturing（能自动做的事不要让用户选）、kanpan-one-entry-per-action
是一脉的，但更具体：它针对的是「算法口径 / 统计方法 / 展示模式」这类选项的数量。
