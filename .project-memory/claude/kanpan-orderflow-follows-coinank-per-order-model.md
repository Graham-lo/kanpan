# kanpan-orderflow-follows-coinank-per-order-model

**项目约定**：看盘「主力订单流」2026-09-24 起照 CoinAnk「主力大额挂单」的逐单模型做：每条大单是某家交易所某个产品上一个 ≥ 门槛的价位，从首次出现的那根 K 线画到撤单/成交或现在；产品分现货、U 本位永续、币本位永续、交割；门槛与步长是用户可改、全端同步的指标设置，只给初始默认值

# 看盘：主力订单流照 CoinAnk 的逐单模型做，门槛与步长是用户设置

2026-09-24 我把 CoinAnk「主力大额挂单」的前端逻辑从它的 JS 包里读出来汇报后，用户拍板：

> 「直接按照这个实现即可，永续应该分 u 本位永续和币本位永续吧，另外交割其实之前项目也做了好像。」
> 「步长和过滤单位那就干脆做成和 coinank 一样自己设置，这里不再为用户设置，只是给出初始默认值，
> 就按照之前定下的那套来作为初始值，后续用户也可以修改并保存全端同步。」

所以主力订单流的定稿模型是这样的：

- **逐单模型，不是聚合桶模型。** 一条「大单」= 某家交易所 × 某个产品 × 某一侧 × 某个价位上的挂单量
  ≥ 该产品的门槛。它有自己的生命周期：首次出现的时刻、初始金额、当前剩余、已成交比例、
  撤单/成交/仍在的状态。画法照 CoinAnk：从首次出现那根 K 线横着画到消失那根（或现在），
  粗细按「金额 ÷ 步长」，透明度随成交比例增加，撤掉的画成虚线并压到 45% 不透明度，
  开关分成「现货 / 永续」「已成交买 / 卖」「已撤销买 / 卖」。
  之前那套「跨交易所合并成桶、算利用率、看邻居中位数与 MAD」不再是主线。
- **产品四类：现货、U 本位永续、币本位永续、交割。** 原项目 send-tradfi 确实做过交割与币本位
  （ProductKind Spot/Perpetual/Delivery，币安 usdm/coinm 两族端点，OKX swap/futures），
  看盘要补币安 COIN-M 与交割、OKX USD-SWAP 与 FUTURES 的簿。现货接 Binance/OKX/Coinbase，
  合约类接 Binance/OKX。同一张图上把所有交易所、所有产品的大单叠在一起画，现货与合约用颜色区分。
- **门槛与步长是用户设置，不替用户定。** 这是 kanpan-sector-page-no-basis-picker
  （算法口径不摆给用户选）的一个明确例外：CoinAnk 就是让用户自己填「现货大单金额 / 永续大单金额」
  和步长，用户要一样的。指标设置里按产品各一个金额、加一个步长，可以改。
- **初始默认值就是之前定下的那张表**（见 kanpan-orderflow-thresholds-are-principal-wall-v1）：
  BTC/ETH 现货 100 万、永续与交割 500 万；SOL 75 万 / 250 万；美股类与金银 200 万；
  山寨币按 24h 成交额分档；步长 BTC 100、ETH 1、SOL 0.1 等，表外品种按前收 × 0.1% 取 1/2/5 档。
- **用户改过的值要落盘并全端同步**：走账号同步通道，客户端字段白名单与 kanpan-api
  `sync_validation.rs` 两端都要加字段（见 kanpan-finish-features-completely 里「两端清单要对账」）。

## 2026-09-24 傍晚的纠正：画法与交互也要照 CoinAnk，历史要长

第一版画出来之后用户看了说「都看不清啊」「点击相应色块都不显示多少个，一共多少 usdt 面额」「也太短了吧」，
然后开了 CoinAnk 网页版（Binance BTCUSDT SWAP 15m）给我看：

> 「你看 coinank 都是横向的价格带啊，生命周期完成后颜色都不一样，比如深颜色是已经成交，部分成交也是深的」
> 「你看我鼠标悬停在这个上面就有相应的展示框」

所以主力订单流在看盘里的定稿画法与交互是：

- **横向实色价格带**，不是半透明细条。带子要粗（按金额分档，刚过门槛也得一眼看见）、完全不透明。
  之前「透明度 0.25 起、已撤销再乘 0.45 加虚线」那套太淡，用户看不清，作废。
- **颜色只分深浅两档**：这一单出现以来只要有成交（部分成交也算）就是深色，一点没成交就是浅色；
  撤单/成交/挂着由详情卡说，不靠颜色和虚线表达。买卖与现货/合约的区分照旧（合约走皮肤涨跌色，现货黄/紫）。
- **点一下色块要出详情卡**（手机没有悬停，用轻点代替），内容照 CoinAnk 的卡：交易所与产品、买/卖单与价格、
  数量（多少个 BTC）与金额（多少 USDT）、状态（挂单中/已成交/已撤销）、成交金额与比例、初始金额、
  成交数量、初始数量、委托时间、持续时间。卡的样式沿用十字线那张开高低收卡，不是浮动控件。
- **历史要长**：CoinAnk 一打开就能看到两天前的带子，因为它服务端在 24 小时跟踪。看盘也要由
  kanpan-api（Rust）常驻跟踪并提供历史接口，手机打开品种先拉历史再接着本地实时跟踪；
  只靠手机打开那一刻起算的历史是不合格的（「也太短了吧」）。
