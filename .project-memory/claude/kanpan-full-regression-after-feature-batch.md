# 看盘：一批功能落地后要再做一轮压测 / 回归

2026-09-28 我排好「回放 → 收设置项 → 部署 → 个性化学习」的顺序后，用户补了一句：
「**注意做完再进行一次压测，因为加入了新功能，可能有很多的 bug**」。

这是长期要求：每当一批新功能（不止一个）落到 main 之后，收尾报告之前要单独做一轮
全面的测试，而不是每个功能只跑自己那一两条受影响的用例就算完。平时改动的验证仍按
kanpan-run-only-affected-ui-tests 只跑受影响的用例；这一轮是**批次结束时**的额外关卡。

这一轮包括：

- **整套用例**：全部单元测试与 UI 套件跑一遍（在模拟器上，走 `make` / `machine-guard.sh run`，
  按机器资源排队），红的一律修掉，不列成待办交回去。
- **以交易员身份走一遍**：新功能和被它们碰到的旧功能都从用户视角完整走一遍（见
  kanpan-verify-by-running-the-app），带着真实任务用，不是点一下看有没有崩。
- **压力与边界**：高频切品种 / 切周期 / 开关面板、大量自选与提醒、弱网与断网重连、
  前后台切换、旧版本落盘数据升级、登录退登来回切；看崩溃、内存增长、卡顿和数据错乱。
- **服务端新接口**：对新加的接口做有界的负载测试（按 kanpan-user-scale-is-tiny 的规模放大
  几倍即可，不是打垮它），先备份、看错误率与延迟、确认不影响线上其他用户。
- 发现的 bug 按 kanpan-fix-root-cause-including-network 直接修、推、再验，最后才写收尾报告。

补充（同日）：我把「压测排在最后」说了一遍之后，用户又强调「**我的意思是当前所有任务都完成再做压测**」。
所以这一轮测试只做一次，时点是手头排队的全部任务（不管几个功能）都落地之后，不要中途按功能
分批做、也不要一个功能落地就先测一轮再继续下一个。中途每个功能仍只跑自己受影响的用例。

## 网页版一样适用，而且要「深度」

2026-09-29 网页版做完账号 / 订单流 / 可拖拽区域 / 多图布局这一批之后，用户又说：
「**注意全部做完对 web 做一次深度压测，这样可以找出更多的 bug**」。所以这条规矩不只针对 iOS，
网页版每批功能收尾也要做，而且他要的是「深度」——不是把回归脚本再跑一遍就算，
要比上一轮回归更狠：整套 vitest + 回归脚本、以交易员身份把新旧功能全走一遍（含 16 图布局、
拖拽分隔条的极值与双击复位、每格独立品种与周期）、高频切换与长时间挂机看内存与 WS 连接数、
多标签页同时登录同步、断网重连、旧 localStorage 升级、服务端新接口的有界并发负载；
发现的 bug 直接修、推、再验，最后才写收尾报告。

我回了一句「全部落地后做深度压测」，他又纠正：「**我的意思是全部功能完成，最后再做深度压测**」。
这已经是第三次强调同一件事，所以要读得更严：「全部功能」指手头排队的**每一项**功能都做完——
包括正在跑的几路子代理、以及像「OpenMarket 通读后要吸收的点」这种还没开工的后续功能——
深度压测是整条队列的**最后一步**，不是当前这一批子代理收尾时的一步。中途各功能只跑自己受影响的用例，
不要在两批功能之间插一轮压测。

## 手机网页版也一样：批次结束时「深度代码审查 + 压测」，有问题直接根因修

2026-09-30 手机网页版（PWA，照 iOS 复刻）四条子代理线快收尾时，用户说：
「**所有移动版项目完成安排一次深度代码审查和压测，有问题直接根因修复**」。

这条把上面的规矩再扩了两处：一是这一轮不只是「压测」，还要**深度代码审查**——按模块
（图表引擎与画线、同步与 store、页面与提醒、行情页宿主）派独立的审查子代理逐文件读代码、
对照 iOS 原文件找移植偏差与逻辑漏洞，不是只跑测试；二是审查与压测发现的问题一律**直接根因修复**
并推上 main，不列清单交回去（与 kanpan-review-items-all-get-fixed、
kanpan-fix-root-cause-including-network 同一意思）。时点仍是「所有移动版项目完成」之后，
也就是全部子代理线都推上 main 并部署之后再统一做一次。

## 还要做并发

2026-10-03 用户在手机网页版这一批（指标布局跟人走、各页对齐 iOS、复盘本页面）还在收尾时说：
「**全部任务完成做压测，做并发，有 bug 全部根因修复**」。所以最后这一轮除了压测，还必须专门
测并发：同一账号多标签页 / 多设备（iOS + 手机网页 + 电脑网页）同时改同一份设置看同步是否收敛、
不互相覆盖；快速连续操作触发的并发请求（切品种、切周期、开关指标）不串数据；服务端接口在有界
并发下的错误率与延迟。时点不变——仍是手头全部任务都落地之后的最后一步。
