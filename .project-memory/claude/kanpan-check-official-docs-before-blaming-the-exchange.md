# kanpan-check-official-docs-before-blaming-the-exchange

**项目约定**：看盘里断定「交易所接口坏了／被墙」之前，必须先查交易所官网文档的现行端点；用户手机上 TV／AICoin／官方 App 有数据就是我端点用错了的证据

2026-09-18 我在查看盘直连模式为什么卡时，实测出 `wss://fstream.binance.com` 上
`aggTrade` / `markPrice` / `ticker` / `kline` 全家族一帧不发，而同一条连接上
`bookTicker` / `depth` 正常；换了十几个不同地区的机场出口、又在用户自己的美国 VPS
上复现，结果一模一样，于是我下结论说「这是币安自己 U 本位推送的故障，和你的网络无关」。

用户当场否掉：「关于 bian ws 的正确连接你去官网查一下，不可能啊，tv aicoin 我手机
bian 都有行情数据」。查了币安开发者文档才发现，USD-M 合约行情推送的基址官方列了两个，
`wss://fstream.binance.com` 和 `wss://stream.binancefuture.com`，后者所有流都正常，
连国内 DIRECT 直接拨都通。前者只是被迁移得半死不活。

所以在这个项目里有两条：

**别拿自己的实测去宣告交易所故障。** 交易所的公开行情接口挂掉是极小概率事件，我的
端点、路径或域名用错了才是常态。哪怕多个网络、多个出口、多个客户端都复现，那也只能
证明「我这个用法到处都不work」，不能证明「交易所坏了」。下结论之前先去官网文档核对
现行的基址、路径和参数——这一步是必需的，不是可选的。

**用户手边的应用有数据，就是我错了的硬证据。** 用户说 TradingView、AICoin、币安官方
App 都有行情，那说明数据源是活的，差别只在连法。这种反驳要当成线索立刻去查文档，
而不是解释成「它们走的是别的通道所以不算数」。
