# kanpan-no-ai-practical-features-only

**项目约定**：看盘不接 AI；新功能方向只要「实用、体验好、替用户着想」的；只读交易所 API 的用途 2026-09-27 定为「自动复盘」（拉成交、拼回合、算结果），不是把仓位画到图上；交易所做不到的条件提醒仍是认可方向

# 看盘：不接 AI，功能只要实用、替用户着想的

2026-09-24 用户问我「以后要加功能最推荐什么」，我推荐了用币安只读 API Key 把用户自己的仓位
画到图上，并顺带能做交易所做不到的自定义提醒（离强平 X%、浮盈回吐、收盘确认等）。用户回：
「你说的接入 api 确实是一个方向，而且很实用，因为可以设置目前交易所做不到的自定义提醒。这点先记下。」

随后我讲了「以后接 AI 要先打哪些底子」，用户直接否掉了：
「**ai 就不要接了，我要实用体验好的，帮用户处理着想的**。」

所以在看盘里：

- **不接 AI**。不做 AI 总结行情、AI 看图、对话式助手，也不为将来接 AI 去铺工具面、上下文快照
  这类基建。提功能建议时不要再往 AI 方向想。
- **功能建议的标准是三条**：实用（交易员每天真会用）、体验好、**替用户先想一步**（自动帮他把
  本来要手动做的事做掉，比如自动标关键位、离开期间的变化、按仓位自动挂提醒），而不是给他更多
  按钮和选项。这是 kanpan-no-flashy-rarely-used-features 的正面表述。
- **直接交付结果，不让用户自定义**。同一天用户把标准说得更明白：「体验最好的事莫过于直接交付结果，
  而不是让用户自定义各种东西，处理好细节，交易员常用的、日常的甚至冷门的都给予处理」。所以新功能
  的形态是「app 替他把繁琐事做完、把结果摆出来」，不是给他一个可配置的工具；细节由我定死，
  冷门但关键时刻有用的事也要覆盖到。可以不受现有功能框架限制去想。
- **已记下的方向**：只读交易所 API 接仓位上图（不下单、Key 只存本机 Keychain、不进云端），
  以及基于仓位与图表条件的自定义提醒。这是用户认可的，但还没排期；真要做时按 kanpan-plan-first
  先出方案。

## 2026-09-27：只读交易所 API 的用途是「自动复盘」，不是把仓位画到图上

2026-09-27 我再次建议「只读交易所 API 接仓位，开仓价 / 强平价画成两条线落在图上」。用户回：
「我建议只读交易所**不是显示在上面，而是做成自动复盘，直接帮用户处理**」，并顺手把我另一条
「提醒触发后一键记一笔」砍掉：「不用做，因为自动复盘了」。

所以以后在看盘里提到交易所只读 API，形态只有一种：app 拉用户的成交明细，自动把每个仓位回合
（从 0 建仓到回 0）拼成一条复盘记录，算出盈亏、费用、持仓期间最大浮盈浮亏、平仓后走势、
战绩统计与周报，用户一个字段都不用填。**仓位、开仓价、强平价、成交标记一律不画到主图上**，
「提醒后自动记一笔」也不做。这正是他说的「直接交付结果」的那种功能：替用户把复盘这件繁琐事做掉，
而不是给他多一层可看的数据。Key 只存本机 Keychain、只收只读权限，不下单，这几条不变。
