# kanpan-stays-native

**项目约定**：看盘坚持 iOS 原生实现，不走 WebView 套壳或跨端方案

2026-09-15 讨论过用「原生薄壳 + WebView + JSBridge，UI 全部用前端实现」来同时覆盖 iOS、鸿蒙和安卓（起因是用户朋友的手机是纯血鸿蒙 HarmonyOS 6，装不了 APK 也装不了 iOS 包）。权衡之后用户明确选择**继续做原生**。

所以后续不要再主动提议 WebView 套壳、Flutter/RN 之类的跨端方案来解决多平台覆盖问题，除非用户自己重新提起。

用户做这个决定的理由是体验：看盘的目标是对齐 AICoin 的手感，而 WebView 方案在「手指贴着屏幕」的那几十毫秒上必然退让——触摸事件要穿 WebKit 的进程间通信，十字线跟手会比原生慢 1 到 2 帧，这一项换语言、换桥接写法都绕不过去。用户宁可接受「每个系统一套原生」的成本，也不接受主图手感退步。
