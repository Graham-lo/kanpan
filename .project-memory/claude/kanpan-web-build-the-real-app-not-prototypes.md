# kanpan-web-build-the-real-app-not-prototypes

**项目约定**：看盘网页版 2026-09-29 起要的是真正能用的产品（真数据、真账号、部署上线），不是静态原型；用户说「直接开始动工」时就是开工写正式代码，不要再做一版原型

2026-09-29 我按用户「默认线条的粗细和大小……直接开始动工，不要和 iOS 混合到一起，但还是同一个仓库」
的话，又在 `prototype/web-2026-09-29/` 的静态原型上改了一轮线宽并部署。用户回：

> 「我的意思是你直接开始动工，**我要的不是原型**」

所以网页版的规矩从这天起变了：

- **原型阶段结束**。此前两版网页原型（TradingView 风格图表、27 寸 2K 排版、三套皮肤、线宽表）
  的视觉与交互就是定稿，之后的工作是把它做成**真正的网页产品**：接真实行情（币安直连 / 网关）、
  接 `Backend/kanpan-api` 的账号 / 同步 / 订单流 / 复盘接口、能登录、能存自选与画线、部署到线上。
- **「直接开始动工」= 开始写正式代码**，不是再做一版原型给他看。有设计上的取舍自己按已有记忆和原型定稿判断，
  写在汇报里，不回头问。
- 原型目录里的图表引擎、样式与图标是这套 UI 的出发点，正式代码可以从它搬，但正式代码要放在仓库里
  网页版自己的目录（与 iOS 工程并列、不混），并且要有正常的工程结构（构建、类型、模块、测试）。
- 与这条相关的既定规矩仍然有效：网页版视觉独立于 iOS（kanpan-web-is-its-own-design-not-ios），
  K 线用 TradingView 那一套、先按 2K 屏做（kanpan-web-uses-tradingview-chart-27in-2k），
  后端一律 Rust 的 kanpan-api（kanpan-backend-rust），做完要部署上线让他在浏览器里直接用。
