# kanpan-no-seams-one-continuous-surface

**项目约定**：看盘界面上下不能出现两块颜色拼接的硬边，整屏要读成一块连续的材料

在看盘（Kanpan）的自选分类页原型里，我做过一版「一张白纸浮在有颜色的底上」：
头部区域是皮肤色（青苔浅 `#E2ECE6`），下面的列表是一张近乎通栏的白纸，
两者在水平方向直接相接。用户的反馈是
「这不对啊，上下两个颜色像拼接的，都没融合到一起，下面是白的，上面是青色的，太割裂了」。

所以在这个项目里，**画面上下两段不能是两块各自平铺的颜色**。用户要的是整屏读成
一块连续的材料：颜色可以有，但必须是「从上往下化开」的——顶部带一点皮肤色，
往下一路过渡到列表所在那一段的颜色，并且在列表开始之前就已经**完全相等**，
这样那条边就没有地方产生。

由此派生出几条同源的做法，都是为了消灭「边」：

- 列表不要自己的容器（不给背景、不给圆角、不给投影），行直接长在整屏底色上；
  有容器就有边，有边就有缝。
- sticky 头部不要底色，只留 `backdrop-filter: blur()`，不滚动时它就是页面本身。
  而且 **不要加 `saturate()`**——饱和度被整体拧高的那一块会在背景上直接印出一个矩形，
  等于又画了一条缝。
- 需要分层时用明度差（比如上抬 4%），不要换一块新材料。
- 极光/大色块那一路同理：行直接长在极光上，不要盖一块毛玻璃卡片，
  可读性靠底部一道**同色**的收敛渐变解决。

判断标准很直接：把整屏缩略图眯着眼看，如果能看出一条横着的直边，就是没做对。


2026-09-18 底栏重画时这条被用户用两句话又推进了一步。我把底栏做成一块左右内缩、带发丝边
和投影的悬浮釉面卡片，他在真机上看完说「好像有点突兀能融合起来吗，因为其它都是融合的，
现在这个搞成悬浮的是不是会不太好看」，接着又点明了症结：「下方那块区域先是纯白显得不搭，
然后四个底栏还悬浮在这块白色区域」。

所以「一块连续的材料」不只是「不能有拼缝」，还有两层意思：

**界面元素不能浮在页面上。** 卡片化、左右内缩、发丝边加投影这一整套「悬浮控件」的做法，
在这个 app 里读起来就是在连续的材料上又贴了一层纸。底栏、面板这类常驻结构要做成页面那块
材料自己抬起来的一段，层次靠明度差而不是靠轮廓，让人找不到它从哪儿开始。

**也不能在页面底部铺一块比页面更白的区域。** 拿 `raised2` 去垫底栏，在浅色皮肤下会变成
一条发白的横带，和上面那张页的底色对不上，这本身就是「不搭」。底栏那块托板要贴着页面
自己的底色走。
