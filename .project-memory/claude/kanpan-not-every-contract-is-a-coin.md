# kanpan-not-every-contract-is-a-coin

**项目约定**：看盘的合约表里有三分之一不是币（美股、ETF、贵金属、指数、Pre-IPO），凡是按「币」的口径算的数字都要先按品种类型分流，宁可留空也不能给错的数

2026-09-18 我把顶栏的「市值」接上后端供应量表，用户看了一眼就说
「另外美股这些市值是不对的啊」，我确认后他又补了一句
「虽然是合约但是市值有问题」——意思很明确：它挂在永续合约页上、代号长得像
`NVDAUSDT`，并不等于它就能按加密货币那套口径去算。

事实依据：币安 U 本位合约里 897 个品种只有 703 个 `underlyingType == "COIN"`，
其余是 EQUITY（美股与 ETF，156 个）、HK/KR/CN_EQUITY、COMMODITY（XAU/XAG/原油/铜）、
INDEX（BTCDOM、DEFI）和 PREMARKET（OPENAI、ANTHROPIC）。而 NVDA、META、V、COIN、HOOD
这些代号同时又是某个山寨币的符号，所以拿 `strip_quote` 去查币的供应量表必然会撞上
不相干的币：当时 NVDAUSDT 报的是某个叫 NVDA 的币的 9.19 万枚供应量，市值算出来 2000 万，
而英伟达真实市值是 5.28 万亿。

所以在这个项目里，任何「按品种算出来的聚合数字」（市值、流通市值、排名、供应量，
以后再加的同类字段也一样）都必须先问一句**这个合约跟的到底是什么**，再决定用哪张表：

- 加密 → 币的供应量表（Binance apex / product list / CoinGecko）。
- 美股 → 股票的**在外流通股数**，不是市值本身。存股数、由前端乘屏幕上那口永续价，
  市值才会跟着盘口跳，而不是停在昨天的收盘价上。
- 其余（ETF、港股韩股 A 股、贵金属、指数、Pre-IPO）→ **留空**。

最后一条是重点：查不到就显示 `--`，绝对不能回落到币的那张表。给一个错的数比给
一个空格严重得多，用户一眼就能看出来，而且会连带怀疑旁边那几个对的数。
品种分类的权威来源是交易所自己的 `exchangeInfo.underlyingType`，不要靠代号猜。
