# kanpan-no-liquidation-feature

**项目约定**：看盘的强平 / 爆仓 2026-09-22 被用户砍掉；2026-10-08 用户翻案放开的口：服务端攒分钟聚合 + 「大单与爆仓」页 / 抽屉里的爆仓摘要 + 图上并进统一透明气泡（向上 = 大买 + 空爆、向下 = 大卖 + 多爆），其它形态（副图、列表、热力、排行、推送）仍不做

2026-09-22 用户一句「强平不要做」砍掉了整个强平（forceOrder）功能。

2026-10-08 用户主动问「是否可以接入爆仓数据」，我评估后他定版：**只做窄口**——
- 服务端 kanpan-api 从接入日起常驻订币安 `!forceOrder@arr`（U 本位 + 币本位）与 OKX `liquidation-orders`，按 base × 分钟聚合多头 / 空头爆仓美元额、笔数、最大一笔，留 3 天，接口 `GET /v1/market/orderflow/liq?base=&from=&to=`（和 `/flow` 同契约）。已部署（`cfb62b35`，2026-10-08）。
- 网页版底部「大单」抽屉里做**一块独立的爆仓摘要**（本根 / 近 1 小时 / 今日 多空爆仓额 + 最大一笔），用户原话「放到大单列表中作为一个单独信息，不用处理太多东西」。
- 同日晚些时候又放开：三端「大单与爆仓」页 / 弹层吃爆仓摘要（见 `kanpan-mobile-bigtrade-liq-page-prototype-pending`），以及**图上**把爆仓并进统一透明气泡——不是单独的爆仓标记，而是每根「向上 = 大买 + 空爆、向下 = 大卖 + 多爆」两个数（见 `kanpan-bigtrade-liq-bubbles-three-ends`）。
- 仍不做：副图指标、独立爆仓列表、热力图、排行、推送、图上单独一种爆仓记号。
- 界面上不写「抽样」，只在名词解释卡里提一句币安那份按秒抽样、金额是下限。

**Why:** 币安强平只有实时流没有历史（归档站无此数据集、REST 无端点），所以必须自家后端常驻攒；09-22 判它不是便宜增量是对的，10-08 用户接受了「从今天起攒、历史只有 3 天」这个代价。`docs/不做清单.md` 对应行已同步改写。

**How to apply:** 别再把强平当「全部不做」，也别顺手扩成副图 / 列表 / 推送；新的强平形态要用户开口。
