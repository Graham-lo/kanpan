# kanpan-no-engineering-status-fields

**项目约定**：看盘界面上不要出现「行情实时」这类后台审计/工程状态字段，它们只会干扰体验

用户在看盘（Kanpan）的 UI 改版里明确要求：实现过程中**不准在界面上出现后台审计、工程
自检之类的字段**，他举的例子是「行情实时」这种连接/数据状态标签，理由是「影响体验」。

也就是说，连接是否实时、数据来自缓存还是流、同步有没有成功、当前走的是哪条线路，这些
都属于程序自己该知道的事，不该占用界面。需要让用户感知异常时，用克制的视觉信号（比如
一个小圆点变色、数字变灰）而不是一行写着状态名词的文字；诊断信息一律留在诊断页 /
日志里，不要顺手摆到行情页、自选页、面板这些日常界面上。

这一条和「界面不要堆解释性文案」是同一个方向的两面：前者反对给用户讲解，后者反对给用户
汇报后台状态。新加任何标签前先问一句——这行字是用户在看盘时需要的，还是我在证明程序在
正常工作。

**2026-09-17 再次确认，而且更严。** 我在交互定板原型里给行情页头部加了一个表示线路状态的
小圆点（主线路 / 备用 / 断开三种颜色），还配了「行情来自 OKX · 备用线路」的 toast 和设置里
的「智能行情线路」开关。用户看后说「行情页面不需要展示行情源等后台无关的数据，用户不关心」。
也就是说，连上面那种「克制的小圆点」也不要——行情来自哪个交易所、走的是主线还是备线、
有没有在切换，**不出现在行情页和 toast 里**。用户需要知道的只有「价格是不是新的」，
这个靠现有的灰价 + 「上次 07:41」时间戳表达就够了。顶栏那颗连接状态点已于 2026-09-18 撤掉
（`Main/TopBar.swift`）。

**这一条管的是「状态播报」，不是「用户的选项」。** 同在 2026-09-17，用户把行情线路定成了
两档由他自己选、没有任何自动切换（见 `kanpan-route-choice-is-binding`），所以设置里那一行
「行情线路」（`Panels/SettingsPanel.swift`）是**要留的**——它是一个用户主动做的选择，
不是程序在汇报自己的状态。被撤掉的是原来那个「智能行情线路」自动开关和整段
「高级与诊断」（API 域名、推送域名、缓存占用）。判断标准因此是：这行字是让用户**决定**
什么，还是只在**告诉**用户程序内部现在怎么样——后者才是要砍的。

**2026-09-18 板块气泡页再加一条：页面上不出现任何「后端维护字段」。** 做板块强弱
（甲版截面 + 乙版日线历史）时用户说「不要在页面出现任何后端维护字段」。这次的对象不是
连接状态，而是数据生产链路自己的字段：接口里的 `asof` 日期、「更新于 / 数据截至」、
「有行情 18/20」「覆盖率」这类分母来自目录登记数的计数、删一区间（jackknife）、
「历史不足」「服务端无数据」这类原因说明、算法名（「中位数」）作为标签——全都不上页面。
它们是程序和维护者才关心的事。用户能看到的只有结果本身：球上的数字、`15/18 跑赢`
这种以**有行情成员**为分母的产品事实、「领涨」记号、`5 日 +8.3%` 这种数字。
数据不够时对应的入口（比如「5 日」那颗 chip）直接不出现，而不是出现一行字解释为什么。

**2026-09-20 连「用户视角」的陈旧提示也不做。** 我作为产品经理列体验细节时提了一条：行情
陈旧时价格已经变灰，但灰得没有说明，建议在价格下面轻轻带一句「停在 3 分钟前」、数据恢复
就消失，并特意把它论证成「用户关心我看到的价是不是现在的价」而不是后台字段。用户批了
其余全部条目，唯独这一条说「不用做」。所以判断标准再收紧一格：**哪怕是描述数据新旧的
一行字，只要它是程序在告诉用户自己的状态，就不上屏**；灰价本身已经是全部的表达。
