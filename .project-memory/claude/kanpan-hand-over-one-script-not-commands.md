# 看盘：要交给用户做的操作打包成一个脚本；但先自己试到底

2026-09-23 我改 Remote Control 宿主的 LaunchAgent 时被会话的自动模式分类器拦下，
把「改 plist、bootout、bootstrap、自检」列成一串命令让用户一条条粘。用户要的是一次执行完，
所以定下规矩：**凡是我做不了、非要用户在终端做的操作（改 LaunchAgent、重启宿主、写权限文件、
修工作树、推被拦的分支等），一律打包成一个脚本文件放到桌面（`~/Desktop/xxx.sh`，`chmod +x`，
可重跑、有只读核对、附回退命令），让他一次执行**，不要列一串命令。

## 2026-09-30 的纠正：桌面脚本不是默认出路，用户常常没有终端

网页版深度压测收尾时，一个子代理的 `git push` 被它自己会话的分类器拒了，我没在主窗口试，
直接把「推分支 + 部署 + 清 VPS 临时文件」打包成桌面脚本交给用户。用户回的是：

> 「**你自己处理好啊，我没办法运行终端**」

所以这条规矩要读得更严：

- **用户经常在手机上遥控会话，手边根本没有终端**。桌面脚本对他来说等于「没做」，
  和列一串命令一样是把活推回去。它只能是最后的兜底，不是默认交付方式。
- **子代理被拦不等于主窗口也会被拦**。权限是按会话算的：子代理报「被分类器拒了」，
  我要先在主窗口自己试同一件事（推分支、ssh 到 VPS 部署、rsync、重启服务都试过是放行的），
  真的在主窗口也被拒了，再按 kanpan-dont-ask-just-ship 里那段说清「想做什么、需要什么权限」，
  并附上能加的权限规则；桌面脚本只在他明确说自己在电脑前时才有意义。
- 注意这和「权限洗白」的边界：子代理被拒的事**我自己试**是允许的（同一个用户、我的会话、我的权限），
  不允许的是反过来把我被拒的事派给别的会话去做。
