# kanpan-device-resource-budget

**项目约定**：看盘可以大方使用手机的磁盘与内存换取更低的等待，用户给的上限是存储加内存合计不超过约 2 GB

用户在 2026-09-16 明确表态：看盘（Kanpan）在优化体验时可以「大胆」使用手机资源，
上限是存储和内存「尽量不超过 2 G」，并要求在这个范围内由我给出各项的合理数值。

这条推翻了项目里早期那套极度节俭的容量假设（例如任务书 A6.11 写的「行情缓存应恒
< 1 MB」、P9.4 写的「常驻 < 80 MB、沙盒行情文件 < 1 MB」）。凡是「多占点磁盘或内存
换掉一次网络等待」的方案，默认应该做，不需要再为省那几十 KB 而放弃明显的体验收益。

需要注意的是，2 GB 是用户给的天花板，不是目标值，尤其不适用于内存：iOS 在 app 退到
后台后会优先杀掉占用大的进程，而「被 jetsam 杀掉」恰恰是「切回来要重新加载」的根因，
所以内存占得越多，用户最在意的那个体验反而越差。给用户解释这一点并把内存控制在
几百 MB 量级、把额度主要花在磁盘上，是符合他本意的做法，不算违背这条指示。

同一天用户又补充了实际机型：主力设备是 8～12 GB 内存、256 GB 存储、当前空余约
160 GB，并要我「看着调整」。也就是说磁盘这一侧几乎没有约束——500 MB 量级的快照
目录在这台机器上不到千分之四，而且放在 `Caches/` 下，系统缺空间可以随时回收；
内存那一侧则仍然要克制，理由同上（jetsam）。所以遇到「花磁盘还是花内存」的取舍，
在这个项目里答案基本固定：花磁盘。
