# 看盘：用得少的、华而不实的功能不必实现

2026-09-22 用户问「当前的看盘项目有哪些设计可以做得更大胆，用户体验比 AICoin 更好」，
我给了六条建议（图表回看层、找相似幽灵叠层、捏合换周期、自选全屏扫图、时间轴市场节律、
朋友在看什么）。他的回应不是挑其中几条，而是给了一条标准：

> 「看细节好像没什么用处啊，另外复盘用的几乎也很少，还有那个气泡图，不如展示成列表，
> 现在只是讨论，我认为**有些华而不实的用的少的其实没必要实现**」

所以在看盘里提设计建议时，**第一道关不是「这个做得出来吗」或者「这个比 AICoin 强吗」，
而是「用户会真的用它吗」**。具体要求：

- **每条建议都要自己先过一遍使用频次**，想不出一个他每天会走到的场景，就不要提。
  提的时候把这个判断写出来，而不是只写它有多独特、多好看。
- **不要在用得少的模块上再加功能。** 加在一个没人用的东西上面，新功能继承的是同一个
  「不会被打开」的命运，不会因为更精致就翻身。
- **「好看」不能替代「有用」。** 用户确实要求过「极致好看优先」
  （见 kanpan-visual-direction-beauty-first），但那说的是**已经决定要做的东西该长什么样**，
  不是拿好看当做它的理由。一个页面漂亮但承担的事情别的形式做得更好，它就该换形式——
  他拿气泡图举的就是这个例子：气泡好看，但回答「哪个板块今天强」这个问题，排好序的列表更直接。
- **宁可少做。** 他明确说的是「没必要实现」，不是「以后再说」。不要把被这条标准筛掉的东西
  转成待办或「预埋」——那正是 docs/不做清单.md 要消灭的状态。

注意这一轮他说了「现在只是讨论」，所以**看细节、复盘、板块气泡图这三样当时并没有被判死**，
不要凭这条记忆就去删它们；这条记忆保存的是那个筛选标准，不是对那三个功能的处置决定。
