# kanpan-term-question-marks-short-labels-stale-gray

**项目约定**：看盘全 app 的功能展示语能缩短就缩短、保持整体美观，有歧义的词照 AICoin 放一个小问号、点了居中弹窗解释；行情停住时价格文字变灰（不要太灰）只靠视觉提醒，不加状态字段

2026-09-28 我给看盘做用户体验评估时提了两条：一是头部六格、副图图例里的「仓 / 额 / 费率 /
差值 / 信号 / 柱值」这类词对非合约玩家是黑盒、又不能堆解释文案；二是 WS 断了、价格停住时
头部看不出来，交易员会按旧价做判断。用户拿 AICoin 行情页截图给了定稿：

- **术语解释用小问号。** 「可以参考 AICoin 的做法，对于有歧义的可以放个小问号，点击弹窗到
  中间就是专门的解释，那么很多词语就可以缩短成一个字或者两个字，整体也会更美观。」
  所以在看盘里，凡是可能看不懂的字段名，做法是：标签压到一两个字（仓、额、费率、结算、
  估值……），旁边跟一枚很小的 ⓘ / ? 记号，点了在屏幕正中弹一张短解释卡，看完即收。
  不要把解释写成常驻文案、不要为了讲清楚而把标签拉长。这是
  kanpan-ui-no-lecturing（界面不堆解释文案）的补充：解释放在问号后面，不放在界面上。
- **数据停住靠变灰提醒。** 「价格停住颜色可以变灰，但不要太灰，靠视觉提醒。」所以行情断流
  或超时时，只把最新价（以及跟着它的涨跌小字）压成一档偏灰的颜色，恢复后再回到涨跌色；
  不加「连接中 / 已断开」这种状态点或文字（kanpan-no-engineering-status-fields 仍然有效）。
  灰度要克制，读起来是「这个数不新鲜」而不是「禁用」。

## 问号的门槛：交易员一看就懂的不挂（费率、结算这种）

第一阶段落地后我在六格里给「仓 / 额 / 费率 / 结算 / OI/MC」都挂了问号，用户 2026-09-28 看了说：
「**费率，结算没必要加问号啊，很明显啊**」。所以「有歧义」的标准是**对一个看合约行情的交易员**
来说读不出指什么，不是「有没有专业含义」：

- **挂**：被缩到一两个字之后才不明确的（仓、额）、英文缩写或比值（OI/MC、Fwd PE、P/S）、
  自造或不常见的短名（买卖比、量差、每笔期望、手续费占毛利、回溯、自动适应、线路）、
  同名但口径不明的（成交里的吃单 / 挂单、条件里的收盘穿过）。
- **不挂**：行业标准词——费率、结算、市值、均线、成交量、持仓量、净盈亏、浮盈浮亏、资金费、
  铃声，以及布林带、相对强弱、随机指标、真实波幅这类指标的标准中文名。
- 宁少勿多：问号一多整行就花了，反而破坏「整体美观」这条前提。拿不准的先不挂。

同一天用户又补了两句「**美股直接显示 fpe 即可**」「**oi/mc 换成 o/m**」：第六格的估值标签
币写「O/M」（不是 OI/MC）、美股写「FPE」（不是 Fwd PE），P/S 不变；问号仍挂着，卡片标题里
再展开（「O/M · 持仓÷市值」「FPE · 预期市盈率」）。这是「能缩短就缩短」在英文缩写上的例子——
用户点名要的英文缩写（O/M、FPE、P/S、K/M/B/T）也要取最短的那种写法，不留空格和多余的字母，
解释交给问号后面的卡片。

## 范围是整个 app，不只是头部六格

我把顶栏重排原型给他看之后（原型里只对头部六格和副图图例做了短标签 + 问号），用户把要求
说成了一般原则：「**现在功能展示语能缩短的缩短，保持整体美观，觉得有歧义的给个小问号**」。

所以这条不限于行情页头部：面板（分析、图表设置）、「我的」、设置、提醒、复盘本、板块页
等所有界面上的功能名、字段名、行标题都适用同一套做法——能缩短就缩短（以整体美观为准，
不是机械砍字），缩短后有歧义的那一个就在旁边挂一枚小问号；本来就一目了然的
（市值、均线、皮肤、退出登录）不挂。问号弹出的解释卡全 app 共用一套样式与一份词典，
新加字段时顺手往词典里补一条，不要各页各写一份。
