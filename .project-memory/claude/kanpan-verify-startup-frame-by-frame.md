# kanpan-verify-startup-frame-by-frame

**项目约定**：看盘里凡是「启动快不快、加载等不等」的结论，必须逐帧抓启动最初几秒，不能等画面稳定后截一张图就下结论

2026-09-16，我改完冷启动优化后报告「冷启动直接落在自选分类页且报价是实时的」，
用户随后反驳：「自选列表我划掉后台冷启动还是一样啊，一个个慢慢加载这个功能是不是
没做好」。原因是我那次验收是在 app 启动约 8 秒之后截的图——那会儿什么都加载完了，
而用户抱怨的整个过程（空图、灰骨架行、一行行填值）发生在前 4 秒，我一帧都没看到。

所以在看盘项目里，任何关于**启动速度、首屏内容、加载等待**的验收结论，都必须建立在
启动最初几秒的逐帧画面上，而不是「等它稳定下来再截一张」。可行的做法是：先把进程杀掉、
停两秒，再一边 `launch` 一边在紧循环里连续截图（每帧文件名带上相对启动的秒数），
然后把这些帧拼成联系表一次看完。判据要落在「第几秒出现了什么」，不是「最后看起来对不对」。

这条同时意味着：报告里不要写「XX 已经正常」这种没有时间轴的结论，要给出时间线
（例如 0.64 s 自选页带值出现、0.85 s 之后不再变化），用户才能判断我看的是不是他看的那一段。
