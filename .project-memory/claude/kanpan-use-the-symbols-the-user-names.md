# kanpan-use-the-symbols-the-user-names

**项目约定**：看盘里用户报了某个品种上的 bug，复现就用他点名的那几只（必要时一次查表换成币安代号），不要一只一只换品种去撞复现——用户 2026-09-22 明说那是浪费 token

2026-09-22 用户报「行情页闪迪右边的 6 个数据跳到了价格的下面」。我没在闪迪上复现，而是在模拟器里
依次开 BTC、DOGE、1000SHIB、BTCDOM、ZETA、1000PEPE、1000SATS 七只加密品种截图找哪只会掉行，
最后拿 1000SATS 写了根因和修法。用户看到后说：「**闪迪美光，我目前发现的，你别一个个查浪费 token**」。

所以在看盘里：

- **用户点名了品种，复现和验收就用那几只。** 中文名对不上币安代号时，查一次
  `docs/板块分类表-2026-09-18/美股-中文名.json`（闪迪 = `SNDKUSDT`，美光 = `MUUSDT`）或
  `exchangeInfo` 就够了，不要拿别的品种去代替，更不要成批换品种去撞。
- **换品种撞出来的复现不等于用户看到的那个现象。** 这次就是例子：我用超长价格的加密品种撞出了掉行，
  但用户看到的是美股合约，价格并不长，宽度多半来自右侧六格里的值——机制和修法的侧重点都不一样。
  只有在用户点名的品种上复现，才算按 kanpan-reproduce-before-naming-the-root-cause 复现过。
- 用户在意的是 token：一只品种一轮「深链 → 截图 → 裁图 → 看图」的开销他不想为我的猜测重复付。
  没有点名品种的 bug 才需要自己去找一只能复现的，找到一只就停。
