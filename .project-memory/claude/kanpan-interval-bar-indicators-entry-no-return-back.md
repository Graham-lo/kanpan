# kanpan-interval-bar-indicators-entry-no-return-back

**项目约定**：看盘行情页周期条行尾固定三件（更多 ▾ · 分析 · 图表设置记号），不许再加第四件——2026-09-28 用户把「画线」赶回与「指标」并列的一个大类里，入口改名「分析」（不是把画线塞进指标）；「返回刚才」被砍掉不再做；排版按 16 Pro 六档满钉 + 「最新」在场算得下

# 周期条：加「指标」入口，砍「返回刚才」

2026-09-24 用户在 UI 整改进行中插话：「现在指标这个大类放到周期条中，我看周期条还可以塞下一个
大分类，你顺便也做了，注意要搞好布局排版」。几分钟后又说：「把返回刚才去掉，不需要这个功能」。

所以行情页的周期条（`Kanpan/Kanpan/Main/IntervalBar.swift`）从此是：

- **行尾常驻三件**：「更多 ▾」（周期网格弹层）、「指标」（直接开指标页）、图表设置记号。
  「指标」是和「更多」并列的一个大类入口，平文字、没有下箭头（它开的是面板，不是从条上拉下来
  的弹层）；从这里进去的指标页顶上是关闭钮，从图表设置里推进去的那条路仍是「‹」返回。
  这和 AICoin 手机端「更多 · 指标 · 设置」的行尾一致。
- **「返回刚才」没有了**：原来点「最新」之后行尾会换成「返回刚才」、一分钟内可回到刚才那一屏
  （§P3-2）。用户明说不需要，整套状态（记一屏、六十秒过期、手一碰图作废）连同测试和使用手册里的
  说明一起删。按「判了不做的功能不准再收编回来」的规矩，以后不要再把它作为体验优化提回来。
- **排版预算**：以 iPhone 16 Pro（402pt，页边 16，内容 370pt）为最紧工况——六档满钉 +
  「最新」在场 + 行尾三件 都要一个字不截、命中区各 44。图表设置记号的 44pt 命中区可以往右伸进
  页边距里，版面只占记号本身的宽度；不要靠缩字号或截字来凑。

## 2026-09-28：行尾只许三件，画线归进「指标」大类

2026-09-27 底栏收成四格时我把「画线」从底栏移到周期条行尾，成了四件（更多˅ · 指标 · 画线 ·
图表设置）。iPhone 16 Pro 上六档满钉 + 「最新」在场只剩 1.2pt 余量，画线与图表设置两颗记号的
命中区还重叠了 10pt。用户第二天看了说：「**周期条中的画线和指标能不能归到一个大类，只放三个，
更多，原来是指标，设置，不然布局会有问题**」。

所以行尾永远是三件，「指标」是一个**大类入口**而不只是指标列表：它打开的面板里放画线（第一节，
一行「画线」，点了就横屏进画线工作台）、指标、对比、主力订单流。以后再有图表上的工具要加入口，
一律往这个大类里放，不往周期条上再塞一件。

## 2026-09-28 追加纠正：是「指标 + 画线并列归一个新大类」，不是「画线塞进指标里」

我按上一节把「画线」做成指标面板里的一节、行尾那格仍叫「指标」时，用户又纠正：
「**不是放到指标中，是指标和画线放到一起，但是换一个名字**」。所以正确结构是：
行尾那格换成一个上位的大类名（我定为「分析」——两个字、宽度与「指标」一样，
「工具」已被横屏画线台的工具选择器占用），点开的面板里「画线」与「指标」是同级的两节
（其后仍是「对比」「主力订单流」）。面板标题、`PanelKind.indicators` 的显示名、周期条格子的
无障碍标签都跟着叫「分析」；「指标」只是面板里的一节名，不再是行尾格子的名字。
以后凡是把两件事收进一个入口，要给入口起一个能同时涵盖两者的名字，而不是借用其中
一个的名字当容器。
