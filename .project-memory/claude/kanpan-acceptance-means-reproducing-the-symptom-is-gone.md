# kanpan-acceptance-means-reproducing-the-symptom-is-gone

**项目约定**：看盘里验收子代理的修复时，必须独立复现「用户看到的那个现象已经消失」，测试全绿和文件范围正确都不算验收通过

# 验收 = 用户那个现象没了，不是测试绿了

2026-09-19 用户报「BTC 持仓量副图中间断开一格」。我派 Opus 子代理修，它交回来两笔提交、
39 条测试全绿、真机包也装好了。我验收时核的是：提交只动了该动的三个文件、没卷进别的窗口的
改动、测试我自己复跑过。据此向用户和两个同伴窗口通报「修好了，而且手机上已有的洞会自愈」。

用户回了一句：「还是存在啊」，紧接着「你复现一下从根因上修复」。

问题出在：子代理那两笔只堵住了「不再产生新洞」，它声称的「旧洞自愈」是错的，而我没有验证这个
断言。我复跑的测试是子代理自己写的，它们测的是子代理理解的那个机制；我核的文件范围只说明
改动干净，不说明改动有效。两样都绿，用户的洞还在。

所以在看盘项目里，验收一个 bug 修复必须包含这一步：**独立构造用户报的那个场景，证明现象确实
消失了**。手段不限——独立的 swift 复现脚本、真机上照着用户的操作走一遍、或者按用户给的截图
量出来的位置去核。这一步要用我自己搭的场景，不能复用子代理写的测试，因为子代理的测试只能证明
它自己的心智模型自洽。

同理，在这一步做完之前，不要向用户或同伴窗口宣布修好了，更不要替修复宣传它的附带效果
（「不用清缓存」「已有的问题会自己好」）——这类断言最容易错，而且一旦发出去，别的窗口会
照着它继续往下建结论。
