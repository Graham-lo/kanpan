# 看盘 UI 要有专业设计规范：字号分层、边距体系、按苹果 HIG 审

2026-09-24 用户转来他设计师朋友对行情页的评价：「有点怪怪的」，并举了例子——
「主标题是 16px 那么副标题就应该是 12px」「外容器边距是 20px，内容器边距应该是 16px 8px」
「就是层级的分层对比关系，看起来才美观，这个要专业的设计规范」。用户随即要求：
查一下苹果的 UI 设计规范（HIG），**审查所有 UI 页面**是否符合（不只行情页），给出优化；
审查交给 Opus 子代理做。

当时代码里的实况印证了这个评价：`.system(size:)` 用到的字号是 6 到 22 之间几乎每个整数
外加 6.5 / 8.5 / 9.5 / 10.5 / 12.5 这些半点值，`.padding` 从 1 到 20 每个整数都有，
圆角有 7 / 8 / 9 / 10 / 12 / 13.6 / 13.7 / 16 / 18 / 20——没有任何阶梯，靠 0.5pt 微调做出的
「假层级」肉眼分不出主次，这就是设计师说的「怪」。

所以以后在看盘里做任何 UI（新页面、改版、微调）都要守这条：

- **字号走阶梯**，映射到 HIG 的 Dynamic Type 文本样式（11 / 12 / 13 / 15 / 16 / 17 / 20 / 22 …），
  相邻层级至少差一档，标题与副标题要差得够开（如 16 对 12），不再出现 12.5、13.6 这类值；
  层级靠字号 + 字重 + 颜色三者一起分，不靠半点微调。
- **边距成体系**：页面外边距、容器内边距、行内间距三层各一个定值（4pt 网格：4 / 8 / 12 / 16 / 20），
  同一页同类元素间距一致，不出现 7 / 9 / 11 / 13。
- **圆角成套**且嵌套时同心。
- 这条与既有的「界面元素尺寸克制」并行：规范化不等于放大，是把散乱的值收敛到阶梯上。
- 新 UI 应通过共用的设计令牌（`DesignSystem/` 下的字号 / 间距 / 圆角常量）取值，
  不再在各处手写数字。

## 2026-09-25 补充：新功能交付前也要过这一关，图上的标签与卡片一样算

2026-09-25 主力订单流重做画法时（图上大单标签、段详情卡、门槛设置），用户在子代理跑测试的间隙
插了一句「注意 ui 设计要符合设计规范」。他没有指出具体哪里不合规，是在提醒：每一个新功能
交付之前，我都要主动按这条规矩过一遍，不能只顾功能对不对。范围包括画在图上的文字与卡片
（大单标签、详情卡、图上药丸）——「K 线图区一律不动」说的是 AICoin 那套蜡烛与指标的还原，
不是图上我自己加的 UI 元素。验收清单：字号只用 `TypeScale`、间距只用 `Space` / `Inset`、
圆角只用 `Radius`、文字 ≥ 11pt、命中区 ≥ 44pt、标题与副标题差一档以上；
子代理的报告里要附这一项的自查结果。

## 规范是底线，不是目标：交互要拉满、视觉要极致精美并融进整体风格（2026-09-25）

2026-09-25 做「创建提醒」页第三轮整改时，用户先插话「注意要符合 ui 设计规范」，紧接着又说：
「**交互体验要拉满，ui 要极致精美好看融合风格同时满足设计规范**」。这两句放在一起是一条一般原则：

- **符合 HIG / 设计令牌只是及格线**。字号、间距、圆角、颜色按阶梯取是必须的，但只做到这一步用户会觉得「粗糙」。
- **视觉要极致精美，而且要融进 app 既有的风格**（皮肤、分组卡片、发丝分割、琥珀色主色、徽章那一套），
  不是一页一个样；新页面要看起来像和自选页、设置页出自同一只手。
- **交互要拉满**：每个动作都要有反馈与动效——删除要有触觉反馈和行收起的动画，输入框聚焦要有明确的高亮，
  数量变化要平滑过渡，空态要好看，切换不闪。能自动做的不弹窗问。
- 派子代理做界面时，这三层（规范 / 精美融合 / 交互拉满）要一起写进任务，只写「按规范」不够。


## 压缩空间、做减法时规范照样不能破（2026-09-25）

2026-09-25 用户要把自选页头部压扁（搜索框收成一颗图标、分类上提与它同行、字号缩小、去掉数量与排序），
目的是把空间让给品种列表。他紧接着补了一句「**但是你要注意要满足设计规范**」。意思是：
「省空间」不是放松规范的理由——收成图标后命中区仍要 ≥ 44pt，分类字号缩小也只能落到阶梯上
（14 → 13，不是 13.5），行高、边距仍走 4pt 网格。以后凡是「精简 / 缩小 / 挤紧」类改动，
先按 HIG 自查一遍再交，尤其是触控目标和字号这两项最容易在做减法时破掉。
