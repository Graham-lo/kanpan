# kanpan-alert-page-design-rules

**项目约定**：看盘「创建提醒」页的定稿规矩（2026-09-25 用户纠正）：图上入口文案是「创建提醒」不是「涨到 X 提醒我」；页里品种不可编辑、不给 ±% 快捷、Webhook 只填地址不让用户写模板/JSON（文案与格式由我定、给默认）；不要备注；页里只列这只品种还没触发的提醒，触发过的不展示；右上「全部预警」进分「价格」「画线」两类的总表；行上只给删除 icon；条件叫「价格达到」；整体要精美不粗糙

# 看盘「创建提醒」页的规矩

2026-09-25 我做完「从图上加提醒」第一版装到真机后，用户看了说：「这个页面是不是布局不太合理啊，
做的有点粗糙了吧，另外 webhook 不要给用户填写 json，只需要输入地址即可，文案和方式替用户做决定，
专业简短有效即可，给个默认。还有点击空白应该是创建提醒，不是涨到什么这个，进去后品种不可编辑，
也不需要 -2% 这种，通常用户就是设置某个具体值提醒。然后改页面还有警报记录，你重新设计精美 ui 和布局」。

逐条落成规矩：

- **图上入口的文案是「创建提醒」**（铃铛 + 三个字），不是「涨到 / 跌到 X 提醒我」。价格从十字线带进页里，
  涨到 / 跌到的方向由创建那一刻和现价的关系决定，只体现在标题里，不摆在入口上。
- **页里品种不可编辑**：从哪只品种的图上进来，就是给哪只加提醒，品种只作为头部信息展示。
  改品种就回图上换一只再点。
- **不给 ±1% / ±2% 这类快捷药丸**：用户加提醒时心里就是一个具体的价，直接输那个数。
- **Webhook 只填地址**：不给推送内容编辑框、不给占位符药丸、不让用户碰 JSON。发什么、怎么发由我定，
  要「专业、简短、有效」，给一个固定默认（正文是「BTC 碰到 84,662.2，现价 84,670.5」这种一句话，
  JSON 字段固定）。同步契约里的 `webhookText` 客户端永远写 null，服务端用默认模板。
  这条是一般原则的具体化：看盘不把「格式怎么写」这种决定摆给用户（同 kanpan-sector-page-no-basis-picker）。
- **不要备注**：用户随后补了一句「也不需要备注啊」。提醒就是一个价 + 一个条件（+ 可选 Webhook），
  不给自由文本字段。契约里的 `note` 键客户端永远写 null。
- **创建页下面只列「当前提醒」**：这只品种**还没触发**的提醒，能删、能进编辑。我第二版把已触发的也列进去
  当「记录」，用户说「记录你搞错了，下面展示的是把还没生效的警报展示出来，警报过的不需要展示」。
  触发过的提醒在哪儿都不展示（和「触发一次就删除」一致）。
- **全部预警的入口是创建页右上那颗按钮**，文案「全部预警」，点进去是分两类的总表：自己建的价格提醒、之前的画线提醒
  （照 AICoin 的「未触发预警」页）。用户 2026-09-25 先说「再增加一个入口，能把所有预警都调出来，一类是自己创建的价格，
  一类是之前的画线预警」，随后定为「右上角可以改成全部预警，点进去就是全部的」——不在图上再加第二颗药丸。
- **行上只给一个删除 icon**：创建页底下的未生效预警、总表里的每一行，右侧只有一枚垃圾桶，不给左划菜单、
  「盯一个」、条件切换这些操作。用户原话「给个删除 icon，全部预警也只给删除 icon 操作」。
- **条件叫「价格达到」不叫「碰到」**：用户 2026-09-25 明说「碰到改成价格达到」；「收盘穿过」不变。
  界面、通知、Webhook 正文、服务端模板要一起改口径。
- **价格必须一看就能编辑**：第二版价格值排得像一行只读文字，用户问「价格可以编辑吧」。输入行要整行可点、
  有明显的可编辑感。
- **「精美」是硬要求**：一页里不能混用「左标签 + 右侧填色输入框」「药丸」「大片空白」几种风格，
  要按 HIG 分组卡片（`Radius.m`、发丝分割、`Inset.rowMin` 行）成体系地排，头部一张品种卡。
  用户对第一版的评价是「粗糙」，以后新页面先按这套排再截图看。
