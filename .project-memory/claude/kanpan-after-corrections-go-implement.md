# kanpan-after-corrections-go-implement

**项目约定**：看盘里用户看完原型给出纠正并说「交给实现」之后，就直接写交接说明并推进实施，不要再回头返工原型

2026-09-17 用户看完交互定板原型，给了一串纠正（副图三个、去掉线路信息、周期条自适应、
接入已有徽章等）并明确说「这些交互设计都交给 opus 5 high 来实现，你负责具体的验收和矫正」。
我却先去把原型按纠正重做一遍（抽徽章、改周期条、重排章节），被他打断：
「要开始实现了不是要改原型，你不要给我交付原型」。

看盘（Kanpan）项目里的节奏因此是：原型只交付一次，用户在原型上给的纠正是实施输入，
不是原型返工的理由。收到纠正之后：

- 把纠正逐条写进给实现方的交接说明（file:line 指向仓库），原型就保持原样，在交接里
  注明「以下几处以本说明为准，原型上的旧写法作废」。
- 直接推进实施：派发 Opus 子代理在最新工作树上实现，然后我做验收和矫正。
- 只有用户明确要「再出一版原型」时才回去改原型；否则重做原型只是拖延实施。
