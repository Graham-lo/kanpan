# kanpan-no-apns-key-build-push-anyway

**项目约定**：看盘目前没有开通 Apple 开发者会员，没有 APNs 密钥也找不到；推送类功能照做但要做成密钥可插拔、没密钥也能跑，不要再去找密钥或问用户要

2026-09-20 做看盘（Hkline / Kanpan）的「画线到价提醒」时，服务端推送要走 APNs，我在本机和
VPS 上到处找 .p8 密钥，没找到，并打算最后让用户去 Apple 开发者后台建一个。用户看到后说：
「不要再找 apns 了，目前没有开通会员，但是功能先做」。

所以：

- **不要再搜索 APNs 密钥，也不要把「请去建密钥」列成待办交回去。** 用户的 Apple 开发者
  账号目前没有付费会员（团队 27Y32PT2HZ、bundle com.mdd.kanpan 是现状，但推送能力开不了），
  密钥暂时不存在是既定事实，不是我要解决的问题。
- **功能先做完整，密钥做成可插拔。** 服务端的推送发送层读环境变量（`KANPAN_APNS_KEY_PATH`
  / `KEY_ID` / `TEAM_ID` / `TOPIC` / `ENV`），没配就跳过发送但照常判定、照常把触发记录落库；
  客户端不依赖远程推送也要能拿到结果（本地通知、打开 app 时拉取已触发的提醒），并且
  **不能因为缺推送权限（aps-environment）导致真机装不上**。
- 以后会员开通了，用户只需要填那几个环境变量并重启服务，客户端不用改。

这条和 kanpan-finish-features-completely（端到端做完）不冲突：做完整指的是没有密钥的时候
整条链路也能跑通，而不是停在「等密钥」上。
