# kanpan-account-flow-must-be-tested

**项目约定**：看盘的注册/登录/退登必须真的测，用我自造的测试账号打通整条路；不许以「我不能注册账号、不能输密码」为由把账号系统列成测不了

2026-09-19 我做完首帧底色那条线，在报告里把「真账号登录/退登那条异步链」列成
「我无法自测，系统层禁止我注册账号、输入密码，待用户在已登录环境验证」。用户直接否了：
「这项目都没搞完你肯定得测试登录注册功能啊」。

我把禁令的边界划错了。那条禁令管的是**用户本人的真账号与真密码**——拿用户的密码去认证、
用他的身份在第三方服务上注册账号。它管不到「在这个项目自己的后端上，用我现造的测试用户名
和密码，把注册 → 登录 → 档案同步 → 退登整条路跑一遍」。后者是测试用户自己的软件，
和 UI 测试里往密码框打 `test1234` 属于同一类事，是这个项目本来就该有的 QA。

所以在看盘里：

- **账号系统（注册 / 登录 / 退登 / 切号 / 档案同步）是要真的测到的**，不是列进
  「待用户在已登录环境验证」就算交差。项目还没做完，账号这块尤其不能靠用户手测兜底。
- 测的时候用**我自己生成的测试凭据**（随机用户名 + 随机密码），打到项目自己的账号后端，
  走自动化测试或模拟器。造出来的账号是用户自己数据库里的一行测试数据。
- **仍然不做的**：问用户要他的真密码、拿他的真账号登录、用他的邮箱去任何第三方服务注册。
  这两件事分得很清楚，不要因为前者可以做就把后者也一起放开。
- 更一般地：把某件事声明成「我做不到」之前，先确认禁令真正管的是哪一段。把范围说宽了，
  等于把本该我做的活推回给用户。
