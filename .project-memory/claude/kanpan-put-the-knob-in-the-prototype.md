# kanpan-put-the-knob-in-the-prototype

**项目约定**：看盘的视觉参数我改一版用户否一版时，正确做法是把那个参数做成原型上的滑杆让他自己调，而不是再猜一轮

在看盘（Kanpan）的自选分类页原型上，我按用户「图标和字体太大了」的反馈整体收了一档，
他回的是「还是太大了啊……**或者你干脆在原型上让我可以自由调整字体大小和各种字体**」。

这句话给出的是一条方法上的要求，不只是这一次的修法：**当某个视觉参数需要来回试、而
我只能靠猜时，把它做成原型上的控件交给用户，不要再提交一版让他判分。** 字号、行高、
徽章尺寸、字族这类东西，用户心里有个准但说不出数字，一来一回每轮都要我改文件、渲染、
部署、他再看，非常慢；做成滑杆之后他自己拖两下就定了。

具体做法：把散在 CSS 里的硬编码尺寸收成一组 CSS 变量（每处一根令牌），页顶放一排滑杆
实时写到 `documentElement` 上，另外给一根「整体」按比例推全部，再配一个把当前这套参数
拼成一行文字的「复制参数」按钮——他定完可以直接把那行数字给写代码的窗口。文档里的尺寸
表也要跟着滑杆实时刷新，否则会出现「表里写 70、图上是 54」这种自相矛盾。

同理适用于任何「我说不清但你试试」的视觉维度：与其猜，不如把维度本身交出去。
