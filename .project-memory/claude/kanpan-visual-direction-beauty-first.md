# kanpan-visual-direction-beauty-first

**项目约定**：看盘原型的视觉方向：极致好看优先，不要工程风/后台风；皮肤三套（青苔·冷默认 / 陶土·暖 / 经典），不要再自创色板，功能与交互由我重新设计

2026-09-17 用户在看盘（Kanpan / 产品名 Hkline）项目里让我重做全套非图表原型时明确说：
「我喜欢青苔冷那一套，但是设计上你不必按照这样的风格，你可以完全自主设计新的原型，
注意还是好看为主，不要工程风不要后台风，极致的好看，可以自己设计色彩搭配图标等各种组合。」

「青苔·冷」指 Opus 在 `完整原型-2026-09-16.html` 里的 SAGE 风格：冷调青绿强调色
（浅色 #2E7D6B、深色 #4FB69C），大圆角（卡片 26、面板 34），柔和的青绿背景光晕，
涨色与强调色同色系。用户喜欢的是这种清冷、克制、有呼吸感的气质，而不是要我照抄它的数值。

因此在这个项目里做视觉设计时：

- **好看是第一目标。** 用户评判原型首先看它是否「极致好看」，其次才是信息密度和功能覆盖。
- **不要工程风、不要后台风。** 等宽字体堆数据、灰底表格、管理后台式的行列、诊断/状态字段
  这类味道都要避开（与已有记忆「界面不出现工程状态字段」一致）。
- **配色、图标、版式可以完全自主。** 用户明确授权我自己设计色彩搭配和图标组合，
  不必沿用 Opus 或 GPT 文档给的调色板；但 K 线与指标底座仍是 AICoin 复刻、不动。
- **整套重来，不是在 Opus 原型上做变体。** 用户后来又强调：「你不必局限于现有的原型，你要重新整套设计」——
  Opus 那套当时正由另一个窗口落地（皮肤已进 app），用户要的是另一套独立的方案来做对比（布局、信息架构、组件、配色、图标
  都可以不同），而不是换个色板的同构版本。

**2026-09-17 补充：配色不要再自创，直接用「陶土·暖」和「青苔·冷」。** 我按上面的授权自创了
「青瓷 / 月白 / 松烟」三套色板做完整原型后，用户看完说：「我感觉设计你这版配色不如陶土暖和
青苔冷好看啊，干脆用陶土和青苔冷这两种配色，其他的功能和交互设计你来重新设计。」所以此后：

- 皮肤只做两套：陶土 TERRA（暖）和青苔 SAGE（冷）（**当天稍晚用户自己点名加了第三套「经典」，
  见下**），色值以 Opus `完整原型-2026-09-16.html` 里的
  定义为准（陶土浅色强调 #C4603A、青苔浅色强调 #2E7D6B、深色 #4FB69C 等），不再自创第三套。
- 「自主设计」的范围收窄为：信息架构、页面布局、组件、图标、交互逻辑。色彩不在其中。
- 用户对配色的判断标准是直觉上的「好看」，不是对比度或语义规则；我认为更「讲道理」的色板
  （墨色选中态、克制的青瓷绿）在他眼里不如带温度的陶土暖和青苔冷。以后不要再拿设计逻辑
  去说服他换色板。

**2026-09-17 再补：配色已「定版」，交互可以从现有功能出发整套重排。** 用户随后说：「配色已经定版了，
但是交互这块你完全可以根据现有的功能重新设计」，又说「k 线底座都做好了，所以接下来最重要的就是从用户的
交互体验、逻辑设计、ui 视觉上下功夫」。也就是：陶土 / 青苔两套配色不再讨论；功能清单以现有 app 为边界
（不凭空加功能、也不丢功能），但功能放哪一层、怎么进怎么退、页面怎么排全部可以推翻重来。此后看盘的工作
重心是交互逻辑与视觉，不是图表底座。

**2026-09-17 再补：第三套皮肤「经典」是用户自己点名加的，不算自创色板。** 用户说：「现在整套风格再接一版
经典风格，背景颜色全部换成 aicoin 那种白色，但是项目还是默认使用青苔冷那套风格」，我给出方案后他又收窄：
「直接实现即可，只是换个背景颜色，其他的都不用改吧」。所以「经典」= 青苔原样，只把底 / 面 / 分割线换成
AICoin 的白，文字、涨跌、强调色、MA 线色一个都不动，出厂默认仍是青苔。皮肤从此是**三套**：
青苔·冷（默认）/ 陶土·暖 / 经典。
「不自创色板」的规矩没变：新增皮肤只能是用户点名的、色值有出处的，我自己不要再提第四套。

**这里的白值我第一版取错了，别再照抄安卓包的通用令牌。** 我当初写的是「页面底 #F7F9FF、
线 #DEE1E5」，两个都是安卓包里给通用列表用的令牌（`sh_base_bg_color` / `sh_base_divider_dim_fill_color`），
K 线页根本不用它们。真机实测 AICoin 行情页从标题到副图**全是纯白 `#FFFFFF`**；写成 #F7F9FF
那支蓝白会让纯白画布在页面上显成一块更亮的补丁。

**但「经典白 = 纯白」只管 `app` / `chart` / `raised` 这三支，别读过头。** `classicSeed.ground`
是中性灰 `#F7F8FA`（`Palette.swift`，断言在 `KanpanCore/Tests/KanpanCoreTests/SkinPaletteTests.swift`），
它是自选页那一层的底。走 `ground` 的页面（自选页、板块气泡页——`Sector/SectorPage.swift` 里
深色档和经典档都取 `seed.ground`，只有青苔 / 陶土的浅色取 `seed.app`）在经典浅色下**本来就不是
纯白**，那是设计意图不是 bug，不要照着「经典 = #FFFFFF」把它们改成纯白。注意这支灰
`#F7F8FA` 和上面那支取错的蓝白 `#F7F9FF` 长得像但不是一回事。分割线同理：图内结构线是 `ui_kline_divider_color`
= #F2F4F7，周期条上下是 `ui_kline_indicator_bar_divider_color` = #EAEAEA，#DEE1E5 离纯白的亮度差
是 #F2F4F7 的七倍，整屏八条把纯白页面切成了格子，用户读成「更刺眼」。现行色值以
`KanpanCore/Sources/KanpanCore/Style/Palette.swift` 和 `.project-memory/PROJECT.md` 第 2 节为准。

**2026-09-17 再补：「经典」的 K 线色也要跟 AICoin 手机端一致。** 用户装上经典皮肤后看了一眼就说：
「经典模式下项目的 k 线颜色和 aicoin 的颜色不一样啊」，并补充「左上角价格涨跌是不同的颜色，好像也是和
k 线一样」。也就是说他心里的「经典 = AICoin」不只是白底：涨跌色、蜡烛、均线、副图指标线、顶栏价格涨跌
都得是 AICoin iPhone App 上的那套色（以真机截图实测为准，逆向出的安卓常量只做旁证；深色版没在真机量过，
取的是安卓包常量）。青苔 / 陶土仍然一个色都不动。随后他又把范围扩到全部皮肤：「浅色所有模式下的 k 线颜色都统一成 aicoin 那种」「以后不再另起一套」
（详见 `kanpan-kline-colors-are-aicoin-only.md`）。所以「经典」仍是「青苔只换底」，而 K 线色三套皮肤浅色一样、都是 AICoin 的。
