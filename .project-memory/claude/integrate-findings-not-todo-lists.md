# 对标发现的有用设计，直接集成，别留成待办清单

在看盘项目里，我把 AiCoin 桌面版逐像素测了一遍，写出一份很详细的对比文档，
末尾列了一节「待办（本次未改）」——影线被 `wickTint` 兑淡、留缝下限只有 1 个设备像素、
副图之间少 9px 空隙，每条都写了建议改法，但都没动手，理由是「这几条会动 A3.11 的
176 张像素基线，要重录」。用户看到后直接回了一句：**「有用的设计直接集成进去」**。

## 规矩

**对标分析的产出是代码，不是清单。** 测量、对比、找出差异只是中间步骤；只要判断这个
差异是「对方做得更好」，就在同一轮里把它实现掉。把结论整理成待办交回去，等于把活儿
又推回给用户——和 `decide-and-proceed-not-ask.md` 说的是同一件事，只是换了个场景。

**「会动已验收的基线 / 要重录证据」不是拖延的理由。** 重录基线是机械步骤，自己跑一遍
就行；正确的做法是改完、重录、在证据里写清楚为什么这批基线动了、附上改动前后的对比，
而不是因为怕动基线就不改。

## 什么时候才真的该留着不做

只有当这个差异**不是**「对方更好」，而是双方口味/定位不同时，才写进文档说明理由并保留
现状。例如 AiCoin 默认蜡烛的体宽比是 0.686，我们默认风格「墩」是 0.86——「墩」这一款
本来就是为「胖」设计的，想要 AiCoin 那个比例，现成的「辉」正好是 0.70。这种情况写清楚
「不改，以及为什么」是对的，和「改不动所以先记着」完全是两回事。
