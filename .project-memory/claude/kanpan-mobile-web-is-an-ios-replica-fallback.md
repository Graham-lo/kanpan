# kanpan-mobile-web-is-an-ios-replica-fallback

**项目约定**：看盘 2026-09-29 起加一个手机网页版（PWA），完全按 iOS app 复刻、尽量还原，定位是装不了 app 时的临时替代；灵动岛、推送、震动这类系统能力不复刻；在 Web/ 下另起手机入口，共用数据 / 账号 / 同步模块，UI 与图表引擎单独写，不往 PC 网页版里塞手机断点

# 看盘：手机网页版是 iOS app 的复刻替代版

2026-09-29 用户提出：PC 网页版已经有了，能不能再做一个手机移动版，「完全按照 iOS 复刻出来」，
加到主屏幕后和 app 没什么区别，这样就不用开通苹果开发者会员（免费 Apple ID 侧载七天就过期，
朋友们装不上 app）。我按层评估了还原度并给出结构方案，用户回复：「可以，我觉得你这个方案合理，
这只是替代版，想用更全的就用 app，想要大屏就用 web，手机适合无法下载 app 时临时用」。

所以三端的定位从此固定：

- **iOS app**：功能最全的正主，系统能力（灵动岛 / 实时活动、推送、震动、强制横屏）只在这里有。
- **PC 网页版**：大屏用，是独立的一套设计（见 kanpan-web-is-its-own-design-not-ios），不动。
- **手机网页版**：装不了 app 时的临时替代，目标是「尽量还原 iOS app」，肉眼看不出区别为准。

做法上用户认可的几条：

- **不复刻 iOS 特有的系统能力**：灵动岛、推送、震动、锁定横屏都不做，用户明说「不需要复刻」。
  这些是浏览器做不到的，不要为它们找替代实现，也不要在汇报里反复列成缺陷。
- **视觉与交互照 iOS 逐屏还原**：三套皮肤、四格底栏、头部六格、周期条钉住与「更多」弹层、
  头部横滑扫图、自选分类页、板块列表、我的、左滑删除、拖动排序，都按 iOS 现有定稿来，
  不另起设计。iOS 定稿的那些记忆（底栏、头部、周期条、自选页等）对手机网页版同样适用。
- **图表引擎从 KanpanChart 逐文件移植**：iOS 的图表是 CoreGraphics 画的，映射到 Canvas 2D
  几乎一比一，坐标与指标算法照搬，不用 PC 网页版那套自写引擎，也不用 TradingView 的路子。
- **结构**：在 `Web/` 下另起一个手机入口，共用 data / sync / account / market 这些模块，
  UI 与图表引擎单独写；不往 PC 网页版的样式里塞手机断点，两者共享的只有数据和账号。
- **后端仍是同一个 kanpan-api**（见 kanpan-one-shared-backend-no-new-service），
  手机网页在「一类设备一台在线」里算手机。

判断「手机网页版做没做对」的标准是「装到主屏后日常用下来和 app 没有区别」，
已知且被接受的差别只有三点：不能强制横屏（用户自己转）、没有震动、切后台要重连并恢复现场。

## 2026-10-03 再强调：对齐的是「体验」，不只是长相

用户在让手机网页版适配华为 nova 16 / iPhone 15 Pro Max 时补了一句：「总之除了 app 不能做的，
移动网页版要尽量做成 ios 那种体验。全面审查一遍相关的功能体验」。所以审查手机网页版时，
对照对象是 iOS app 的**功能清单与交互手感**：iOS 有、浏览器做得到的功能都要有；
弹层怎么出怎么收、手势、过渡、文案、空态、出错态都照 iOS 来，不是截图像就算完。
做不到的只限于系统能力（灵动岛、推送、震动、强制横屏、小组件）。
