# kanpan-symbol-badges-must-be-real-marks

**项目约定**：看盘的品种徽章必须一个品种一个记号，既不能拿代号缩写兜底，也不能整类共用一个图形

用户在看盘（Kanpan）里两次因为品种徽章纠正我，两次的落点不一样，合起来才是完整的要求。

**第一次**：「我发现很多品种的图标不对啊，这点你没有设计吗，像 xau 展示的图标就是 xau，
美股的一些展示缩写」。当时徽章只为十来个头部币种画了记号，其余一律回退成「取代号前 1–2
个字母」，于是黄金 XAU 的徽章上就真的印着 XAU，NVDA 印着 NV、MRVL 印着 MR。
用户把这个判定为「图标不对」，不是「还没做完」。

**第二次**：我照第一次的结论改成了按资产类别给「类记号」——所有个股共用一个交易所门廊、
所有 ETF 共用三根柱、所有贵金属共用金锭。用户看了之后说「另外美股的图标设计的不对啊」
「每个品种都有单独的图标啊」。也就是说，整类共用一个图形同样不合格：一屏美股里每行都是
同一座房子，和每行都印着自己的字母一样分不出来。

所以在这个项目里，品种徽章是设计对象，判据是「一屏列表扫下去，每一行能不能靠图形分开」：

- **一个品种一个记号**。美股、港股、A 股这些个股要各自的品牌标，不能共用交易所门廊；
  加密也一样，不能只画头部那十几个。
- 字母缩写不算图标，整类共用的图形也不算图标——前者是把文本再印一遍，后者是把一屏
  印成同一个图案，两种都回答不了「这行是哪个品种」。
- 材质类品种的渐变色要符合物理直觉（金是金色、银是银灰、铜是铜色、原油是近黑），
  不要跟长尾一样用代号哈希出来的随机配色。
- 类别判断跟着 `SymbolClassifier` 那套事实分类走，不要靠猜。

一般化的教训：这个项目里凡是「给每个条目配个图形」的地方，兜底方案要能把条目彼此分开。
退成字符不行，退成同类共用的一个图形也不行——兜底的图形至少要随条目变，才叫图标。

**2026-09-17 补充：项目里已经有一套品种图标，接进去，不要另起一套。** 用户看交互定板原型时说
「项目已经有了各个品种的 icon 这点要接入进去，不要另起一套，没有的品种 icon 你重新设计即可」。
也就是说 app 里的 CoinBadge 那批记号是既定资产：原型和实现都直接复用它（原型里用字母圆点
占位是不合格的），我要做的只是核对当前品种池里哪些还没有专属记号，给缺的那些补设计，
补的记号也要沿用同一套皮肤调色与线宽规则。
