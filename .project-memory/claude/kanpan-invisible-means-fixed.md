# kanpan-invisible-means-fixed

**项目约定**：看盘里闪帧、过渡、延迟这类问题的验收标准是「肉眼看不见」，不是「归零」；量到看不见就结案，不要继续往下优化

2026-09-19 我在给用户解释冷启动首帧底色时，把「系统启动屏那一帧跟不了人」当成一个还没解决
的遗留问题反复说明，并打算继续缩短它。用户回了一句：「肉眼看不到就没事」。

所以在看盘里，**闪帧、过渡、纠正、延迟这类问题的验收标准是感知，不是数值归零**：

- 判据是「用户能不能看见」。量到看不见（一两帧、百毫秒以内这个量级），这一条就**结案**，
  不要再为了把数字做到零而继续改架构——那是拿工程洁癖换用户感觉不到的收益。
- 反过来，**「看不见」必须是量出来的，不是推出来的**。这条和
  kanpan-verify-startup-frame-by-frame 是配套的：那条管「怎么验」（逐帧抓，不许稳定后截一张
  就下结论），这条管「验到什么程度算过」。先拿到毫秒数，再用这个标准判。
- 也不要反过来把用户看得见的东西用「理论上只有一帧」搪塞过去。用户原话的前提是**真的看不到**。

更一般地：这个项目的验收尺子是用户的眼睛。凡是能换算成「他看不看得出来」的问题，都先把它
换算过去再决定要不要动手。
