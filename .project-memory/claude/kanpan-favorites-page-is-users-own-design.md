# kanpan-favorites-page-is-users-own-design

**项目约定**：看盘的自选分类页是用户自己定稿的（「琉璃」版，2026-09-17 起去掉玻璃纸改为融合），我不主动改它；用户自己提出改动时做对比原型让他选

2026-09-17 用户看完我的交互定板原型后明确说：「自选分类页面我专门设计过了，你不要动这个」。
这里指的是底栏「自选」进去的那张带「加密 / 美股 / 贵金属」分类的整页自选，用户之前在
`/ui/favorites-ultimate.html`（琉璃 · 晕染 · 鎏金三种材质）里挑过方案并已交给另一个
Opus 窗口实现。

所以在看盘（Kanpan）项目里，自选分类页是用户自己的作品，不是我的设计对象：

- 原型里不要再为自选分类页出新的布局、材质或行样式；需要提到它时只写「按你定稿的自选页」。
- 交互也别顺手改。我在原型里画的编辑多选、左滑删除、移到分类、重命名这类流程，只能当
  参考，实施说明里要明确把自选分类页排除在改动范围外。
- 别的页面通往自选页的入口（底栏「自选」格、行情页头部品种名）可以设计，但目的地就是
  那张页，不要为入口再造一份自选列表。

这一条和「底栏的自选必须进带分类的完整自选页」是配套的：入口归我，页面归用户。

补充（2026-09-17 晚）：这条「不要动」针对的是我主动的改动。用户自己会继续微调这张页——
当天他先让我把迷你走势线改成默认关闭，又问「自选列表是否可以和背景融合起来而不是分层」。
我做了「玻璃纸 vs 融合 vs 滑杆自调」的对比页（`/ui/favorites-fuse.html`），他回「可以直接融合，
非常好看」，于是现在的定稿是：**没有玻璃纸**，行直接长在光斑底上，只留发丝线，底部叠同色
渐变保可读（提交 `fda4e1c`）。以后再提到自选页的现状，以这版为准，不要再把它描述成
「玻璃纸」。用户自己提出的调整照常做，方式还是先出带旋钮的对比原型让他选。

补充（2026-09-18）：用户又亲自定了这张页的**头部排版**——「设置按钮稍微搞大一点，现在
有点太小了，不容易点击，今日 9 涨 0 跌那段去掉，自选和数字也去掉，右边那条线也去掉，
空间都给分类文件夹，分类文件夹可以稍微大一点，加号也稍微大一点」。于是「自选」大字、
数量印章、右边的涨跌比小条、「今日 N 涨 N 跌 · 平均振幅」那行状态小字全部撤掉，圆片从
32 放大、分类字号从 12.5 放大到 14。**头部当天晚些又被重排了一次并定稿，现行排版
（两行、长搜索框居中、右边「…」、返回与齿轮已被常驻标签栏取代）只看
`kanpan-favorites-header-layout`，别拿这一段的中间态当现状。**

这里有两条能带到以后的：一是**这张页上的元素尺寸以他的手感为准**，`kanpan-ui-restrained-element-scale`
（元素要克制、别往大里做）说的是我自己挑尺寸的时候，他点名说「太小、不好点」时就照他说的放大；
二是他紧接着补的那句「重新排版设计一下」——**删掉一堆元素之后不能把剩下的原样留在那儿**，
要把剩下的重新排一版，不要留下一条只剩两颗按钮的空行。

补充（2026-09-22）：这条「不要动」不只管我**主动**的改动，也管**顺手带出来的**改动。
当天一次和视觉毫无关系的修复（给自选页每一行加 `.onGeometryChange` 去量滚动落脚点）
把「融合」弄丢了：行特征被挡住，每行冒出一块不透明白底加一根半截系统分隔线。用户看到
后先问「自选列表怎么改成这种了」，再问「我记得以前是融合的吗」，最后直接把 2026-09-21
17:22 那张截图甩过来说「**我要的是这种，你得改回来啊**」。

能带到以后的是两条：

- **这张页的现状由用户手里的截图说了算，不由我的记忆说了算。** 他一旦给出一张基准图，
  验收标准就是「同机型、同皮肤截一张和它并排比，除了行情数字和时间不许有别的差」，
  而不是「我觉得看起来对了」。
- **凡是改动落在自选页文件里的任务——哪怕改的是滚动、同步、无障碍这类看不见的东西——
  改完都要在模拟器上截一张图和定稿比一眼再收工。** 这张页没有「只改逻辑不碰视觉」
  这回事：SwiftUI 里一个修饰符的排序就能把行特征挡掉。
