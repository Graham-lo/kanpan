# kanpan-decided-not-to-do-stays-dead

**项目约定**：看盘里凡是文档或用户已经判「不做 / 建议不做 / 缓」的功能，整理待办和交接时直接剔除，不准再做、不准当欠账收编回来

2026-09-22 我把另一个窗口盘出来的「未完成事项」清单拿去追溯出处，发现其中几项在原始文档里
本来就是「建议看盘不做」（CNY 换算）、「⏸ 缓」（固定起点强弱比较）、「1.0 不做」（多空比等
预埋字段）、以及用户当天刚对另一个窗口拍过板的「强平不做」。我在汇报里把它们列成「需先确认
是否翻案」。用户的回答是两句：「确定不做的不要管」，接着交接给 Codex 时又补了一句
「**不要做的功能不准做**」。

所以在看盘里：

- **整理待办、写交接书、给子代理或 Codex 派活时，凡是已有「不做」结论的项直接剔除**，不列成
  「待确认」、不列成「可选」、不留在清单尾巴上。用户不想再看到它们，更不想它们被顺手做出来。
- 「不做」的来源包括：原始方案 / 盘点文档里明写的「不做 / 建议不做 / 缓 / 不在 1.0」，以及
  用户在任何窗口口头定过的（比如「强平不做」记在了另一个窗口改的盘点文档里）。
- 交接书里要把这些项**明确列成禁做清单**发给实现方，因为实现方看到「基建现成」很容易顺手做掉；
  「不准做」是硬约束，不是优先级低。
- 判断一项是否「不做」要以**最新**的表态为准：早先「不在 1.0」但后来被用户抬成 P1 的
  （小组件、实时活动）算要做；早先列过、后来被判「不做」的算不做。

这条和 kanpan-review-items-all-get-fixed（审查项每条都要改）不冲突：那条管的是审查报告里的
缺陷项；这条管的是功能范围——范围之外的东西，不因为它便宜就进来。

## 2026-09-22 补：口径只能有一份，误导人的文档要删，不是留着加注

同一天晚上用户又说：「新开窗口很多文档会误导，明确过的功能不做又翻出来顺手做，这个问题统一
处理一下，统一口径，不要再留这种文档」。他要的不是在每份旧文档上加一句提醒，而是：

- **不做清单只有一份**：`docs/不做清单.md`。交接书、AGENTS.md、PROJECT.md 只指向它，不再各抄一份；
  抄多了就会有一份过期。
- **待办来源只有一份**：当前的交接书。`docs/` 下其它文档要么是现行规格，要么删掉；
  「历史上曾经的待办 / 审查报告 / 方案 / 提示词」这种第三态不许留在仓库里，git 历史就是归档。
- **新判「不做」当场做两件事**：写进不做清单，并把它在别处的「待办 / 建议 / 缓 / 预埋」措辞删掉。
- 新开的 Claude 窗口是靠 AGENTS.md / PROJECT.md 入门的，所以这条规矩必须写在那两处顶部，
  只写在我的记忆里挡不住别的窗口。
