# kanpan-map-the-route-before-fixing-it

**项目约定**：看盘排查行情取数故障时，先把完整链路摸清楚（直连/网关两条路 × REST/WS 两种传输 × 各自的主机名）再动手改

2026-09-18 模拟器上出现「K 线历史取不到」（诊断里 `bars: 1`，而实时报价、成交量、
持仓量都正常到了）。我查到症状之后就想直接往下修。

用户的提醒是：「因为这个网络涉及到直连，网关等，很复杂，所以先摸清链路」。

看盘的行情取数不是一条路而是一张网，至少有这几个正交的维度：

- **路线**：直连 与 网关 两档，出厂默认直连、没有自动切换（见
  `kanpan-route-choice-is-binding`）。
- **传输**：REST（取历史 K 线、快照）与 WebSocket（实时推送），这两个在币安本来就是
  不同的主机，换镜像或走代理时经常只有一边通。
- **主机名**：REST 与推送各有自己的默认域名，而且「国内可直连」与「国内被墙」是按
  单个主机名分族的，不能按交易所或顶级域下结论（见
  `kanpan-binance-domestic-vs-overseas-domains`）。网关自己的上游域名还得在 VPS 上
  单独实测选（见 `kanpan-gateway-picks-its-own-domain`）。
- **本机中间层**：Mac 上可能有代理在中间（curl 会显示 `CONNECT`），模拟器走的是
  Mac 的网络栈，所以本机代理规则会一起影响测量结果。

所以遇到取数故障，正确的第一步是**画出这一次实际走的完整链路**——哪条路线、哪种传输、
解析到哪个主机、中间有没有代理——再判断断点在哪。跳过这一步直接改配置或改代码，
很容易修错地方，或者把「只有一边不通」误判成「整个交易所不可用」。
