# kanpan-account-username-not-email

**项目约定**：看盘的账号系统改用用户名 + 密码注册，不做邮箱注册与邮箱验证码

# 看盘账号用用户名密码，不用邮箱

2026-09-15，用户明确决定：看盘（kanpan）的账号系统**不用邮箱注册，普通的用户名 + 密码注册就行**。

起因是邮箱验证码这条链路卡在外部依赖上——没有自有域名、没有可用的 SMTP 发信身份，服务也还没部署，
所以后端 `Mailer::from_env()` 拿不到配置，`mail_enabled` 恒为 false，所有发码接口只能返回 503。
与其为了发一封验证码去买域名、配 SPF/DKIM、接 Resend/SES，用户选择直接把邮箱这一环去掉。

因此在看盘项目里：

- 不要再提议用邮箱注册、邮箱验证码、邮箱找回密码，也不要把「接发信服务商」当作待办推给用户。
- 已有的 `Backend/kanpan-api` 邮箱认证代码（`mail.rs`、`account_mail`、`account_challenges`、
  `/v1/auth/register/verify`、`/v1/auth/code/resend`、`/v1/auth/password/code`、`/v1/auth/password/reset`）
  属于要被替换掉的实现，不是要继续补完的实现。
- 相应地，`docs/账号系统方案.md`、`docs/账号系统-实施提示词.md`、`docs/账号同步与复盘-最终落地方案.md`
  里关于邮箱、发信限速、防邮箱枚举的规格已经过时，不能再照着它们验收。

没有邮箱就没有「发一封信重设密码」这条通路，所以忘记密码如何找回是这个决定的直接后遗症，
需要另找办法（例如注册时给一串本地保存的恢复码），不能默认还有邮箱兜底。
