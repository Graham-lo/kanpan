# 行情页统计：市值口径与数据来源

2026-09-18 写，2026-09-20 按第四轮审查（B-01 / B-02 / B-03 / B-09）的最终实现改写。
2026-09-22头部为右侧两列三行六格；本文描述其中持仓量 / 成交额 / 市值 / 费率四项的取数，另两项为结算倒计时与振幅。数额一律用 K / M / B / T 金融单位，
不用万 / 亿。**市值 = 总市值 = 总供应量 × 现价**，不是流通市值。

这一轮改掉的四件事，先摆在前面：

1. **分类是 fail-closed 的**：认不出的合约是 `Unknown`，不再默认当成币。
2. **市值按身份合并**，两个来源对同一个代号说法不一致就留空，不再互相补字段。
3. **每个数字都有保质期**：币的供应量与股票乘数 7 天、持仓量名义价用的价格 5 分钟、
   OKX 持仓量表 15 分钟；过期就是这个字段不出现。
4. **未上市（Pre-IPO）一律留空**，`private/<slug>` 那条路整个删掉了。

四格的来源：

| 格子 | 来源 |
| --- | --- |
| 持仓量 | VPS 的 `kanpan-api` `/v1/market/open-interest`，Binance / OKX 两个上游 |
| 成交额 | 客户端已订阅的 24h ticker 流，本来就有 |
| 市值 | VPS 的 `kanpan-api` `/v1/market/meta`，`totalSupply × 现价` |
| 费率 | 客户端已订阅的 markPrice 流（标签写「费率」，不写 FR） |

下面只讲市值。

## 1. 币安永续里有三分之一不是币

`https://www.binance.com/fapi/v1/exchangeInfo` 每行有个 `underlyingType`。
2026-09-18 的 766 个 TRADING 合约：

| underlyingType | 个数 | 是什么 |
| --- | --- | --- |
| COIN | 573 | 加密货币 |
| EQUITY | 156 | 美股正股，以及在美国上市的 ETF / 杠杆 ETP |
| HK_EQUITY | 15 | 港股 |
| KR_EQUITY | 8 | 韩股 |
| COMMODITY | 8 | 金银铂钯、原油、布油、天然气、铜 |
| INDEX | 2 | `BTCDOM`、`ALL` |
| CN_EQUITY | 2 | A 股（CXMT、UNITREE） |
| PREMARKET | 2 | 未上市公司（ANTHROPIC、OPENAI）——**一律留空** |

按「币」的口径去算这 193 个非币合约，出来的一定是错数。所以市值先按
`underlyingType` 分流，认不出的**留空**，宁可空着也不给错的数。

分流是 **fail-closed** 的（B-01）。上表这八种各自映射到一个 `Kind`，**除此之外的一切**
都落到 `Kind::Unknown`：字段不存在、字段是空串、币安某天加了一种这版代码没见过的
`underlyingType`、以及这个合约根本不在 exchangeInfo 里。`Unknown` 什么都不发。

| `underlyingType` | `Kind` | 契约里的写法 | 发市值吗 |
| --- | --- | --- | --- |
| `COIN` | `Crypto` | `crypto` | 发，总供应量 |
| `EQUITY` | `TickerEquity` | `equityUS` | 发，乘数 |
| `HK_EQUITY` / `KR_EQUITY` / `CN_EQUITY` | `NamedEquity` | `equityNamed` | 发，乘数 |
| `PREMARKET` | `PreMarket` | `preMarket` | **不发** |
| 其它已知值（`COMMODITY`、`INDEX` …） | `Other` | `other` | 不发 |
| 缺字段 / 空串 / 没见过的值 / 不在表里 | `Unknown` | `unknown` | 不发 |

这条规则有一个明知道的代价：**只在 OKX 上、不在币安 exchangeInfo 里的合约现在是
`Unknown`，因此没有市值。** 以前这种合约会走「默认当币」的老路，拿一个同名代号的
供应量乘上去——那正是 NVDA 被报成 1500 万市值的那类错。宁可空着。

客户端的品种目录用上表第三列对账，样本文件是
`KanpanCore/Tests/KanpanCoreTests/Fixtures/underlying_kinds.json`，两边各有一条用例读它，
所以任何一侧改了映射、或者新增了一个 `Kind` 而忘了登记，都会红。

## 2. 服务端存的不是股数，是乘数

服务端把 `k = 该公司真实市值(美元) ÷ 该合约当前价` 写进 `totalSupply`，
客户端照旧显示 `totalSupply × 现价`。

这样做的原因是：同一家公司在币安可能有几个报价口径完全不同的合约。

- `HK0700USDT` 按**港元**报价（426.00）
- `TENCENTUSDT` 按**美元每股**报价（54.90）
- `SKHYUSDT` 是 **ADR**，一份存托凭证只代表约 0.14 股

存股数的话，第三种必须知道折股比例才算得对。上一版拿 Nasdaq 筛选器的股数，
它把 SK 海力士的 ADS 比例当成整十，算出 1.34T，比真实的 929B 高了 44%
（用户当场指出「韩国海力士也不对啊」）。用「市值 ÷ 合约价」，报价币种、
ADR 折股比例、AB 股结构一次全被约掉，而且乘回现价之后数字还跟着行情实时走。

验证：`TENCENTUSDT`（k=8.90B）与 `HK0700USDT`（k=1.137B）都读出 488B；
`SKHYUSDT`（ADR，929.6B）与 `SKHYNIXUSDT`（韩股，928.5B）差 0.12%。

## 3. 数据从哪里拉

| 用途 | 地址 |
| --- | --- |
| 币的供应量 | Binance apex / 产品表（强来源）+ CoinGecko（弱来源），按身份合并，见第 5 节 |
| 合约分类与 base | `https://www.binance.com/fapi/v1/exchangeInfo` |
| 合约现价 | `https://www.binance.com/fapi/v1/ticker/price` |
| 公司市值 | `https://stockanalysis.com/<路径>/__data.json` |
| 汇率 | `https://open.er-api.com/v6/latest/USD` |

两条注意：

- **VPS 在美国，`fapi.binance.com` 返 451**，但 `www.binance.com/fapi/v1/*`
  是 200。所以服务端走 `www.binance.com`。（「REST 在 VPS 上不通」这句
  只对 `fapi.binance.com` 成立。）
- stockanalysis 的页面是 SvelteKit 的 devalue 格式：`nodes[].data` 是一个扁平
  数组，`data[0]` 是「字段名 → 下标」的映射，真值要再去数组里取一次。直接把
  `data[0]` 当值读会静默取错。

stockanalysis 的路径按上市地分：

| 上市地 | 路径 | 市值币种 |
| --- | --- | --- |
| 美国 | `stocks/<代码>` | USD |
| 香港 | `quote/hkg/<代码>` | HKD |
| 韩国 | `quote/krx/<代码>` | KRW |
| 上海 | `quote/sha/<代码>` | CNY |

`listing_currency()` 同时识别 `she`→CNY、`tpe`→TWD。这里的币种仅用于服务端把公司市值统一为美元；客户端法币换算不做，见[不做清单](不做清单.md)。

**`private/<slug>` 那一档删掉了（B-09）。** 未上市公司的页面没有 `marketCap`，只有
`statsLeft` 里的 Implied Valuation / Valuation——前者是二级市场传闻价，后者是上一轮融资
的投后估值，发布当天就已经是旧的。两个都不是「总供应量 × 现价」这个口径里的市值，把它们
当市值发出去是拿另一个单位冒充。所以 `parse_private_valuation()` 整个删了，
ANTHROPIC / OPENAI 也从 `LISTINGS` 里删了，`Kind::PreMarket` 本身就不发乘数——
**Pre-IPO 是按构造留空的，不靠关键词兜**。

## 4. 抓回来的页面必须先自证身份

地址对不等于页面对。stockanalysis 会改版、会重定向、会把一个退市代码指到另一家公司，
偶尔还回一个挑战页。所以每一页在被读出市值之前，要先证明它讲的是我们要的那家公司（B.3）。

`page_identities()` 从 devalue 那个扁平数组里把这几个字段捞出来：
`symbol`、`db_symbol`、`nameFull`、`name`、`titleName`、`ticker`、`exchange_symbol`
（它们在 `data[0]` 里是下标，要再去数组里取一次值）。然后 `page_is()` 判两件事之一成立：

- **代码相等**：页面自报的代码 == 地址里那个代码（`0700`、`000660`、`BRK.B`…）；
- **名字前缀命中**：页面的公司名规范化之后（去掉空格、标点、大小写）以 `LISTINGS` 里
  登记的那个关键词开头。

两样都拿不到（页面读得出来但一个身份字段都没有）→ **算不通过**，不是算通过。
不通过就 `Blank`：这个合约这一轮没有市值，而且**不沿用**上一轮的旧乘数——因为页面
已经证明我们对这个地址的理解错了，旧数字的可信度跟着一起没了。

关键词就是 `LISTINGS` 第三列，全表 24 条都填了：TENCENT、XIAOMI、SHEIN、LENOVO、
MEITUAN、KUAISHOU、POPMART、BYD、MINIMAX、GIGADEVICE、ZHONGJI、ZAI、SKHYNIX、
SAMSUNGELECTRONICS、HYUNDAIMOTOR、SAMSUNGELECTRO、HANMISEMICONDUCTOR、
LGELECTRONICS、NAVER、CXMT、YUSHU、BERKSHIRE、QUANTINUUM。
美股那条直拼 `stocks/<base>` 的路用 base 本身当代码核验，不需要登记关键词。

## 5. 币那一半：身份优先合并，歧义留空

币的供应量有两族来源，口径不是一套：币安自己的 apex / 产品表用交易所的资产代号，
CoinGecko 用它自己的 `id`。以前两族的字段是混着填的（谁有填谁），于是「同一个代号在
两边指两个不同的币」这件事被悄悄抹平了。现在（B-02）：

- 两族**各自**按身份归并（`by_identity`）。同一族里一个身份对上两个不同的资产 →
  这个身份的值是 `None`，也就是**歧义 → 留空**，不挑一个看起来更像的。
- 合表时 CoinGecko 先进，币安覆盖；币安那边判定为歧义的，连 CoinGecko 那份一起删掉。
- **绝不跨族拼字段**：币安那行缺 `totalSupply` 就是缺，不去借 CoinGecko 的数。
  这是明知道的覆盖率下降，换的是「一行数据只来自一个身份」。
- 每个值记着自己是从哪一族采纳的（内部字段 `family`，落进快照，**永不下发**）。

`1000SATS` 这类打包合约的解法在 `strip_multiplier()` + `lookup()` 里，优先级是固定的四步：

1. 币安那族里查**原名**（`1000SATS` 自己就是一个已登记的资产）→ 用它，**不再除以 1000**；
2. 币安那族里查**剥掉前缀**的名字（`SATS`）→ 用它，并按前缀缩放；
3. 两边都只有弱来源（CoinGecko）且都对得上 → **留空**；
4. 弱来源的原名 → 弱来源的剥前缀名（同样缩放）。

数字前缀只认 10 的整数次幂且 ≥1000（`1000`、`10000`…），剩下的部分至少两个字符且以字母
开头；另外认字面的 `1K` / `1M` 两种写法（剩下的部分至少三个字符）。所以 `1INCH` 不会被
当成打包合约，`2024ABC` 也不会被当成「2024 个 ABC」——它只是一个以年份开头的名字。
而 `1000SATS` 绝不会被缩放两次：那个内部的 `family` 字段就是为了让这件事在重启之后
仍然成立，所以它进快照。

## 6. 每个数字都有保质期

旧版这张表只要抓到过一次就一直发，上游坏了一个月也照发（B-03）。现在三条上限：

| 数字 | 上限 | 常量 |
| --- | --- | --- |
| 币的总供应量、股票乘数 | **7 天** | `MAX_PUBLISH_AGE` |
| 算持仓量名义价用的合约价（缓存兜底） | **5 分钟** | `OI_PRICE_MAX_AGE` |
| OKX 的持仓量表（缓存兜底） | **15 分钟** | `OKX_OI_MAX_AGE` |

三条规矩配着它：

- 年龄用 `SystemTime`，并且**写进快照**（币那张表一个 `coins_at`，每个股票乘数各带一个
  `at`）。用 `Instant` 的话重启就等于把所有年龄清零，7 天上限一次重启就绕过去了。
- 过期的表现是**这个字段不出现**，不是发一个旧数、也不是发一个 0，更不会给客户端加
  「数据时间」「来源」这类展示字段。年龄是服务端自己的事。
- 年龄不是唯一判据：**拆股当天就作废**。沿用旧乘数时会比一次「算这个 k 时的价格」和
  「现在的价格」，比值落在 0.667…1.5 之外就认定单位变了，直接丢掉那一行
  （`unit_changed()`）。1:10 拆股之后再乘七天，会把市值报成十分之一。

## 7. 非美股一律要点名，不猜

只有 `underlyingType == EQUITY` 且 base 是纯字母数字时，才允许直接拼
`stocks/<base>`。其余一律要在 `market_meta.rs` 的 `LISTINGS` 里点名映射。

猜的代价是实打实的：`stocks/ANTH` 会命中 AN2 Therapeutics，一家 1.92 亿的
生物科技公司；把它写成 Anthropic 的市值，比留空糟得多。

`listing()` 还有一道闸：**只有 `kind.equity()`（即 `TickerEquity` / `NamedEquity`）才查得到
地址**。`PreMarket`、`Other`、`Unknown` 一律 `None`，所以哪怕将来有人在 `LISTINGS` 里
误登记一个未上市的名字，也发不出市值来。

当前 `LISTINGS`（**24 条**，每条三列：合约 base → 页面路径 → 核验关键词）：

- 港股（13）：HK0700 与 TENCENT 都 → `quote/hkg/0700`（TENCENT），HK1810（XIAOMI）、
  HK0625（SHEIN）、HK0992（LENOVO）、MEITUAN → 3690、KUAISHOU → 1024、
  POPMART → 9992、BYD → 1211、MINIMAX → 0100、GIGADEV → 3986（GIGADEVICE）、
  ZHONGJI → 3308、ZHIPU → 2513（关键词 ZAI，公司现名 Z.ai）
- 韩股（7）：SKHYNIX → 000660，SAMSUNG → 005930（SAMSUNGELECTRONICS），
  HYUNDAI → 005380（HYUNDAIMOTOR），SAMSUNGEM → 009150（SAMSUNGELECTRO），
  HANMI → 042700（HANMISEMICONDUCTOR），LGELECTRONICS → 066570，NAVER → 035420
- A 股（2）：CXMT → 688825，UNITREE → 688836（关键词 YUSHU，宇树）
- 美股但合约名不是代码（2）：BRKB → `stocks/BRK.B`（BERKSHIRE），
  QNTX → `stocks/QNT`（QUANTINUUM；QNT 已经是个币，币安改了名）

原来的 26 条里，**ANTHROPIC 和 OPENAI 被删掉了**——不是因为地址不对，而是因为那条路发的
不是市值（见第 3 节）。

base 取自 exchangeInfo 那一行的 `baseAsset`，不是从 symbol 尾巴上切。
币安的计价资产有 `USDT USDC USD1 U BTC` 五种，`SPCXUSD1` 只有按行里的
`baseAsset` 才读得出 `SPCX`。

它们不存在：

- **`Unknown`**：不在 exchangeInfo 里（例如只在 OKX 上的合约）、或者 `underlyingType`
  是这版代码没见过的值。
- **过期**：7 天没能刷新成功的币或股票（第 6 节）。

## 9. 抓取失败怎么办

stockanalysis 偶尔会对正常的上市公司回一个挑战页而不是 JSON（实测 Visa 中过一次）。
`equity_price()` 把结果收成三种：`Value`（算出来了）、`Blank`（这个合约确实没有市值）、
`Carry`（这一轮没问到，沿用上一轮）。

| 情况 | 处置 |
| --- | --- |
| 抓失败 | **立刻重试一次**（间隔一个 `LISTING_GAP`）；再失败 → `Carry` |
| 页面打开了但读不出 `marketCap`（ETF 就是这样） | `Blank`，真的空，不沿用 |
| 页面讲的是**另一家公司**（第 4 节的核验没过） | `Blank`，而且**不沿用**旧乘数 |
| 这个合约没登记页面地址 | `Blank` |
| 价格表 200 了但缺这一行 | `Carry`（是表缺一行，不是公司没市值） |
| 缺这个币种的汇率，或汇率 ≤ 0 | `Carry`。**绝不把缺失的汇率当 1**——那等于把 1369 韩元报成 1369 美元 |
| 汇率表 / 价格表整个拿不到，或价格表回了个空数组 | 整张股票表沿用上一轮，不做半张 |
| exchangeInfo 拿不到 | 用上一轮的分类继续算——少了分类，每只股票都会被读成同名的币 |
| exchangeInfo 拿不到、上一轮也没有分类可继承（冷启动那一次） | **这一轮一个字都不发**，请求收到 503，十分钟后再刷一轮 |

最后那一行是发布这件事本身的副作用决定的：发布会把「币那一半的时刻」写成此刻，于是这张
表在接下来 24 小时里都算新鲜、预热循环也把下一轮推到 24 小时后。要是把一张「有币表、没分类」
的表发出去，冷启动时 exchangeInfo 失败一次，代价就是整整一天答不出一个市值。宁可这一轮
明说没有。

沿用（`Carry`）有两条附加规矩，都是这一轮加的：

- 沿用的行**带着旧的时间戳**一起留下，所以它会继续变老，7 天之后自己就不再发布了。
  不会出现「每天沿用一次、于是永远新鲜」的循环。
- 沿用之前先比价格单位，拆股就丢（`unit_changed()`，见第 6 节）。
