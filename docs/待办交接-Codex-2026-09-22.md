## P0 · 行情页头部：右侧六格掉到价格下面（今天用户报的 bug）

**用户实际看到的品种：闪迪 `SNDKUSDT`、美光 `MUUSDT`**（币安上的美股合约，中文名映射在 `docs/板块分类表-2026-09-18/美股-中文名.json:16-17`）。这两只是首要复现与验收对象，`1000SATSUSDT` 是我在模拟器上另找到的一只。美股合约价格不长（两位整数 + 两位小数），掉行的宽度多半来自右侧六格里的值（市值 / 额的 K·M·B·T 数额、结算倒计时、费率位数），不只是超长价格——修的时候要按「价格块 + 六格实际最宽值」而不是只按价格长度去想。**不要再一只一只去试别的品种**，就用这三只。

**现象**（模拟器 iPhone 16 Pro 上用 `1000SATSUSDT` 已复现，截图 `/tmp/hdr/16pro-sats-top.png`，验收报告里要附同样的图；`SNDKUSDT`、`MUUSDT` 由 Codex 在动手前先深链打开各截一张头部图放进报告作为修前基线）：
打开 `hkline://symbol/1000SATSUSDT`，价格 `0.00001234`（10 个字符）+ 胶囊 `▲+0.33%` 之后，右侧「仓 / 市值 / 结算 · 额 / 费率 / 振幅」六格整块掉到价格下面，头部长高一截，周期条和图被往下推。
BTC、DOGE、1000PEPE、ZETA 这些还并排着，但已经贴到极限——价格再长一位、或者涨跌幅到两位数、或者系统开了粗体文本，就掉。

**根因**（`Kanpan/Kanpan/Main/TopBar.swift:246-275`）：`PriceRow.body` 是 `ViewThatFits(in: .horizontal)` 三档，
第三档 `stacked`（`:269`）就是「六格挪到价格下面」。价格块 `priceBlock`（`:277`，22pt 等宽数字 + 胶囊，`fixedSize(horizontal: true)`）
加上六格 `stats`（`:359`，两张 `Grid`，`fixedSize(horizontal: true)`）在 402pt 屏减去 12pt 两侧留白的 378pt 里装不下时，就落到这一档。
当初这一档的注释写着「价特别长的品种走这一档，头部再长高一截」——这个取舍用户不接受：**六格必须永远在价格右边**。

**改法（最终版，2026-09-22 晚用户两次拍板：先是「涨跌放到价格下面」，再是「把这一行布局彻底优化」；覆盖此前一切分档写法）**：

参照 AICoin 头部（`/Users/mdd/.claude/uploads/c45039af-0f4e-5028-bb46-b751ec5280d4/24cf2b55-image.png`）：大字价格一行，紧贴其下一行小字涨跌额 + 涨跌幅，右侧数据格。看盘照这个骨架把整行重排，**只有一种布局，任何屏宽、任何品种都不分档**。

**A. 整行骨架**（`PriceRow.body`）

1. 一个 `HStack(alignment: .center, spacing: 0)`：左边价格块，`Spacer(minLength: 8)`，右边六格。两侧留白与上面品种名那一行对齐（现有 12pt）。
2. 行高由六格三行决定（约 48pt），价格块（两行，约 40pt）在其中**垂直居中**。头部高度和现在并排时一模一样，不长高；上下内边距不动。
3. `ViewThatFits`、`sideBySide`、`verticalPrice`、横排的 `priceBlock`、`pill` 全部删掉。你之前写的 `verticalPrice` 分档也不要留。
4. 整行仍是扫图横滑手势的落点（价格块 + 六格一整块），id `top.lastPrice` / `top.changePercent` / `top.stats` 三个都保留。

**B. 价格块**（左，`fixedSize(horizontal: true)`，`VStack(alignment: .leading, spacing: 3)`）

5. 第一行：最新价，22pt medium 等宽数字，涨跌色（AICoin 那套），停更时 `ink3`，不缩不截，`top.lastPrice`。
6. 第二行：`+6.72  +0.64%`——涨跌额、两个空格、涨跌幅；13pt semibold 等宽数字；颜色与价格同一支涨跌色（是**文字色**，不是 `badgeFill` 填底）；**没有药丸底色、没有圆角矩形、没有箭头图标**；无数据时 `—`，停更时 `ink3`。id 沿用 `top.changePercent`。

**C. 六格**（右，`stats`，两张 `Grid`，内容与顺序不动：仓/市值/结算 · 额/费率/振幅）

10. 每列宽度按这一列里最宽的一格算（现状），右列右缘贴内容留白；六格整体 `fixedSize(horizontal: true)`，不缩字、不截字、不换行。
