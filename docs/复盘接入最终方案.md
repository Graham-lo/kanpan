# 复盘接入最终方案

日期：2026-09-15。范围：原生看盘 App 接入既有 Scorebook 数据与业务；本文是实施方案，复盘功能尚未接入。用户追加：找相似纳入接入范围，整个复盘模块独立抽出，便于后续优化。

依据：当前看盘源码与 `docs/实施任务书.md` 第 9、10 章、最新 `docs/AICoin-K线复刻规格.md`、完整 `prototype/复盘原型.html`，以及实际 `scorebook-backend` 的契约、创建记录、重温和规则引擎源码。用户最后决定：**横屏移至周期行，底栏增加复盘；具体产品决策由 Codex 完成。** 原型中的入口与算法不作为最终契约。

## 1. 入口定稿

| 位置 | 最终安排 |
|---|---|
| 顶栏 | 品种、连接状态、搜索、自选星保留 |
| 周期行 | 可横向滚动的周期区；右侧「画线 / 更多 / 图表 / 横屏图标」；iPad 对应全屏 |
| 底栏 | **风格 · 指标 · 自选 · 设置 · 复盘**，只替换原横屏槽位 |
| 图区 | 右下「记一笔」，让开价格轴、底轴和已有辅助按钮；回到最新存在时向上排列 |
| 横屏右侧工具栏 | 增加「记」和「复盘」；工具可滚动，返回竖屏固定可达 |
| 复盘内部 | 全屏「复盘簿」，三项：待办 / 记录 / 战绩 |

- 底栏使用明确的「复盘」，不用单字「簿」让用户猜。保留现有风格与图表两种面板：前者选造型、配色，后者管坐标、显示与布局。
- 周期行不强塞六个周期与四个操作。周期区可滚动，当前周期始终滚入可见区；横屏用 44pt 触达区的图标并带可访问性标签。
- 周期行「更多」只管周期。截图补录放复盘簿右上「＋」菜单，避免把周期菜单变成杂项菜单。
- 角标仅统计**需要用户处理的去重记录数**（待确认结果、待写复盘、同步需处理）；“等答案”保留在待办列表，不占催办角标。
- 冷启动仍按当前看盘规则进入自选/行情，不额外增加复盘首页；退出复盘恢复进入前的品种、周期、视野和选中状态。

## 2. 记一笔：先框图，再表达判断

### 正常流程

1. 点「记一笔」，进入明确的框选模式；暂停视野跟随，行情连接继续工作。画线落笔与框选不能同时接管触摸。
2. 横拖选取连续区间，至少 3 根**已经收盘**的 K 线。左右边界吸附到真实根，贴边缓慢滚动并按需补历史；缺口不能假装连续。
3. 松手出现紧凑卡片。图区保留左右边界、目标、失效和到期把手；卡片显示对应数字，支持点击精确输入，键盘打开时可折叠卡片继续看图。
4. 方向由用户点选「看多 / 看空 / 只记录」，**不按刚才的涨跌预选多空**。把握提供 50/60/70/80/90 与“未填写”，默认未填写；不默认 70 污染校准统计。
5. 原话可填写，支持系统键盘听写。有效框选允许不写原话保存，详情显示“未写原话”；不自动替用户生成一句观点。
6. 来源默认「图在先」，可改「想法在先 / 两者交织 / 不确定」，映射既有 `chart_first / thought_first / interwoven / unknown`，不把原型 `idea` 直接交给后端。
7. 点「记下」先完成本机事务保存，随即反馈。联网同步成功后显示服务端确认；失败保留记录和操作队列，可重试，不重复创建。

### 价格与时间的规则

- 目标和失效默认取所选区间高低，并根据方向安排上下。用户动过的值不被重新框选或切方向静默覆盖；数值不再适合新方向时就地提示，用户可点“按方向重置”。
- 判定锚点采用**判断时刻的真实原始市场价**，不采用平均 K 线价格、标记价或所选旧区间末根的价格。记录卡明确给出判断时刻与参考价。
- 看多必须目标高于参考价、失效低于参考价；看空相反。旧区间高低无法满足时要求调整，不能保存后立即自判成功。
- 到期用绝对 UTC 时间存储；显示按用户时区。默认“24 小时后”，可选 4 小时/1 天/3 天/自定义，也可拖竖线。默认策略记住用户选择，拖动结果不重新套默认值。
- 用户缩短区间到不足 3 根、手势取消、切品种或退后台时，未完成草稿保留并可继续。开始新草稿才替换当前正在编辑的区间。
- 框选时可隐藏形成中的末根，避免把其最终完整 OHLC 误认成当时已知信息；最新报价可以单独展示，但不能变成已收盘证据。

## 3. 判定规则定稿

**新图上记录默认“收盘确认”，提供“触价确认”选项。两种规则均由服务端执行，提交后冻结。**

| 情况 | 收盘确认（默认） | 触价确认 |
|---|---|---|
| 目标先达成 | 观察开始后第一根完整判定 K 线收盘达到目标，判对 | 成交/可靠细粒度证据证明目标先触达，判对 |
| 失效先达成 | 第一根完整判定 K 线收盘达到失效，判错 | 证明失效先触达，判错 |
| 截止到期都没达成 | 未达目标，判错 | 未达目标，判错 |
| 数据缺失、无法证明顺序 | 待核实，不挤进对错 | 待核实，不任意指定目标优先或失效优先 |
| 只记录 | 不判对错 | 不判对错 |

- 判定周期随提交冻结，之后为了看图切周期不改变它。截止边界采用 `[assessment_start_at, expires_at]` 的明确版本化约定；收盘模式不使用跨越开始时刻的整根历史 OHLC，截止时刻恰好收盘的根可以计入。
- 触价模式中同一根 OHLC 同时越过两条线，并不能证明先后。优先细周期/逐笔核实，仍不能确定就保留待核实。
- 判定终止于第一个有充分证据的终结事件；已判对后再走到失效不翻案。行情订正可以产生新的结果修订，必须保留旧版本和证据。
- 不提供直接把服务器结果点成“对/错”的无痕覆盖。详情提供“结果有疑问 → 说明原因/补证据”，沿用结果修订及复盘版本控制；个人感受写在复盘中。
- 旧规则记录继续显示原冻结规则和原正式结果，不按新规则重算历史胜负。旧原始结果、探索回放和新正式判定分开统计。

### 与旧后端的真实差异

当前 `Criteria` 只有 `criteria-v1`、`horizon_hours` 等字段。`Trigger.kind = bar_close/trade_touch` 属于 T3 的**启动观察条件**，不是目标/失效的先后判定开关。T1/T2/T3 最终仍按期限末价比较，失效在路径中触达会判未兑现；T4 是“守住边界”，不是目标价先达成。不能把原型三根线硬塞到旧 T4。

实施时新增 `criteria-v2` 的独立规则描述与评估分支（绝对到期、目标、失效、判定周期、确认方式、终结事件和证据原因），同时扩展创建记录校验、实时 checkpoint、重温标记和统计分组。旧版本处理保留是为了尊重已冻结证据。

## 4. 四种时间不能混成一根竖线

| 字段 | 含义 |
|---|---|
| `range_start_at / range_end_at` | 用户框选的行情范围，末端采用已收盘区间结束边界 |
| `client_recorded_at` | 本机点击记下的时间 |
| `submitted_at / assessment_start_at` | 服务端接收时间与正式评估开始时间 |
| `original_claimed_at` | 用户明确声明的过去判断时间，仅用于事后补记 |

- 今天研究上周一段行情，今天提出新判断，是“今天的判断 + 历史参考区间”，不能把上周区间尾巴自动变成判断时刻。
- 若用户要补记“我当时就这么想”，明确选择事后补记，显示“补记”，独立归档。它不自动取得实时预判证据资格。
- 离线本机时间不能伪装成服务器当时确认。离线记录永久保留，补传标记延迟确认；已错过的观察窗口可作为复盘练习，排除于默认正式战绩。
- 图上分别画淡区间、判断标记、到期标记；三者不必相邻。

## 5. 复盘簿、记录详情与重温

### 待办 / 记录 / 战绩

- 待办按行动顺序：待确认 → 写复盘 → 等答案。草稿/同步异常在对应行标状态，支持继续、重试、稍后。
- 记录支持品种、方向、时间、来源、规则与状态筛选；旧数据直接读同一账户，不复制成第二份记录。
- 详情仍在共享的真实图表上打开：原话、当时标准、系统结果、复盘、相关局面。展开与收起不创建另一套 K 线图。
- 复盘编辑使用“当时 / 市场的答案 / 现在怎么看 / 下次怎么做”，允许一句话开始；逐步内容作为草稿保存，正式发布走既有 revision 与 outcome IDs 校验。
- 保存前可修改草稿；正式记录用更正、作废处理，沿用后端历史。**作废复盘记录与删除一根画线是两类操作**，不共享删除按钮。

### 战绩口径

- 默认分母只含正式、符合统计资格、已经判对/判错的样本；待定、未触发、只记录、数据不足、作废、补记与探索回放不混入。
- 图在先 / 想法在先 / 两者交织独立显示数量与比例；未填写把握不进把握校准图。
- 新旧规则及不同确认方式分组展示。正式统计沿用后端冻结样本与同局面代表规则，不根据客户端当前加载的一页记录临时算“总胜率”。
- 没有样本显示“—”，不显示 0% 暗示全错。总数、有效样本数、待处理数保持可追溯。

### 重温

- 复用 `ChartView`，增加独立回放会话，播放/暂停、前后一步、跳到判断、1×/2×/4×。
- 每一步只给渲染器和指标计算器截至当前游标可知的数据；主副图、自动 Y 轴、图例、十字线、报价条都受同一个截止点约束。隐藏未来蜡烛但仍用未来最高价算 Y 轴也属于泄漏。
- 重温时顶部显示“重温 · 时间”和当时价格，不把当前实时报价摆在同一价格位；原行情连接可在独立状态里继续更新。
- 从记录进入时优先恢复该记录提交时的指标参数、输出开关、均线颜色、坐标方式及关联画线快照；这些是记录专属快照，查看/调整不覆盖日常看盘偏好。
- 后来才画的分析线和后来知道的结论默认隐藏，结果在用户看完后续或主动揭晓时显示。
- 暂停游标、播放速度、视野本机保存；重开恢复为暂停。退出回到之前的看盘现场，不像原型直接 `resetView()` 跳最新。

## 6. 复用边界与新增接口

### 直接复用

- 原生壳：`TopBar`、`IntervalBar`、`BottomBar`、`LandscapeChrome`、五种 `Panel` 及主题令牌。
- 图表：`KanpanCore` 的真实时间/价格映射、主副图、指标、当前画线几何与选择基础设施。
- Scorebook：账户权限、记录列表/详情、复盘队列、复盘草稿发布、历史版本、局面、统计及已有截图附件/定位路径。

### 需要新增的业务能力

1. **原子创建图上记录**：记录正文 + `chart_context` + criteria + 本机幂等 ID 一次提交，避免先创建记录后写区间留下半份数据。`chart_context` 包含交易所、市场、精确合约、周期、起止、截止点、图表配置/关联画线快照与 schema 版本。
2. **无截图证据**：当前 CreateCall 没有起止字段；`PUT scene` 仍要求 attachment_id。新增原生 range 证据类型，不能伪造 attachment UUID。有效 range 允许空原话；截图旧接口继续支持原语义。
3. **无截图找相似**：当前公开/私库图形搜索入口仍依赖 attachment_id。新增 range 查询，由服务器按受支持的精确市场标识取 OHLC，以同一特征算法生成查询；锁定 cutoff、排除自身及重叠区间，结果仍回真实品种和时间范围。
4. **规则 v2 与结果**：按上一节新增，不改旧 T 模板含义。按需取数据，保留派生证据和哈希，不长期囤全量 K 线。
5. **原生概览/同步读取**：记录增量 cursor 与 tombstone、去重待办数、按规则/来源聚合的统计读模型；复盘草稿继续沿用已有版本冲突规则。

接口名称在 OpenAPI 变更时定，本文不把尚不存在的接口说成现成能力。原生客户端使用清晰的 `ScorebookClient` 边界，不把 HTTP 和记录业务塞进 ChartRenderer。

### 找相似的完整流程

入口放在框选完成卡和记录详情的「找相似」。默认搜索同周期的市场历史，可切「我的记录」；返回数量、分数、品种、时间范围和可用性来自服务端。结果点击进入共享真图，支持原区间/相似区间切换与后续重温，不把匹配缩略图当行情。

- 原生输入：精确市场身份 + 周期 + 起止 + 查询截止时间；服务器取原始 OHLC，与索引采用相同的特征版本。平均 K 线、主题颜色、均线不会进入形状特征。
- 默认同周期；跨周期是显式选项，沿用服务端能力声明。索引周期不足时显示实际可查范围，不暗中换成 1h。
- 搜索冻结 `cutoff_at`，排除查询本身及重叠邻域。回放中的搜索截止随可知时间限制，不能通过匹配后的走势泄露尚未揭晓的信息。
- 公开库和私库是两种明确范围，不混淆账户数据；文本辅助只作用于后端支持的私库查询。旧截图记录仍可用已有图片检索；已定位的截图可走相同 range 路径。
- 公共 OHLC 索引可复用；原生 range 私库记录需要同源特征索引。旧仅有图片而未定位的记录继续独立走图片路径，不能把不可比的分数混成一张排序表。
- 大量区间可通过作业查询、分页、取消和重试处理。保存相似案例是显式动作，普通翻看不批量写入个人复盘簿。

### 独立复盘模块（用户明确要求）

新增本仓库内独立 Swift Package `KanpanReview/`，内部三个 target，分别测试：

```text
KanpanReview/
  Sources/
    ReviewDomain/    记录、区间、草稿、回放与搜索状态、规则展示
    ReviewData/      Scorebook API、事务存储、迁移、同步与幂等队列
    ReviewUI/        复盘簿、记录卡、找相似、复盘编辑、回放控制
  Tests/
  README.md         接入契约、存储版本与验证方法

Kanpan App
  ReviewIntegration/  入口装配、账户连接、共享图表适配器
```

- 主 App 仅装配 `ReviewFeature`，传入账户/服务配置和图表适配器；`MainScreen` 不实现复盘请求、存档、统计或搜索算法。
- `ReviewDomain` 不依赖 SwiftUI/UIKit、App 的 `PrefsStore`、行情 WS 或具体数据库。`ReviewData` 实现存储/服务边界；`ReviewUI` 使用模块状态和注入的图表能力。
- 共享图表通过两个小接口接入：读取真实品种/周期/区间、保存恢复视野的上下文接口；呈现区间/标记与回放截止点的图表接口。具体 `ChartView` 与主图行情控制器适配留在 App，不要求图表引擎了解 Scorebook 的 call/review/search 概念。
- 扩展现有图表时仅增加通用覆盖层、手势接管和截止数据源接口；画线、框选、回放由统一仲裁决定当前触摸归属，不复制一套图表或手势引擎。
- 模块持有自己的存储 schema、迁移、同步游标、缓存隔离和测试数据。移除复盘入口不影响看盘编译与日常偏好；更新复盘存储不重置画线。
- 搜索策略、参数、分页和结果组件都在复盘模块内；后端新增 range 查询与规则处理仍在 Scorebook 现有分层中独立实现。未来替换搜索模型或增加记录类型无需重写看盘壳。
- 首先做到清晰目录与可测试边界，不为初版预建动态插件系统；必要时可将此 Swift Package 单独拆库而保留宿主接口。

## 7. 品种、存储与状态隔离

### 品种

- 新建范围覆盖看盘**实际支持的币安 USDT 普通与 TradFi 永续**，包括已接入的美股/贵金属合约，不接受“目前只有币”的过时假设。
- SNDKUSDT 等合约不能等同于交易所现货股票，XAUUSDT 永续不能等同于现货 XAUUSD。统一身份使用 venue + market + symbol，显示名称只用于展示。
- 旧记录都能读；能精确映射的在原生真图打开。旧现货/未知市场保留原身份与附件，标明行情源未接入，不能静默换成相似名称的永续。截图补录继续保留。

### 持久化

- 本机采用可迁移的事务存储保存草稿、待同步操作、已读记录、复盘草稿、回放位置和界面偏好。使用独立用户/服务器命名空间；凭证放 Keychain。
- 提交队列持久保存幂等键，超时重试复用同一键；联网不覆盖正在编辑的本地草稿。版本冲突保留双方内容供继续处理。
- 服务端保存正式记录及历史版本，是跨设备正式数据源。连接同一 Scorebook 账户即可看旧记录，无需重导图片。
- 图上画线、复盘记录、用户偏好都不归“行情缓存”；清缓存不能清掉它们。K 线沿现有内存/有限启动快照约定，不为复盘新增长期全行情缓存。
- 画线层与复盘层分开管理：隐藏/清空画线不删除复盘目标线；复盘线只是冻结规则的投影，不能在日常画线模式下被拖改。

### 状态

交互工具用互斥模式（浏览 / 画线 / 框选 / 回放）；记录选中状态、复盘簿开关与功能面板是独立的呈现状态。避免把五种不同概念都堆成页面状态再互相清空。

切换入口先提交或保存当前草稿，转屏不重建业务会话。已完成的标注即时落盘，拖动过程只改预览，松手一次提交；正常面板仍遵循首个外部点击只关闭面板的规则。

## 8. 交付顺序和完成标准

1. **入口与持久化底座**：周期行横屏、底栏复盘、会话状态、本机草稿/同步队列、服务连接和旧记录只读。看盘启动不被账户连接拦住。
2. **原生记录闭环**：框选/把手/精确输入 → 保存 → 图上留痕 → 复盘簿 → 重开恢复；同步 v2 契约和正式规则。
3. **重温与复盘闭环**：真实数据回放、未来信息屏蔽、恢复看盘、复盘草稿/正式发布、结果核实、旧数据兼容显示。
4. **同源搜索与战绩**：range 找相似、冻结截止、规则分组/有效样本统计与跨设备验证。

各阶段为分次验收，最终接入包含四阶段；第一阶段的空入口不算复盘完成。

必须覆盖：关进程/断网/重试不丢不重；转屏保留草稿；切周期不改判定规则；目标失效冲突、同根双触达、缺行情与到期边界；正式记录和事后补记分开；图上/详情/统计结果一致；新旧源不能错配；删画线不删记录；所有主副图和报价不泄露回放未来；退出复盘恢复原看盘现场。实体设备测试依用户后续安排，本轮方案本身不冒充接入验收。

## 9. 已识别的原型差距

- K 线为种子随机数据，部分按钮只是 toast；可拖不等于已接入完整业务。
- `judge()` 从所选末根开盘时间开始扫描、先检查 target 后检查 invalid，可能使用判断前价格并偏向“对”。
- `bar_close/trade_touch` 的后端含义被混用；T4 也不能当新目标策略。
- 原型把 `na` 放入判对率分母，且未使用正式统计资格、规则版本及代表样本。
- `CreateCall.original_text` schema 必填不等于必然非空：当前代码允许有附件的空原话；原生无附件 range 仍需新契约。
- 原型本地存储遇到空数组会重新填入示例，写失败被吞掉；退出记录重置视野；回放期间换周期没有统一结束播放定时器。正式版必须使用生命周期和持久化状态处理。
- 形成中 K 线、真实时间轴/月年历、断档、延迟确认、图表参数快照、旧数据源映射、身份认证和冲突同步均需正式实现。
