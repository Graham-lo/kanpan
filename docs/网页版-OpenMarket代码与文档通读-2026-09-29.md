## 一、结论

**OpenMarket（前身 Kiyotaka）官方没有开源仓库。** 平台内的 64 个指标都是 kScript Hub 上的官方或社区脚本，
只能在平台里用，不能下载。Hub 页面只有介绍文字，分成 Core / Advanced / Flow / Specialized 四类，另有本周精选（如 Volume Delta Pro、Rolling VWAP）
和一个流行度分 kScore，没有源码。`app.openmarket.xyz` 用 curl 访问超时。在 GitHub 上用代码搜索，没有找到任何社区 kScript 仓库。

实际读到的是以下三类材料：

- **官方文档的本地镜像**：包括用户手册、kScript 语言手册（含 cookbook 示例源码和函数口径）、数据 API 文档。
- **员工公开仓库里的前端验收说明**：从中能看到终端的真实控件结构，比如 testid、工具条折叠、布局选择器。
- **两份第三方对标文档**。

所以，指标和形态只能按**文档里写出的口径**来判断，拿不到脚本源码。这对看盘影响不大：看盘本来就不搬判定算法，只取展示和聚合。

## 三、可吸收点（按优先级排）

工作量标准：**小**指 1–2 天，只动网页端；**中**指 3–5 天，或需要服务端配合；**大**指一周以上。

### P1-1 关键水平位（Key Levels）：前日 / 前周高低、今日开盘，加前日成交量控制点与价值区

- **来源**：`docs/kscript/cookbook/key-levels.md`；足迹图设置里的 POC Naked Extension 和 Show Levels on Price Scale（`order-flow/footprint/settings-reference.md`）；TPO 设置里的 pPOC / pVAH / pVAL（`order-flow/tpo/settings-reference.md`）。
- **OpenMarket 的做法**：
  - 画五条线：PDH / PDL（前一日高低）、PWH / PWL（前一周高低）、当日开盘价。
  - 只取**已走完**的日、周桶，所以不会重绘。
  - 每条线从它所属时段的起点画到最新一根 K 线右边 12 根的位置（`labelOffset=12`），标签用 `stickyRight` 钉在图表右缘，格式是「PDH  价格」。
  - 颜色：日级用 `#f5a623`，周级用 `#4a90d9`。
  - 可以扩展到月、季、年、前收盘价，以及日中点 EQ = (PDH+PDL)/2。
  - 足迹图和 TPO 还提供「前一时段 POC / VAH / VAL」，并支持 **naked 延伸**：线一直向右画，直到价格第一次回到这一价位才停；价格轴上同时显示一颗胶囊。
- **放在哪**：主图叠加，作为指标库「主图」分类下的一项「关键价位」，只有一个开关。
- **看盘的口径（我们定，不给设置）**：
  - 日界用上海 8:00，即 UTC 0 点，和看盘日线切换点一致；周界用上海周一 8:00。
  - 画这几条：前日高、前日低、前周高、前周低、今日开盘价。
  - 另加**前日成交量控制点和七成价值区上下沿**，这三条做 naked 延伸：回测后线停在回测那根 K 线上，不再往右画。
  - 标签用中文短词「昨高 / 昨低 / 上周高 / 上周低 / 今开 / 昨控 / 昨值上 / 昨值下」，钉在右缘；价格轴上显示同色小胶囊。
  - 颜色按网页版皮肤取两级（日级、周级），不用 OpenMarket 的橙蓝配色。
  - 日线以上周期只画周级，周线以上不画。
- **和现状的差距**：现在完全没有。`vpvr()`（`chart/overlays.ts:37`）可以直接拿来算前日的 POC 和 VA，但需要一根完整日的 1m 或 5m K 线，可以取当前已加载的 bars，不够时补拉一次日内 K 线。
- **工作量**：小。

### P1-2 画线补「锚定 VWAP」和「固定区间成交量分布」两把工具

- **来源**：`docs/kscript/cookbook/anchored-vwap.md`、`functions/special-indicators.md`；`third-party/OPENMARKET_DRAWING_SYSTEM_PARITY.md`「Tool-specific analytics」一节。
- **OpenMarket 的做法**：
  - **锚定 VWAP**：点一根 K 线作锚，从那根起按典型价和实际成交量累计 VWAP，带 ±1/2/3σ 偏差带（最多六条），带之间用 0.08 透明度填充。
  - **固定区间 VP**：拖一个时间区间，用 24 个价格桶分配成交，按 K 线价格区间与桶的重叠比例摊量，标出 POC，价值区从 POC 向两侧扩到 70%。
  - 这两把工具 TradingView 手机版的画线面板里也有，符合「画线清单以 TradingView 手机版为准」这条规矩。
- **放在哪**：画线工具栏，新开「成交量」一组。
- **看盘的口径**：
  - 锚定 VWAP 只画 ±1σ 和 ±2σ，和现有 VWAP 一致，不给档位设置。
  - 固定区间 VP 直接复用 `vpvr()` 和 VPVR 的三种显示模式；桶数不用固定的 24，按区间像素高度自动定，每行 ≥ 4 px。
  - 两把工具都随品种保存，并参与账号同步。
- **和现状的差距**：现有画线类型只有 `trend | ray | hline | vline | rect | fib | measure`（`chart/chart.ts:47`），这两把都没有。计算代码已经有 `vwap()`（`chart/indicators.ts:76`）和 `vpvr()`，缺的是画线外壳和命中测试。
- **工作量**：小到中。

### P1-3 深度梯子加「成交」两列和净差列，悬停显示离中间价的距离

- **来源**：`docs/learn/core/terminal/order-book-dom.md`、`order-book.md`。
- **OpenMarket 的做法**：
  - 梯子共六列：Bids | Buys | Price | Sells | Asks | Delta。
  - Buys / Sells 是**本次会话在这个价位累计的主动买 / 卖量**。绿色和红色背景条透明度 20%，Buys 从左往右长，Sells 从右往左长。
  - Delta 列 = (Buys − Sells) / (Buys + Sells) × 100%。
  - 热度柱的强度相对于当前可见的最大深度。
  - 有「Center」按钮，一键回到中间价并高亮最优买价。
  - 在订单簿上悬停某价位时，显示它离中间价的百分比。
- **放在哪**：现有 240 px 深度梯子（`orderflow/ladder.ts`）。
- **看盘的口径**：
  - 不加宽梯子，在现有「买深度 | 卖深度」两半之间插一条 56 px 的中列，显示这一行的「主动买 − 主动卖」净额，数额用 K/M/B/T，涨跌色表示正负。
  - 这一行累计的主动买和主动卖，用两侧深度柱底下一层 0.2 透明度的细条表示。
  - 累计范围是「打开这只品种以来」，换品种就清零；脚注写「自 hh:mm 起」。
  - Delta% 只在悬停卡里给。
  - 悬停卡加一行「距中间价 +0.42%」。
  - 数据来自现有三家 aggTrade 合流，已经在 `orderflow/tape.ts` 里；按梯子当前的行（桶）累加即可。
  - 回中间价不加按钮，双击梯子就回到中间价。
- **和现状的差距**：现在梯子只有挂单深度，没有成交；设计稿 2.2 引用了 Tape Mode「成交与净差堆在成交价位上」，但实现只做了深度那一半。
- **工作量**：小。

### P1-4 侧栏加「24 小时流动性」和「24 小时成交」两块统计小部件

- **来源**：`docs/learn/core/terminal/liquidity-stats.md`、`volume-stats.md`、`market-stats.md`；`workspaces-and-widgets.md` 说明新工作区默认就带 Volume Stats、Liquidity Stats 和 Tape。
- **OpenMarket 的做法**：
  - **流动性统计**：统计中间价 ±2.5% 以内的买、卖挂单美元额。取滚动 24 小时，每 30 分钟一个点，画绿红两条线。默认显示当前簿的数值；悬停某个点时显示那 30 分钟的流动性，以及相对上一段的变化百分比。右上角显示 BID VOL / ASK VOL。
  - **成交统计**：滚动 24 小时，每 30 分钟一段。默认显示 24 小时成交总额，买卖（按主动方向）拆开，画红绿两条叠加的波形线；悬停显示那一段的成交额和环比。
  - **市场统计**：包括 TPS（每秒成交笔数）加 sparkline、Book Depth 比例条、Volume Flow 比例条，可以按交易所拆分。
  - 统计类小部件只能各开一个，而且跟着主图的品种走。
- **放在哪**：侧栏「自选」视图里的小部件，和盘口、成交、大单、提醒一样可以折叠、可以拖动排序。
- **看盘的口径**：
  - 两块各高 120 px，数额用 K/M/B/T，时间轴按上海时间。
  - **流动性**的历史直接从 `GET /v1/market/orderflow/heat` 回填推算：每一列里，低于当时中间价的桶算买、高于的算卖，取 ±2.5% 以内求和，每 30 分钟取平均。热力带宽是 ±5%（`orderflow/heat.ts:17`），足够覆盖。只有服务端常驻跟踪的品种才有 24 小时历史，其余品种从打开页面起才开始画，不补假数据。
  - **成交**用三家的 30m K 线。币安 K 线自带主动买入额；OKX 的主动买卖拆分拿不到 K 线级数据，只算总额，并在悬停卡里说明「OKX / Coinbase 只计总额」。
  - 市场统计里只取 TPS 加 sparkline，放进现有「详情」小部件，作为一行小字；其余与盘口压力条重复，不做。
- **和现状的差距**：现在只有实时压力条（±1/2/5%），没有任何时间维度的流动性或成交统计。
- **工作量**：流动性小；成交中（需要补 OKX 和 Coinbase 的 30m K 线拉取）。

### P1-5 订单簿变化（Order Book Delta）：每个价位在最近 1 小时 / 1 天里挂单净增还是净撤

- **来源**：`docs/learn/core/terminal/order-book-delta.md`。
- **OpenMarket 的做法**：
  - 每个价位显示挂单净增减：绿色为增加，红色为撤掉。
  - 时间窗有 1h / 4h / 12h / 1d 四档；分组精度随价格自动定；可以在币和美元之间切换。
  - 点一个价位会弹出直方图，显示这一价位随时间的增减。
  - 有 Center 按钮、Link（是否跟随主图）按钮，还能快速切换最近 5 个品种。
- **放在哪**：底部抽屉加一个标签页「挂单变化」，和「大单」并列，不另开侧栏小部件。或者作为深度梯子的一种显示模式，梯子右上角一个切换「深度 / 变化」。倾向后者，因为和价格轴对齐时最好读。
- **看盘的口径**：
  - 变化值 = 该桶现在的挂单名义 − 窗口起点的挂单名义，买卖分开算，数据来自热力的环形缓冲和服务端回填。
  - 时间窗只给 1 小时和 1 天两档（一页的模式不超过两个常用的）。
  - 点一行时，在悬停卡里画这一价位在窗口内的小折线。
  - 这里只是两个快照相减，不做「诱多 / 撤单欺骗」一类的判定。
- **和现状的差距**：没有。热力数据已经具备，缺的是差分和展示。
- **工作量**：中。

### P1-6 成交带的几处细节：bps 角标、背景深浅随金额变化、鲸鱼行加高

- **来源**：`docs/learn/core/terminal/trade-and-liquidations.md`（只取成交部分）、`tape.md`。
- **OpenMarket 的做法**：
  - 每行依次是：方向箭头、交易所 logo、价格、bps 角标、美元额（K/M）、相对时间（now / 5s / 2m）。
  - **bps 角标** = (本笔价 − 同一交易所上一笔价) ÷ 上一笔价 × 10000，绝对值小于 0.5 时不显示。
  - 整行按方向上色，**背景透明度随金额相对门槛的倍数增大**；行高 25 px，鲸鱼单行更高。
  - 默认四档门槛：$500 / $1.3K / $5.0K / $50.0K，另加一个整体倍数。
  - Tape 小部件最左侧有一条「aggression」竖条，表示成交的力度和频率；相对近期均值明显偏大的成交用粗体。
- **放在哪**：侧栏「成交」小部件（`orderflow/tape.ts`、`widgets.ts`）。
- **看盘的口径**：
  - 加 bps 角标（小于 0.5 不显示）。
  - 背景透明度 = clamp(金额 ÷ 大单门槛, 0.04, 0.35)。
  - 金额 ≥ 门槛 ÷ 5 的行（现在已经加粗并在图上落点）行高从 20 px 加到 28 px。
  - 不加方向筛选，也不加四档门槛；现有的「最小额」一个输入框就够了。
- **和现状的差距**：现在有 1 秒合并、最小额过滤、加粗和图上落点，缺上面三项视觉细节。
- **工作量**：小。

### P2-1 大单 / 散户 CVD（按单笔金额分档的主动买卖差）

- **来源**：`docs/kscript/cookbook/tape-reader.md`、`core-concepts/data-sources.md` 里的 `trade_volume_by_size`。
- **OpenMarket 的做法**：
  - 每根 K 线把成交按单笔美元额分成七档：1 = $0–1K，2 = $1K–10K，3 = $10K–100K，4 = $100K–500K，5 = $500K–1M，6 = $1M–10M，7 = $10M+。
  - 每格记录 `[档号, 买额, 卖额, 买笔数, 卖笔数]`。
  - 「鲸鱼 CVD」取第 5 档及以上，「散户 CVD」取第 2 档及以下，同一副图画两条线，另外画每根的成交笔数柱。
  - 历史深度：1m 约一周，1h / 1d 约几个月。
- **放在哪**：副图指标「大单与散户累计量差」。
- **看盘的口径**：
  - 纯粹是聚合，没有判定，符合规矩。
  - 分档标准由我们定：大单 = 单笔 ≥ 该品种大单门槛 ÷ 50（和成交小部件的默认过滤线一致，会随每个币自动调整）；散户 = 单笔 < $10K。只画两条线，不画笔数柱。
  - **数据**：浏览器实时部分从三家 aggTrade 按档累加。历史需要服务端给常驻跟踪的品种每分钟记一行 `[分钟, 大买额, 大卖额, 小买额, 小卖额]`，每品种每天 1440 行，几十 KB，在 20–40 GB 预算里可以忽略。
  - 注意 aggTrade 是把同价同向的成交合并后的「单」，比真正逐笔偏大，这是可以接受的口径。
- **和现状的差距**：没有。现有 CVD 只有一条合计线。
- **工作量**：中（服务端要加采集和一个接口）。

### P2-2 CVD 口径补两处：显示在线场所数、现货和合约分开

- **来源**：`docs/kscript/cookbook/aggregated-cvd.md`。
- **OpenMarket 的做法**：
  - 把四个场所求和。某个场所缺数据时计 0，并在图例上写「Venues live 3 / 4」。
  - 可以扩展成现货一条线、合约一条线。
  - 另有 ±1σ（回看 60）带，这一项属于统计判定，不取。
- **看盘现状的问题**：`cvd()`（`chart/indicators.ts:136`）是一条线。历史 K 线只有币安，按 `2×tb − v` 算；实时 K 线有 `venueDelta` 时是三家之和。所以**同一条线在「历史 → 实时」的交界处口径会跳变**，而且用户看不出来。设计稿写的「三家分线 + 合计」也没有落地。
- **看盘的口径**：
  - 图例里写「币安 · 三家」，表示历史段只有币安，实时段是三家，并在交界处画一条竖虚线。
  - 实时段可以拆成「现货 / 合约」两条，不按交易所拆三条，因为现货和合约的分歧更有交易含义。
- **工作量**：小。

### P2-3 VWAP 的第一段不完整时不画，加载更多历史时已画的值不变

- **来源**：`docs/kscript/cookbook/anchored-vwap.md`；`functions/ta-library.md` 里的约定：预热期一律为空，不编造早期值；滚动加载更多历史不会改变已经算出的值。
- **看盘现状的问题**：`vwap()`（`chart/indicators.ts:76`）从第一根已加载的 K 线就开始累计。第一段（当天、当周或当月）在锚点之前的数据没有加载进来，所以第一段的 VWAP 是错的；往左加载更多历史后，这一段的值还会变。
- **做法**：第一个锚点之前的 K 线输出 null；或者在需要时补拉锚点起的 K 线。前者只需改一行判断。
- **工作量**：小。这一条算 bug。

### P2-4 VPVR 用更细周期的 K 线来摊量

- **来源**：`docs/kscript/functions/volume-profile.md`（按价位逐笔聚合，每根 K 线一行 `[低, 高, 买量, 卖量]`，`ticksPerBar` 默认 1）；REST `VOLUME_PROFILE_AGG` 由服务端按品种元数据自动定桶；`tradingview-teardown.md` 里写的 VP 工具「需要更低周期的数据」。
- **看盘现状**：`vpvr()` 把每根 K 线的成交额按它的高低区间**平均摊**到各行。在 1h 以上周期，这会让分布偏平，POC 不准。
- **做法**：可见区间落在 4h 以上周期时，补拉同一时间段的 15m K 线（1d 以上补 1h）来摊，K 线数量上限 5000；拉不到时退回现在的摊法。POC 和价值区的算法不变。
- **工作量**：中。

### P2-5 画线交互补一批（只取「让画线顺手」的部分，工具数量不扩张）

- **来源**：`docs/learn/charting/drawing-tools.md`；`third-party/OPENMARKET_DRAWING_SYSTEM_PARITY.md`「Professional creation and editing interactions」「Settings and workspace controls」「Persistence and ownership reality」。
- **OpenMarket 有、看盘网页版还没有的**：
  1. 工具组按钮：单击启用这一组上次用过的工具，双击锁定连续画（按钮上出一个点），右键或 Esc 退出。
  2. 拖动端点时按住 Shift，吸附到最近的 45°。
  3. 选中后用方向键微移 1 px，加 Shift 微移 10 px。
  4. ⌘ 加拖动复制一份；⌘C / ⌘V 在同一张图里复制粘贴。
  5. 选中后出现一条快捷条：当前色加**最近用过的两色**、完整取色、线宽、线型、单个锁、删除。拖动画线时快捷条淡出。
  6. 批量删除分三种范围：「全部画线 / 全部指标 / 全部」，带实时计数，并且可以撤销。
  7. 磁铁三档（关 / 弱 / 强），按住 ⌘ 临时反转。
  8. **同一族工具记住上次改过的样式**，下次画时沿用。
  9. 「信息线」：画一段后显示区间的涨跌、百分比、根数和时长。现有「测量」工具已经覆盖，可以不做。
  10. **多空仓位工具**：TradingView 手机版有，第三方对标也说它「用得非常频繁」。
  11. 回放时已有画线变成只读、不能新建。
  12. 存储上限：每个品种 500 个对象，2 MB。**登录态加载失败时，绝不把「空」写回云端**；未同步的快照按账号身份暂存，只能由同一账号重放。
- **看盘的口径**：
  - 1–8 照做。快捷条用网页版自己的视觉。
  - 磁铁保留现有的开关，加一个「按住 ⌘ 临时反转」，**不加**弱 / 强档，以免多一个设置。
  - 多空仓位工具只显示「风险回报比 R、止损和止盈离开仓的百分比」，**不算仓位数量**。算数量需要账户额和风险比例两项设置，不做。
  - 11 与复盘回放对齐。
  - 12 要对照 `sync/engine.ts` 自查一遍。「加载失败」和「真的为空」必须能区分，这是会丢用户画线的那类 bug。
- **和现状的差距**：现在有 7 把工具，磁铁、隐藏、锁为全局开关，撤销 / 重做和 Alt 快捷键都有；上面 1–8 和 10 都没有。
- **工作量**：中。

### P2-6 自选：键盘、多图时「在第 N 格打开」、粘贴导入、补两列

- **来源**：`docs/learn/core/terminal/watchlist.md`；`tradingview-teardown.md` 把「导入 TradingView 自选」列为 P0，理由是「一键消除迁移成本」。
- **OpenMarket 的做法**：
  - **键盘**：↑↓ 移动并切换图表，Home / End 跳到首尾，Enter 在图上打开，Space 收藏或取消，Delete 从列表移除，Shift / ⌘ 点击做多选，Esc 清除选择。
  - **多图时**：控制条上显示「Chart N」，表示点击会在哪一格打开；行菜单里有「Open in Chart」。
  - **行显示**：不适用的数显示「—」，悬停说明原因；价格更新时闪一下。
  - **列多放不下时**：多出的列收进「+N」。
  - **导入**：支持 TradingView 的 `.txt` 或粘贴文本；保留分区，列出匹配不上的代号，超过 250 个时自动拆分。
- **放在哪**：侧栏自选小部件（`pages/chart.ts:546` 附近的 `#wTbl`）。
- **看盘的口径**：
  - 键盘：↑↓ 已有，补 Home / End、Enter、Delete（移出自选，⌘Z 可撤，已有 `lastWatchUndo`）、Esc。Space 与「加自选只在星上做」不冲突，因为它就是星的键盘版。
  - 多图时，自选头部写「在第 3 格打开」，跟随当前活动格；行右键菜单里加「在第 N 格打开」。
  - 列固定为「品种 · 最新价 · 涨跌幅 · 成交额」，侧栏宽 400 时再加「资金费 · 持仓额」两列（有就显示，美股等没有的显示「—」，悬停说明「该品种没有永续」）。不给列设置。
  - 价格变动时文字闪一次涨跌色，150 ms。
  - 「我的」页加「从 TradingView 导入」：粘贴 `BINANCE:BTCUSDT.P` 这类代号，或上传 `.txt`。按币安合约表匹配，匹配不上的列出来。`###分区` 映射到现有分类，映射不上的全部并进加密。
- **和现状的差距**：只有四列和 ↑↓；其余都没有。
- **工作量**：小到中。

### P2-8 复盘页补四个统计量（只取对复盘有用的）

- **来源**：`docs/kscript/strategies/stats-reference.md`、`cookbook/historical-returns.md`。
- **看盘现状**（`review/model.ts`）：已有净盈亏、已实现盈亏、手续费、资金费、胜率、盈亏比（平均赚 ÷ |平均亏|）、每笔期望、最长连败，以及按方向 / 品种 / 持仓时长 / 开仓时段 / 星期的分组。
- **值得补的**：

  | 统计量 | 算法 |
  |---|---|
  | **盈利因子** | 总盈利 ÷ 总亏损；没有亏损时显示「—」，不显示无穷大 |
  | **最大回撤** | 按平仓顺序累加的已实现资金曲线，从峰到谷的最大跌幅（金额和百分比） |
  | **最大单笔占比** | 最大一笔盈利 ÷ 净盈亏。OpenMarket 的原话是「如果最大一笔主导了净利润，就是一笔撑起了整个回测」；复盘里可以写成一句提示「这段时间的盈利主要来自 1 笔」 |
  | **多空拆分** | 多、空各自的净盈亏、回合数、胜率。分组里已有「按方向」，这一项只是提到 KPI 行 |

  另外可以考虑一张**按月净盈亏矩阵**（行 = 年，列 = 月，末行为胜月比例），画法照 historical-returns 的 plotMatrix。但只有交易历史跨越半年以上才有意义，先不做。
- **不取**：Sharpe、Sortino、Kelly、破产风险、walk-forward。它们针对按根 K 线的策略权益曲线，对手动交易的回合复盘没有意义，还需要额外假设。
- **工作量**：小。

### P3-1 以后做足迹图时，只取这些

- **来源**：`order-flow/footprint/settings-reference.md`。
- **取**：
  - 显示模式只要 Split（买 × 卖）、Delta、Total 三种（和 VPVR 的三种对齐）。
  - K 线下方的**统计行**（成交量、净差、净差 %、累计净差），固定放在下方。
  - 每根 K 线的 POC 用细框标出。
  - Scale & Grading 固定用 Visible（按可见区间定深浅）。
  - 行太薄时自动合并（Auto Scale Bars）。
  - **缩放到放不下数字时自动退化成紧凑柱**。
  - 每根 K 线的 tick 数按周期各自记忆，由我们定：1m 为 1 倍步长，往上照现有的桶倍数。
- **不取**：Imbalance（比例 3、堆叠 3、按对角线比较）、Stacked imbalance、Unfinished auction 标记、Big trades only 开关。前三项是判定；最后一项和成交小部件的最小额重复。
- **说明**：K 线下方的统计行可以**先于足迹图单独做**，作为副图指标「逐根统计」。在 2K 屏上，每根 K 线下方用数字列出成交额、净差和净差 %，比柱状图信息密度高。工作量小。
- **工作量**：足迹图整体大，统计行小。

## 五、给布局那一路的补充（不重复设计，只列 OpenMarket 的做法和建议）

1. **布局选择器的形状**（`deez-skills/skills/verify-kiyotaka/features/symbol-search-and-ticker-bar.md`、`workspaces-and-widgets.md`）
   - 分组是 1 / 2 / 3 / 4 / 5 / 6 / 8 / 9 / 12 / 16，另有一个 **4×4 点阵**：悬停时画出将要得到的形状，点击后应用；点阵坐标按「列-行」、从 0 开始。
   - 下拉面板是「悬停预览、点击钉住」。
   - 建议我们的布局按钮也用「预设 + 点阵」，点阵上限 4×4 正好是 16 格。
2. **超过一定格数自动进入 Monitor grid**：品种固定不联动、周期固定联动，十字线联动仍由用户决定。
   - 建议：≥ 9 格时不再给「联动品种」开关，自动按「每格一个品种、周期一起切」处理。9 格以上本来就是盯多个品种的用法，这样也少一个要考虑的开关。
3. **多图时禁止新建画线**（OpenMarket 在多图网格下禁止新建画线，已有画线仍可编辑）。
   - 建议只在 ≥ 9 格时禁用新建画线：格子太小，画不准，也容易误触。≤ 8 格照常可以画。
4. **按住 Shift 点「添加指标」= 加到所有格。**
5. **格子降级**：OpenMarket 的足迹图缩到放不下数字时退化成紧凑柱，DOM 的行太薄时合并。
   - 建议按格子的像素尺寸自动降级，**不给设置**：
     - 格宽 < 640 px 或格高 < 360 px：副图最多留一个，隐藏 VPVR 和深度热力，图例只留品种、周期和最新价一行。
     - 格高 < 240 px：只留 K 线和价格轴，价格轴按最宽刻度贴边。
     - 梯子、大单带、成交落点只跟随活动格。
   - 16 格在 2560×1440 下每格约 610 × 300，正好落在第一档。
6. **工作区保存**：OpenMarket 没有保存按钮，改动约 1 秒后自动存到账号；每个工作区有自己的 URL，可以在多个标签页同时打开；页脚「Layouts」悬停出菜单（新建、最近、星标），旁边列出最近工作区的标签，双击改名；Shift+T 打开完整管理器（搜索、重命名、复制、分享、导出 JSON、删除）。
   - 看盘规矩（kanpan-persist-on-gesture-end）：**手势一结束就立刻落盘**，不靠 1 秒定时器节流。拖分隔线、拖小部件排序都要在 mouseup 时立即保存。
   - 「每个布局一个 URL、多标签页各开一个」值得吸收，2K 屏用户常开两个窗口。
7. **工具条折叠**：`verify-kiyotaka` 手册写明，右侧有 15 个面板 id；默认只把热力、新闻、编辑器钉在工具条上，其余收进常驻的「面板」菜单（固定常驻）。工具条变窄时按阶梯再往菜单里折（宽度折叠）。钉选随账号保存。
   - 建议顶栏右侧也采用「常驻少数 + 一个『面板』菜单」，布局格数多、顶栏变挤时按固定顺序折叠，不换行。
8. **拖动副图分隔线的实现细节**（`repos/kiyotaka-chart/index.html:615–1140`）
   - 只改相邻两块的高度，两块高度之和不变；每块最小占 6%；抓取热区为分隔线上下各 4 px。
   - 高度按比例存储，指标增减时按比例归一。
   - 没有手动调过时，按副图个数给默认比例：1 个为 74 / 18，2 个为 68 / 12 / 12，3 个为 58 / 12×3，4 个为 50 / 10×4。
   - 建议再加一条：**双击分隔线恢复默认比例**（TradingView 也是这样），不再另设「重置」按钮。
9. **小部件多开**：数据类小部件可以复制成两份并排或堆叠，统计类只能各开一个。
   - 看盘侧栏宽度固定 400，不建议多开；只需保证 P1-4 的两块统计小部件各一个即可。
10. **搜索结果**：按资产类别分组，每组末尾有「See all」；右侧栏预览高亮品种有哪些交易所；单一交易所的结果点一下直接切换。
   - 网页版 ⌘K 已按分类分组，可以补上「右侧预览这只品种在三家的报价」，方便多交易所时一眼比价。

## 六、kScript 指标与形态逐个判断

说明：Hub 上 64 个脚本的源码拿不到，下面按文档里的口径（cookbook 有源码的按源码）和通行定义逐个判断。
「展示型」指只做聚合、画几何事实、按门槛过滤，不给买卖结论；「信号型」指输出方向、进出场，或给形态下结论。

### 展示型：吸收或可以考虑

| 脚本 | 结论 | 画法与参数（我们定，不开放） |
|---|---|---|
| **Key Levels** | 吸收（P1-1） | 前日高低、前周高低、今日开盘，加前日成交量控制点和价值区上下沿（naked，回测即停）；日界为上海 8:00；右缘钉中文短标签，价格轴上显示胶囊 |
| **Anchored VWAP**（画线） | 吸收（P1-2） | 点锚；典型价 × 成交量累计；±1σ、±2σ 两档带；带间填充 0.08 |
| **Fixed Range VP**（画线） | 吸收（P1-2） | 复用 `vpvr()`；桶数按像素自动定；POC 加七成价值区；三种显示模式跟随 VPVR 的全局选项 |
| **周 / 月 VWAP（Rolling VWAP）** | 已有 | 现在按周期自动选锚（`vwapAnchor`）；补「第一段不完整不画」（P2-3）。OpenMarket 的「stretch 读数」（(收 − VWAP) ÷ VWAP）不做，它是在暗示均值回归 |
| **Aggregated CVD** | 已有，补口径（P2-2） | 在线场所数；历史与实时的交界处画竖虚线；现货 / 合约两条线。±1σ 带不做 |
| **Whale vs Retail CVD / Volume Delta Pro** | 吸收（P2-1） | 大单 = 单笔 ≥ 大单门槛 ÷ 50，散户 = 单笔 < $10K；两条累计线；笔数柱不画 |
| **FVG（三根 K 线缺口）** | 可以考虑，排在最后 | 是几何事实（第 i−2 根的高 < 第 i 根的低，就留一个缺口区），不是判定。画法：半透明矩形从缺口处向右延伸，价格回补到缺口一半时变淡，完全回补就删除；只保留最近 6 个，只在 15m 以上周期画。**先确认朋友里有没有人用 SMC 的看法**，没人用就不做（kanpan-no-flashy-rarely-used-features） |
| **Supertrend / PSAR** | 超级趋势已有；PSAR 不做 | PSAR 与超级趋势功能重复，用得少 |
| **RSI / BOLL 及其变体** | 已有基础版 | 变体（RSI 背离标注、布林带「挤压」提示）属于信号，不做 |
| **逐根统计（足迹图统计行）** | 吸收（P3-1 说明） | 副图，每根 K 线下方写成交额、净差、净差 %；缩到放不下时退化成净差柱 |

### 信号型：不吸收

| 脚本 | 为什么算信号 |
|---|---|
| **市场结构（BOS / CHoCH）** | 枢轴高低点是几何事实，但「结构破坏 / 性质转变」是在给趋势下结论，还依赖枢轴回看参数这种算法选择。连枢轴点也不单独画，没有 BOS 标注时它用处很小 |
| **流动性扫荡（Liquidity Sweep）** | 「影线刺穿前高后收回 = 扫止损」是对行为意图的判定；而且和强平、止损聚集是同一类叙事 |
| **突破（Breakout）** | 输出进场信号 |
| **ABCD / Shark / Flag 等形态自动识别** | 自动识别形态就是给形态下结论。手画的 ABCD / XABCD 属于画线工具，也不在 TradingView 手机版对标清单的补充范围内 |
| **Zone tracker（供需区）** | 按枢轴生成供需区（lookback 20、最多 6 个、收盘穿越即判定消化并删除、向右延伸 40 根）。「供需区」和「被消化」都是判定 |
| **Volume Spike（成交量 z-score，回看 50、门槛 2.5）** | 统计显著性标记，用来暗示「异常」。大额成交已经由成交落点和大单带展示 |
| **Regime filter（4h 趋势门控 EMA 交叉、蜡烛着色）** | 直接是信号 |
| **Delta-RSI、盘口失衡 EMA、POC 迁移速度** | 在微结构数据上再叠一层指标，属于量化派生 |
| **期权式波动率报告（波动率锥、Implied Move、IV 曲面）** | 波动率锥可以只用 K 线算，但用得少；其余没有数据源（见第四节期权一条） |
| **Market Snapshot（Regime 文字卡）** | 判定 |
| **Sharpe / Sortino / Kelly / 破产风险 / walk-forward** | 用于策略回测，不适用于看盘；复盘只取 P2-8 的四项 |
| **Historical returns 年 × 月收益矩阵（行情）** | 季节性统计。teardown 也把 Seasonals 列为 P3（需求低）。同样的画法用在复盘的个人盈亏上价值更高（P2-8 的备注） |
