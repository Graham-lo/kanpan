# 看盘账号系统：登录 / 注册 / 找回密码 / 私人数据分开存（整段复制给 Codex）

---

你要给「看盘」加一套账号：**邮箱 + 密码**注册登录、找回密码、改密码、登录设备管理、注销账号，以及配套的
**跨设备同步**与**私人数据按账号隔离**。前端 iOS，后端新写一个独立服务。

界面规格已经定版，在 `prototype/账号原型.html`，逐屏逐令牌照抄，不要重新设计、不要询问已经定死的事。
原型里的交互不是示意：登录失败会累积并锁定、验证码会用完次数、离线时按钮改文案而不是转圈、登录成功后本机
有匿名数据就一定弹合并面板。这些都要实现。

硬规则（和 `docs/开工提示词.md` 同一套）：

- iOS 代码写在本仓库根目录下（新增 `KanpanAccount/`，UI 落在 `Kanpan/Kanpan/Account/`）。
  后端写在 `Backend/kanpan-account/`。`prototype/` 与 `docs/` 是已定版的规格，**只读，不要改**。
- 不许碰 `Backend/kanpan-gateway/`。那是行情网关，它的 README 写得很清楚：只处理公开行情，
  **不接收交易 / API 密钥 / 账户数据**。账号是另一个服务、另一个进程、另一个数据库角色。
- 装 Xcode / `xcode-select`、申请证书、改 VPS 上的 systemd 与 Caddy 需要用户密码，把命令交给用户自己跑。
- 交付前写 `docs/acceptance/账号系统.md` 证据（见文末「验收」），没有证据不算完成。

## 〇、先定的四件事，别推翻

1. **登录是可选项，不是门槛。** 冷启动照旧进行情。不登录能用全部看图功能：品种、周期、指标、画线、自选、设置。
   账号只多给三样：跨设备同步、复盘记录由服务器判定、换手机不丢东西。第一屏永远不是表单。
2. **只做邮箱 + 密码。** 不接 Google / 微信 / 手机号。这不是偷懒：App Store 指南 4.8 的
   「必须同时提供 Sign in with Apple」只在你**接了第三方登录**时触发；只有自家邮箱密码就不触发。
   以后真要加第三方登录，同一次改动里必须把 Sign in with Apple 一起加上，别分两次发版。
3. **行情连接永远匿名。** 看盘的 WS / REST 不带 `Authorization`，不带 user_id，不因为登录而改变。
   账号服务挂了、令牌过期了、后端在升级——图照样能看。这条是硬约束，不许为了"统一鉴权"合并掉。
4. **私人数据按账号分开存**，端上和服务端各一层，两层都要做。端上少做一层，别人拿起你的手机换个账号
   就能看见你的画线；服务端少做一层，一条忘了 `WHERE user_id` 的 SQL 就把所有人的数据端出去。

## 一、私人数据分开存（端上）

### 1.1 现状

| 数据 | 现在存在哪儿 |
|---|---|
| 设置（配色、字号、指标参数、常用周期）+ 自选 + 最近 | `UserDefaults`，键 `kanpan.prefs.v<n>`（`PrefsCodec.key`） |
| 画线 | `Application Support/kanpan/draws.json`（`DrawStore.applicationSupport()`） |
| K 线快照 / exchangeInfo / OI 归档 | `Library/Caches/kanpan/`（`KanpanData.Paths.caches()`） |
| 复盘记录 | 还没有。按 `docs/复盘接入最终方案.md` 新建，落点见下 |

### 1.2 改成按「账号槽位」分目录

引入 **slot**（账号槽位）这个概念：一台设备上可以存在多个槽位，同一时刻只有一个是当前槽位。

```
Application Support/kanpan/
  current                      ← 一行文本，当前槽位名
  accounts/
    local/                     ← 匿名槽位。装 app 就有，永远不删
      prefs.json
      draws.json
      review.sqlite
      outbox.json
    u-7f3a…/                   ← 登录后的槽位，名字是服务端 user_id
      prefs.json
      draws.json
      review.sqlite
      outbox.json
Library/Caches/kanpan/         ← 行情缓存，不分槽位，不上传，不备份
```

- **`Caches/` 不按账号分。** K 线、exchangeInfo、OI 不是私人数据，谁登录都能拉到一样的公开行情，
  按账号分只会把缓存打碎、把流量翻倍。
- 设置从 `UserDefaults` **搬到槽位目录下的 `prefs.json`**。`PrefsStorage` 协议保留，
  加一个 `SlotPrefsStorage`（文件实现）；`InMemoryPrefsStorage` 原样留给单测。
  首次启动做一次性迁移：`UserDefaults` 里有 `kanpan.prefs.v<n>` 就读出来写进 `accounts/local/prefs.json`，
  写成功后再删 UserDefaults 的键，并打一条迁移日志。迁移失败不删，下次再试。
- `DrawStore.applicationSupport()` 改成 `DrawStore.slot(_:)`，老路径 `kanpan/draws.json` 存在就搬进
  `accounts/local/draws.json`。**搬之前先复制，复制校验通过再删原文件**，别在用户的 104 条画线上玩原地重命名。
- 槽位目录**要进 iCloud 备份**（用户的东西该备份）。`Caches/` 本来就不进。

### 1.3 切槽位的规矩

- 登录成功 → 拿到 `user_id` → 目标槽位 `u-<user_id>`。目录不存在就建空的。
- **匿名槽位的数据永不自动搬走、永不自动删除。** 登录时如果 `local/` 里有东西（自选非空、画线非空或复盘非空），
  必须弹原型里那张合并面板，三选一（合并 / 只要云端 / 只要本机），用户不选就不往下走。
  点遮罩不算选择——原型里点遮罩只会 toast 提醒。
- 退出登录 → 切回 `local/`，**不删** `u-…/`。同一账号下次登录还在，不用重新拉一遍。
- 「清除本机这份副本」是显式操作（在「同步与数据」里），删的是当前槽位目录，云端不动。
- 同一设备两个账号的槽位互不可见。切槽位后所有内存缓存（PrefsStore、DrawStore、自选、复盘）必须重建，
  不许把上一个账号的 `@Observable` 对象接着用。

### 1.4 令牌放 Keychain，不放文件

```
service:  com.mdd.kanpan.account
account:  <slot>                      // 一个槽位一份
value:    { refresh_token, device_id, issued_at }
access:   kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly
```

- `ThisDeviceOnly` 是故意的：刷新令牌不进 iCloud 钥匙串、不进 iTunes/Finder 备份。
  换了新手机就重新登录一次，这是对的。
- **access token 只活在内存**，不落盘不进 Keychain。app 进后台不用清（进程还在），杀掉自然就没了。
- `device_id` 是本机随机 UUID，建槽位时生成，只用来在「登录设备」里认出这台机；不是 IDFA、不是
  `identifierForVendor`，不跨 app、不做广告用途。
- 任何地方都不许把令牌写进 `os_log`、崩溃日志、`print`。日志里出现令牌算 P0。

## 二、iOS 侧的模块与类型

新建 SwiftPM 包 `KanpanAccount/`（Swift 6，iOS 17+，零第三方依赖）。**不要塞进 `KanpanCore`**——
Core 是纯值与图表数学，不该依赖网络、Keychain 和时间。

```
KanpanAccount/Sources/KanpanAccount/
  Model/      Account.swift  AuthError.swift  SlotID.swift  SyncDoc.swift
  Auth/       AuthClient.swift  TokenBox.swift  Throttle.swift
  Store/      SlotStore.swift  Migration.swift  Outbox.swift
  Sync/       SyncEngine.swift  Merge.swift  Revision.swift
KanpanAccount/Tests/KanpanAccountTests/
```

- `AuthClient` 只管 HTTP，注入一个 `URLSessionProtocol`，单测用假 transport（照 `KanpanData` 里
  `Support/Fakes.swift` 的做法）。**不要在单测里连真服务器。**
- `TokenBox` 封 Keychain，协议化，单测用内存实现。
- `SyncEngine` 是 actor。并发刷新令牌只能有一条在飞：第二个请求 await 同一个 task，不许并发刷新
  ——并发刷新会撞上服务端的一次性轮换，把自己踢下线。
- `Outbox` 是离线操作队列，落在槽位目录的 `outbox.json`，每条带 `op_id`（UUID）、`kind`、`payload`、
  `created_at`。联网后**按原顺序**补传。`op_id` 保证补传两次不会变成两条。

UI 落在 `Kanpan/Kanpan/Account/`，一屏一个文件，名字对着原型：

`AccountSettingsRow` · `SignInScreen` · `SignUpScreen` · `VerifyCodeScreen` · `NewPasswordScreen` ·
`AccountScreen` · `SyncDataScreen` · `DevicesScreen` · `ChangePasswordScreen` · `CloseAccountScreen` ·
`MergeLocalDataSheet`

输入框必须设对 `textContentType`，否则密码 App 和邮件验证码自动填充都不工作：

| 字段 | textContentType | keyboardType |
|---|---|---|
| 邮箱 | `.username`（不是 `.emailAddress`，密码 App 认这个） | `.emailAddress` |
| 登录密码 / 当前密码 | `.password` | 默认 |
| 注册密码 / 新密码 | `.newPassword` | 默认 |
| 验证码 | `.oneTimeCode` | `.numberPad` |

一律 `autocapitalization(.never)`、`autocorrectionDisabled()`。密码框右侧那颗眼睛按原型给，
`accessibilityLabel` 随状态在「显示密码 / 隐藏密码」之间切。

## 三、逐屏状态（照原型，不要自由发挥）

### 3.1 设置页那一行

- 未登录：灰色人形 +「未登录 · 本机模式」+ 副行「自选、画线、设置只在这台 iPhone 上」+ 右侧胶囊「登录」。
- 已登录：首字母头像 + 邮箱 + 副行同步状态，整行可点进账号中心。
  同步状态三种：`已同步 · <相对时间>`（绿点）、`<n> 项待同步`（琥珀点）、`离线 · <n> 项等着上传`（琥珀点）。

### 3.2 登录

- 错误文案**永远是**「邮箱或密码不对。（还可以试 n 次）」，不区分邮箱不存在还是密码错。
- 客户端也计数：连错 5 次禁用按钮 60 秒并倒计时（服务端同样有自己的限速，两边都要有）。
- 锁定期间「忘记密码」仍然可点——被锁住的人恰恰最需要它。
- 离线时按钮文案改成「离线中，连上网再登录」并禁用。不要转圈等超时。
- 底部两段脚注照抄，尤其是「看盘不接任何交易所账户，也没有任何地方需要你的 API 密钥或助记词。
  谁向你索要，谁就不是看盘」——这是防钓鱼的教育文案，不许删。

### 3.3 注册

- 三条规则实时打勾：至少 8 位 / 字母和数字都有 / 不是常见弱密码。强度条按原型的四段算分。
- 条款勾选框**默认不勾**，不勾不让下一步。
- 点「发送验证码」→ 验证码页。注册这一步服务端**不创建用户**，见 §5.1。

### 3.4 验证码

- 6 格数字，粘贴自动分配，满 6 位自动提交。
- 错误：「验证码不对，还可以试 n 次」，3 次用完作废，必须重发。
- 重发冷却 60 秒，倒计时可见。
- 「换个邮箱」退回上一屏，邮箱原样留着。
- 找回密码进来时，头部文案是恒定的那一句：
  「如果 x***@y.com 注册过看盘，验证码已经发出去了。」下面还有一行小字解释为什么这么说。
  **这句话对存在和不存在的邮箱一模一样**，不许优化成"该邮箱未注册"。

### 3.5 设置新密码（找回密码的最后一步）

- 新密码 + 再输一次。
- 「改完会退出其他所有设备」是横幅陈述，**不给开关**。会走到这一屏的人，多半是担心密码已经不只自己知道。

### 3.6 账号中心 / 同步与数据 / 登录设备 / 修改密码 / 注销账号

照原型。几个不能改的点：

- 「同步与数据」里那张**数据去向表**七行原样搬，包括最后一行「交易所账户、API 密钥、资金 —— 从不存在」。
  这张表是本次改动对用户的承诺，实现必须和它一致；哪天实现变了，先改表再改代码。
- 「退出登录」和「注销账号」必须是两行、两种颜色、两段说明。混成一个是事故。
- 注销要输入完整邮箱才解锁按钮，7 天冷静期，期内用原邮箱登录即撤销。
- 「登录设备」里当前设备不给退出按钮（要退就用退出登录）。地区只写到省/市级，说明白是按 IP 粗估的。

### 3.7 会话过期

access token 过期由 `SyncEngine` 静默刷新，用户无感。**refresh token 也失效时**（被踢、密码被改、90 天没用）：

- 不弹全屏登录墙，不清空当前图表，不切槽位。
- 账号行变成「登录已过期 · 点这里重新登录」，同步状态停在最后一次成功的时间。
- 本机改动继续进 outbox，重新登录后照常补传。

## 四、本机与云端怎么合（最容易做错的一步）

整包覆盖是错的。逐类按下表合：

| 数据 | 合并规则 |
|---|---|
| 设置 `prefs` | 逐字段。服务端给每个字段存 `updated_at`，取新的那个。没冲突的字段各自保留 |
| 自选 `favorites` | 集合 + 墓碑。加入/移出各带时间戳，移出也要上传（不上传的话，删掉的会从另一台设备长回来） |
| 自选排序 / 分组 / 置顶 | 整段 last-write-wins，按 `updated_at`。顺序是一个整体，逐项合会排出谁也没要过的顺序 |
| 画线 `drawings` | **逐条**。每条有 `id`(UUID)、`updated_at`、`deleted_at`。同 id 取 `updated_at` 新的；有 `deleted_at` 就是删除。每品种 50 条上限在合并**之后**裁，按 `updated_at` 留新的 |
| 复盘记录 | 只增不改的事件流，服务端权威。客户端不改判定结果，只补传创建与复盘正文 |
| 最近打开、上次视野、十字线 | 不同步。换台设备接着看的是你的自选，不是你的滚动位置 |

合并面板三个选项的确切含义：

- **两边合起来**（默认）：按上表逐类合。
- **只要云端**：本机槽位整体改名成 `local-backup-<日期>`，7 天后清理，期间能在「同步与数据 › 导出一份」里拿出来。
  **不是直接 `rm`。**
- **只要本机**：本机整体上传覆盖云端。服务端把被覆盖的版本留 30 天（`vault_snapshot` 表），可回滚。

`Merge.swift` 里每一条规则都要有单测，用两份构造好的 fixture 比对结果。这块出 bug 用户不会报 bug，
他们只会发现画线少了然后卸载。

## 五、后端：新服务 `Backend/kanpan-account`

技术栈跟着现有网关走：**Python 3.11+、aiohttp、独立 venv、`python -m unittest discover`**。
不要引入新框架，让运维只用记一套东西。

- 进程：`kanpan-account.service`，监听 `127.0.0.1:8794`，systemd 里照网关那套收紧
  （`DynamicUser`、`NoNewPrivileges`、`ProtectSystem=strict`、`ProtectHome`、`PrivateTmp`，内存与 CPU 限额）。
- 路由：在项目独立 Caddy 站点加 `/account/*`，**不要动网关现有的 `/market`、`/oi`、`/chart-gateway` 路由**。
  强制 HTTPS + HSTS。
- 秘密（DB 口令、pepper、邮件服务商 key）放 `/etc/kanpan-account/secret.env`，`0600`，不进 git。
  git 里只留公开地址、实现与验证记录——和网关一个标准。
- 数据库：PostgreSQL 15+。**网关不连这个库，账号服务不连网关的任何东西。**

### 5.1 注册为什么分两步

`POST /register/start` **不创建用户**，只往 `email_tokens` 写一条待验证记录并发信：

- 邮箱没注册过 → 发 6 位验证码。
- 邮箱已注册 → **也返回一模一样的 202 和一模一样的文案**，但发出去的信不一样：
  信里写「你已经有看盘账号了，忘了密码就点这里重设」，不给验证码。

用户在 `/register/verify` 提交邮箱 + 验证码 + 密码，服务端这才建用户。这样：
拿别人邮箱来试的人，从接口响应上**看不出这个邮箱有没有账号**；真邮箱主人收到的是一封说得清楚的信。

`POST /password/forgot` 同理，恒定 202，恒定文案，恒定耗时。

## 六、后端：库表与隔离

两个 schema，两个数据库角色。这是「私人数据分开存储」在服务端最实在的一层。

```
identity/                     角色 kanpan_auth，只能碰这里
  users              id uuid pk, email citext unique, email_verified_at, created_at,
                     deleted_at, purge_after
  credentials        user_id fk, argon2_hash text, algo, params jsonb, updated_at
  email_tokens       id, user_id nullable, email citext, purpose(register|reset),
                     code_hash bytea, expires_at, attempts int, consumed_at
  sessions           id uuid, user_id fk, refresh_hash bytea, family_id uuid,
                     device_id, device_name, ip_region, user_agent,
                     created_at, last_seen_at, revoked_at, replaced_by
  login_attempts     key text (email|ip), window_start, count

vault/                        角色 kanpan_vault，只能碰这里
  prefs              user_id pk, doc jsonb, field_times jsonb, revision int8
  favorites          user_id, symbol, added_at, removed_at, revision   (pk user_id+symbol)
  fav_layout         user_id pk, doc jsonb, updated_at, revision
  drawings           user_id, id uuid, symbol, doc jsonb, updated_at,
                     deleted_at, revision                              (pk user_id+id)
  review_records     user_id, id uuid, …（字段照 docs/复盘接入最终方案.md）
  vault_snapshot     user_id, taken_at, reason, blob                   ← 覆盖前的回滚点
  op_log             user_id, op_id uuid, done_at                      ← 幂等去重，留 24 小时
  user_revision      user_id pk, revision int8                         ← 每用户单调序列
```

三条必须做到：

1. **`vault` 每张表开 Row Level Security**：
   `USING (user_id = current_setting('kanpan.user_id')::uuid)`。
   每个请求在事务开头 `SET LOCAL kanpan.user_id = $1`。
   这样即使某条 SQL 忘了 `WHERE user_id`，数据库也不会把别人的行交出来。
2. **`user_id` 一律从会话解析，绝不从请求体或查询参数取。** 任何接口都不接受 `user_id` 入参。
   代码评审时看见 `request.query['user_id']` 直接打回。
3. **`identity` 与 `vault` 用不同的数据库角色连接**，两个连接池。密码哈希所在的库，业务查询碰不到。

关于加密的老实话：**不做端到端加密。** 复盘的判定要在服务器上跑，服务器必须看得见目标价和失效价，
号称 E2EE 是假的。实际做的是：磁盘加密、备份加密、日志里不落业务正文、最小化留存、注销真删。
隐私政策里就这么写，别写"军事级加密"。

## 七、接口契约

统一前缀 `/account/v1`。请求响应都是 JSON。错误体：`{"error": "<code>", "message": "<给人看的中文>"}`。

| 方法 | 路径 | 入参 | 成功 | 说明 |
|---|---|---|---|---|

## 八、安全参数（照抄，不要"优化"）

- **密码哈希**：Argon2id，`m=48MiB, t=3, p=1`（按 3 核 / 4GB 那台备用节点定的，主节点也用同一套，
  两台行为要一致）。加 32 字节 pepper，来自 `secret.env`，不进库。
  密码长度 8–200（上限是防止拿 1MB 密码打 Argon2 做 DoS）。入库前 NFKC 归一化。
  不强制大小写符号，但拒 10 万条常见弱口令表——原型里那个 `WEAK` 数组是示意，真表用公开的 top-100k。
- **登录失败**：按 `email` 和 `ip` 双计数。5 次 → 锁 60 秒；10 次 → 锁 15 分钟；窗口 30 分钟。
  邮箱不存在时**也要跑一次假 Argon2 校验**再返回同样的 401，否则响应快慢就把账号是否存在告诉对方了。
  所有密码 / 验证码比较用恒定时间比较。
- **验证码**：6 位十进制，`secrets.randbelow` 生成；存 `SHA-256(code ‖ 每条记录的 salt)`，**不存明文**；
  TTL 600 秒；最多核对 5 次；一次性消费。
  发信限速：同邮箱 3 封/小时、同 IP 20 封/小时，超了仍然返回 202（对外看不出区别），只是不发。
- **令牌**：都是不透明随机串（32 字节 base64url），服务端存 SHA-256。
  - access：TTL 15 分钟，进程内缓存 60 秒。
  - refresh：TTL 90 天，**一次性轮换**，同 `family_id` 串起来。
    检测到已用过的 refresh 被再次使用 → 判定为窃取，**整个 family 立即失效**，该设备需要重新登录。
  - 为什么不用 JWT：「登录设备」要能立刻把某台设备踢下线，改密码要能立刻踢掉所有设备。
    JWT 做不到即时吊销，除非再加一张黑名单表——那就等于又回来查库，白绕一圈。
- **传输**：只 HTTPS，HSTS。iOS 侧不加自定义证书校验绕过，ATS 保持默认。
- **日志**：不记密码、验证码、令牌、邮箱全文（记 `x***@y.com`）。请求日志留 30 天。

## 九、合规与上架

- 有账号体系就必须在 **app 内**提供注销入口（指南 5.1.1(v)）。原型里「账号 › 注销账号」就是它，
  不许只给一个客服邮箱。
- `PrivacyInfo.xcprivacy` 要声明收集：**邮箱地址**（用途 App Functionality，linked to user，不用于追踪）、
  **用户 ID**（同上）。不收集设备 ID 用于追踪，不接广告 SDK。
- 隐私政策与服务条款要有真实可访问的 URL，注册页那两个链接指向它们。
- 看盘不提供投资建议，条款里写明白。注册页勾选框那句话照原型抄。
