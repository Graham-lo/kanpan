# 发给朋友：画线分享（实施方案，2026-09-22）

> 结论先行：**分享的是线，不是图。** 朋友打开之后，看到的是**他自己的图**（他的皮肤、
> 指标、参数、副图），只是上面多了我画的那几条线。他可以只看看，也可以把线留下——
> 留下之后那就是他自己的线，能改、能删、能像自己画的一样加提醒。
>
> 传递不走链接，走账号：我在图上点「发给朋友」选一个人，他下次打开 app 顶上就有一张卡。

替代 `docs/提醒与体验细节-实施方案-2026-09-20.md` 第 8 节（那一节写的链接与「覆盖布局」
两条都作废；深链 `.share(id:)` 那条解析保留不删，将来有付费开发者账号补通用链接时是加法）。

## 0. 用户视角：这件事从头到尾长什么样

### 我（发的人）

1. 在 BTC 的 1 小时图上画了两条趋势线和一个矩形，其中一条趋势线设了提醒。
2. 打开图表设置面板，「这张图」一节里点 **发给朋友**。
3. 弹一张朋友名单（就是几个名字），点「小王」。面板收掉，头部说一句「已发给小王」。完事。

   - 名单是空的（第一次用）：同一张面板上就是一个输入框「朋友的用户名」，输完直接发，
     顺手就成了朋友，不用先去哪里「添加好友」再回来。
   - 没登录：这一行点下去说「登录后才能发给朋友」。这是权限（东西要经服务器过一手），
     不是同步闸门。

### 小王（收的人）

4. 小王下午打开 app，图表页头部价格行那一行**就地变成一张卡**（和画完线问「要不要提醒」
   那张卡同一个位置、同一个长相）：左边我的名字和「BTC · 3 条线」，右边一个「看看」。
   卡上带一张我发出时那张图的小缩略图——他一眼知道是什么，不用点开猜。
   六秒不理它不会消失（和提醒卡不同：那是「沉默 = 只画线」，这个是「没看见」），
   划掉才走，走了也还在「朋友」页里能翻回来。
5. 点「看看」：图切到 BTC、切到我发时的周期，视野滚到线所在的那一段并放到刚好装下。
   **图还是他自己的图**——他的指标、他的皮肤、他的均线参数——上面叠着我的三条线，
   他自己在 BTC 上原有的线淡下去（35%），一眼分得清哪些是刚来的。
   头部那张卡换成：「正在看 XX 的线 · **留下** · 退出」。
6. 他可以随便拖、缩放、换周期看，线都钉在原位（线是时间 + 价格）。不能改、不能删、
   点不中——这是别人的线，还没留下。
7. 点 **留下**：三条线并进他自己的存档，变回正常颜色、和他自己的线一样。**紧接着**同一张卡
   变成加提醒的那句问话：「XX 在其中 1 条上设了提醒，也给你设上？」——「加入提醒」一下
   就把那条线（用我设了提醒的那些作默认）加进他的提醒；六秒不理等于只留线。
   之后这些线和他自己画的一模一样：可以进画线台改、可以删、以后想在别的线上加提醒
   走画线的老路（提醒是画线模块的既有入口，本方案不新开入口）。
8. 点 **退出**：我的线消失，他的线亮回来，周期回到他点「看看」之前那一档
   （他要是在看的过程中自己换过周期，就留在他换的那一档——那是他的动作，不替他撤销）。
   什么都没写进他的偏好，所以也没有什么要「恢复」。

### 顺手的两件事

- 「朋友」页（设置里一节）：名单 + 收到的线（按时间倒序，每条带缩略图、来自谁、
  留没留下），点一条就是第 5 步。这样过两天想回头看「他那条线走到哪了」有地方翻。
- 第二步再做「回给他」：在他的线上我再画几笔，卡上多一个「回给 XX」——两个人在同一张图上
  来回说话。本轮不做，但数据模型（第 3 节）已经给它留了 `replyTo`。

## 1. 设计决定（替用户拍过板的，不摆出来选）

| 决定 | 理由 |
| --- | --- |
| 只带线，不带布局 | 用户原话：「画线应该用的是朋友自己的 K 线图表布局，这样不会感觉到别扭」。指标、参数、皮肤、副图、价格轴一概不带。线是时间 + 价格，在任何布局上都落在对的位置。 |
| 发「图上看得见的线」 | 不做多选。要少发几条，先把不想发的隐藏掉（画线本来就有隐藏）。`hidden == true` 的不发。 |
| 分享时带周期与视野时间段 | 打开时切到发的人当时的周期，视野滚到线那一段。**这是唯一会动到对方界面的两样**，退出时周期还回去（他自己没换过的话）；视野不必还，本来看完就在别处了。 |
| 看的时候自己的线淡下去 | 不是虚线（虚线是线的样式，有含义）。淡 35% 是「这不是主角」的通用画法，和复盘回放里的记号一个道理。 |
| 看的时候别人的线点不中 | 没留下就不是他的，不能选中、不能拖、不能进画线台。任何会改图的动作（进画线、换品种、进复盘、记一笔）先静默退出预览。 |
| 留下 = 复制成自己的线 | 换新 id、其余原样。**不给 `Drawing` 加「来自谁」字段**——那会碰画线同步的字段白名单（两端各一份），收益只是一个小角标。来源记在收件箱那条记录上就够了。 |
| 留下之后立刻问提醒 | 用户点名要「用分享的现成画线 + 画线提醒」。复用画完线那张卡（`AlertPromptModel`），一句话带上发的人在哪几条上设了提醒，默认就那几条。摊不出线的种类（文字、标注）不算。 |
| 朋友不用「同意」 | 输用户名就是朋友，对方收到第一份时自动互为朋友。这个 app 十个人以内，同意流程只会碍事。 |
| 不做推送、不做轮询 | 没有 APNs。回前台时拉一次收件箱（挂在既有的同步拉取后面）就够——人打开 app 第一眼就看到那张卡。 |
| 不带图片给对方看 | 缩略图只在卡上和收件箱里当「这是什么」的提示，**不是内容**。内容是线，在他自己的图上活的。 |

## 2. 客户端

### 2.1 入口（发）

`Panels/ChartPanel.swift`「这张图」一节，「分享图片」下面加一行：

```
PanelRow(name: "发给朋友", meta: "把图上的线发过去", ...)   // accessibilityIdentifier "chart.send"
```

- 图上没有可见的线：这一行 `meta` 变「先在图上画点什么」，点了说一句，不发。
- 未登录：`meta` 变「登录后可用」，点了说「登录后才能发给朋友」。
- 复盘回放 / 预览别人的线时：这一行不出现（和「记一笔」同一个前提）。

**画线台上再放一颗（2026-09-22 用户点名加的，「画完就发，更方便」）。** 画线的人手里正拿着笔，
让他先「完成」、再开「图表」面板、再找「发给朋友」是三步；一颗按钮就在他拇指底下才对。
它和面板那一行是**同一个动作的两个落点**（kanpan-one-entry-per-action 说的是「一个动作一个入口」，
这里入口仍是一个——`FriendPickerSheet`——只是两处都能够到它，就像「记一笔」既在面板也在复盘）：

- 竖屏 `Drawing/DrawingBar.swift`：上排右端，`重做` 右边再加一格 `icon("paperplane", "发给朋友", "draw.send")`，
  44pt 一格，和撤销 / 重做同一画法；选中一条线时上排左边换成 `DrawingSelectionBar`，这一格照旧在。
- 横屏 `DrawingDock`（同文件）：`管理画线` 右边、`完成` 前面那道分隔线左边加同一颗，id 同为 `draw.send`。
- 点下去：**不退出画线态**。竖屏弹 `FriendPickerSheet`（半屏）；横屏按 `drawToolsLayer` 那套贴左边推出
  同一张卡（`MainScreen.swift:635` 附近那段），不用半屏表单。发完 `say("已发给 …")`，人还在画线台上。
- 没线 / 未登录的禁用态和面板那一行同一口径：图标灰掉（`enabled:` 与撤销一样），点了说一句。
- `DrawingBar` / `DrawingDock` 各加一个 `var onSend: (() -> Void)?`，由 `MainScreen` 传进来，
  和 `ChartPanel.onShare` 同一路（画线模块不认识分享模块，它只管喊一声）。

点下去收面板、弹 `Share/FriendPickerSheet.swift`（半屏 `PanelSheet`）：

- 有朋友：一列名字，点一个就发。发完 `say("已发给 \(name)")`。
- 没朋友或点底部「新朋友」：一个输入框（ASCII 键盘，按 kanpan-symbol-search-keyboard 的口径），
  输完「发送」——服务端一次完成「加朋友 + 发」；用户名不存在说「没有这个用户名」。

发的载荷（`ShareOutbound`）：

```
symbol, interval,                 // 当前品种、当前周期
view: { from, to },               // 当前视野的时间段（毫秒）
drawings: [Drawing],              // 该品种上 hidden == false 的线，原样
alerted: [drawingID],             // 其中我设了活动提醒的线（AlertStore.alertedDrawingIDs）
```

外加一张 `ChartSnapshotRenderer.chartImage`（**只画图那张**，不要身份条；1×，JPEG 0.8，
宽度 600pt 缩放）作为缩略图，第二个请求 `PUT /v1/shares/{id}/shot` 传上去；传失败不影响分享本身。

### 2.2 收件箱与那张卡

新模块 `Share/`：

- `ShareInbox.swift`（`@Observable`）：`items: [ShareItem]`，`unseen: [ShareItem]`，本地缓存
  一份 JSON（按账号，走 `PrefsStore.deviceStorage()` 同一套目录规则），回前台/登录后
  `GET /v1/shares/inbox?after=<cursor>` 增量拉。
- `ShareCard.swift`：头部那张卡。**位置与形态复用 `AlertPromptBar`**（`MainScreen.swift:683`
  与 `:878` 两处挂点，`inHeader: true` 那一套）：左侧缩略图（36pt 高圆角）、
  「小王 · BTC · 3 条线」、右侧「看看」；有多张时只露最新一张，卡上角一个「+2」。
  划掉 = 标已读、卡消失、收件箱里还在。
  **和提醒卡撞车时提醒卡优先**（人刚画完线，那六秒是他的）。
- 「朋友」页：`Settings` 页里一节「朋友」→ `Share/FriendsPage.swift`：上半名单（左滑删），
  下半「收到的线」列表（缩略图、谁、品种、几条、时间、留下了没）。点一条 = 预览。

### 2.3 预览（影子态）

`Drawing/DrawingController.swift` 加一个「客线」层，**不走 `ReviewChartBridge` 那种整张
换状态的路**——那条路是为「整张图都换掉」设计的，这次图不换：

```
func preview(_ guest: [Drawing], symbol: String)   // 进：记住 guest、把它交给 chart
func endPreview()                                  // 出：清掉
private(set) var previewing: ShareItem?
```

`ChartView`（KanpanChart）加 `guestDrawings: [Drawing]` 与 `ownDimmed: Bool`：

- 渲染：own 先画（`ownDimmed` 时整体 alpha 0.35，含铃铛与手柄），guest 后画、正常 alpha。
- 命中：guest 不参与 `hitTest`，不可选中、不可拖。
- `setDrawings` 不动 guest；`endPreview` 清 guest 并把 `ownDimmed` 复原。

`MainScreen` 里 `openShare(item)`：

1. `dismissPanel()`；正在复盘 / 画线台 → 先退出。
2. `intervalBeforePreview = market.interval`；`open(linkedSymbol:)`（和深链一条路，
   [MainScreen.swift:1611](../Kanpan/Kanpan/Main/MainScreen.swift)）；`pick(interval:)` 切到
   `item.interval`。
3. 品种就位（`draw.focus(symbol)` 之后）→ `draw.preview(item.drawings, symbol:)`，
   `proxy.box?.chart` 视野滚到 `item.view` 并放到装下（复用 `switchInterval(anchorRight:)`
   那一族已有的时间锚定，不新写视野算法）。
4. 头部卡换成「正在看 XX 的线 · 留下 · 退出」。`POST /v1/shares/{id}/opened`。

退出（显式点「退出」，或任何会改图的动作触发的静默退出）：`draw.endPreview()`；
`market.interval == item.interval && intervalBeforePreview != item.interval` 时
`pick(interval: intervalBeforePreview)`——他自己换过周期就不动。

### 2.4 留下 + 提醒

`keepShare(item)`：

1. `let kept = item.drawings.map { var d = $0; d.id = Drawing.newID(); return d }`
2. `draw.append(kept, symbol:)`（新方法：并进 `archive[symbol]`、`persist` 走既有落盘 + 同步；
   撤销栈里作为一步「留下 3 条线」，可以一下撤掉）。
3. `draw.endPreview()`（客线变成了自己的线，淡的亮回来）。
4. `POST /v1/shares/{id}/kept`；收件箱那条标「已留下」。
5. 提醒：`alertPrompt.offerBatch(kept, symbol:, preferred: <alerted 对应到新 id>, from: XX)`
   ——`AlertPromptModel` 加一个批量形态：句子「XX 在其中 N 条上设了提醒，也给你设上？」
   （N = 0 时「要在这 M 条线上提醒你吗？」）；「加入提醒」= 对 preferred（N = 0 时对全部
   可摊平的线）逐条 `alerts.add(drawing:symbol:)`；名额不够时加到哪条算哪条并说「提醒最多 X 条」。
   六秒不理 = 只留线。这一段之后，这些线和他自己画的没有任何区别。

### 2.5 文件范围

新文件：`Kanpan/Kanpan/Share/{ShareItem, ShareInbox, ShareClient, ShareCard, FriendPickerSheet, FriendsPage}.swift`。
共享文件最小改动：`Panels/ChartPanel.swift`（一行）、`Main/MainScreen.swift`（`openShare` /

## 3. 服务端（`Backend/kanpan-api`，Rust）

### 3.1 表（一条迁移 `0016_shares.sql`）

```sql
CREATE TABLE friendships (
 user_id uuid NOT NULL REFERENCES account_users(id) ON DELETE CASCADE,
 friend_id uuid NOT NULL REFERENCES account_users(id) ON DELETE CASCADE,
 created_at timestamptz NOT NULL DEFAULT now(),
 PRIMARY KEY(user_id, friend_id), CHECK(user_id <> friend_id)
);
-- 互为朋友 = 两行。发送时若 (to,from) 不存在就顺手插一行。

CREATE TABLE shares (
 id text PRIMARY KEY,                       -- 22 位 base62 随机，不可枚举
 from_user uuid NOT NULL REFERENCES account_users(id) ON DELETE CASCADE,
 to_user   uuid NOT NULL REFERENCES account_users(id) ON DELETE CASCADE,
 symbol text NOT NULL, market text NOT NULL DEFAULT 'binance/usd_m', interval text NOT NULL,
 view_from bigint NOT NULL, view_to bigint NOT NULL,
 drawings jsonb NOT NULL, alerted jsonb NOT NULL DEFAULT '[]',
 reply_to text REFERENCES shares(id),        -- 第二步「回给他」用，本轮恒 NULL
 shot bytea,                                 -- 缩略图，≤ 300 KB
 created_at timestamptz NOT NULL DEFAULT now(),
 opened_at timestamptz, kept_at timestamptz
);
CREATE INDEX shares_inbox ON shares(to_user, created_at DESC);
```

RLS：`shares` 的策略是 `from_user = current_user OR to_user = current_user`；`friendships`
按 `user_id`。和 0014 一样 FORCE ROW LEVEL SECURITY，新表普通事务建。

### 3.2 路由（`src/share.rs`）

| 路由 | 说明 |
| --- | --- |
| `GET /v1/friends` | `[{username}]` |
| `POST /v1/friends {username}` | 不存在 → 404 `no_such_user`；自己 → 400；幂等 |
| `DELETE /v1/friends/{username}` | 只删自己这一行 |
| `POST /v1/shares {to, symbol, interval, view, drawings, alerted}` | → `{id}`。`to` 不是朋友就先加为朋友再发；对方那一行 `(to, from)` 不存在也补上。 |
| `PUT /v1/shares/{id}/shot` | image/jpeg 正文 ≤ 300 KB，只有 `from_user` 能放 |
| `GET /v1/shares/{id}/shot` | 双方可读 |
| `GET /v1/shares/inbox?after=<created_at cursor>` | 我收到的，按时间倒序，不带 shot（缩略图另取，客户端按需） |
| `POST /v1/shares/{id}/opened` / `/kept` | 只有 `to_user` 能打 |

校验：`symbol` 用 `sync_validation` 里画线对象同一套代号规则；`interval` 必须是客户端
`Interval` 的 rawValue 之一（白名单写死一份，和 `ReviewContract` 的做法一致）；
`drawings` 数组 ≤ 200 条、每条按 `sync_validation::field` 里 `drawings` 集合的规则逐字段卡
（**不另写一套画线校验**，复用同步那一套）；`alerted ⊆ drawings.id`；整个 body ≤ 512 KB。
限流：每人每分钟 20 次发送（`account_limits` 那一套）。留存：`kept_at IS NULL AND created_at < now() - 90d`
的由既有清扫任务删掉；留下的永久保留（它是收件箱里的历史）。

### 3.3 不做的

- 不做未读推送（没有 APNs）。
- 不把 share 塞进同步协议（它不是「我的状态」，是一封信；两个人之间的东西不走个人同步）。

主窗口验收（按 kanpan-acceptance-means-reproducing-the-symptom-is-gone）：两个测试账号、
两台设备（真机 + 模拟器），走完第 0 节 1–8 每一步；重点复现三件事——
① 打开朋友的线时**自己的皮肤与指标一样都没变**；② 退出后自己的线亮回来、周期还回去；
③ 留下之后那条线上能加提醒且提醒真的能同步到服务端物化表（`alert_watches` 里出现）。
UI 用例只加两条：`ShareFlowUITests.previewKeepsOwnLayout`、`ShareFlowUITests.keepThenAlert`。
