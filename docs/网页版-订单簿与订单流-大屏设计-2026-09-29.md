# 网页版 · 订单簿与主力订单流的大屏设计（2026-09-29）

用户当天的话：「订单簿这里就需要重新设计了，因为 PC 屏幕大，不要用手机那一套，手机那一套是专门为了手机而适配，
所以展示方式你要有所变化。另外你看看 https://openmarket.xyz ，这也是 K 线图表，你可以访问官网或者推特把它
优秀的功能和设计拿过来。」

这份文档两件事：一、openmarket.xyz 值得吸收的东西与取舍；二、网页版订单簿 / 主力订单流在 27 寸 2K 屏上的展示形态。
**数据口径一律不变**（三家聚合、按门槛过滤、只展示不判定、门槛与步长是用户可改全端同步的设置），变的只是展示。
手机端的方案见 `docs/主力订单流-方案-2026-09-24.md`。

### 不吸收（与看盘既定规矩冲突或用得少）

| 功能 | 原因 |
|---|---|
| 清算热力图、清算流 | 看盘不做强平（kanpan-no-liquidation-feature） |
| TPO / 混合 TPO | 与 VPVR 二选一，交易员更常用 VPVR（TradingView 付费功能整理里已定） |
| 足迹图（Footprint）整套 | 信息密度极高、只在秒级 / 1 分钟有意义；先做 CVD 与热力图，足迹留到下一批 |
| Suites（预设工作区）、社区脚本、Pine | 看盘不做用户脚本；工作区只给「保存布局」 |
| 预测市场、股票券商数据、宏观数据、新闻流 | 美股只用币安标的；不接新闻 |
| 邮件 / Discord / Telegram 通知 | 提醒渠道保持 app 内 + Webhook（手机端已定） |
| 99 把画线工具、表情、自由手绘 | 画线工具清单以 TradingView 手机版为准（kanpan-drawing-tools-align-with-tradingview） |

## 二、订单簿 / 主力订单流在 2K 屏上的形态

### 2.1 页面骨架（2560 × 1440，DPR 1）

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ 顶栏 56：品种搜索 · 周期条 · 图表类型 · 指标 · 画线 · 热力 · 布局 · 提醒 · 账号            │
├───┬───────────────────────────────────────────────────┬──────────┬──────────────────────┤
│ 工│  主图（K 线 + 主力大单带 + 深度热力 + VPVR）          │ 深度梯子 │ 侧栏 400（可折）      │
│ 具│                                                   │ 240      │  ┌ 自选 / 详情       │
│ 栏│                                                   │ 共用价格轴│  ├ 盘口              │
│ 56│──────────────────────────────────────────────────  │          │  ├ 成交              │
│   │  副图 1–4（CVD、持仓量、资金费率…）                  │ （副图区 │  ├ 大单              │
│   │                                                   │  留空）  │  └ 提醒              │
├───┴───────────────────────────────────────────────────┴──────────┴──────────────────────┤
│ 底部抽屉 0 / 280：大单列表（表格）                                                        │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ 页脚 32：布局 · 时钟 · 连接状态                                                            │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

- 深度梯子夹在价格轴与侧栏之间，宽 240，折起后 0；侧栏 400，折起后 0；底部抽屉默认收起，打开「订单流」后自动展开 280。
- 三块都记在布局里（跟账号同步的 settings），不是每次打开都要重新摆。

### 2.2 深度梯子（DOM ladder）

- **共用价格轴**：每一行对应一个价格桶（步长 × 周期倍数），行的纵向位置由图表价格轴映射，图表纵向缩放时行高跟着变；
  行高 < 6 px 时自动把桶合并（2 / 5 / 10 倍步长）直到 ≥ 6 px。
- **每行三层**：底层浅色累计量柱（从盘口向外累加）、中层实色个别量柱（bid 向左长、ask 向右长，两侧各占 120 px），
  顶层文字（美元名义，K/M 单位，右对齐）。买卖色沿用网页版皮肤的涨跌色，累计层用 0.25 透明度。
- **大单标记**：个别量 ≥ 该产品门槛的桶，柱变成饱和色、左缘加 3 px 实心条，行尾出一个胶囊写 「币安永续 · 4.8M · 12m」
  （交易所 · 名义 · 存活时长）；多家在同一桶就叠成两三个小圆点，悬停展开。
- **盘口线**：最优买卖之间画一条 1 px 分隔线，中间价与价差（bps）写在线上；最新成交价的一行整行浅底。
- **来源聚合**：三家 × 四种产品的簿按桶相加。行内悬停出小卡：每家每产品各多少（这是手机上「详情卡」唯一保留的用途）。
- **交互**：滚轮在梯子上 = 纵向缩放（和图表同步）；点一行 = 在那个价位放提醒（和价格轴同样的动作）；
  拖一行到图上 = 画一条水平线（画线工具的「水平线」）。

### 2.3 图上的主力大单带（替代手机的「垫在蜡烛下面」）

- 每条大单仍是「从首见那根 K 线画到结束 / 右缘」的一条横带，但在大屏上：
  - 厚度 = 桶在价格轴上的高度（最小 3 px、最大 24 px），不再是细线；
  - 颜色按产品（现货 / U 本位 / 币本位 / 交割）四色，买卖用色相偏移区分；透明度 0.35，K 线仍在上层；
  - 右端一个小标签：名义（峰值）+ 交易所缩写，标签只在带宽 ≥ 80 px 时显示，否则悬停出；
  - 已成交的带末端画一个实心三角，已撤销的画空心方块，部分成交的画半实心；
- 悬停出 tooltip（不是点开卡片）：交易所 · 产品 · 价位区间（合并桶时是区间，否则单价） · 首见 / 结束时间 · 峰值 / 结束时剩余 · 累计成交 · 结局。
- 点一条带 = 底部抽屉表格滚到那一行并高亮。

### 2.4 深度热力（新）

- 主图叠加，默认关，顶栏一个「热力」开关（照 openmarket 放在顶栏而不是指标库里）。
- 网格：横向一列 = 一根 K 线（1m 及以下按 1 秒列），纵向一行 = 一个桶；格子颜色 = 皮肤的一条单色渐变（不用红绿，
  避免和 K 线打架），亮度 ∝ 该桶挂单名义 ÷ 当前可见范围的 95 分位。
- 数据：
  - 打开页面后，浏览器每秒把三家聚合簿按桶存一列（±5% 带，环形缓冲 2 小时）；
  - 更早的时间从服务端 `GET /v1/market/orderflow/heat?base&from&to&step` 回填（第三节的新接口），只对服务端常驻跟踪的品种有；
    没有的品种热力从打开那一刻开始，左边留空，不补假的。
- 悬停一格出 tooltip：时间 · 价位 · 名义 · 三家分量。

### 2.5 侧栏四个订单流小部件

| 小部件 | 内容 | 高度 |
|---|---|---|
| **盘口** | ±1 / ±2 / ±5% 买卖压力条（三条，各写百分比）；三家 × 产品的深度小柱（个别 + 累计）；计价 美元 / 币 切换 | 360 |
| **成交** | 三家 aggTrade 合流，最小额过滤（默认门槛 ÷ 50），每行 时间 · 交易所缩写 · 方向色块 · 价 · 额；≥ 门槛 ÷ 5 的行加粗并在图上落点；暂停滚动按钮；1 秒合并同价同向 | 弹性 |
| **大单** | 还挂着的大单，按名义降序，行：方向 · 产品 · 价 · 名义 · 存活；点行图表滚到那个价位 | 240 |
| **提醒** | 这只品种未触发的提醒；价格轴点击创建 | 160 |

小部件可折叠、可拖动排序，宽度固定 400，状态存布局。

### 2.6 底部抽屉：大单列表

表格列：首见时间 · 结束时间 · 存活 · 方向 · 交易所 · 产品 · 价位（区间） · 峰值名义 · 累计成交 · 结局。
列可排序、可按产品 / 结局筛选（复用手机端六个显示开关的语义）；点行图表居中到那条带。
数据 = 本地模型里的单 + `GET /v1/market/orderflow/history` 回填的历史，同一条按 (交易所, 产品, 桶, 首见) 去重。

### 2.7 设置（尽量不让用户设）

- 门槛、步长：沿用手机端的参数表（按币存、全端同步），放在「指标 › 主力订单流」齿轮里；数字输入框，无步进器。
- 六个显示开关（现货 / 合约 / 已成交买 / 已成交卖 / 已撤销买 / 已撤销卖）沿用。
- 新增只有两项：热力开关（顶栏）、成交最小额（成交小部件内）。其它（梯子行高、合并倍数、颜色、透明度）全部自动。

## 三、服务端要补的一块（kanpan-api，Rust）

热力图需要历史深度，服务端目前只存判出来的大单（`orderflow_history`）。补一张表：

- `orderflow_heat(base, exchange, product, bucket_ms, price_bucket, bid_notional, ask_notional)`，
  服务端常驻跟踪的品种每 5 秒把 ±5% 带内按步长聚合的簿写一行一桶（三家分开存，读时聚合），保留 3 天滚动删。
  按 40 个品种 × 200 桶 × 17280 行/天 ≈ 1.4 亿行/天太多，所以写入前先按「每桶名义 ≥ 步长门槛的 5%」过滤，
  实测再定；预算 20–40 GB（kanpan-server-storage-budget-20-40gb-rolling）。
- `GET /v1/market/orderflow/heat?base=BTC&from=&to=&step=`：返回
  `{"step":100,"bucketMs":5000,"rows":[[t_ms, price, bid_usd, ask_usd], …]}`，三家已聚合；step 是客户端当前桶步长，
  服务端按它合并；行数超 20 万时时间格自动放粗（10 s / 30 s / 60 s，再往上 5 / 15 / 30 / 60 分钟并抽样），
  客户端要细时间格就把 step 调大。没在跟的 base 回 `rows: []`。
- 已实现并上线（2026-09-29，迁移 0033，`orderflow_history/heat.rs`），实测与运维见 `docs/主力订单流-方案-2026-09-24.md` 末节。

## 四、给 Phase 2 订单流子代理的验收标准

1. BTC 打开订单流：梯子、图上大单带、盘口 / 成交 / 大单 / 提醒四个小部件、底部表格全部有真实数据，三家都在（悬停能看到每家分量）。
2. 图表纵向缩放时梯子行与 K 线价格轴严丝合缝（截图对比一条水平线穿过 K 线与梯子）。
3. 热力开关打开后，右侧实时累积的列逐秒出现；服务端有历史的品种左侧回填。
4. 成交小部件每秒不卡（三家合流 ≥ 50 笔/秒时仍 60 fps，用 requestAnimationFrame 批量刷）。
5. 改门槛保存后，梯子大单标记、图上带、大单列表同时按新门槛重算，并且同步到账号（手机端能看到改动）。
6. 2560×1440 截图三套皮肤各一张放 `docs/acceptance/网页版-2026-09-29/`。
