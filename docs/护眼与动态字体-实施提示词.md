## 一、两套护眼配色

### 1.1 它们是什么，不是什么

不是加一层黄色滤镜。黄色蒙版会把「绿涨」拖成泥、「红跌」拖成橙，毁掉盘面上最要紧的那一个信号。这两套是**整套令牌在暖中性轴上重新定过**：白点更低、对比更收、彩度更低，涨跌两色单独提亮到能过 WCAG AA。

也不要在 app 里再加暖色叠层——iOS 的 True Tone / Night Shift 已经在做这件事，叠两层只会更浑。

### 1.2 种子（照抄，不要自己调）

在 `KanpanCore/Sources/KanpanCore/Style/Palette.swift` 里加两个种子，字面量与原型逐字相同：

```swift
public static let paperSeed = PaletteSeed(
  dark: false,
  ground: "#B7B2A0", app: "#F4F0E4", chart: "#EDE8D9", raised: "#FAF7EE", raised2: "#E5DFCD",
  line: "#D9D2BD", grid: "#E3DDC9", hair: "#3A35241A",
  ink: "#2F2C25", ink2: "#625D4D", ink3: "#736D5D",
  up: "#387A58", down: "#B74B3F", amber: "#96660F",
  palette: ["#96660F", "#5A63A8", "#3F8A63", "#A85A78", "#7A6BA8", "#3F7FA0"])

public static let nightSeed = PaletteSeed(
  dark: true,
  ground: "#0D0C0A", app: "#191712", chart: "#201D17", raised: "#262219", raised2: "#2C281F",
  line: "#3A342A", grid: "#2C281F", hair: "#FFFFFF0A",
  ink: "#E0DAC9", ink2: "#A19A86", ink3: "#887F6A",
  up: "#56A883", down: "#D3766A", amber: "#D3A15C",
  palette: ["#D3A15C", "#9AA0D8", "#6FC2A4", "#D99BB0", "#BDAEDC", "#85B8D6"])
```

`hair` 现在是 `Palette.chart()` 里按 `dark` 推的（`dark ? "#FFFFFF0A" : ink.alpha("0F")`），护眼浅色推不出来。所以：

- 给 `PaletteSeed` 加一个 `public var hair: Hex` 字段（放在 `line, grid` 后面），`chart()` 改成用 `t.hair`；
- 现有两个种子分别填 `hair: "#12163A0F"`（浅，等于 `ink.alpha("0F")`）和 `hair: "#FFFFFF0A"`（深），这样 `KanpanCoreTests/StyleTableTests` 的固定值一个字节都不变。

`veil` / `scrim` 不用改：`Palette.veil` 推出的 `#F4F0E4F0` / `#191712EE` 正好等于原型的 `--veil`。

`--seg-on`、`--pill-ink`、`--soft-amt`、`--pill-amt` 这些面板派生令牌在 `PanelTheme` 里，按原型的值走（护眼 `segOn = raised`、`pillInk = #FFFFFF`；夜读 `segOn = raised`、`pillInk = #17150F`），不要再用 `dark ? … : .white` 这种二选一。

### 1.3 主题从三档变四档

`Kanpan/Kanpan/Settings/Model/ThemeChoice.swift`：

```swift
case system = "auto"
case light
case dark
case paper   // 显示名「护眼」
case night   // 显示名「夜读」
```

原始值照抄原型的 `data-theme` 字面量，别自己换词。`PrefsCodec` 是按 `rawValue` 解的，旧档自然兼容；新枚举值在旧版本上解不出来会落回 `fallback = .system`，可接受，不要为此改存档格式。

### 1.4 关键改动：主题解析必须收口到一个地方

现在全仓库有十来处在写 `dark ? Palette.darkSeed : Palette.lightSeed` 或 `scheme == .dark`：

- `Kanpan/Kanpan/Panels/PanelTheme.swift:13`
- `Kanpan/Kanpan/Panels/PanelPresentation.swift:44`、`:58`、`:144`、`:148`
- `Kanpan/Kanpan/Main/MainScreen.swift:41`
- `Kanpan/Kanpan/Symbols/SymbolPickerView.swift:33`
- `Kanpan/Kanpan/Symbols/FavoritesView.swift:34`（**这一处还漏了 `prefs.theme`，直接看系统的 `colorScheme`，顺手修掉**）
- `Kanpan/Kanpan/LaunchScreen.swift:9`

四档配色之后 `Bool` 不够用了。加一个唯一入口：

```swift
extension ThemeChoice {
  /// 系统色调 + 用户选择 → 唯一的一套种子。
  func seed(systemDark: Bool) -> PaletteSeed { … }
  /// 只有浅 / 深要强制 colorScheme；护眼 / 夜读各自锁一边。
  var forced: ColorScheme? { … }
}
```

把上面每一处都改成走 `prefs.theme.seed(systemDark:)`，`PanelTheme` 的初始化从 `init(dark:redUp:)` 改成 `init(seed:redUp:)`（保留一个 `init(dark:redUp:)` 便利构造给测试用）。`preferredColorScheme` 对 `paper` 给 `.light`、`night` 给 `.dark`，免得系统控件（键盘、菜单、选择器）和页面反着来。

`KanpanChart` 那边只吃 `ChartColors`，不需要知道有几套主题——确认它没有任何地方自己判 `dark`。

### 1.5 设置页

`Kanpan/Kanpan/Panels/SettingsPanel.swift` 的「外观」那一行，`PanelSegment` 放不下五格：按 `prototype/护眼设置原型.html` 的「配色」区改成**横向滚动的配色卡**（每张卡 112pt 宽、带一小段假行情预览、选中描琥珀边），顺序：跟随系统 / 浅色 / 深色 / 护眼 / 夜读。卡片里那段预览用真实令牌渲染，不要截图。

## 二、动态字体

### 2.1 现状是硬伤

`Kanpan/Kanpan/Panels/PanelTheme.swift` 的 `enum PanelFont` 全是 `Font.system(size: 14, weight: .medium)` 这种固定磅值，`FavoritesView` 里也散着十几处 `.font(.system(size: 10…15))`。`Font.system(size:)` **完全不跟随系统文字大小**：用户在「设置 › 辅助功能 › 显示与文字大小」把字调大，app 一动不动。这是目前最该补的一项——比任何配色都更影响长时间盯盘的舒适度。

### 2.2 怎么做

单一缩放因子，和原型的 `--ds` 一一对应：

```swift
struct PanelFonts {
  /// 17pt = 系统默认 body。ds 就是当前 body 磅值 / 17。
  var ds: Double = 1
  func size(_ base: Double, max cap: Double = .infinity) -> CGFloat { CGFloat(min(base * ds, cap)) }
  var name: Font { .system(size: size(14), weight: .medium) }
  …
}
```

- 在面板 / 自选的根视图上 `@ScaledMetric(relativeTo: .body) private var unit: Double = 17`，`ds = unit / 17`，用 `.environment(\.panelFonts, PanelFonts(ds: ds))` 往下发；组件只从环境取字号，不再直接写 `.system(size:)`。
- 图表**内部**（轴标签、指标读数、十字线气泡）跟着放大会挤爆布局：给这一档单独 `cap`，`ds` 夹到 1.0…1.35。图表外的一切（自选行、设置行、面板标题）不夹。
- 数字继续 `design: .monospaced`。

### 2.3 AX 档必须重排

iOS 的文字大小一共 12 档：常规 7 档（body 14 / 15 / 16 / 17 / 19 / 21 / 23 pt）＋辅助功能 5 档（AX1–AX5 = 28 / 33 / 40 / 47 / 53 pt）。到 AX 档，一行塞不下「图标 + 名称 + 价格 + 涨跌胶囊」，必须换行，不许靠 `minimumScaleFactor` 把字缩回去——那等于把用户的设置作废。

自选行的重排规则照 `prototype/护眼设置原型.html` 的预览（`.prow.stack`）：

- `dynamicTypeSize >= .accessibility1` 时，一行变两行：第一行 图标 + 名称（+ 计价单位），第二行 价格 + 涨跌胶囊，胶囊右对齐；
- 迷你走势图在 AX 档隐藏（它是装饰，不是数据）；
- 行高改成自适应，`frame(height:)` 一律换成 `minHeight`；
- 编辑态的把手、勾选框保持 44pt 最小触达。

### 2.4 设置里那一档

`Prefs` 加两项：

```swift
var textFollowsSystem: Bool = true      // 跟随系统文字大小
var textSizePt: Double = 17             // 关掉跟随时用的绝对磅值，取上面 12 档之一
```

关掉跟随时，在 app 根上 `.dynamicTypeSize(<映射到的 DynamicTypeSize>)` 覆盖。设置页那段实时预览照原型做：滑杆一动，预览里的两行行情立刻换字号，并在 AX 档当场变成两行——用户要能先看见再决定。

## 三、盯盘舒适度

`Prefs` 加：

```swift
var ambientTheme: Bool = false          // 随环境亮度自动切换
var stillMode: Bool = false             // 静止模式
var eyeBreak: Bool = false              // 用眼提醒
var eyeBreakMinutes: Int = 20           // 20 / 30 / 45
```

**随环境亮度自动切换**：iOS 没有公开的环境光传感器 API，别去找。用 `UIScreen.main.brightness` 作代理，监听 `UIScreen.brightnessDidChangeNotification`：低于 0.32 切 `night`，高于 0.45 切 `paper`，中间保持不变（滞回，免得在门槛上来回跳）；再叠一个 90 秒的最小切换间隔。开关打开时接管 `theme`，关掉时回到用户上一次手选的那一档——所以要另存一个 `themeManual`，不要把用户的选择覆盖掉。切换走 0.35s 的淡入，不要瞬切。

**静止模式**：关掉所有周期性动效——自选行的涨跌闪一下、走势图重绘动画、数字滚动、骨架屏呼吸；行情照常更新，只是不再用动画提示。等同于局部的 `reduceMotion`，但只作用于行情外观。已经打开系统 `accessibilityReduceMotion` 的用户默认当作开启。

**用眼提醒**：只在前台、且图表 / 自选可见时计时（`scenePhase == .active`），到点弹一层轻提示——「看 6 米外 20 秒」＋ 20 秒倒计时＋「跳过」，这是 20-20-20 的标准形式。退到后台暂停并清零，不要发本地通知，不要在用户正在拖十字线时弹。

## 四、诚实口径（写进设置页的说明文案，也写进验收）

这三样是**显示舒适度**的调校，不是医疗手段。文案里不要出现「防蓝光」「保护视力」「缓解干眼」这类说法：Cochrane 2023 的系统综述显示滤蓝光镜片对视疲劳基本无效；真正有据的杠杆是亮度与环境匹配、字够大对比够高、少闪烁少周边动效、以及定时远眺和眨眼。OLED 的 PWM 频闪是硬件层面的，app 影响不了，别暗示能。

设置页那句话照原型写：「iOS 的原彩显示与夜览已经在调色温，这里不再叠一层黄。」

## 五、验收（写进 `docs/acceptance/护眼与动态字体.md`）

1. **对比度**：新增 `KanpanCoreTests` 用例，按 WCAG 相对亮度公式算，断言 `paperSeed` / `nightSeed` 的 `ink`、`ink2`、`ink3`、`up`、`down` 压在 `app` 与 `raised` 上都 ≥ 4.5:1。参考实测值：护眼 `ink` 12.2:1、`ink3` 4.52:1、`up` 4.50:1；夜读 `ink3` 4.51:1。测试跑出的数字贴进验收文档。
   - 现有浅 / 深两套的 `ink3` 只有 3.1 / 3.9，低于 4.5。那是 `prototype/src/style.css` 里的既定值，**这次不动**，只在验收文档里如实记一笔，要不要改由仓库主人定。
2. **四档主题**：浅 / 深 / 护眼 / 夜读各截一张自选页 + 一张图表页，放进 `docs/acceptance/`；确认没有任何一处还在按 `colorScheme` 自己判色（`grep -rn "scheme == .dark" Kanpan/` 应只剩 `ThemeChoice.seed` 一处的调用方）。
3. **动态字体**：在 xs、默认、AX1、AX5 四档各截一张自选页；AX1 起行必须是两行版式，AX5 下没有任何截断、重叠或横向滚动。
4. **静止模式 / 用眼提醒**：录一段 15 秒，静止模式开关前后各一次涨跌更新；用眼提醒把间隔临时调成 1 分钟录一次弹出与倒计时。
5. `swift test`（KanpanCore）与 `xcodebuild test`（app）日志各一份。

先做第一件（两套配色 + 主题收口），跑通再做动态字体，最后做舒适度三项。每做完一件报告一次。
