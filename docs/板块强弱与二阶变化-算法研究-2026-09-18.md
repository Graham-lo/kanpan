## 0. 结论先行

推荐采用 **“5 日典型成员相对表现主排序 + 20 日趋势与广度确认 + 独立的相对价格加速度 + 领涨成员异动通道”**。保留中位数作为板块整体的核心统计，不用当期成交额加权取代它，也不把价格、成交额、持仓量和加速度硬拼成一个“龙头总分”。“当前领先”和“正在转强”分别回答两个问题，不能相互替代。第一期只能判断近 24 小时相对强弱、广度与单点异动；第二期补充约 60 日的 1 小时 K 线，才正式判断持续领涨、持续弱势和加速 / 减速。历史采集、计算及版本记录放在 Rust 服务端，手机读取结果。默认强弱视图的面积与位置使用同一口径的 **5 日相对表现**，加速度以状态文字或箭头补充，不让它接管主榜。

**对现有三档口径的裁决：三者都不能仅凭一个截面完成“找持续龙头”。但中位数没有选错；缺的是时间维度、代表性检查，以及与整体强弱分开的领涨成员信号。**

本方案中的“龙头”是可观察的价格领导状态，不是资金净流入结论，不是估值判断，也不是买入信号。只用币安数据，能够评价“币安可交易合约池里的板块领导状态”；不能据此宣称已经测出了真实美股全行业或全加密市场的资金轮动。

## 1. 先列假设，再给反证

以下假设来自问题和前面对话，不能直接当成已证实的事实。

| 待检验假设 | 足以推翻简单版本的反例 | 设计上的处理 |
| --- | --- | --- |
| 涨得最多的板块就是龙头 | 昨天跌 10%，今天涨 8%，两天仍跌 2.8% | 24h 热度与持续强弱分开 |
| 相对强弱排名比同周期涨幅排名更有效 | 同一个基准收益从所有板块收益中扣除，排序不变 | RS 用于解释跑赢 / 跑输和跨期状态，不把相减本身包装成新信息 |
| 加速度为正，说明板块已经转强 | 相对日变动从 −10 个对数百分点变成 −2 个，仍在跑输，只是速度改善 | 同时检查当前相对速度及广度 |
| 加速度下降，说明资金在撤离 | 相对日变动从 +10 变成 +4，仍可能是最强板块 | 标注“领涨减速”，不写“派发” |
| 中位数会错过龙头，因此应把极端上涨加入板块分 | 一只币涨 300%，另外四只基本不涨 | 极端成员单独展示，不篡改整体状态 |

| 指标越多越可靠 | 1D、5D、20D、上涨率、站上均线比例可能反复计算同一段上涨 | 主排序、确认、转向、解释分别承担不同职责 |
| 板块成员很多，统计置信度就高 | 88 个高度相关成员不等于 88 次独立实验 | 不用成员数伪造置信概率，增加删一检查和重叠检查 |

最后两项尤其重要：**不做参数拟合，不等于不需要验证；没有一个加权总分，也不等于没有参数选择。** 本文的窗口和门槛是公开的产品定义与初始政策值，不是被证明最优的交易参数。

## 2. 仓库核对：哪些是现状，哪些是设计建议

### 2.3 比加公式更优先的三个问题

**第一，规范品种身份。** 当前“按实时成交额选最大计价对”的规则，用于单截面尚可；直接扩展到历史，会在 USDT / USDC 等合约之间切换，制造价格跳变或伪加速。趋势算法必须保存稳定的 `instrument_id → symbol → base → quote` 映射。默认沿用固定计价币优先级，选择后不随每次成交额排序切换。发生下架或必要切换时，重新回填同一合约历史；没有重叠换算依据，就中断该序列，不裸拼价格。[R4]

**第二，采集成功不等于数据齐全。** 缺失成员不能按 0% 处理；交易所返回的合法零成交 K 线与请求缺失，是两种状态。字段非有限值、价格不为正、重复时间戳、未完成 K 线都必须明确处理。

**第三，板块目录和合约映射需要版本号。** 当前 `setCatalog` 及相关缓存主要按数量判断是否变化；“数量未变、内容已变”可能被忽略。历史算法不能用数量替代内容版本或哈希。[R4]

## 3. “龙头 / 弱势”的操作性定义

先定义三个不同层次，避免 UI 一句话混在一起。

**相对领先：** 在同一合约池、同一时间窗口中，典型成员表现位于前列。它是一个排序描述。

**持续领涨：** 不仅 5 日领先，而且中期仍跑赢、多数成员支持，不只是在单个日段跑赢。若绝对表现仍为负，应标为“抗跌领先”，不是“上涨主线”。

**正在转强：** 当前相对速度改善并有成员参与，但不要求它已经处在主榜第一梯队。它可以是反弹，也可以是新趋势的早期阶段；本指标不能提前保证是哪一种。

采用以下初始规则，所有条件均在有效数据覆盖下判断：

### 3.1 持续领先候选

同时满足：

1. 5 日相对表现为正，且同池 5 日分位不低于 75。
2. 20 日相对表现为正。
3. 至少三分之二成员在过去 5 日跑赢池基准。
4. 最近 5 个不重叠的 24h 窗口中，至少 3 个窗口典型成员跑赢基准。
5. 删去任意一个成员后，5 日典型相对表现仍为正。

连续两个有效小时评估满足后，确认为“持续领先”。其中绝对 5 日表现为正，叫“持续领涨”；绝对表现不为正，叫“抗跌领先”。

对只有 3—4 个有效成员的板块，广度条件提高到所有成员同向，且仍需通过删一检查；这是一项保守展示政策，不是统计学显著性结论。

“5 个日段中 3 个跑赢”只约束跑赢天数，不保证收益贡献均匀，也不能排除其中一天贡献了绝大多数涨幅。因此详情应保留这 5 段原值，不能把该条件宣传成已经排除了所有事件日驱动。

### 3.2 持续弱势

对称定义：5 日分位不高于 25，5 日与 20 日相对表现都为负，至少三分之二成员跑输，最近 5 个不重叠窗口至少 3 个跑输，删一后 5 日相对表现仍为负。连续两个有效小时满足后确认。

**注意：持续弱势可以发生在绝对上涨的板块。** 例如池基准涨得更快。不要强行把弱势定义成“跌幅最大”。

### 3.3 不强制生成龙头

前 25% 只是必要的横向位置条件，不是充分条件。可以出现“有最强板块，但没有满足持续领涨定义的板块”。同样，气泡图展示两端，不代表两端所有气泡都通过了龙头 / 弱势确认。

有效成员不足 3 个的板块不进入多成员强弱主排名，仍在全部板块列表及成员异动入口展示，注明单成员 / 少成员。不能把 `BIO` 的 100% 上涨参与率解释成 DeSci 板块全面共振。该规则不改变其静态分类，也不把它冒充成 fallback。

## 4. 从成员到板块：保留中位数，另建领涨成员通道

### 4.1 现有三档的裁决

| 口径 | 它实际回答的问题 | 用作主榜的问题 | 最终用途 |
| --- | --- | --- | --- |
| 中位数 | 典型成员表现如何 | 少数先行成员不改变中位数；小板块仍可能敏感 | **整体强弱的核心统计** |
| 算术均值 | 每个成员等份参与该区间时，简单收益的平均水平 | 单个极端值可显著抬高均值 | 保留作诊断，不作为默认龙头口径 |
| 当期成交额加权 | 本期成交活跃品种的加权价格表现 | 暴涨本身可能带来放量，因而同时放大收益和权重；不是事前固定权重组合 | 保留作活跃交易偏向诊断，不作为默认排序 |
| 总市值加权 | 较大总估值品种主导的价格表现 | 本项目部分合约没有对应市值；与“板块普遍强弱”不是同一目标 | 本方案不新增 |

中位数、截尾均值和缩尾均值的鲁棒性属于不同取舍；NIST 对这些统计量及极端值的影响有清晰定义。[W2] 不建议现在再增加一个没有必要的第四聚合档。

**不选截尾 / 缩尾均值作为默认值的理由：** 它们需要额外定义尾部比例，3—5 个成员时不自然；仍然不能同时解决“单点先行”和“整个板块强”两个问题。把这两个问题拆开，比寻找一个折中的平均数更直接。

### 4.2 极端成员不删除，但不劫持板块

例：5 个成员的 24h 涨跌幅为 `−2%、−1%、0%、+1%、+300%`。

- 中位数为 0%。
- 均值为 59.60%。
- 上涨率为 40%。
- 若最后一个成员的成交额为其他每只的 20 倍，成交额加权涨幅为 249.92%。

正确结论是：**板块内出现极强个体，但整体并未同步上涨。** 既不把这个板块直接认证为龙头，也不让 +300% 的成员消失。

主板块字段之外，另存：领涨成员代码、24h / 5 日表现、领先成员数、相对广度、删一后的板块表现以及成交集中度。详情页优先呈现这些成员；没有必要新增第二层成员气泡。

### 4.3 领涨成员的可计算规则

在同一个市场池内，以成员 24h 相对收益的横截面分位为准：同时满足相对收益为正、分位至少 90 的成员，记为“前沿成员”。

- 只有 1 个：单点异动。
- 至少 2 个，且板块过半成员跑赢：多点启动迹象。
- 是否成为持续龙头，仍由第 3 节决定。

90 分位是用于限制异动列表数量的初始阈值，不是“未来上涨概率 90%”。小板块要同时显示绝对数量，不能只显示比例。

## 5. 基准、时间与完整基础公式

### 5.1 符号与时间约定

| 符号 | 定义 |
| --- | --- |
| `g` | 比较池：加密，或股票相关 AI 合约池 |
| `s` | 静态板块 id |
| `i` | 去重后的规范品种身份，不是每一条计价对 |
| `t` | 已完成 1h K 线的共同收盘时点，按 UTC 对齐 |
| `P_i(t)` | 品种 i 在 t 的有效已完成收盘价 |
| `q_i(t)` | 该小时计价币成交额 |
| `U_g(d)` | UTC 日期 d 冻结的池成员名单及版本 |
| `V_g(t)` | `U_g(d)` 中在 t 与上一小时均有有效价格的成员 |
| `S_s(t)` | 本次评估使用的板块有效成员集合 |
| `n_s(t)` | `S_s(t)` 的成员数 |
| `B_g(t)` | 下文定义的池等权几何价格参考线 |
| `H` | 回看长度，默认 24、120、480 小时 |
| `h` | 加速度窗口，默认 1 日，即 24 小时 |
| `med` | 排序后中间值；偶数时取中间两项平均 |

文内收益公式使用小数；对外显示时再乘 100。**5 日 = 120 小时，20 日 = 480 小时，均为自然时间，不冒充美股 5 / 20 个交易日。** 股票相关合约页面应明确这一点。

三种长度分别承担短期状态、主排序、中期背景；不把它们通过主观权重揉在一起。

### 5.2 比较池与去重

加密基准采用本应用覆盖的币安加密合约池，每个规范品种只出现一次。未分类但属于该池的品种可以作为基准成员；这不等于把 fallback 桶拿来参加板块排名。

股票相关基准采用当前 AI 分类实际覆盖、可取得有效行情的去重合约集合，不把未纳入分类的 ETF、反向 / 杠杆产品和不相关合约机械混入。它的名字应是“AI 合约池基准”，不能叫“美股大盘”。

不额外强求 SPY、QQQ 或外部市值。BTC 相对表现可以在详情中补充作加密的另一参照，但不与主池基准混用。

成员名单每日冻结，盘中上市的新合约先进入异动观察；正式历史排名要等其历史满足相应窗口。静态分类不因此被改写。

完整趋势主榜的 24h、5 日和 20 日字段使用同一组具有所需历史的成员，不让每个窗口分别挑一批币。每天冻结候选集合，当次评估再取所需时点均有效的共同交集作为 `S_s(t)`。连续状态确认还要求成员集合、合约映射和目录版本一致；发生变化时重新开始确认，并用当前这组成员重算 3 点加速度滤波的历史输入。这样不把成员进出本身解释成价格转向。历史不够的成员仍在观察列表，不按零收益加入。

不同计价稳定币按近似等美元比较，是本版的明确近似；脱锚时不能保证可比。优先固定 USDT 合约，必须使用其他计价对时记录 quote。不能假装已有外部美元汇率或可靠脱锚修正。

### 5.3 构造一个真实可差分的参考序列

先计算成员小时对数收益：

\[
\ell_i(t)=\ln\frac{P_i(t)}{P_i(t-1\,\mathrm{h})}.
\]

池参考线：

\[
b_g(t)=\frac{1}{|V_g(t)|}\sum_{j\in V_g(t)}\ell_j(t),
\qquad
B_g(t)=B_g(t-1\,\mathrm{h})\exp(b_g(t)).
\]

初始 `B_g(t_0)=100`，100 只是尺度，不影响任何相对收益。每天更换名单时，只用新名单成员各自的价格比连接参考线，不把不同公司 / 币的价格水平直接平均。

这是**每小时等权几何价格参考线**，不是市值指数、资金流指数或可直接交易的总收益指数。它不含资金费、手续费等持有收益调整。

选择它是为了得到一个可连续差分、身份可追溯的共同参照，不是声称其有最优预测能力。其成分等权，不使用本期成交额；对数变换降低但不消除极端价格对基准的影响。

`V_g(t)` 可能小于冻结名单；按可用数据估计时必须附带覆盖率。覆盖不足时停止产生新强弱结论，不能把缺失收益填成零。任何补数导致的重算必须保留修订版本。

### 5.4 相对收益与板块强弱

品种在 H 小时的绝对与相对对数收益：

\[
L_{i,H}(t)=\ln\frac{P_i(t)}{P_i(t-H)},
\]

\[
E_{i,H}(t)=L_{i,H}(t)-\ln\frac{B_g(t)}{B_g(t-H)}.
\]

板块典型相对表现：

\[
E_{s,H}(t)=\operatorname{med}_{i\in S_s(t)}E_{i,H}(t).
\]

用于显示的相对百分比：

\[
ER_{s,H}(t)=100\left[\exp(E_{s,H}(t))-1\right].
\]

它是典型相对价格倍数的百分比变化，**不是严格的“板块简单涨幅减基准简单涨幅”百分点值**。例如品种涨 20%、基准涨 10%，相对价格比上涨约 9.09%，不是 10 个百分点。界面采用“5 日相对”这个名称，避免混淆。

绝对表现的对应显示值为：

\[
AR_{s,H}(t)=100\left[\exp\left(\operatorname{med}_{i\in S_s(t)}L_{i,H}(t)\right)-1\right].
\]

偶数成员时，“先取对数中位数再指数还原”是中间两项价格倍数的几何平均，与现有简单涨幅的算术中位数可能略有不同。因此**现有 24h 涨跌模式保持原算法与原测试，新增历史强弱字段另算，不能悄悄替换 `pct` 的含义**。

### 5.5 为什么减基准不改变同周期板块排序

在同一比较池、同一个 H 与 t，基准项对所有板块都是同一个常数。因此按 `E_s,H` 排序与按该板块典型绝对对数收益排序一致。真正新增的信息来自：时间窗口、相对零轴、持续性与成员分布，不是减法本身。

### 5.6 分位、广度、持续性与集中度

若同池有 M 个合格板块，`r_s` 是由弱到强的中间名次：

\[
F_s=100\frac{r_s-1}{M-1}\quad(M>1).
\]

并列用中间名次；全部一样时都为 50；只有一个合格板块时也为 50。没有可比对象时不能给出“全国第一式”的 100 分。确认领涨 / 弱势要求至少 5 个板块可参与比较。

相对广度、绝对上涨广度：

\[
RB_{s,H}=\frac{\sum_{i\in S_s}\mathbf{1}(E_{i,H}>0)}{n_s},
\quad
AB_{s,H}=\frac{\sum_{i\in S_s}\mathbf{1}(L_{i,H}>0)}{n_s}.
\]

平盘既不记上涨，也不记下跌；同时保存平盘家数。主确认用相对广度，而非仅仅上涨率。

最近 5 个不重叠 24h 窗口的跑赢次数：

\[
D_s^+(t)=\sum_{k=0}^{4}
\mathbf{1}\left(\operatorname{med}_{i\in S_s(t)}E_{i,24\mathrm{h}}(t-k\cdot24\,\mathrm{h})>0\right).
\]

跑输次数 `D_s^-` 用 `<0` 对称计算。评价时固定同一组成员，不把每天变化的子集混成“持续性”。

离散度采用 `IQR_s,H = Q75(E_i,H) − Q25(E_i,H)`。分位数统一使用排序位置 `(n−1)p` 的线性插值，避免语言库默认值不一致。

成交集中度：

\[
C_{s,24}=\frac{\max_i Q_{i,24}}{\sum_i Q_{i,24}},
\]

其中 `Q_i,24` 是过去 24h 成交额。总额为零时该字段缺失，不设为 0%。

删一稳健性范围：

\[
J_{s,H}=
\left[
\min_j\operatorname{med}_{i\in S_s\setminus\{j\}}E_{i,H},
\max_j\operatorname{med}_{i\in S_s\setminus\{j\}}E_{i,H}
\right].
\]

它回答“去掉一个成员结论会不会翻转”，不是置信区间。成员少、离散度大或结论对删一敏感时，应降级解释，而不是伪造一个精确置信概率。

## 6. 二阶变化：正式纳入，但不对‘龙头分’盲目求二阶差分

### 6.1 先说清楚在对什么求导

定义成员相对价格的对数水平：

\[
X_i(t)=\ln P_i(t)-\ln B_g(t).
\]

在长度 h 的窗口上，相对速度为：

\[
v_{i,h}(t)=\frac{X_i(t)-X_i(t-h)}{h}.
\]

相对加速度为：

\[
a_{i,h}(t)=\frac{v_{i,h}(t)-v_{i,h}(t-h)}{h}
=\frac{X_i(t)-2X_i(t-h)+X_i(t-2h)}{h^2}.
\]

h 按日计，默认 h=1。因此本版是**相邻两个完整 24h 区间的相对速度之差**，单位为对数收益 / 日²。这是相对价格水平的二阶差分。

如果“RS”指的是某个过去窗口的超额收益，它已经是价格变化量；对它再做两次差分，不等于上述价格二阶变化。对百分位名次、0—100 分或滚动标准分求二阶差分，也会混入其他板块变化与归一尺度变化。因此，本方案不这样做。

### 6.2 先匹配成员，再聚合加速度

板块加速度定义为：

\[
A_{s,h}(t)=\operatorname{med}_{i\in S_s(t)}a_{i,h}(t).
\]

三个时点采用同一批成员、同一合约、同一基准序列。**这个量是“典型成员的相对加速度”，不宣称它等于板块中位数收益序列的二阶导数。**

中位数与差分不交换：

\[
\operatorname{med}(u_i-v_i)\ne\operatorname{med}(u_i)-\operatorname{med}(v_i).
\]

例：前一段成员速度为 `[-10,0,10]`，后一段为 `[0,0,100]`。逐成员变化为 `[10,0,90]`，其中位数是 10；两段中位数之差却是 0。先匹配成员是为了防止“中间那只币换了”被误当成同一个代表性资产在加速。

### 6.3 平滑与尺度

第一层只对已完成小时的 A 做因果 3 点中位数滤波：

\[
\widehat A_s(t)=\operatorname{med}\{A_s(t),A_s(t-1\,\mathrm{h}),A_s(t-2\,\mathrm{h})\}.
\]

不使用未来样本，不使用居中窗口，不把 10 秒噪声当作加速。

每天冻结一个可解释的自身尺度。以当天 00:00 UTC 为 `t_d`：

\[
\theta_s(d)=\max\left(
\operatorname{med}_{j=1,\ldots,20}|A_s(t_d-j\cdot24\,\mathrm{h})|,
10^{-4}\ \text{日}^{-2}
\right).
\]

计算这组历史 A 时保持当日评估成员口径一致；完整校准需要约 22 日历史。若该组成员没有足够历史，保留原始 A，不输出标准化转强确认。 尺度按“UTC 日期 + 成员集合哈希 + 数据版本”缓存；集合变更时属于新版本，重新开始状态确认，不把两个版本间 Z 的跳变解释成市场加速。

\[
Z^A_s(t)=\frac{\widehat A_s(t)}{\theta_s(d)}.
\]

分母是过去典型加速度的绝对量级，不是可解释成正态分布的标准误。`Z=1` 表示达到自身过去中位绝对加速度量级，不是“统计显著”，更不是某个上涨概率。`10^-4` 对应约 0.01 个对数百分点 / 日²，是避免低于显示精度的变化被极小分母夸大的初始数值地板；不是按收益拟合的阈值。

分母只用于幅度判断，不能对 Z 的变化再次求导，否则分母下降也会制造伪“加速”。

加速参与率：

\[
GB_s(t)=\frac{\sum_{i\in S_s}\mathbf{1}(a_{i,h}(t)>0)}{n_s}.
\]

初始确认：连续两个有效小时满足 `Z^A ≥ 1` 且 `GB ≥ 2/3`，标记加速；减速使用 `Z^A ≤ −1` 且负加速度成员占比至少 2/3。其他情况中性。加速度确认也要求删去任意一个成员后，典型成员加速度仍与确认方向同号；3—4 个成员时要求全员同号。未达到这些条件可显示原始数值，但不确认共同加速。不能用精确百分比掩盖样本单薄。

### 6.4 加速度必须与当前速度一起解释

| 当前 24h 典型相对速度 | 加速度 | 应有解释 | 不能推出的结论 |
| --- | --- | --- | --- |
| 正 | 正 | 正在增强；广度支持时是转强候选 | 一定成为新龙头、一定适合买 |
| 正 | 负 | 仍跑赢，但速度放缓 | 已转为空头、机构派发 |
| 负 | 正 | 跑输速度减慢；可能止跌修复 | 已经强势 |
| 负 | 负 | 相对弱势加深 | 一定继续跌 |

“新转强候选”至少还要求 `E_s,24h > 0`、`RB_s,24h ≥ 2/3`。若 20 日仍跑输，标为“修复转强候选”；若已经是持续领涨，则标为“领涨加速”。仅有 A>0、但当前相对速度仍负，显示“跌势收敛”，不推到龙头榜。

### 6.5 必须防止的四种伪解释

**滚动窗口退出效应。** 对 `R_H(t)=X(t)−X(t−H)`：

\[
R_H(t)-R_H(t-\Delta)
=[X(t)-X(t-\Delta)]-[X(t-H)-X(t-H-\Delta)].
\]

变化既来自当前新增行情，也来自旧行情移出窗口。不能看到 24h 涨幅从 3% 变成 5%，就认定刚刚新增了 2% 的买盘推动。Binance 的 ticker 是滚动 24h，不是固定交易日收益。[W1]

**孤立跳升。** 一次价格跳升后完全横盘，24h 加速度会先正后负，即使没有出现新的下跌。详情必须能追溯两个相邻窗口的原始表现。

**先平滑还是先求差分。** 差分会放大测量噪声。在独立同方差的价格水平观测误差假设下，系数 `1,−2,1` 的二阶差分误差方差为 `6σ²/h⁴`。这只是代数示例，不是声称真实市场误差独立正态；它说明缩短 h 会明显提高噪声敏感性。

**排行变化不等于自身加速。** 别的板块下跌，也会抬高自己的名次。排名变化可以展示，但不替代 X 的二阶差分。

### 6.6 研究中的角色

加速度在本版拥有独立字段、状态和验证任务，但**主排序权重为零**。这样不会因为近期反弹幅度大，把一个仍持续跑输的板块挤到持续龙头榜首。

未来是否增加“正在转强”独立排序，应由第 13 节的增量验证决定。即使最终没有增量预测力，它仍可能是有用的状态描述；两者要分别验收。

## 7. 其他候选维度怎么用：不用一组拍脑袋权重

| 维度 | 本版职责 | 是否影响主排序 |
| --- | --- | --- |
| 5 日典型相对表现 | 主排序 | 是，唯一连续排序键 |
| 20 日相对表现 | 中期背景 / 持续领先确认 | 不加分，做条件 |
| 24h 相对表现 | 短期方向与修复判断 | 不加分 |
| 广度、最近 5 日跑赢次数 | 验证代表性和持续性 | 不加分，做条件 |
| 加速度 | 区分增强、减速、收敛、恶化 | 独立通道 |
| 成交额放大 | 解释参与活跃程度 | 不加分 |
| OI 变化 | 衍生品结构解释 | 不加分，第三期选做 |
| 离散度、删一敏感性、覆盖率 | 解释结论可靠边界 | 降级 / 暂停确认 |
| 站上均线比例、新高比例 | 与既有趋势 / 广度部分重叠 | 第一版不堆叠 |

此前对话中的 `35% / 25% / 15% / 15% / 10%` 综合分没有经过验证，不应直接成为实现依据。即使先标准化，收益、广度与持续性也可能对同一价格上涨重复计分。

### 7.1 成交额放大

加密默认使用完整的、不重叠的 24h 窗口：

\[
Q_{i,24}(t)=\sum_{u\in(t-24\,\mathrm{h},t]}q_i(u),
\]

\[
RV_i(t)=
\frac{Q_{i,24}(t)}
{\operatorname{med}_{k=1,\ldots,20}Q_{i,24}(t-k\cdot24\,\mathrm{h})}.
\]

板块取 `med_i(RV_i)`，即先按成员自身历史归一，再聚合。不能先加总板块成交额，再把“大板块更大”误当成更强。

分母为零或历史缺失时为缺失，不给无限大倍数。价格上涨本身也会提高计价币成交额，因此 RV 不是纯粹的换手强度，更不是净流入。

股票相关池存在交易时段和星期效应，24h 成交额不宜直接与过去 20 天全体混比。初始建议用此前第 7、14、21、28 日相同截止时点的 24h 窗口作中位基准，至少 3 个有效窗口才展示；节假日等仍可能失真。它只是四周同星期参照，不是完善的交易日季节性模型。

若多数成员最近小时没有有效交易活动，不新增“转强 / 转弱”确认，显示为交易不活跃的缺失状态；未经交易时段验证，不直接判定“休市”。不能在没有新交易的时段把平盘当成低噪声、高可靠性。

### 7.2 OI

OI 是未平仓合约数量，而成交量是区间交易数量；两者不是一回事。[W3] 当价格上涨时，美元名义 OI 也可能仅因价格提高而上升。

因此，先用同一合约单位的数量 OI：

\[
\Delta OI_i=\ln\frac{OI_i(t)}{OI_i(t-24\,\mathrm{h})}.
\]

再与价格联合描述为“上涨且 OI 增加”“上涨且 OI 减少”等事实组合；不自动翻译成新增多头 / 空头主导。只有美元名义 OI 时，必须说明价格成分，不把它与数量 OI 混用。

供应量接口不进入本算法。用户指定总市值口径与自由流通市值不是同一件事，而股票相关 / 指数等合约也不能直接沿用代币供应量算法。

## 8. 可比性、成员数与板块重叠

### 8.1 加密与股票相关合约不做统一经济强弱榜

两边各自计算基准、分位、加速度尺度与排名。一页可以并排展示，但“加密分位 90”和“股票相关分位 90”只表示各自池内的位置，不表示同等涨幅、风险、流动性或预期收益。

不为了让两边分数“看起来可比”而强行 z-score 混排。标准化改变的是单位，不会消除交易时段、标的性质和样本选择差异。

即使在加密池内，未经 beta 调整的相对收益也可能来自更高的市场敏感度。它回答价格领导，不回答风险调整后的 alpha。本版不新增短样本 beta 回归来制造另一层不稳定参数。

### 8.2 小板块不靠统一乘个折扣分解决

`n/(n+k)` 式收缩看似稳健，但 k 仍是人为参数，也可能长期压低真实的小板块机会。本版优先采用：成员下限、绝对家数、删一稳健性、历史完整率，而非无依据的置信权重。

正式主排名要求有效成员至少 3；3—4 个按更严格同向条件解释；不足 3 留在观察层。n 很大也不宣称其误差按 `1/√n` 缩小，因为成员并非独立随机样本。

### 8.3 数据覆盖

分别保存：静态目录成员数、当前实际挂牌匹配数、具有目标窗口历史的数量、本次有效数量。不能把“2/2 个有数据成员上涨”写成“该板块 100% 上涨”，同时隐藏另外 20 个未匹配成员。

初始门槛：板块目标窗口有效成员 / 当前可挂牌匹配成员至少 80%；池每小时有效价格对 / 当日冻结基准名单至少 90%。低于门槛不产生新的持续状态。门槛是数据完整性政策，并不能保证剩余缺失随机。

### 8.4 跨板块重叠

一个币在 3 个板块中出现，板块内可以各自使用，池基准中只算一次。两个板块之间的 Jaccard 重叠度：

\[
O_{s,u}=\frac{|S_s\cap S_u|}{|S_s\cup S_u|}.
\]

两个高重叠板块同时变强，不应解释成两笔独立资金流。验证“轮动”时，应再看各自独有成员 `S_s\setminus S_u` 与 `S_u\setminus S_s`；独有成员不足时，应承认这两种标签无法提供独立证据。

## 9. 稳定性：10 秒刷新不等于 10 秒确认趋势

### 9.1 两个时钟

**实时截面时钟：** 保留 10 秒级的最新 24h 涨跌与异动观察。它不产生 5 日持续性和已确认二阶趋势。

**历史趋势时钟：** 使用已完成的 1h K 线，每个共同整点计算一次主排序、广度、持续性与加速度。手机可以每 10 秒读取结果，但同一个 `trend_asof` 下正式趋势状态不变。

这是主动选择的时间尺度，不是靠过度 EMA 掩盖不稳定。若产品要的是几分钟级板块爆发侦测，应单独定义快信号，而不是把这套持续龙头系统偷偷改成高频系统。

### 9.2 平滑方案

- 主排序收益保持真实已完成窗口值，不叠加一层长期 EMA，否则数字不再表示所写的 5 日表现。
- 加速度用第 6 节的因果 3 小时中位数滤波。
- 状态进入 / 退出都要求两个连续有效小时确认；缺失小时不算“再确认一次”。
- 同值或显示到 0.01% 后相同的板块保持旧序；首次遇到并列按稳定 id 排序，避免随机顺序。
- 气泡入选名单改变采用两次有效评估确认，不每次以几乎相同的数值更换成员。详情列表可展示当前精确排序。

EMA 并不是不能用。它的形式为 `y_t = αx_t + (1−α)y_(t−1)`，通过 α 取舍新旧信息。[W4] 但本版有明确的小时采样和确认机制，再叠多层 EMA 会增加不必要滞后，因此不选它作为核心。

### 9.3 龙头掉下来多久能看见

必须区分“突然变弱预警”与“失去过去 5 日领先地位”。

- 1h 相对表现为负、至少三分之二成员同小时跑输，连续两根成立：加“短期走弱”标记。行情持续符合时，通常需要约 1—2 小时加数据汇聚延迟。
- 加速度经 3 点滤波和两次确认，持续变化一般在约 2—3 小时评估尺度上反映；具体取决于路径是否达到阈值，不能承诺所有行情固定时间触发。
- 5 日主排名下降依赖新的 5 日实际表现。过去明显领先的板块可能还在前列，这是窗口语义，不是系统失灵。

“旧龙头、现在减速 / 短期走弱”是一条完整信息，不需要强迫两项指标瞬间给同一个方向。

### 9.4 跨品种同步与失联

每个批次按共同整点对齐，不能让已拉完的前 50 个成员用新小时，剩下成员还用旧小时就开始比较。允许设一个汇聚截止点，建议整点后 5 分钟；在本文推荐的限速假设下可容纳常态批次，实际需用线上延迟验证。

覆盖不足则保留上一完整趋势批次，暂停状态迁移；连续错过两个应有小时批次后，相关当前数值返回缺失，而非无限期把旧值冒充当前结果。实时 ticker 连续约 30 秒没有新成功批次时不再生成新的即时异动结论。

内部保留数据时间、修订号与覆盖率；界面用 `—` 等中性缺失表达，不新增错误码、重试次数等工程状态面板。这与当前页面“不要工程状态字段”的约束兼容。

## 10. 产品编码：面积、位置和数字说同一件事

### 10.1 推荐两个模式，不默认塞一个龙头分

| 模式 | 主数字 | 位置 | 面积 | 加速度 |
| --- | --- | --- | --- | --- |
| 24h 涨跌 | 现有 `pct`，默认中位数 | 按该口径排序 | 绝对涨跌幅 | 不伪造；历史可用时仅作为补充状态 |
| 持续强弱（默认历史模式） | `ER_s,120h`，明确写“5 日相对” | 按同一个 5 日相对值排序 | 同一值的绝对幅度 | 小型“增强 / 减速 / 收敛”状态或箭头 |

方向颜色维持现有强端 / 弱端语义，不改成正负颜色；涨跌符号由数字表达。图标仍表示板块身份。没有第二层气泡。

历史模式只有一个主排序口径，不再随“中位数 / 均值 / 成交额加权”选项改变持续龙头定义。旧三档仍在 24h 观察模式中保留。

### 10.2 为什么不选“面积看 24h 涨幅，位置看龙头分”

这种做法能保留日内爆发，但同一颗巨大气泡可能处于弱端：它可能只是超跌反弹。逻辑并非错误，代价是用户必须同时记住两个尺度，容易把“大”误认为“强”。这与“一眼读懂”的目标冲突，所以不作为默认模式。

让综合分接管面积的问题则是：分数不是收益，50 分也不等于零强弱；原来的百分号和半径含义必须全部改写。使用真实的 5 日相对表现，可以避免一个不必要的黑箱总分。

### 10.3 面积归一建议

不继续使用“本次入选球的最大绝对值”作为动态分母，否则一颗极值球进入 / 离开就会令全屏其他球一起变大变小。[R2]

建议每个比较池独立使用：过去 24 个有效小时、所有合格板块绝对主指标的 95 分位作为参考 `d_g`；零分母时取显示精度 0.01 个百分点。每天冻结这把尺子。超出上限的值仍显示真实数字，只把面积截到最大。

\[
\text{area}_s\ \propto\ \min(|ER_{s,120h}|/d_g,1),
\qquad
\text{radius}_s\ \propto\sqrt{\text{area}_s}.
\]

冷启动不足 24 小时的历史输出时，以同池全体当前合格板块计算 95 分位，并在当次页面会话内固定。零值与近零值保留现有设计要求的最小可点击尺寸，此最小尺寸属于可读性，不再声称严格面积正比。

这是一个**建议的视觉变更**，会改变现有原型与测试的最大值归一预期；需要更新 `SectorSelection` 对应字段及 UI 测试。若先不改，旧归一可以暂留，但全屏尺度联动抖动仍会存在。

## 11. 数据、请求与存储成本

### 11.1 先确定 N，不能把 707 写死

`N` 是实际采集的规范品种数，先按 symbol 映射、挂牌状态和用途去重。

- **容量场景 A：N=707。** 按附件的 526+181 做上界示例，便于对照原委托。
- **聚焦场景 B：N≈610。** 若加密 526 个均纳入池基准，股票相关只采当前 AI 目录覆盖的 84 个去重标的，则为 526+84。不是断言此刻 610 个全部都有行情或有完整历史。
- 已有历史缓存、重复计价对、未上市 / 不支持合约，会改变真实请求数。部署前根据 `exchangeInfo` 和目录版本生成实际名单。

只按分类成员采 478+84 能更少，但会失去未分类加密成员作为池基准的覆盖。本文优先选择基准覆盖，因此列 610。

### 11.2 最小历史结构

每个品种保存 UTC 小时起点、OHLC、基础成交量、计价成交额、成交笔数，以及有效性 / 合约版本标记。K 线已有的主动买入计价量可顺手保存，但不进入本版评分。未完成 K 线不入正式趋势批次。

在线算法读取约 60 日窗口；首次可用 `limit=1500` 取得约 62.5 日小时记录，额外部分为对齐与校准留余量。历史数据最多留 1 年，便于事后检验；无需保存每个 10 秒的全量 JSON。

### 11.3 冷启动与小时增量

Binance 文档列明 K 线单次上限 1500，权重依 limit 分档；全量 24h ticker 的权重为 40。以下按查询当时文档口径估算，部署仍须读取当前限制及响应头。[W1]

| 项目 | 610 品种 | 707 品种 |
| --- | ---: | ---: |
| 首次 `limit=1500` 请求数 | 610 | 707 |
| 首次请求权重合计 | 6,100 | 7,070 |
| 返回 K 线行数上限 | 915,000 | 1,060,500 |
| 按 200 字节 / 行估算冷启动未压缩传输 | 183.0 MB | 212.1 MB |
| 按 96 字节 / 行估算结构化记录 | 87.84 MB | 101.81 MB |
| 每小时增量请求数 | 610 | 707 |
| 每日增量请求数 / 权重 | 14,640 | 16,968 |
| 每日真正新增小时记录 | 14,640 | 16,968 |
| 增量每次取 2 根，估算每日传输 | 5.86 MB | 6.79 MB |

增量请求用同一个已关闭整点的 `endTime`，`limit=2` 同时复核上一根，按 `(instrument_id, open_time)` 幂等写入。通常每次只新增一根。中断超过一个小时后，根据缺口长度补拉，不永远只取两根。

200 字节 / 行、96 字节 / 行是容量模型，不是本次线上测量；HTTP 头、JSON 字段长度变化、压缩、索引、重试不包含在传输裸估计里。MB 使用十进制。

### 11.4 推荐调度预算

初始建议：冷启动全局 1 请求 / 秒，常态整点增量最多 4 请求 / 秒，同时统一计入既有业务权重。

按 707 品种且无重试估算，冷启动约 11.8 分钟；增量批次约 177 秒。冷启动每分钟消耗约 600 权重，增量波峰约 240 权重 / 分钟；若同时服务一个共享全量 ticker，每分钟再加约 240 权重。

这些是可调部署预算，不是硬编码的交易所上限。不根据代码注释中“差两个数量级”直接作容量保证；应读取当前配额、响应头和现有服务的实际用量。429 进入退避，明确不支持的合约停止重试，地区 / 权限类错误不能当成临时超时无限重试。

若特别想省初次权重，约 60 日可以拆成 `499+499+443` 共 1441 根，三次请求、总权重 6，而一次 1500 根权重 10。707 品种会从 707 次请求变成 2121 次。**本项目约束是复杂度，因此默认选一次 1500 根，不为节省这点权重增加分页状态。**

### 11.5 真正更重的现有开销：全量 ticker

以附件约 285 KB / 次估算，持续 10 秒一次相当于每天 8640 次、约 **2.46 GB / 日** 的未压缩响应量；实际前台使用乘以活跃占空比。3 个一直开启的客户端约 7.39 GB / 日，10 个约 24.62 GB / 日，并不意味着本用户实际会持续开启。[R4]

第二期推荐由服务端共享一份全量 ticker，并为手机返回板块摘要。摘要按 20 KB / 次的设计目标估算，单个全天活跃客户端约 173 MB / 日；20 KB 是目标，不是实测承诺。成员详情按需读取服务端缓存，不再由每个手机额外拉一次完整上游。

若短期不迁移全量 ticker，亦可保留手机现有截面通道，仅新增历史趋势服务；此时小时历史成本照表增加，但不能声称已经节省了手机客户端全量流量。

手机首次打开不应承担 N 次历史回填。历史是服务端共享资产，不按每位用户分别下载、分别计算。

### 11.6 一年保留成本

按每条小时记录 96 字节：

- 610 品种：约 534.36 万行 / 年，裸记录约 513 MB。
- 707 品种：约 619.33 万行 / 年，裸记录约 595 MB。
- 34 个板块按每小时 256 字节保存结果：约 76 MB / 年。

加入数据库索引、页开销、日志与短期修订，建议单个主节点预留 **2—5 GB** 的工作存储预算；备份和另一节点副本另计。该范围需要用实际数据库编码压测校准，不是保证值。

约 60 日、707 品种的基础记录按上述布局约 98 MB；不必把全年记录全部常驻内存。算法主要是差分、中位数和短窗口统计，不需要 GPU 或复杂分布式计算。

两台 VPS 采用一个主动采集者、一台读取复制或接管。不要为了“有两台”默认将币安请求量翻倍；必须有采集者租约 / 主从标识，接管后按缺口补齐。

**部署前置验收：** 两台美国 VPS 到目标 Binance 行情端点的可达性、合法可用性与既有业务资源余量，本次未实测。当前手机全量直连能够运行，并不能证明服务端也可访问。未通过该项时，不能把“服务端可以算”写成“已具备服务端连续数据”。

### 11.7 OI 与 metrics 为什么不进第二期必需项

查询时官方 OI 历史说明为：单次最多 500 条，只提供最近约 1 个月数据，另有限制 1000 次请求 / 5 分钟；请求权重为零不等于没有请求限额或没有运维成本。部署时重新核对该口径。[W1]

需要纠正一个容量理解：**metrics 是每个 symbol 每天一个文件，不是整个市场每天一个文件。** 仓库路径包含品种目录和品种文件名。[R5]

707 品种回填 30 天是 21,210 个 zip；按附件 12 KB / 文件约 254.52 MB 压缩数据，解压为 6,108,480 行 5 分钟记录。下载量不夸张，但文件数量、缺失文件与重试管理没有必要提前承担。

第三期先对 20 个研究品种使用 `period=4h` 的 OI：每 4h 一次约 120 请求 / 日；20 日初始化每品种一趟即可覆盖 120 个 4h 点，总计约 20 次请求。用于解释与研究，不反向改变主榜口径。需要完整未来回测时，必须把选择品种的偏差写清楚，不能把关注过的 20 个品种冒充全市场。

## 12. 分期、冷启动与降级

### 第一期：现有 24h 截面，值得做，但不要叫持续龙头

新增截面相对广度、成员绝对家数、领涨成员、删一检查、单成员识别。仍以中位数主排序，保留三档观察口径。

截面基准可取当前池内有效成员 24h 对数收益的均值，并给各板块减去同一个基准。它是截面参照，不与第二期的历史链式参考线混称为同一条长期指数。

这一期能回答：近 24h 哪些板块相对领先；是不是多数成员参与；是否只有一只在暴涨。

这一期不能回答：连续领涨几天、20 日是否领先、成交额相对自身历史是否放大、真实加速度是否转正。

这些不可计算字段为缺失，不补 0，不推测，不用“先给个临时龙头分”填空。已有 10 秒轮询只用于刷新快照；本地保留几次结果用于视觉稳定，不据此声称已有趋势历史。

### 第二期：小时历史，完成主目标，优先级最高

部署规范品种映射、小时 K 线共享库、池参考线、5 / 20 日状态、独立加速度、相对广度和版本记录。完成前述成本与可达性验收后，上线“持续强弱”。

冷启动按能力逐步解锁：

| 历史状态 | 可以显示 | 不能显示 |
| --- | --- | --- |
| 只有当前快照 | 24h 强弱与成员异动 | 持续龙头、历史放量、加速 |
| 至少 48h + 对齐样本 | 相邻窗口原始加速度、24h 相对方向 | 已校准的加速度状态 |
| 至少 5 日 | 5 日相对表现与日级跑赢次数 | 完整 20 日持续确认 |
| 至少 20 日 | 主排序与中期背景 | 不足约 22 日时仍不输出完整自身尺度校准 |
| 约 22 日及充分有效样本 | 完整加速度校准 | 不等于预测能力已验证 |
| 约 29 日 | 股票相关同星期成交额参照可基本形成 | 不等于节假日问题已解决 |

正式“持续强弱”主排名使用相同目标窗口的可比成员集合；历史较短的板块留在近期观察组，不与完整历史板块以不同窗口混排。服务器已有历史时，新手机首次打开不需要重新等待积累。

### 第三期：可选研究，不应阻碍第二期

做加速度的增量验证、短周期预警需求评估、OI 结构解释，以及必要的报价 / 标记价格偏离和交易时段验证。后两项可能需要新增 Binance 端点接线，不能假装当前 `Endpoints.swift` 已经提供全部能力；没有验证必要性就不先扩大采集面。

若研究发现加速度只复述刚刚上涨、对转强识别没有增量，就保留它作为详情描述，撤掉突出状态或独立转强排序。**纳入研究，不等于必须保留为交易信号。**

### 13.2 实现必须通过的确定性用例

| 用例 | 预期行为 |
| --- | --- |
| 单个成员 +300%，其他成员不涨 | 保留单点领涨信号；整体不能只因均值暴涨被认证龙头 |
| 多数成员连续跑赢，而单日不突出 | 可进入持续领先；不被今日热榜完全遮蔽 |
| 先跌 10% 再涨 8% | 保留累计仍跌事实，不用第二天单日涨幅冒充趋势反转 |
| 相对对数价格匀速上升 | 速度正、加速度为零；不能要求持续龙头必须一直加速 |
| 相对速度 −10→−2 | 加速度正，但当前仍跑输，标收敛 / 修复 |
| 相对速度 +10→+4 | 仍可能领先，只是减速 |
| 跳升一次后横盘 | 加速度有窗口效应，不能写成确定的新买盘 / 新卖盘 |
| 同一品种重复多个计价对 | 池基准不重复计数，序列不随 10 秒成交额切换 |
| 价格整体乘一个常数 | 收益与加速度不变 |
| 缺失一批成员 | 覆盖率下降，不能当零收益或当弱势 |
| 新增 / 删除板块 | 不制造旧板块自身价格加速；名次变化另计 |
| 所有板块相同 | 并列，不强制生成一强一弱的统计结论 |
| 一成员板块 | 不能称 100% 广度为板块共振 |
| 同一源快照重复到达 | 不算作第二次时间确认 |
| 单只成交额扩大 100 倍，价格不变 | 主强弱排序不因此改变 |

### 13.3 历史重放与前向影子记录

必须保存“当时显示给用户的输出”：时间、目录版本、基准版本、合约映射、有效成员、原始指标、滤波值、状态与修订号。后续补数可以修正数据，但不能覆盖原始发布记录，再假装系统当时就知道修正结果。

回放用当时可知的成分与挂牌状态。今天的分类回填到过去，可以用于算法原型，但须标注为“当前成分回溯”，不能称为无幸存者偏差的实盘回测。

验证两个目标，不能混算：

**描述有效性：** 处于持续领先状态的板块，是否真的有多数成员、多个不重叠窗口支持？删去前沿成员后是否仍强？这些应由定义直接满足，主要用于发现实现错误。

**预测增量：** 在相同的当前强度条件下，正加速度是否更早识别后续广泛增强，而不是只标出了已经涨完的反弹？这一点只能靠历史 / 前向证据回答，不能由公式保证。

### 13.4 加速度的增量实验

预先固定对照模型，不反复挑选最漂亮的参数：

- B0：24h 板块中位数。
- B1：5 日相对表现。
- B2：5 日 + 20 日背景 + 24h 方向 + 广度 / 持续性。
- B3：B2 加本文加速度状态。

比较未来 24h、72h、5 日的板块典型相对表现、未来相对广度，以及候选成为持续领先的比例和时间。短期预警需求另加未来 6h，但不能事后择优只报告其中一个周期。

关键对照是 B3 对 B2，而不是只对 B0：否则加速度可能只是通过重新利用最近 24h 上涨而看似“有效”。可先按现有 5 日强度、24h 表现和波动水平分组或匹配，再比较组内加速度状态，不必上复杂预测模型。

样本单位是事件段，不是每小时重复的一万个重叠信号。相邻板块高度重叠，日期之间有序列相关；误差评估应按连续日期块并保留同日横截面一起抽样，块长至少覆盖目标收益窗口。短样本不能给出虚假的精确显著性或固定胜率。

如果 B3 在多数预设窗口不优于 B2、反弹误报更多、或只在个别极端时期有效，应降低其突出程度；不要通过调权重掩盖无增量。

### 13.5 参数稳定性与产品验收

固定一小组敏感性检查：主窗口 3 / 5 / 7 日；加速度窗口 12 / 24 / 48 小时；广度阈值 60% / 2⁄3 / 75%。这些只用于查看结论是否容易翻转，不从中挑过去收益最高的组合来上线。

记录气泡名单更换次数、状态反复切换次数、真实广泛转向到提示的延迟、缺失率和不同数据版本结果差异。先观察，再确定可接受的噪声预算。不能把任意“每天最多几次变化”的产品指标宣称为交易信号的自然规律。

## 14. 已知失效场景与反对意见

**最常见：市场整体反弹。** 高 beta 板块自然跑得更快，价格相对领先不等于获得独立基本面重估。正加速度也可能只是从更差的位置反弹。

**单点或少数成员启动。** 中位数会晚于最早领涨币；本方案接受这种整体确认延迟，通过独立前沿成员通道补偿，而不是承诺同时做到零噪声和最早发现。

**高度相关与重叠分类。** 多个板块可能在重复描述同一批币。仅凭同时变强不能证明资金在不同主题之间搬家。

**合约价格与底层资产不一致。** 股票相关合约、盘前类品种、不同挂牌形式的价格，未必等于底层正股；融资、溢价与交易深度可能影响表现。只有币安数据时，不能归因为真实股票行业资金变化。

**低流动性、新上市和合约改名。** 稀疏成交、极端跳价、报价单位变化会破坏速度和二阶差分；必须先验证品种身份与数据质量。不能把每个真实大涨都删掉，也不能把每个异常价格都保留为机会。

**闭市 / 清淡时段。** 缺少新交易并不意味着稳定可靠。不同市场时段混合，尤其容易造成短期相对加速度误读。

**窗口效应。** 旧大涨 / 大跌移出窗口，就可能改变排名与 A。A 是变化描述，不是原因识别。

**覆盖与目录偏差。** 未分类、下架、历史缺失或分类随事后认知调整，会使回放比实盘好看。当前 1—2 个有效成员不能代表整个静态板块。

**价格强不等于交易好。** 本系统不衡量估值、拥挤程度、止损距离、资金费或下单成本。龙头可能最不适合追入；弱势板块也可能有高赔率反弹。

### 更简单的方案能否拿到主要价值？

可以先做：**5 日中位相对表现主排序 + 20 日背景 + 5 日相对广度 + 领涨成员**。这已经回答大部分“谁持续强、谁只是单点强”的问题。

二阶变化本身在已有小时历史后，计算成本很低；真正需要克制的是解释、状态机和验证复杂度。建议第二期把 A 一起计算并记录，但默认只以小型状态展示，不急于推出“加速龙头总榜”。

如果还要减少采集频率，60 日采用 4h K 线，首次约 361 根 / 品种，一次请求、权重 2；707 品种初次权重 1414、日增量请求 4242。代价是两个时点确认约需 4—8 小时，且短时减速更晚发现。对于只看数日轮动可以接受；对希望同一交易时段及时提示走弱的用途，仍推荐 1h。

## 15. 常数总表与落地顺序

| 参数 | 初始取值 | 原因 / 边界 |
| --- | --- | --- |
| 主排序窗口 | 120h | 数日领导状态；不等于最优收益窗口 |
| 中期背景 | 480h | 与主窗口拉开层次；自然时间，不假装交易日 |
| 短期方向 / 加速度分段 | 24h | 区分相邻日级速度，避免 10 秒差分噪声 |
| 历史粒度 | 1h | 为小时级转向提示保留空间 |
| 冷启动 | 1500 根 | 一次请求覆盖约 60 日与校准余量 |
| 持续领先分位 | ≥75；弱势 ≤25 | 选择前 / 后四分之一；小池名次离散 |
| 相对广度 | ≥2/3 | 要求明显多数参与；不是概率估计 |
| 连续性 | 最近 5 个日段中 ≥3 个 | 排除仅靠一个孤立日的简单版本 |
| 最低多成员数 | 3 | 单点与板块区别的最小政策值 |
| 小样本更严条件 | n=3—4 全员同向 | 保守解释，代价是漏掉部分真实小板块 |
| 最低横向比较板块数 | 5 | 过小池只显示原始值，不认证分位龙头 |
| 板块 / 池覆盖门槛 | 80% / 90% | 完整性政策，需要线上验证缺失影响 |
| A 滤波 | 3 个已完成小时中位数 | 抑制单点尖峰，约付出 1 小时响应代价 |
| 状态确认 | 2 个连续有效小时 | 限制反复翻转；不是两个重复响应 |
| A 自身尺度 | 前 20 个日采样绝对 A 中位数 | 不依赖正态性，不把它叫标准误 |
| A 数值地板 | 0.0001 / 日² | 约 0.01 个对数百分点，避免极小分母 |
| A 幅度阈值 | ±1 个自身尺度 | 可读的初始门槛，不是统计显著性 |
| 前沿成员分位 | ≥90 | 限制异动列表规模，另保留最大值 |
| 加密量能参照 | 前 20 个非重叠 24h 段 | 不把当前放量放进分母 |
| 股票相关量能参照 | 前 7/14/21/28 日同窗，至少 3 个有效 | 粗略处理星期效应，不能处理全部假期 |
| 面积尺度 | 全池过去 24h 主值的 95 分位，每日冻结 | 减少一只球更换引起全屏缩放 |
| 实时快照刷新 | 约 10 秒 | 延续已有节奏，不等于趋势评估频率 |
| 正式趋势汇聚 | 整点后目标 5 分钟内 | 依据请求预算，需实测尾延迟 |
| 历史失联降级 | 连续错过两个小时批次 | 不无限期把旧结论当当前 |
| 数据保留 | 小时原始数据 1 年 | 用于事后验证，服务端共享 |

**建议实施顺序：先修品种身份和覆盖，再加历史；先让主排序可解释，再把加速度加入状态；最后证明它是否提供增量。** 不要从调一串“龙头分权重”开始。

## 16. 最小输出契约与责任边界

服务端每个板块至少返回：`sector_id`、`market`、`catalog_version`、`benchmark_version`、`trend_asof`、静态 / 挂牌 / 有历史 / 有效成员数、24h 观察值、`ER_24h/120h/480h`、`AR_120h`、相对广度、5 日跑赢 / 跑输次数、原始及滤波 A、自身尺度、加速参与率、量能参照、删一范围、前沿成员和状态。

状态拆成三类，避免单一枚举丢信息：

- 趋势：持续领涨 / 抗跌领先 / 持续弱势 / 未确认。
- 变化：增强 / 减速 / 收敛 / 恶化 / 中性。
- 可用性：正常 / 少成员 / 历史不足 / 覆盖不足 / 过期；属于数据契约，不要求画工程状态面板。

缺失统一为缺失值，不用 0 代替。`quote_asof` 与 `trend_asof` 分开；不将最新 24h 快照和上个整点的 5 日值伪装成同一采样时刻。

`SectorAggregator` 继续负责旧截面聚合；历史公式与状态机放在 Rust。`SectorSelector` 增加明确的排序 / 面积字段选择，不能把所有语义偷偷塞回 `pct`。客户端只负责展示口径、入选名单稳定与交互，不再独立维护一套略有不同的历史算法。
