# 多交易所接入指南（现行规格）

> 2026-09-23 起生效。看盘接一家新交易所（或同一家的另一个市场）时，照这份清单改；
> 清单之外的文件一个都不该动。改到了清单之外，说明抽象漏了，先补抽象再接。
> 守卫：`Tools/check-venue-isolation.sh`（挂在 `make app-logic-test` 里）。

## 1. 三个正交概念

| 概念 | 在哪 | 说什么 |
| --- | --- | --- |
| 品种身份 `InstrumentID` | `KanpanCore/Sources/KanpanCore/Model/InstrumentID.swift` | `venue/market/symbol`，键 `key` 形如 `binance/usd_m/BTCUSDT`、`coinbase/spot/BTC-USD`。自选、画线、提醒、复盘、K 线缓存、账号同步全按这个键。裸符号（旧数据）一律归默认交易所。`display` 把代号里的 `-` 显示成 `/`。 |
| 行情提供者 `MarketProvider` | `KanpanNetwork/Sources/KanpanNetwork/Provider/` | 品种表、K 线、24h 行情、推送、历史翻页。上层只认协议 + `ProviderCapabilities` 能力位，从不问「这是哪家」。 |
| 线路 Route | `MarketRoutePolicy`（直连 / 网关）+ `RouteResolver` | 一个全局开关，对所有交易所生效，无自动切换。每家提供者自己决定两条线路各连哪台主机。 |

## 2. 客户端：新建一个目录 + 注册表一行

1. **新建** `KanpanNetwork/Sources/KanpanNetwork/<交易所>/`，照 `Coinbase/` 的分工写：
   - `<X>Provider.swift`：实现 `MarketProvider`，并给出 `static let capabilities`。
   - `<X>DTO.swift`：报文 → `SymbolInfo` / `Bar` / `Ticker` / `WSPayload`（单位、字符串数值、时间、顺序都在这里翻平）。
     `SymbolInfo.underlyingType` 按币安口径填（全是币就填 `COIN`），徽章与分类都认它。
   - `<X>Endpoints.swift`：直连主机、网关路径（`/v1/market/raw/…?source=<id>`、`/v1/market/stream?source=<id>`）。
   - `<X>WS.swift`：实现 `MarketStream`（订阅增量、分层看门狗、退避重连）。
   - 限速器（按该交易所公开限额取保守值）。
2. **能力位**（`ProviderCapabilities`）如实填写，界面据此自动降级，不写任何 `if venue == …`：
   - `nativeIntervals` + `aggregatedFrom`：14 档周期里原生没有的由上层聚（源周期必须是原生档）。
   - `liveKlineIntervals`：有原生 K 线推送的档；其余档用逐笔拼末根 + 定时 REST 对表。
   - `hasMarkPrice` / `hasFunding` / `openInterestSource` / `hasDerivativeMetrics`：没有就 false / nil，
     顶栏六格对应格写「—」；持仓量与衍生统计都没有时，外部指标副图直接不画、不报错。
   - `quoteAssets`、`maxKlines`、`initialKlines`、`hasBulkTickers`。
   - `hasOrderFlow`：没有盘口（算出来的指数）填 false，主力订单流不起、图上不挂、不转圈。
   - `hasSessionChange`：帧里的涨跌已按交易日算好（对上一交易日收盘）填 true，客户端照用，不再拿 UTC 0 点开盘价重算。
   - `hasVolume`：K 线没有成交量（算出来的指数）填 false，成交量（连均量）、量差副图与均价线不画，十字线读数不写「量」；指标布局不动，切回有量的品种原样回来。头部右侧那块按 `InstrumentSurfaces.showsHeaderStats` 判：成交量、资金费率、持仓量一样都没有、品种又不是币 / 美股，整块不摆。
3. **注册**：`KanpanNetwork/Sources/KanpanNetwork/Provider/VenueRegistry.swift` 里新建一个
   `VenueDescriptor`，加进 `all`。这一行决定：
   - `displayName`：显示名；`hasFavoriteCategory == true` 时它也是自选页上那一类的名字
     （第一次加这家的品种时在「美股」之后开这一类，这家的品种固定进这一类）。
   - `searchTag`：搜索结果行名字右侧的灰色小字（默认交易所为 nil，不标）。
   - `joinsSectors`：板块页只收分类表所属那一家，其它家填 false。
   - `defaultSymbol`、提供者工厂（`make`；网关上有替身时另给 `makeOwn`）。
   - `all` 里的第一家是默认交易所（裸符号旧数据归它，自定义域名只作用于它）。
4. **隔离脚本**：把新目录加进 `Tools/check-venue-isolation.sh` 的 `VENUE_DIRS`，
   并把该交易所的名字 / 域名加进 `PATTERN`。
5. **复盘**（要支持复盘才做）：`KanpanReview/Sources/ReviewDomain/ReviewContract.swift`
   的 `supportedMarkets` 与品种形状判断，要和服务端 `sync_validation.rs` / `review_market.rs` 同一口径。

自动跟上、**不用改**的：品种表缓存（`SymbolCatalog` 按交易所各一份，非默认交易所落在
`sources/<venue>/` 子树）、K 线快照（文件名按品种键，天然分开）、多家推送合流（`MergedMarketStream`）、报价簿、搜索（代号去分隔符再比）、
深链（`hkline://drawing/<venue>/<market>/<symbol>/<id>`）、账号同步编码、顶栏小签
（市场为 `spot` 写「现货」，其余写「永续」）。

## 2b. 客户端：接进主力订单流（盘口 + 逐笔 + 大单与爆仓）

> 2026-10-08 起主力订单流只查交易所注册表；`OrderFlow/` 里的通用代码不认识任何一家（隔离脚本不再整目录放行它）。
> 现有五家，清单顺序即合并顺序：`VenueRegistry.orderFlow = [.binance, .okx, .coinbase, .bybit, .hyperliquid]`。

1. **适配器**放在那一家的目录：`KanpanNetwork/Sources/KanpanNetwork/<交易所>/<X>…Adapter.swift`，实现 `DepthFeedAdapter`
   （`streamURLs`、`connect`、`decode`、可选 `keepAlive` / `resubscribeMessages(venueID:)` / `fetchSnapshot`）。
   `decode` 只产 `VenueMessage`：`.snapshot(BookSnapshot)`、`.delta(BookDelta)`、`.trade`；回执、pong、心跳帧回空。
   成交的 `hit` 一律按「主动方吃哪一侧」：主动买 = `.ask`。
2. **注册表条目** `<交易所>/<X>OrderFlow.swift`：`extension OrderFlowExchange { static let x = OrderFlowExchange(…) }`，
   一条说清楚：
   - `key`（与品种表 `exchange` 列、簿 id 第一段同一个）、`displayName`（图例、弹层副标题、爆仓最大一笔的来源）；
   - `sequenceModel`：按产品 / 面值口径回 `DepthSequenceModel`——`rangeOverlap`（币安 U 本位）、`previousFinalOverlap` /
     `previousFinalExact`（币安现货 / 币本位、OKX）、`strictIncrementing`（Bybit：`u` 严格 +1）、`snapshotOnly`
     （每帧整本、没有序号，Hyperliquid）。没有「信任上游、不校验」这一档；
   - `snapshotInBand`：快照随流下发填 true；要另拉 REST 快照（币安）填 false，模型在连上时回 `.fetchSnapshot`；
   - `maxBooksPerConnection`：按中继 / 上游的订阅配额取（Bybit 12、Hyperliquid 8）；
   - `liquidationCode`：服务端 `/liq`「哪家」列的编号（0 币安 / 1 OKX / 2 Bybit），没有强平推送填 nil；
     同时在 `KanpanCore/…/OrderFlow/BigTradeDigest.swift` 的 `LiquidationRow.Exchange` 加同号一项；
   - `fallback`：服务端品种表没收这只时保底订哪几本（Bybit `<BASE>USDT`；Hyperliquid `<BASE>`，价格乘回图上缩放）；
   - `makeAdapters`：把这一家的一批簿分到连接上（`OrderFlowExchange.chunks`）；只能走中继却没有 kanpan-api 主机就回空。
3. **加进** `VenueRegistry.orderFlow`。`OrderFlowCatalog.venue(…)` / `catalog.adapters(_:)`、`OrderFlowBase.exchanges`
   （代号 → 显示名）、大单流（`BigTradeFlow`，五家合并按门槛 ÷ 50 记）、「大单与爆仓」弹层的现货 / 合约分账、价位梯、
   每根柱都自动跟上，**不用改**。
4. **测试**（`KanpanNetwork/Tests`）：用真实录下的帧写解码用例（快照、增量、成交方向、回执 / pong 忽略、跳号只重订那一本）；
   把这家加进 `StressFiveVenueStreamTests`（深度流 × 模型 × 大单流）与 KanpanCore `OrderFlowStressFiveVenueTests`。
5. 隔离脚本 `VENUE_DIRS` 加这家的目录、`PATTERN` 加名字 / 域名（第 2 节第 4 条）。

| | Bybit | Hyperliquid |
| --- | --- | --- |
| 线路 | 一律经 kanpan-api 中继 `/v1/market/ws/bybit?category=spot\|linear\|inverse` | 一律经 `/v1/market/ws/hyperliquid` |
| 订阅 | `orderbook.1000.<代号>` + `publicTrade.<代号>`；一条消息 ≤ 10 个 args，一条连接 ≤ 12 本 | `l2Book`（`nSigFigs` 4，每侧 20 档）+ `trades`；一条连接 ≤ 8 本；`subscriptionResponse` 忽略 |
| 序号 | `strictIncrementing`；`u == 1` 的 snapshot 整本重来；接不上只退订再订那一本 | `snapshotOnly`（每帧整本） |
| 心跳 | 每 20 秒 `{"op":"ping"}` | 每 30 秒 `{"method":"ping"}`，静默看门狗 60 秒 |
| 成交方向 | `S = Buy` 吃卖盘 | `side = B` 吃卖盘 |
| 爆仓 | `/liq` 编号 2 | 无 |

## 2c. 网页版（电脑 `Web/src` + 手机网页 `Web/src/m`）接进主力订单流

> 2026-10-08 起网页两端的订单流只查 `Web/src/venues/` 注册表；`Web/src/orderflow/**` 去注释后不许出现任何一家的名字或域名
> （守卫 `Web/tests/venues-isolation.test.ts`，挂在 `npx vitest run` 里）。清单顺序即合并顺序：
> `VENUE_LIST = [binance, okx, coinbase, bybit, hyperliquid]`。

1. **新建** `Web/src/venues/<id>.ts`，导出一个 `VenueAdapter`（类型在 `venues/common.ts`）：
   - `key`（与服务端品种表 `exchange` 列、簿 id 第一段同一个）、`label`（图例、读数卡、抽屉分家、手机弹层副标题）、`color`（皮肤变量 `--of-<id>`）；
   - `sequenceModel(product)`、`snapshotInBand`、`maxBooksPerConn`：口径同第 2b 节（Bybit `strictIncrementing` / 12，Hyperliquid `snapshotOnly` / 8）；
   - `connections(books, ctx)`：把这一家的簿分组成 `ConnSpec`（`urls` 按顺序试，`subscribe`、`decode`、`ping`、`silenceMs`、
     `resubscribe` 只重订跳号那一本）。`ctx.route === 'gateway'` 时只给中继；中继路径同 iOS（`${ctx.gw}/v1/market/ws/<id>…`）；
   - 要另拉 REST 快照的给 `snapshot`；服务端品种表没收这只时的保底簿给 `fallback`（只在目录为空时用）。
   - `decode` 只产通用帧：快照 / 增量 / 成交，成交 `hit` 按主动方吃哪一侧（主动买 = 吃卖盘）；回执、pong 回空。
2. **加进** `venues/index.ts` 的 `VENUE_LIST`。`EXCHANGE_NAMES` / `EXCHANGE_CH` / `EXCHANGE_COLORS`、`feed.ts` 建连、电脑大单带合墙
   （`orderflow/bands.ts`：一本簿 = 交易所 + 产品，读数卡一本一行，最多列 8 本、其余并成「其余 N 本」）、电脑大单抽屉五家分家、
   手机「大单与爆仓」弹层副标题（五家放不下时依次去「合并」→ 后几家收成「+N」，读屏念全名）都自动跟上，**不用改**。
   有强平推送的再加进 `LIQ_EX`（与服务端 `/liq` 编号同序：0 币安 / 1 OKX / 2 Bybit）。
3. **测试**：真实录帧放 `Web/tests/fixtures/`，解码 / 序号 / 分连接 / 心跳 / 跳号只重订一本写进 `Web/tests/venues-<id>.test.ts`

## 3. 服务端 `Backend/kanpan-api`

1. **新建** `src/venues/<id>.rs`：REST 原样透传（不翻成币安格式）+ 推送 hub（一条上游共享给所有手机，帧原样转发）；
   复盘要用的 K 线 / 逐笔取数也放这里。
2. `src/venues/mod.rs`：`raw` 与 `stream` 两个分发各加一行 `Some(<id>::SOURCE)=>…`。
   路由挂在 `/v1/market/` 下——`/market/*` 在 Caddy 上整段归 Python 网关，不许占。
3. 白名单（同一口径，漏一处同步就会整条被拒）：
   - `src/sync_validation.rs`：`venue` / `market` 取值与 `identity(venue, market, symbol)` 的代号形状；
   - `src/search.rs`：`reviewMarkets` 与历史检索的 venue 白名单；
   - `src/review_market.rs` / `src/review_worker.rs`：按 `(venue, market)` 分支取 K 线与逐笔。
4. 提醒（`src/alerts.rs` + `src/watch_move.rs`）：服务端评估要这家的实时价。
   - 加一个市场常量（照 `BINANCE` / `COINBASE`，值就是 `alert_watches.market` 里存的 `venue/market`），
     `load(&s, <常量>)` 只读这家的画线 / 价格提醒；复盘到点只在币安那条循环里结算，不要重复。
   - 照 `run_coinbase` / `coinbase_session` 为它开一条订阅（重连之间保留 `Movers`），在服务端拼
     一分钟 K 线交给同一个 `evaluate`，同一根再喂 `movers.observe` → `watch_move::notify(…, <常量>)`。
     价格不是从上游推送来、而是 `kanpan-api` 自己采好落库的（美元指数），照 `run_macro` 在 worker 里
     轮询库里的 1 分钟 K 线（worker 与 api 是两个进程，不共享内存）。
   - 条件提醒（`src/conditions.rs`）只判币安，`load` 已经跳过其它市场的行。
   - 自选五分钟波动按交易所分开盯：`load_mover(tx, owner, venue)` 按自选对象的 `venue` 字段筛
     （旧对象没有这个字段算币安），这家的自选不会被塞进别家的订阅。
   - 深链与标题：`symbol_path(market, symbol)` 给非默认交易所加 `venue/market/` 前缀
     （`hkline://drawing/coinbase/spot/BTC-USD/<id>`），`display_symbol` 把代号里的 `-` 写成 `/`；
     `watch_move::short` 认 `BASE-QUOTE` 形状。代号形状不同的新交易所要在这三处各补一个分支。
5. 市值（`src/market_meta.rs`）：代号形状和币安不同时，在 `meta_payload` 里把代号折回 base 币查供应量表。
6. 部署：先推上 `origin/main`，从干净的 `origin/main` 检出 → 加部署锁 → 备份 → rsync 到
   `/opt/kanpan-api` → `cargo build --release` → `python3 ops/install.py` →
   `systemctl restart kanpan-api kanpan-worker` → 只读验证（下面第 4 节）。不改 Caddy、不动行情网关。

## 4. 验收

- `bash Tools/check-venue-isolation.sh` 通过；四包 `swift test`、`make app-logic-test`、
  `cargo test --lib`、App 编译全绿；`make sync-contract` 后工作树无差异。
- 线上只读：`/v1/market/raw/<品种表路径>?source=<id>` 200、K 线 200、
  `/v1/market/stream?source=<id>` 能连上并收到行情帧、`/v1/market/meta?symbols=<代号>` 有供应量。
- 模拟器：搜代号 → 加自选（进它自己那一类）→ 1m / 1h / 1w 都有图 → 切直连 / 网关都有推送 →
  画一条线、设一条提醒 → 币安品种的自选、画线、提醒、复盘不受影响。
- 不依赖 `/v1/capabilities`（待办 P4.11 要删它）：客户端能力一律取自 `ProviderCapabilities`。
