## 2. 技术决策（定死，不再讨论）

| 项 | 决定 | 理由 |
|---|---|---|
| 语言 / 版本 | Swift 6，严格并发（`-strict-concurrency=complete`） | 数据层是多线程的，编译期把数据竞争堵死 |
| 最低系统 | iOS 17.0 | 拿到 `Observation`、SwiftData 可选、`UIHostingConfiguration`；覆盖 15 / 16 / 17 全系 |
| 外壳 | SwiftUI | 品种页、面板、设置这种表单型界面 SwiftUI 效率最高 |
| 图表 | UIKit `UIView` 子类 + CoreGraphics 分层绘制，`UIViewRepresentable` 嵌入 | 手势、逐帧重绘、像素对齐这三件事 SwiftUI 做不干净；Metal 对这个数据量（一屏 ≤ 2000 根）是过度设计，CoreGraphics 一帧 < 3 ms 足够 120 Hz |
| 网络 | `URLSession` + `URLSessionWebSocketTask` | 零依赖 |
| 存储 | **K 线行情不永久落地。** 运行期只在内存里缓存（有上限、LRU），退出即没；磁盘上唯一的例外是一份「上次画面快照」（≤ 600 根、≤ 60 KB，放 `Caches/`，只为冷启动秒开，每次启动读完即覆盖）。设置 / 自选 / 画线 / 常用周期：JSON + `Codable` 放 Application Support | 手机存储不能被行情数据吃掉（思路同 Trader Foresight 的回放：临时落地、退出就删）；币安随时能拉，没必要囤；体验需要的那一点点（秒开快照）用资源换 |
| 依赖 | **零第三方** | 图表引擎、指标、网络都不复杂，引依赖只带来升级成本 |
| 工程 | 一个 Xcode workspace：`KanpanCore`（SwiftPM 纯 Swift 库，`swift test` 可跑，不 import UIKit）+ `Kanpan` app target | Core 不依赖 UIKit 才能在没装 Xcode 的机器上先做；也保证算法可单测 |
| 目录 | 本仓库根目录，独立 git 仓库 | `KanpanCore/` 与 `Kanpan/` 并列，`prototype/` `docs/` 只读 |

### 3.1 数据流

```
Binance REST ──┐
Binance WS  ───┼──▶ MarketFeed(actor) ──▶ BarSeries 快照 ──▶ ChartView(主线程)
BarCache(内存)─┘          │
                          └──▶ Ticker（最新价 / 24h）──▶ 顶栏
```

- `MarketFeed` 是一个 `actor`。对外只暴露 `AsyncStream<FeedEvent>`：`.series(BarSeries)`（整段替换）、`.lastBar(Bar)`（末根更新 / 新根追加）、`.prepend(count)`（前面补了 N 根，视野要平移保持不跳）、`.ticker(Ticker)`、`.oi([OIPoint])`、`.status(.live/.reconnecting/.offline)`。
- 图表侧持有的 `BarSeries` 是**值类型快照**，每次事件换一份；绘制线程永远只读一份不可变数据，没有锁。
- 主线程只做两件事：收事件改 `state`、置 `dirty`；`CADisplayLink` 到点才画。

## 4. 数据层

### 4.1 币安端点（USDT 本位合约）

| 用途 | 端点 | 备注 |
|---|---|---|
| 品种表 | `GET https://fapi.binance.com/fapi/v1/exchangeInfo` | 取 `pricePrecision`、`quantityPrecision`、`filters[PRICE_FILTER].tickSize`；放 `Caches/` 24h |
| 历史 K 线 | `GET /fapi/v1/klines?symbol&interval&endTime&limit=1500` | 每次 1500 根，向前翻 `endTime = firstOpenTime - 1` |
| 24h 行情 | `GET /fapi/v1/ticker/24hr?symbol` | 首屏一次，其后走 WS |
| 持仓量 · 近 30 天 | `GET /futures/data/openInterestHist?symbol&period&limit=500` | 只回最近 30 天（`startTime` 更早返回 `-1130 parameter 'startTime' is invalid`），最细 5m；`period ∈ {5m,15m,30m,1h,2h,4h,6h,12h,1d}`。这是**接口**的窗口，不是数据的上限 |
| 持仓量 · 全历史 | `GET https://data.binance.vision/data/futures/um/daily/metrics/<SYM>/<SYM>-metrics-<YYYY-MM-DD>.zip` | 币安公开归档站，**和历史 K 线是同一个站**。一天一个 zip（≈ 12 KB），解开是 CSV，**5 分钟粒度、288 行**；列为 `create_time, symbol, sum_open_interest, sum_open_interest_value, count_toptrader_long_short_ratio, sum_toptrader_long_short_ratio, count_long_short_ratio, sum_taker_long_short_vol_ratio`。BTCUSDT 自 **2020-09-01** 起（2020-08-31 及更早 404），新品种自其上市日起，归档滞后约 1 天。**metrics 只有 daily 一档，没有 monthly 打包**（请求 monthly 返回 404） |
| K 线归档（备用） | `https://data.binance.vision/data/futures/um/{daily,monthly}/klines/<SYM>/<interval>/…` | 同一个站也有 K 线归档（UM 合约月档自 2020-01 起）。app 常规取数走 REST 分页即可，归档留给批量回补和做 fixture |
| 实时 K 线 | `wss://fstream.binance.com/stream?streams=btcusdt@kline_1m/btcusdt@ticker/btcusdt@markPrice@1s` | 组合流，一条连接 |

限流：REST 权重 2400/min，`klines limit=1500` 权重 10。翻历史串行、每次间隔 ≥ 120 ms；遇 418/429 读 `Retry-After` 停够再发。

网络前提：手机端直连币安。VPS 已验证被 451 拦，所以 **app 不经过 VPS**；用户在国内网络需自备代理，app 不内置。设置页留一个「自定义 API 域名」输入（默认 fapi.binance.com），方便日后换镜像域。

### 4.2 BarSeries 数据模型

```swift
struct BarSeries: Sendable {
  let symbol: String
  let interval: Interval = .h1                // 与原型一致
  let t0: Int64            // 第一根 openTime, ms
  let step: Int64          // 周期毫秒；1M / 1y 用名义步长（30 天 / 365 天），映射时按真实 openTime 数组
  var open, high, low, close, volume: [Double]   // 列式，SoA
  var openTime: [Int64]    // 1w / 1M / 1y 这类不等距周期必须带；等距周期可省，由 t0+i*step 推
  var count: Int { close.count }
}
```

列式而不是 `[Bar]`：指标是逐列扫，绘制是逐列扫，缓存落盘是逐列写，三处都省一次拆包。

**不等距周期**：1M（月长不等）和 1y（闰年）的 openTime 不等距，`x(t)` 映射一律用 `openTime[i]` 二分查找，不用 `t0 + i*step`。1w 是等距（周一 00:00 UTC）。其余全部等距。

**年线（1y）要自己合成**：币安 `fapi/v1/klines` 支持 `3d 1w 1M`，但**没有 `1y`**（传 `1y` 返回 `-1120 Invalid interval`）。做法：请求 `interval=1M` 拉够月线，再在 `KanpanCore` 里按**自然年（UTC）**分桶聚合——`open` 取该年第一根的 open，`close` 取最后一根的 close，`high/low` 取极值，`volume` 求和，`openTime` 取该年 1 月 1 日 00:00 UTC。当年未走完的那根是「未定稿」的，和普通末根一样随 WS 跳动（WS 订阅 `kline_1M`，每次月线更新后重算当年那根）。同一套分桶函数也用来从 1d 合成 1w/1M，写成 `Aggregator.bucket(series:into:)` 一个纯函数，单测覆盖闰年、跨年、月末。

### 4.3 BarCache：内存缓存 + 启动快照（不永久存 K 线）

**原则**：K 线行情数据不永久存在手机上。理由是两条：手机存储不能被行情吃掉（一个品种 14 个周期存满就是几十 MB，自选十几个币就上 GB）；币安随时能拉，囤着没有意义。做法参考 Trader Foresight 的回放：**用的时候放内存，退出就没**。体验需要的那一点点（冷启动秒开）用一份很小的快照换，其余一律不落盘。

**内存缓存 `BarCache`（actor 内部）**
- 键 `(symbol, interval)`，值 `BarSeries`；总上限 **40 MB**（≈ 100 万根），按 LRU 淘汰，当前品种周期和自选里最近看过的优先留。
- 生命周期 = 进程生命周期。进后台不清（回来秒切），收到内存警告时清到只剩当前 (品种, 周期)。
- 向前补历史追加到内存序列前端；单个 (品种, 周期) 在内存里上限 20 万根，再往前拖则丢掉最右端已看不到的段（视野仍是绝对时间，回拖时按需重拉）。

**启动快照（磁盘上唯一的 K 线痕迹）**
- 路径 `Library/Caches/kanpan/last.kbar`（系统缺空间时可自动清，app 也不依赖它存在）。
- 内容：上次看的 (品种, 周期) 的**最后 600 根**（默认 spacing 下一屏 ≈ 40–150 根，600 根够拖两三屏），列式小端，≤ 60 KB。
- 写：退后台时写一次、切品种或周期时写一次（合并 2 秒内的写）。读：冷启动 mmap 读、画出第一帧、随即被网络数据覆盖并重写。**永远只有这一个文件**，不按品种累积。
- 设置里「启动快照」开关，默认开；关了就连这份也不写，冷启动等网络（≈ 300–800 ms）。
- ticker 不永久存，只在内存；exchangeInfo 放 `Caches/` 24 小时（几十 KB，系统可清）。
- **OI 归档切片是唯一的例外，且可以否决**：`data.binance.vision` 的每日 metrics 文件是**不可变的历史事实**（一天一个 ≈ 12 KB），重取一次要一个网络往返，看两年 OI 就是 700 多个请求。所以解压后按天存成精简二进制放 `Library/Caches/kanpan/oi/<SYMBOL>/<YYYY-MM-DD>.oi`（只留 `create_time + sum_open_interest`，一天 ≈ 3 KB），**总上限 20 MB、LRU 淘汰、系统缺空间可自动回收**。这不是 K 线，也不会随时间膨胀成 GB；如果你不要这一份，关掉后 OI 面板每次拖到 30 天以外都会重新下载，其余功能不受影响。设置页「清缓存」一并清掉并显示占用。

**冷启动时序（有快照）**：读快照 → 第一帧（< 100 ms）→ REST 拉 `startTime = 快照末根` 补缺并拉满 1500 根 → 静默替换 → 接 WS。用户看到的是「打开就有图，一眨眼末根跳成最新」，没有空白。

**什么情况下会多用一点资源**（体验优先，允许）：
- 自选列表里的品种在品种页时预拉 24h 行情（`!ticker@arr` 一条流，不是 K 线）。
- 切周期时若目标周期不在内存，先用**当前周期的数据在内存里聚合**出粗略的大周期 K 线（1m→5m/15m/1h 可精确聚合；小周期无法从大周期得到），先画这份、网络回来再替换，避免白板。
- 内存缓存 40 MB 是上限不是目标：常用只会占几 MB。

### 4.4 实时合成规则

WS `kline` 事件 `k.x == false` → 覆盖末根；`k.x == true` 或 `k.t > lastOpen` → 追加新根并把上一根定稿。
`ticker` 事件 → 顶栏最新价、24h 高低额、涨跌幅（涨跌幅用 `P` 字段，不自己算）。
`markPrice` → 仅顶栏小字，图上不画。

断线：指数退避 1s → 2s → 4s → … ≤ 30s；重连成功后先 REST 拉 `startTime = lastOpen` 补缺，再接 WS，补缺期间收到的 WS 事件排队，补完后按 openTime 去重合并。
前台 / 后台：进后台 5 秒后断 WS；回前台立即重连 + 补缺。
切品种或周期：取消旧订阅、新订阅；同一条 WS 连接用 `SUBSCRIBE / UNSUBSCRIBE` 方法，不重连。

### 4.5 OI：两个源，一条序列

**OI 是有完整历史的**，和历史 K 线来自同一个站。所以 OI 面板不设 30 天上限，能拖多远看多远（到该品种上市，或 2020-09-01，取晚者）。

| 距今 | 源 | 粒度 |
|---|---|---|
| 近 30 天 | REST `futures/data/openInterestHist` | 按 `period` 直接要，最细 5m |
| 30 天以外 | `data.binance.vision` 每日 metrics zip | 固定 5m，客户端自己降采样 |

**取数策略（按需，不预拉）**
1. 只有 OI 副图**打开时**才取；关掉就不取。
2. 先按当前视野算出需要的日期区间，近 30 天走 REST 一次拿完；更早的按天列出缺口。
3. 缺口按天并发下载，**并发上限 8**，先取视野中间再向两边扩散（用户最先看到的先有）；每个文件 ≈ 12 KB。
4. 下载中在 OI 面板底部走一条细进度条，已到的部分立刻画，不等全齐（**不转菊花挡着图**）。
5. 解压：zip 里只有一个 deflate 条目，用系统 `Compression` 框架 `COMPRESSION_ZLIB` + 一段极简的 ZIP 本地文件头解析（≈ 60 行），**不引第三方库**。CSV 逐行扫，只取第 1、3 两列。
6. 解析结果按 §4.3 的规则落 `Caches/kanpan/oi/`，第二次看同一段不再下载。

**对齐到 K 线**：对每根 K 线 `i`，取 `openTime[i]` 之前最近的一条 OI（二分），即原型 `oiAligned()` 的规矩。周期 ≥ 5m 时用 5m 源降采样到该周期（取桶内最后一条）；1m/3m 比 5m 还细，就用 5m 序列直接对齐（相邻几根会共用一个值，这是数据本身的粒度，面板底部小字注明「OI 最细 5 分钟」）。**> 1d 的周期（1w / 1M / 1y）不再显示「不支持」**，而是把 5m 源聚合到周 / 月 / 年（取每桶最后一条）后正常画。

**实时**：当前这根的 OI 每 5 分钟随 REST 刷新一次（`period` 取 5m，只要最后一条），不占 WS 连接。

**顺带**：同一个 metrics 文件里还有多空持仓人数比、大户多空比、主动买卖量比四列。1.0 不做，但解析时一起读出来放在 `OIPoint` 的可选字段里，将来要加一个「多空比」副图就是加一条曲线的事。

## 5. 图表引擎（KanpanCore + ChartView）

### 5.1 视野模型

视野是**时间窗** `View(from: Int64, to: Int64)` 毫秒，不是「根索引」。这是 TradingView 的规矩：切周期时时间窗按新周期的默认根间距重算宽度、右边缘不动，所以 K 线的**像素宽度不变**，不会大周期变成大方块。

```swift
barSpacing = plotW / ((to - from) / step)          // 每根占的 CSS 像素
x(t)       = (t - from) / (to - from) * plotW
tAt(x)     = from + x / plotW * (to - from)
indexAt(x) = clamp(round((tAt(x) - t0) / step), 0, count-1)   // 不等距周期改二分
```

常数（与原型一致）：
```
MIN_BAR_SPACING = 0.4   MAX_BAR_SPACING = 40
DEFAULT_BAR_SPACING = 每款风格自带（见 §6）
```

### 5.2 视野夹取 `clamp(view, soft:)`

```
minSpan = plotW / MAX_BAR_SPACING * step
maxSpan = min(plotW / MIN_BAR_SPACING * step, count * step * 3)
span    = clamp(view.span, minSpan, maxSpan)      // 缩放越界时以中心为锚修正
to      = view.to + (span - span0) / 2
give    = soft ? span * 0.12 : 0                  // 手指按着时允许多越界 12%，松手回弹
maxTo   = lastT + span * 0.7 + give               // 右边最多把最后一根推到 30% 处
minTo   = firstT + span * 0.3 - give              // 左边到头留 30%
```
右侧的大片空白是**正常行为**（用户确认过），不要收紧。

### 5.3 布局 `Layout`

```
plotW = max(40, W - style.axisW)
subH  = min(style.subH, max(44, (H - style.timeH) * 0.3))
mainH = max(80, H - style.timeH - subs.count * subH)
panes = [main(y:0,h:mainH)] + subs 依次向下
timeY = H - style.timeH
```
所有距离都从当前风格表读，没有全局常数。

### 5.4 价格映射

可见区间 `[lo, hi]`：`lo = floor((from - t0)/step) - 1`，`hi = ceil((to - t0)/step) + 1`。
价格范围：可见 K 线的 high/low，**并入**主图叠加指标（MA / EMA / BOLL 上下轨）和画线端点；上下各留 `style.pad` 比例；再叠加用户拖价格轴产生的 `zoom`（≥ 0.15）与 `shift`。

三种模式的前向变换 `fwd(p)`：linear → `p`；log → `ln(max(1e-12, p))`；percent → `(p / base - 1) * 100`，`base = close[lo]`。`yOf / pOf` 在变换后的空间里线性插值。

### 5.5 K 线宽度（设备像素）

```swift
func candleWidths(spacing: Double, scale: Double, bodyR: Double) -> (body: Int, wick: Int) {
  let wick = max(1, Int((scale / 2).rounded()))          // 影线半个设备像素
  let raw  = spacing * bodyR * scale
  if raw < 2 { return (wick, wick) }
  var body = max(1, Int(raw.rounded()))
  if body % 2 != wick % 2 {                              // 奇偶对齐，边缘不起毛
    let up = body + 1, down = body - 1
    body = (down >= wick && abs(raw - Double(down)) <= abs(raw - Double(up))) ? down : up
  }
  return (max(body, wick), wick)
}
```
影线粗细最终取 `max(0.5, style.wick) / scale` 点，与上式取宽者。

### 5.6 绘制顺序（每帧）

```
主图：底色 → 价格网格(按 style.grid) → 蜡烛 → 叠加线(MA/EMA/BOLL) → 画线 → 最新价线 + 右轴胶囊 → 图例
副图：底色 → 分隔线 → 指标 → 图例
时间轴：刻度 + 标签
覆盖层：十字线 + 三处读数（顶部读数条、右轴价格胶囊、下轴时间胶囊）
```

蜡烛绘制完全按风格表（原型 `drawCandles`）：
- `thin = spacing < 1.3 || bodyW <= wickW * 1.2` → 只画影线
- 影线：`wickCap == round` 用 stroke 圆头，否则 fillRect；`wickTint < 1` 时颜色 = `mix(bg, col, tint)`
- 实体：`shape == solid` 填；`hollowUp && up` 或 `outline` → 先用底色挖空再描边（线宽 `max(1, round(scale*0.9))/scale`），实体或宽度小于 2.2 倍线宽时退回实心
- `radius > 0 && h > 2r` → 圆角矩形
- 十字星实体高度 ≥ `max(wickW, style.minBody/scale)`
- 网格 `both / h / tick / none`：`tick` 只画右端 22 pt 一截
- 最新价线 `lastDash` 决定虚实

所有 x 坐标先乘 `scale` 取整再除回，保证落在设备像素边界。

### 5.7 分层与重绘

`ChartView` 挂三个 `CALayer`，每层一个 `CGContext` 位图，`contentsScale = screen.scale`：

| 层 | 内容 | 何时重绘 |
|---|---|---|
| `plotLayer` | 网格、蜡烛、指标、画线、轴 | 视野 / 数据 / 风格 / 尺寸变了 |
| `liveLayer` | 最新价线 + 右轴胶囊 | 每次 ticker（不重画整图） |
| `crossLayer` | 十字线 + 读数 | 手指移动 |

`CADisplayLink`（`preferredFrameRateRange = 80…120`）每帧检查三个 dirty 位，只重画脏层。静止时 DisplayLink 暂停（`isPaused = true`），惯性 / 手指按住时恢复。

指标缓存键 = `symbol|interval|overlays|subs|params|count`；数据只在末根变化时做**增量重算最后 N 根**（N = 最长参数 + 1），整段变化才全量算。

### 5.8 刻度

价格：`niceStep(span, want)` 1/2/2.5/5/10 × 10^k，`want = paneH / 44`。
时间：`TIME_STEPS = [1m,5m,15m,30m,1h,2h,4h,6h,12h,1d,2d,7d,14d,30d,90d,180d,365d]`，取第一个 `≥ spanMs / floor(plotW / 78)`；标签跨日显示 `MM-dd`，跨年显示 `yyyy-MM`，日内显示 `HH:mm`；时区按设置。

## 7. 手势（ChartGestures）

全部用 `UIGestureRecognizer` 子类或原始 `touchesBegan/Moved/Ended`，**不用** SwiftUI 手势。图表视图 `isMultipleTouchEnabled = true`，禁止父级 ScrollView 抢事件。

| 手势 | 判定 | 行为 |
|---|---|---|
| 单指拖 | 一指、位移 > 4 pt、无十字线 | `view -= dx / plotW * span`，`clamp(soft: true)`；记录最近 100 ms 的速度 |
| 甩 | 抬手时速度 ∈ [0.2, 3] px/ms | 惯性 `pastPx = v·τ·(1 - e^(-t/τ))`，τ = 325 ms，最长 1400 ms，剩余 < 0.5 px 停；结束后 `settle()`（非 soft clamp 回弹，spring 200 ms） |
| 双指缩放 | 两指距离 ≥ 8 pt | **单次快照**：按下时记 `(from0, span0, d0, m0)`；每帧 `span = span0 · d0 / d`，锚点 `mid = from0 + m0/plotW · span0` 固定在两指中点。先捏开再捏拢和反过来速度一样 |
| 长按 | 450 ms 内位移 ≤ 6 pt | 出十字线；之后手指移动即更新；抬手不消失；下次轻点或再次长按消失。磁吸开 → x 吸到最近 K 线中心、y 吸到最近的 open/high/low/close；关 → 自由 |
| 价格轴拖 | 按下点 x ≥ plotW | 竖向拖动改 `price.zoom`（以按下点价格为锚），双击复位 |
| 时间轴拖 | 按下点 y ≥ timeY | 横向拖动以按下点时间为锚缩放 |
| 轻点 | < 200 ms、位移 ≤ 4 pt | 有十字线 → 关；命中画线 → 选中；否则无 |
| 画线模式 | 工具条进入 | 第一点落 → 第二点落 → 完成；选中后拖手柄；拖整条 |

触觉：长按出十字线 `UIImpactFeedbackGenerator(.light)`；磁吸换到另一根 K 线 `UISelectionFeedbackGenerator`；缩放到边界 `.rigid`。`UIAccessibility.isReduceMotionEnabled` 开时惯性直接停、回弹无动画。

补历史触发：拖动 / 惯性把 `view.from` 推到 `t0 + 200·step` 以内 → `MarketFeed.loadMore()`；收到 `.prepend(n)` 事件后视野不动（时间窗本来就是绝对时间，天然不跳）。

## 8. 指标（KanpanCore/Indicator）

全部为纯函数，输入列数组，输出 `[Double]`（前导用 `.nan`）。算法与原型 `chart.js` 逐行对应，黄金值测试直接拿原型输出。

| 指标 | 定义 | 默认参数 |
|---|---|---|
| SMA | 滑动窗均值，窗内含 NaN 则 NaN | — |
| EMA | `k = 2/(n+1)`，首值用前 n 根 SMA 起步 | — |
| RMA | Wilder 平滑 `k = 1/n`，RSI / ATR 用 | — |
| MA | 3 条 SMA(close) | 7, 25, 99 |
| EMA 叠加 | 2 条 EMA(close) | 12, 26 |
| BOLL | mid = SMA(n)，`up/dn = mid ± k·σ`（总体标准差） | 20, 2 |
| VOL | 柱 + 2 条 SMA(volume)，涨跌染色 | 5, 10 |
| MACD | `dif = EMA(f) - EMA(s)`，`dea = EMA(dif, sig)`，`m = 2·(dif - dea)` 柱 | 12, 26, 9 |
| RSI | `100 - 100/(1 + RMA(gain)/RMA(loss))`，3 条 | 6, 12, 24 |
| KDJ | `RSV = (c - LLV(n)) / (HHV(n) - LLV(n)) · 100`，`K = SMA(RSV, kn)` 用 1/3 递推，`D` 同法，`J = 3K - 2D` | 9, 3, 3 |
| StochRSI | 对 RSI(rlen) 做 Stoch(slen)，K = SMA(kn)，D = SMA(K, dn) | 14, 14, 3, 3 |
| ATR | `TR = max(h-l, |h-c₋₁|, |l-c₋₁|)`，RMA(n) | 14 |
| OI | 折线 + 渐变填充。数据源见 §4.5（近 30 天走 REST，更早走归档），**不设 30 天上限**；面板底部小字「OI 最细 5 分钟」，正在补历史时走进度条 | — |

副图刻度：RSI / StochRSI 固定 0–100 并画 20/50/80 参考线；KDJ 固定 0–100 画 20/80；其余按可见极值。
增量更新：末根变化时只重算最后 `maxParam + 1` 根；新根追加时同样。整段替换时全量。

## 10. 交互与体验（重点）

这一章是整份任务书里最要紧的一章。前面九章保证「做得对」，这一章保证「用得爽」。所有条目都从一个正在盯盘的人的角度写：他一只手拿着手机，眼睛在看价格，随时可能被打断，不想被任何东西打扰。AICoin 做对的地方照搬，做错的地方（广告、弹窗、加载慢、面板挡图）全部反着来。

### 10.1 五条原则（冲突时按这个顺序取舍）

1. **打开就是图。** 没有启动页、引导页、权限弹窗、更新提示、评分请求、登录。冷启动第一帧就是上次看的那张图。
2. **一只手能做完所有常用操作。** 切周期、切品种、开十字线、回到最新、换风格，全部在拇指够得到的下半屏。上半屏只放看的东西。
3. **图永远不停。** 面板打开时图在后面继续跳；断网了图仍能拖着看历史；后台回来先给旧图再补数据。任何时候不出现空白或转圈盖住图。
4. **可预期。** 同一个手势永远只做一件事；切周期 K 线粗细不变；拖到头有阻力；出错静默降级，不弹窗。
5. **不做多余的。** 没有的功能不留入口。每一个像素要么是数据要么是控制数据的东西。

### 10.2 打开与回来

| 场景 | 体验 |
|---|---|
| 首次安装打开 | 直接 BTCUSDT 1h，主图 MA、副图 MACD + RSI、风格墩、跟随系统外观。缓存空 → 图区中间一行小字「正在连接币安」，≤ 500ms 内出图（网络正常），字消失。不提示任何「欢迎」 |
| 之后每次冷启动 | < 400ms 出上次的品种、周期、**视野**（记的是右边缘离末根几根 + 每根多宽，不是绝对时间，所以隔夜打开视野仍然对着最新）、上次的副图和画线。第一帧来自那份 ≤ 60 KB 的启动快照（§4.3），网络补上后末根静默替换，不闪；手机上除此之外没有任何 K 线文件 |
| 从后台回来 | 先给旧图 → 立刻重连 → 缺的 K 线补齐后**视野不动**（时间窗是绝对时间，天然不跳）。离开 > 5 分钟时右轴胶囊做一次 300ms 闪动提醒「价格更新了」 |
| 飞行模式 / 断网 | 顶栏品种名右边的小圆点变灰（实时绿 / 重连黄 / 离线灰），图可拖可缩可看历史；不弹任何窗。恢复后圆点变绿，缺口自动补 |
| 品种下架 / 找不到 | 顶栏显示「已下架」小标，图保留最后缓存，切品种正常 |
| 低电量模式 | 帧率降到 60、胶囊闪动关、指标增量计算不变；不弹提示 |
| 屏幕常亮 | 设置里有「盯盘时不锁屏」开关，默认开；只在 app 前台且电量 > 20% 时生效（`isIdleTimerDisabled`），退后台立即还原 |

### 10.3 图上的手感细节

在 §7 手势表之上再加这些（都是 AICoin / TradingView 用户会下意识期待的）：

- **惯性中一触即停。** 甩出去滑行时手指一碰图立刻停在当前位置，不弹、不继续。
- **拖动到边界的阻力曲线。** 超过右侧 30% 空白后位移按 `dx · 0.35` 衰减，松手 200ms spring 回到边界；到最左侧同理。
- **缩放的锚点永远是两指中点，** 而不是屏幕中心；单指在右轴上下拖是价格缩放，在底轴左右拖是时间缩放，锚点都是按下点。
- **双击图区空白 = 回到最新 + 复位价格缩放**（不复位 spacing）。这是最常用的「我拖跑了，回来」操作，比找按钮快。有十字线时双击先关十字线。
- **双击右轴 = 复位价格缩放；双击底轴 = 复位 spacing 到当前风格默认。**
- **十字线读数条**固定在图区顶部一行，不挡 K 线：`时间 · 开 高 低 收 · 涨跌额 涨跌幅 · 量 · 额`，涨跌用颜色；副图各自在图例位置显示该根的指标值。读数条在手指位于图区上 1/4 时**自动移到底部**，避免手挡住看。
- **右轴胶囊带百分比。** 十字线的价格胶囊下面一行小字显示相对最新价的 `±x.xx%`（AICoin 有，很实用）。
- **最新价胶囊的跳动。** 价格变了胶囊底色按涨跌闪 150ms 后回到琥珀；同时顶栏大字价格的变化位数字做 120ms 上下滚动（只滚变化的位）。减少动效开启时都关。
- **本根倒计时。** 最新价胶囊下面一行小字倒计时到当前 K 线收盘（`mm:ss`，1d 以上显示 `hh:mm`）。设置里可关，默认开。
- **十字线磁吸切换根时轻震一下**（selection），只在移动过一根以上时触发，快速划过不连震（节流 60ms）。
- **十字线保留策略。** 抬手保留；轻点空白关；切周期时保留在同一时间点；切品种关。
- **副图分隔线可拖**改高度（拖动区 ±8pt），最小 44pt；拖动时分隔线高亮；松手保存到该指标的高度设置。
- **图例可点。** 主图图例上点 `MA(7,25,99)` 临时隐藏 / 显示这条叠加（眼睛状态），长按打开参数；副图图例同理，副图右上角一个小 `×` 直接移除该副图。
- **右下「回到最新」按钮**离开末根 0.5 根以上淡入（150ms），点击 250ms 滑回；靠近末根淡出。按钮在图区右下、底轴上方 8pt，不压最新价胶囊。
- **左侧到头**（历史耗尽）：左边界有阻力回弹，图区左上角淡出一行「已经是最早的了」2 秒。
- **thin 模式提示**：缩到 spacing < 1.3 只画影线时，不做任何提示（这是正常行为），但捏合到最小 0.4 有一次 rigid 震动告诉你到底了。

### 10.4 周期条

- 常用行 6 档 `1m 5m 15m 1h 4h 1d` + 「更多」；当前周期若不在常用行，则常用行末尾临时显示它（高亮），不挤掉常用项。
- **长按常用行的周期项 = 从常用行移除；在「更多」面板里长按 = 加入常用行**（最多 8 个），触觉 medium，即时生效，持久化。
- 选中指示条在周期项之间**滑动**（200ms spring），不是跳。
- 切周期时图不闪：先用新周期缓存画（有缓存 100ms 内），无缓存时旧图**保持显示并降为 60% 不透明**，新数据到了 crossfade 150ms。绝不出现白板。
- 切周期保持根宽、右边缘不动（§5.1）。

### 10.5 品种

- 顶栏品种按钮一点进整页；页面进入时搜索框**自动聚焦弹键盘**（这是来搜的），返回时收键盘。
- 搜索：输入即过滤，base 资产前缀匹配排最前（搜 `eth` 先出 ETHUSDT 再出 ETHFIUSDT），匹配片段高亮；空结果一行「没有这个品种」，不放插画。
- 顶栏右侧星星：一点加自选 / 再点移除，星星填色动画 200ms + light 触觉，不需要进品种页。
- 自选分区支持**长按拖动排序**、左滑删除；最近分区最多 10 个，自动去重。
- 全部列表按 24h 成交额降序，价格与涨跌幅实时跳（进页订阅 `!ticker@arr`、出页退订）；列表用 `List` + 行级 diff 更新，2000 行滚动不掉帧。
- **左右快切自选。** 在顶栏品种名上左右滑（不是图区，图区手势保持纯净）切换自选列表的上一个 / 下一个品种，配合 light 触觉；这是盯多个币时最快的方式，AICoin 没有。

### 10.6 面板

- 四个面板都是半屏 sheet（`.medium`），可拉到全屏，下拉关闭，点遮罩关闭；面板打开时图在后面**继续更新**且**仍可单指拖**（遮罩只盖面板以外的图区 40% 高度，图区上半部分不盖）。
- 面板内的任何改动**即时反映到图上**（改 MA 参数、切风格、切价格轴模式），不需要「确定」按钮，也没有「取消」——想撤回就改回去。
- 风格面板：11 张卡的缩略图与主图同源；点卡 150ms crossfade 换风格；当前卡有高亮边；卡上的「一句话」「赌什么」照原型逐字。底部一排 跟随系统 / 浅 / 深。
- 指标面板：开关行右侧有参数小字，点参数进入参数行（数字键盘，`tickSize` 无关，整数），改完即算；副图区右侧有拖柄可排序；每个副图有 小 / 中 / 大 三档高度。
- 周期面板：14 档网格（日线以上只有周、月、年），当前高亮；长按加入 / 移出常用行。
- 设置面板条目顺序：涨跌配色 · 价格轴 · 十字线磁吸 · 本根倒计时 · 盯盘时不锁屏 · 启动快照 · 时区 · API 域名 · 清缓存 · 关于。每项一行，改了立即生效并有 selection 触觉。
- 面板弹出 / 收起 spring 280ms；减少动效时改为 120ms 淡入淡出。

### 10.7 横屏

- 跟随系统转屏（若系统未锁定方向），或点底栏「横屏」强制横屏；横屏下再点该按钮（此时在右侧竖排工具条里）回竖屏。
- 横屏布局：图占满；周期竖排贴左（当前项高亮，可上下滚）；右侧一列竖排图标：风格 · 指标 · 画线 · 设置 · 回竖屏；顶栏只剩一行小字（品种 · 最新价 · 涨跌幅），叠在图区左上角图例位置，不占高度。
- 横屏下的面板从右侧滑入为侧栏（宽 320pt），不盖图的左 2/3。
- 转屏过程视野、十字线、画线全部保留；转屏动画期间图不重绘，转完一次性重排。
- 灵动岛 / 刘海在左时，图区从安全区开始，右轴永远在右边（不会因为转向被切）。

### 10.8 画线

- 进画线态底栏变成 趋势线 / 水平线 / 删除 / 完成；选中工具后图区顶部一行提示「点两下画一条趋势线」，落第一点后变「再点一下」。
- 第一点落下后，手指移动时**预览线实时跟随**（不是落第二点才出现）；磁吸开时点吸到最近 K 线的 OHLC 并震一下。
- 选中态两端手柄直径 22pt（好按），线身命中 ±8pt；拖手柄时读数条显示该点的 时间 · 价格。
- 画线态下单指拖图、双指缩放照常，只有「点」才是落笔（按下到抬起 < 200ms 且位移 < 4pt）。
- 每条线记在 (时间, 价格) 上，切周期 / 缩放 / 换价格轴模式都贴合；按品种保存，杀 app 不丢；每品种上限 50 条。
- 删除有一次 rigid 触觉，无确认弹窗（可以重画，没必要问）。

### 10.9 动效系统

用户看重动效，这个 app 的动效要**少而准**：每一个都在告诉你「发生了什么」，没有装饰性动画。

| 主题切换 | crossfade 200ms | 直接换 |
| 十字线出现 / 消失 | fade 120ms | 直接出 / 消失 |
| 最新价胶囊闪动 | 150ms 底色闪 | 关 |

### 10.11 文案与数字

- 全部中文，不出现英文界面词（品种代码除外）；不用「加载中…」的省略号动画，用一行静态小字。
- 价格小数位跟 `tickSize`；≥ 1000 加千分位；量 `K / M / B`；额显示 USDT 计价加千分位；涨跌幅两位小数带符号。
- 时间 24 小时制；十字线时间胶囊：日内周期 `MM-dd HH:mm`，日线以上 `yyyy-MM-dd`；时区按设置，设置里显示当前时区 UTC 偏移。
- 状态圆点旁不写字；长按圆点弹一行「实时 · 延迟 xx ms」/「重连中 · 第 n 次」/「离线」。
- 错误只说一句话 + 怎么办：「连不上币安，检查网络或代理」「这个域名不通，已改回默认」。

### 10.12 可访问性

- 动态字体只作用于面板与品种页，图区字号固定（图的信息密度不能被系统字号破坏）。
- 图区作为一个 VoiceOver 元素：「BTCUSDT 1 小时 K 线，最新价 xxx，24 小时涨 x%」；十字线读数条可被读出。
- 减少动效、减少透明度、粗体文字三项系统设置全部尊重。
- 涨跌除颜色外，涨跌幅胶囊带 `+ / −` 符号，色盲也能分。

### 10.13 明确不做的（用户角度）

无广告、无弹窗、无评分请求、无引导页、无推送与通知权限、无登录、无「新功能」气泡、无任何遮住图的浮层（除了你主动打开的面板）。

## 11. 性能预算

| 指标 | 目标 | 手段 |
|---|---|---|
| 冷启动到首屏有图 | < 400 ms（有启动快照）/ < 300 ms + RTT（无） | 快照 mmap 直接画，网络异步补 |
| 拖动 / 缩放帧率 | 120 Hz 不掉帧（Pro 机型），一帧绘制 < 3 ms | 只画可见区间、分层重绘、DisplayLink 空闲暂停 |

| 内存 | 内存缓存总量 ≤ 40 MB，常用 < 10 MB；磁盘 K 线痕迹 ≤ 60 KB | 列式 Double + LRU；不永久存 K 线 |
| 电量 | 静止不绘制、后台断 WS | DisplayLink 暂停 |

## 12. 验收总则

### 12.1 谁验、怎么验、什么算过

- **每个里程碑两道关**：第一道我自验（自动化测试 + 模拟器 / 真机取证），产出一份 `docs/acceptance/M<n>.md`，里面每条标准后面跟证据（测试日志、截图、录屏、Instruments 导出）；第二道你验，按同一张表在你自己的 iPhone 上逐条过。**两道都过才算过**，任何一条不过就打回，不进下一个里程碑。
- **证据类型固定四种**：① 测试命令的完整输出（不截断）；② 模拟器 / 真机截图，文件名 `M<n>-<机型>-<主题>-<风格>-<编号>.png`；③ 录屏（手势类必须录屏，模拟器用 `xcrun simctl io booted recordVideo`，真机用系统录屏）；④ Instruments `.trace` 或导出的 csv。
- **对照物只有一个：定版原型** `prototype/看盘原型.html`。「和原型一致」的判定方式：同一机型、同一主题、同一风格、同一数据快照下，app 截图与原型截图并排放，肉眼看不出差别；能量化的（间距、轴宽、根宽、颜色值）必须量化，误差写明。
- **数值口径**：像素类允许误差 ±1 设备像素；颜色一律精确匹配十六进制；指标数值与原型 chart.js 输出比对，绝对误差 ≤ 1e-9（Double）；时间类以 `Date()` 为准，允许 ±1 帧。
- **通过标准的写法**：每条都是「可以做 / 可以看到 / 可以量出来」的句子，不写「体验良好」「基本可用」这种没法判断的话。
- **回归**：每个里程碑验收时，前面所有里程碑的自动化测试和快照基线必须重跑并全绿；手势类回归至少重做 M4 表里的 G1–G4 四条。
- **真机**：M4 起每个里程碑必须在至少一台真机上验（免费 Apple ID 签名装到你的手机）；模拟器只做机型矩阵和截图，不做手感和性能的最终判定。

## 14. 风险与对策

| 风险 | 对策 |
|---|---|
| 币安在国内网络不可达 | app 不内置代理；设置页可换 API 域名；文档写明 |
| WS 长时间无消息 | 每 3 min 收 ping 必回 pong；60 s 无任何帧主动重连 |
| 1M / 1y 周期 openTime 不等距 | 模型带 `openTime[]`，映射走二分，单测覆盖闰年与月末 |
| 十字星 / 极端行情 `max == min` | 价格范围退化处理（原型：`max = min·1.001 + 1`） |
| 120 Hz 掉帧 | 分层 + 只画可见 + 静止暂停；M9 用 Instruments 定量 |
| OI 归档按天取，拉长历史请求数多（看两年 ≈ 700 个文件） | 按需取 + 并发 8 + 视野中间优先 + `Caches/` 切片缓存（§4.3）；进度条可见，已到先画 |
| 旧存档盖新默认 | prefs 键带版本号 |
| 行情数据吃掉手机存储 | 不永久存 K 线；只有 ≤ 60 KB 启动快照；A2.12 / P9.4 用 `find` / `du` 量化验收 |

## 15. 开工顺序

1. 现在就能做：`KanpanCore`（M1）——不需要 Xcode，`swift build / swift test` 在现有 CLT 上就能跑。
2. 你装好 Xcode 并跑完两条 `sudo` 命令后：M0 收尾 → M2 / M3 并行 → M4 → …
3. 每个里程碑交付时附：变更清单、测试结果、真机 / 模拟器截图或录屏；你验收通过再进下一个。
