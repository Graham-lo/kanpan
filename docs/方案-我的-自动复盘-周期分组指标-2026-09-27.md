## 3. 自动复盘（交易复盘）

### 3.1 定义

- 现有「记一笔」改称**观点复盘**，照旧。新增**交易复盘**：一个「回合」= 某品种某方向的仓位从 0 建起到回到 0（或反手穿 0）；每个回合自动生成一条复盘记录，用户不用填任何字段，只可以补一句「当时怎么想」。
- 复盘本顶部两段切换：**观点 · 交易**。战绩一页两侧切换，交易那侧从真实成交算。

### 3.2 数据来源与边界

- **第一期只接币安 U 本位合约**（单向与双向持仓都要认）。第二期：币安现货、OKX 合约、Coinbase 现货；模块按交易所插拔（`ExchangeAccountProvider` 协议，品种身份对齐多交易所模块的 venue）。
- **只收只读 Key**：接入时先调 `GET /sapi/v1/account/apiRestrictions`，`enableWithdrawals` / `enableSpotAndMarginTrading` / `enableFutures` 任一为真直接拒收，红字一句「只收只读 Key」。代码里不出现任何下单、撤单、划转端点，`ReleaseHookScanTests` 同款机械守卫：扫 `Kanpan/Kanpan/Exchange/` 里不许出现 `/fapi/v1/order`、`/sapi/v1/capital` 这类路径。
- **Key 只存本机 Keychain**，`deviceOnly`：不进云端、不随账号同步、「导出我的数据」里也没有。换手机要重贴一次 Key；交易复盘记录本身随复盘同步回来。
- **拉取在手机上做**。用户手机走直连线路能到币安账户端点；定稿时 VPS 在美国，币安对美区 IP 回 451，服务端不能也不需要碰用户账户接口（2026-10-02 服务端已迁新加坡，451 不再是理由，但这条设计照旧）。这也让 Key 从头到尾不离开手机。
- 拉取节奏：进前台一次、前台每 5 分钟、打开复盘本时；`BGAppRefreshTask` 机会性后台刷新（不依赖 APNs）。断网静默，不重试轮询（`kanpan-no-idle-waiting-for-phone`）。
- 端点：`/fapi/v1/income`（`REALIZED_PNL` / `FUNDING_FEE` / `COMMISSION`，7 天窗分页，用它当「哪些品种有过成交」的索引）；`/fapi/v1/userTrades`（按品种、7 天窗分页拉明细）；`/fapi/v2/positionRisk`（当前未平仓与杠杆）。首次接入回溯 90 天，之后按上次水位增量。权重走现有 `RateLimiter`。

### 3.3 拼回合（纯逻辑，`KanpanCore/Sources/KanpanCore/Trades/`）

- 输入成交明细（时间、买卖、数量、价格、手续费、realizedPnl、positionSide）；按品种 + positionSide 累计净持仓；从 0 离开 = 回合开始，回到 0 = 结束，穿 0 = 结束一回合并开始下一回合（反手）。
- 回合字段：品种、交易所 · 产品、方向、开仓时间 / 均价、加减仓明细、平仓时间 / 均价、最大持仓量、名义峰值、杠杆（`positionRisk` 有就用，推不出留空）、已实现盈亏、手续费、资金费、净盈亏、持仓时长。
- 未平仓回合也生成记录，标「持仓中」，结果留空，平仓后补齐。
- 幂等：回合 id = 哈希(交易所, 账户标识, 品种, positionSide, 首笔成交 id)；同一笔成交拉到两次只计一次。
- 单测覆盖：加仓、分批平、反手、双向持仓同时开、手续费用 BNB 抵扣、资金费为负、跨 7 天窗分页拼接。

### 3.4 结果（服务端 `review_domain.rs` / `review_worker.rs` 扩）

- 交易复盘作为复盘记录的一种类型（`kind = trade`）走现有复盘存储、RLS 与同步。服务端已能取行情（`review_market.rs` 经 `binance_gate`），负责算并写回三样：
  1. **持仓期间**：最大浮盈 / 最大浮亏（1m K 线高低对开仓均价）、盈亏比（净盈亏 ÷ 最大浮亏）。
  2. **离开后**：平仓后 1h / 4h / 24h 价格相对平仓价的变化。只给数字和一句事实（「平仓后 4 小时再涨 2.1%」），不打分、不评价（`kanpan-chart-shows-data-not-quant-judgement`、不接 AI）。24h 那格到点才有，走现有到期机制，**不进待判定角标**。
  3. **图**：那段行情自动截一张，周期按持仓时长挑（≤4h → 5m，≤2d → 1h，≤14d → 4h，否则 1d）；开 / 加 / 减 / 平只标在复盘的图上，**主图一个点都不碰**。
- **战绩（交易侧）**：胜率、盈亏比、期望值、总净盈亏、费用（手续费 + 资金费）占毛利比例、最大连亏、平均持仓时长；分组：品种、方向、持仓时长档（<1h / 1h–1d / 1d–7d / >7d）、开仓时段（本地时间四段）、周几。全是算术，客户端算，服务端不另存聚合。
- **周报卡**：交易段顶部一张「上周」：笔数、净盈亏、胜率、最赚 / 最亏一笔、费用。周一 00:00 本地时区滚动生成，不推通知。

### 3.5 与观点复盘对上号

同品种、时间区间重叠的观点记录与交易回合在各自详情页里互相列出「对应的交易 / 对应的观点」。只是链接，不合并、不评判。

### 3.6 界面

- **接入页**（我的 › 交易所账户）：交易所一行（第一期只有「币安 · 合约」）、API Key 与 Secret 两个输入框（ASCII 键盘、支持粘贴，占位符「只读 API Key」）、「接入」。校验失败红字一句；已接入后显示 Key 尾号四位、上次同步、回溯到哪天、「立即同步」「移除」。不写怎么去币安创建 Key 的教程。
- **复盘本 · 交易段**：周报卡 + 按天分组的回合行（品种徽章、方向、净盈亏、持仓时长、缩略图）。详情页：图（带标记）、明细、持仓期间、离开后、「当时怎么想」、对应的观点。
- **战绩页**：观点 / 交易两侧切换。

### 3.6.1 交易回放（阶段 3d，2026-09-28）

- **一下看完**：已平的一笔，详情页图上点一下（正中一枚播放圆片，持仓中的没有）→ 回到行情图，从开仓前 20 根起停 0.8 秒自动播，1 根/秒 × 倍速（1×/2×/4×，记住），开仓、平仓两根各停 1.2 秒轻震一下，平仓后第 5 根自动停，按钮变「重播」。退出回到这一笔的详情；还没写「当时怎么想」就直接滚到那一节、点亮输入框。
- **周期**：先用人此刻图上那一档（这笔落在 10–200 根里才用），否则服务端复盘图那份，再否则按持仓时长挑一档让这笔落在 30–60 根。
- **图上**：只有 K 线 + 已经发生的成交三角（「开 · 价」「平 · 价」）+ 持仓那一段的开仓均价虚线；头部「回放 · 品种 · 周期」，持仓那一段一枚浮盈胶囊；这笔写过「当时怎么想」，开仓停顿时头部下面淡入那句原话。
- **回放条**：退出 · 播放/暂停/重播 · 进度线 · 倍速 · 开仓处。原来播放条有前一根/后一根 → 现在去掉，定位靠拖进度线（笔记重温同样）：拖时游标跟手、越过开仓/平仓刻度轻震，松手停在那儿、播停状态不变。
- **不记游标**：每次都从头播。取不到 K 线吐司一句、自动退回详情；加载中不弹任何东西。
- 3.7 的「成交标记画到主图上」仍然不做：说的是实时行情图；回放是复盘里的一段重放，退出就没了。

## 4. 指标按周期分组记忆

- 三组：**分钟组** 1m 3m 5m 15m 30m；**小时组** 1h 2h 4h 6h 8h 12h；**日组** 1d 1w 1M 1y。
- 一组「布局」包含：主图指标与参数、副图指标与参数、隐藏输出、K 线画法、价格轴类型。不含皮肤、网格、价格线等显示项（那些跟人不跟周期）。
- **继承直到分叉**：新装与老档案三组共用一份（迁移把当前那份当作三组的共同源）；用户在某一组里改了任一项，那一组分叉成自己的一份，其余组仍共用。分叉那一刻浮一条 toast「日线及以上的指标现在单独记」，每组只提示一次。没改过的人永远看不到任何变化。
- 切周期跨组时按新组布局重算，同一帧完成、不闪；同组内切周期不变。
- 同步：Prefs 从单份变三份（`indicatorLayouts.minute / hour / day`），走 `PrefsFieldPlan` 生成契约，服务端 `sync_validation.rs` 白名单同一提交对账（`kanpan-finish-features-completely` 两端对账那条）；老字段保留为迁移源。
- 不加设置开关；唯一的管理入口是指标页底部一行「恢复这一组的默认」。

- **2026-10-03 修订：副图高度与副图顺序跟人走**。用户在手机网页版「在一小时周期调整了指标区域大小和顺序，切换周期发现又被改回去了」。改成：开关指标、参数、K 线画法、价格轴仍按三组各记；副图高度（`subHeightOverrides`）与副图顺序三组一起改、不触发分叉也不 toast（`carryPersonWide`）；老档 / 云端里各组已各记一份的，读档与整份换进来时以分了叉的组为准并成一份（`unifyPersonWide`，高度按指标取并集）；「恢复这一组的默认」不再清高度与顺序（`groupFactory`）。iOS `IndicatorLayouts.swift` 与网页 `Web/src/m/app/prefs.ts` 同一套；存档与线上形状不变，服务端不用改。K 线大小（`barSpacing`）本来就是全局一份，不受分组影响。

## 5. 条件提醒（第四阶段）

在创建提醒页的「条件」里从两种（价格达到 / 收盘穿过）扩成：

1. **费率**：费率高于 / 低于 X%，结算前 15 分钟判一次。
2. **持仓量**：1 小时持仓量变化超过 X%。
3. **均线**：某周期收盘站上 / 跌破 MA N，周期与 N 取当前图上的。
4. **大单**：主力订单流出现超过门槛的挂单墙。
5. **品种状态**：自选品种被标为停牌 / 下架、目录出现新上线品种。这一条不用建提醒，设置 › 通知里一个开关。

服务端 `alerts.rs` 评估器扩条件，仍然只响一次。仓位类提醒（离强平 X%）不做：仓位不进服务端、也不上图。
