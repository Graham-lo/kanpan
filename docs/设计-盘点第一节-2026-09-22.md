## 一、落点

| 项 | 落点 | 形态 |
| --- | --- | --- |
| 多空比 | 副图指标 `.lsr` | 单线。全市场多空账户数比 |
| 主动买卖比 | 副图指标 `.taker` | 单线。主动买入量 ÷ 主动卖出量 |
| 基差 | 副图指标 `.basis` | 单线。基差率（%） |
| aggTrade 逐笔明细 | **不做独立列表页** | 兑现成 `.taker` 当前这根的实时尾巴 |
| 五档深度 | 图区右缘、按价位锚定的十根横向量柱 | 不占版面高度 |

### 为什么 aggTrade 不做成「逐笔明细」列表

行情页的纵向结构是 `头部 / 周期条 / 图 / 画线栏`（`MainScreen.swift:624-650`），图占剩下的全部。
插一张滚动的逐笔列表要么吃掉图的高度（撞 `kanpan-chart-and-indicators-one-viewport`），
要么另起一页而底栏五格是钉死的。逐笔明细本身也是一屏数字瀑布，撞「不堆信息」。

aggTrade 真正值钱的地方是**它比 REST 快**：`/futures/data/*` 是 5 分钟粒度、还滞后一档，
而 aggTrade 逐笔实时。所以它的用法是给 `.taker` 补上「当前这根还没成型的桶」，
让主动买卖比不是一条停在五分钟前的线。这条流照接，只是不给它单独做一张脸。

### 为什么五档深度贴在图区右缘

头部是封死的（`kanpan-header-price-and-change` 只放最新价和涨跌幅，右侧统计块
`kanpan-header-right-block-is-six-cells` 固定六格），没有插盘口的位置；单开一个常驻条
又要从图上割高度。贴右缘、按价位锚定的横向量柱占的是图区右边本来就空着的那片留白，
高度成本为零，而且它天然和右侧价格刻度对齐——看的就是「这个价位上挂了多少」。

注意这**不违反** `kanpan-no-floating-controls-over-chart`：那条管的是「控件」，
画布上早就有图例和极值标注这类数据标记。开关放在「图表」面板里，不浮在图上。
也不违反 `kanpan-price-axis-column-narrow`：量柱画在图区内、刻度列左边，不加宽刻度列。

## 二、硬约束（照着做，别重新发明）

1. **网关不代理 `/futures/data/*`。** `MarketSource.swift:100-125` 里 `gatewayPlan` 返回
   nil 就直接认输。所以多空比 / 主动买卖比 / 基差在**网关线路下取不到**，和持仓量今天的
   处境一模一样。复用 `ChartState.swift:54-55` 已经有的那个空态，**不要**自动切线路
   （`kanpan-route-choice-is-binding`），也**不要**借 429 那条路报错——
   `MarketSource.swift` 里那段注释专门警告过。

2. **配额必须合并成一个桶。** 现在 `RateLimiter.swift:17` 只有
   `EndpointQuota.openInterestHist`（名字就是端点名，1000 次 / 5 分钟）。
   币安这 1000 次是**整个 `/futures/data/` 路径族共享的**，不是每个端点各 1000。
   再加三个各自的桶 = 名义 4000 次，撞上去连带把今天好好的持仓量一起打挂。
   → 改成 `EndpointQuota.futuresData`（name 就叫 `futures/data`），四个端点共用。
   `openInterestHist` 作为 deprecated 别名保留或直接改掉调用点，二选一，别留两个桶。

3. **`basis` 的字段名是 `futuresPrice`，不是 `contractPrice`。** 实测返回：
   ```json
   {"indexPrice":"85696.35239130","contractType":"PERPETUAL","basisRate":"-0.0003",
    "futuresPrice":"85668.80","annualizedBasisRate":"","basis":"-27.55239130",
    "pair":"BTCUSDT","timestamp":1790045700000}
   ```
   `annualizedBasisRate` 实测是**空字符串**，不是数字——解析要容忍，别让它把整条记录判废。
   参数是 `pair` + `contractType=PERPETUAL`（不是 `symbol`）。

4. **强平（forceOrder）这一项砍掉了，不做。** 2026-09-22 用户定的。

   留下缘由备查，免得下次又被当成「便宜的增量」捡起来：币安的强平**只有 WebSocket
   实时流，没有任何历史**。实测归档站
   `data/futures/um/daily/liquidationSnapshot/` 返回 404；列桶出来
   `data/futures/um/daily/` 下只有
   `aggTrades / bookDepth / bookTicker / indexPriceKlines / klines / markPriceKlines /
   metrics / premiumIndexKlines / trades`，没有强平这一族；REST 也没有公开端点。
   所以它根本不是「和持仓量同一族的增量」——要做得完整就得自家后端常驻订
   `!forceOrder@arr` 攒历史，那是另一个量级的活。

   网络层的 `forceOrderStream` / `LiquidationEvent` 已经写好了，留着不删（无害，
   将来真要做就现成），但**没有任何消费方**，副图里也不出现「强平」这个指标。

5. **多空比 / 主动买卖比的历史归档是白捡的。** `OIArchive.parseCSV`
   （`Store/OIArchive.swift:12-30`）**已经**把 metrics CSV 的第 5～8 列解出来了，
   填进 `OIPoint.accountRatio` / `takerVolumeRatio` / `topTrader*`。但
   `encodeSlice`（`:68`，magic `KOI1`，12 字节/点，只有 time + value）把它们丢在缓存外面，
   全仓库除了单测没有第二个地方读过这四个字段。
   → 扩 slice 格式（新 magic，老 magic 解出来当缓存未命中重取即可），历史就有了，
   一个额外的网络请求都不用发。**基差不在 metrics CSV 里**，只有 REST 那 30 天。

6. **副图最多同时三个**（`kanpan-max-three-sub-indicators`）。副图候选从 7 个变成 11 个，
   指标面板要排得下，但「同时最多三个」的限制和提示文案一个字不改。

7. **界面上不出现英文缩写**（`kanpan-ui-labels-are-chinese`）。`IndicatorID` 的 rawValue
   是存档用的、可以是英文；`name` / `lineNames` 必须中文：多空比、主动买卖比、基差。K/M/B/T 数额单位是例外，照用。

8. **口径我已经拍板，不给用户选**（`kanpan-sector-page-no-basis-picker`）。
   多空比 = 全市场多空账户数比（`globalLongShortAccountRatio`，对应 metrics CSV 的
   `count_long_short_ratio`）。不做「大户持仓 / 大户账户 / 全市场」三选一的切换。

## 三、实测过的接口

| 端点 | 参数 | 返回关键字段 |
| --- | --- | --- |
| `/futures/data/globalLongShortAccountRatio` | symbol, period, limit≤500, startTime, endTime | `longShortRatio`, `longAccount`, `shortAccount`, `timestamp` |
| `/futures/data/takerlongshortRatio` | 同上 | `buySellRatio`, `buyVol`, `sellVol`, `timestamp` |
| `/futures/data/basis` | **pair**, **contractType=PERPETUAL**, period, limit, startTime, endTime | `basis`, `basisRate`, `indexPrice`, `futuresPrice`, `timestamp` |

`period` 和持仓量同一套：5m/15m/30m/1h/2h/4h/6h/12h/1d。

新流：`<symbol>@forceOrder`、`<symbol>@aggTrade`、`<symbol>@depth5@100ms`。
组合流拼装走 `BinanceHosts.combinedStream`（`Endpoints.swift:103`），和
`klineStream` / `bookTickerStream` 并排加静态方法即可。

## 四、分工

- **A 网络层**（只动 `KanpanNetwork/`）：共享配额桶、三个 REST 端点 + 解析、三个流名 + 帧解析。
- **B 数据与图表**（`KanpanCore/`、`KanpanData/`、`KanpanChart/`）：slice 扩列、
  比率数据源、三个新指标、副图画法。
- **D 深度梯与面板**（`KanpanChart/`、`Kanpan/Kanpan/`）：`@depth5` 订阅、右缘量柱、面板开关。

A 先做。B 依赖 A；D 依赖 A、又和 B 抢 `KanpanChart`，所以排在 B 后面。
