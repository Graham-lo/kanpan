# 原生配色、行情数据完整性与性能审查

2026-09-15；本节覆盖本轮新增代码。前一轮基础包 `310e8c1` 的真机与兼容结果不自动代表本轮新增功能通过真机。

## 范围与设计取舍

参考 `prototype/护眼设置原型.html` 和 `docs/护眼与动态字体-实施提示词.md`，按用户后续要求收敛为 Swift 原生颜色功能：新增纸感护眼、暖暗夜读，统一图表、自选、搜索、设置面板和横屏配色。保留原有靛色浅深主题。只有一个可选“自动护眼配色”开关；不新增休息提醒、大字模式、静止显示或一组手动色温/亮度滑块，不改变行情更新节奏。

原型中两处不能直接照抄：暖暗次级文字在卡片底色上约 3.99:1；纸色强调文字在实际页面底色上约 4.38:1。保留原始令牌用于核对，但按实际表面派生文字与指标图例颜色，使相关小字达到 4.5:1。涨跌语义、输出线编号和图表几何不随配色改变。派生结果静态缓存，不在每根蜡烛或每帧里循环计算对比度。

自动模式读取 iOS 屏幕亮度通知，以屏幕亮度作为明暗代理；它不是环境光传感器。低于 0.32 选择夜读，高于 0.45 选择纸色，中间区域保持原状态，两次切换至少相隔 90 秒。手动点主题会关闭自动选择；偏好写入现有 Prefs。应用不写屏幕硬件亮度，不叠加黄色滤镜，不与 iOS 原彩/夜览重复调温。这是显示舒适度方案，不作医学效果承诺。

依据：[Apple UIScreen brightness notification](https://developer.apple.com/documentation/uikit/uiscreen/brightnessdidchangenotification)、[W3C WCAG 2.2 对比度](https://www.w3.org/TR/WCAG22/#contrast-minimum)。

## 价格异常的代码根因与修复

1. `MainScreen.readoutPrice` 原先优先读取 `market.series.close.last`。切周期时这是旧周期或缓存的末根收盘，不是最新 ticker；切新品种时 `MarketModel` 又保留着上一品种的 series，导致旧价格短暂顶到新品种标题下。现在顶栏只读共享 QuoteBook 当前品种的有效报价；历史 OHLC 只进入十字线专属容器。
2. Feed 原先 `.price(last:markPrice:)`、`.lastBar(Bar)` 没有切换上下文。排队消息可能在切换后被接收，旧价被构造成当前品种的 Ticker，继而进入自选。现在所有 Feed 事件封装为带 UUID 选择标识的 `FeedUpdate`，模型先验证选择，再验证序列品种/周期。切换立即清理旧序列、OI 和十字线；旧图的视野参数单独用于新周期的坐标过渡，不复用旧蜡烛作新数据。
3. REST 与 WS 原先按到达顺序覆盖 ticker，并丢弃了交易所时间和成交编号。现在解码 REST `closeTime/lastId` 与 WS `C/L`；`LatestQuote` 按交易所版本处理乱序、同一版本重复、同毫秒不同成交，成交编号回退也拒绝。标记价独立处理，不覆盖最新成交价。没有报价时留空，不以历史/缓存 K 线、标记价、零值或磁盘旧报价凑数。
4. K 线原先只检查开盘时间是否早于末根，没有拒绝同一根内倒序更新。现在校验品种、周期、事件时间 `E` 和同毫秒成交编号 `L`，重复事件不推进 revision，已收线的旧帧不能重写尾部。REST 请求发出后若已有新 WS 蜡烛到达，历史合并保留该实时末根；其它历史仍补齐。OHLCV 的有限性、高低范围和成交量在入口校验。
5. 仅比较品种和周期挡不住 A→B→A 的迟到请求。历史首次取数、补缺、分页、缓存等待、状态回调、OI 发布现在均受当前选择或任务取消约束。取消的旧补缺也不能清空新 composer 的队列。

实时价格还有一层独立合并：交易所单品种 ticker 约 2 秒推送，而当前图已订阅的 K 线 WS 最快 250 ms。直接只读 ticker 会降低刷新频率。因此仅从**有效实时 WS 帧**提取 `close/E/L` 表示的最近成交，交给同一 QuoteBook 的 `QuoteState`；缓存和 REST K 线不会生成报价。成交编号是价格版本，24 小时统计以自身快照时钟更新，晚到统计可以补开盘价/成交额但不能覆盖更新成交价。涨跌幅随最新成交重新计算；缺统计时只显示已取得的真价格。复用已有 K 线流，不额外增加高频订阅，也不把其它收藏行的 2 秒 ticker 节奏伪装成逐笔。

本轮新增的复现测试使用会忽略取消、可人工控制返回顺序的 HTTP transport：先发 BTC，再发 ETH，再回 BTC；先返回第三次请求，最后才返回第一次、第二次，当前图仍必须保持第三次数据。

交易所字段依据：[Binance Market WebSocket](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/ws-streams/market)、[Binance REST Market Data](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data)。

## 指标和 OI 审查

MA、EMA、VOL、MACD、KDJ、RSI 从已接受的当前 BarSeries 计算；OI 从当前选择下的历史请求对齐，不复用其他周期的原始数组。新增渲染测试比较增量结果与全量新建结果，覆盖同长度历史修正、实时末根、参数改变、OI 到达/移除、换品种换周期。七类指标的曲线、直方图及缺失值均比较。OI REST 还校验响应品种和有效数值，取消请求停止后续分页。后端历史桶键包含品种、周期与范围；原有周/月/年聚合及缺口对齐测试继续保留。

## 自选快捷切换与板块

行情左上角打开扁平的全部收藏快捷列表，展示真实报价和涨跌幅，包含所有文件夹成员；独立自选页仍使用用户文件夹。快捷列表的搜索入口进入完整品种页。

独立自选页顶部移除“行情／自选”双标题和页内搜索，直接展示 17 pt、48 pt 点击高度的用户分类。以原生容器宽度和文字实际宽度计算可见分类；多余分类进入右侧“…”菜单，选中隐藏分类后会移到可见位置。加号仍可搜索并添加品种；“…”保留新建、编辑、重命名、删除及返回行情。用户长名称允许截断，完整名称和品种数由辅助功能读出。列表长按排序、滑动删除/移分类不变；已有存档无迁移或重置。

品种页新增“市场”和“板块”筛选。资产类型使用 `underlyingType` 和现有 SymbolClassifier，细分使用交易所 `underlyingSubType`；未知类型保留其他分类，新标签原样保留以便后续扩展。不是宣称交易所已给每只股票配置完整行业：本次目录中许多股票仅有 TradFi 标签，加密则有 DeFi、AI、Layer-1 等细分。板块筛选不创建、移动或覆盖用户收藏文件夹。

搜索行的选中与收藏按钮改为两个明确的原生按钮，修复原来辅助功能标识继承到星标、自动化点击只切星标而没有进入行情的问题。菜单打开时先收键盘，避免模拟器上输入助手与菜单持续布局。

## 性能落实与测量边界

- 当前品种 ticker 由 QuoteBook 与自选共用；App 的 MarketFeed 不再重复订阅和请求同一 ticker。品种切换和周期切换不重建健康报价连接，当前图优先占有订阅名额。
- 已接受版本只维护当前值和版本，重复报文不发布 UI；仅交易所时钟前进、数字不变时不重绘整行。订阅集合不变不再重复提交替换任务。
- 隐藏在全屏搜索/自选后面的 ChartHost 不更新 renderer；行情仍接收，回到图表直接使用最新已接收序列。没有在可见界面增加静止显示功能。
- 十字线、倒计时、配色等展示变化不重新准备指标；平均 K 线只在蜡烛/视野/造型变化时更新。
- 新分类栏通过只比较文件夹、编辑状态和主题的视图边界隔离报价刷新。采样实际发现 `UpdateContextMenuInteraction.updateValue → updateVisibleMenuWithBlock → _replaceVisibleMenu` 持续出现；初步 Equatable 隔离仍有更新穿透，故最终把“…”改为独立 SwiftUI popover 列表，去掉系统 Menu 的持续替换路径。报价列表继续更新，弹出列表支持滚动及点外部关闭，关闭后再呈现分类命名框，避免叠加弹窗。
- 实时成交先于滚动统计时，缺失成交额只作为排序中的缺失键，避免 NaN 破坏比较器；原始缺失值仍显示破折号，不变成虚构的零成交额。
- 搜索报价更新只修补行内数值；不再每笔报价都对整个目录重新分区和排序。进入页面、修改搜索/筛选时才重建顺序，用户手指下的行保持稳定。
- exchangeInfo 同时被主行情、搜索、自选请求时合并为一个进行中的请求。迟到旧行情请求不再继续触发图表与指标重算。
- 现有后台断开/前台恢复、只订阅所需品种、VPS 共享上游、慢客户端隔离和缓存上限保留；未为了少量延迟改为无限历史预取或保留失效报价。

Release 算法基准（Mac 宿主，12,000 根、100 次真实末根更新、七指标）：增量 p95 0.720 ms，全量重建 p95 3.196 ms；每次输出均逐元素核对。该数据说明当前计算路径成本，不代表整 App 相比旧版提速倍数，更不是 iPhone 真机帧率或 VPS 容量结论。完整日志 `eye-colors/performance-release.log`。

一次模拟器搜索页采样曾见输入助手/键盘布局占据主线程，已作为上述收键盘修复依据。最终 iPhone 15 模拟器弹出列表开关期间的 3 秒采样，不再包含上述三个系统菜单更新/替换调用（`popover-profile-after.json`）；这只是调用路径验证，不将不同轮次 UI 测试耗时折算成 App 提速百分比。CPU 采样不与真机电量或温度直接等同。网络 RTT、交易所推送间隔和系统调度仍是外部下限，不承诺所有网络条件下“零延迟”。

## 2026-09-15 真机补验

用户重新授权后，确认没有其他设备测试任务占用，在已解锁的 iPhone 16 Pro（iOS 26.6.1，有线连接）安装当前签名 Debug 包。App Swift 源码与模拟器最终版本一致；本机已有显示名称和图标修改随安装保留，未混入本次提交。测试使用真实网络行情，常规用例偏好隔离在内存，不覆盖正式收藏；最后另行启动正式存档验证，再以无测试环境变量正常启动 App。

19 个不同用例均取得通过记录：第一轮 16 通过、1 失败，第二轮 2 通过、1 失败，第三轮 1 通过。共 21 次执行、19 次通过、2 次失败，失败均为同一个分类用例。不可把前两轮标成整轮通过。逐项记录在 `eye-colors/physical-final-summary.json`，源码/二进制哈希及各轮原始 summary 同目录。

覆盖：冷启动自选与持续报价；四种配色和分类触区；顶部分类折叠、新建和返回；自选整行排序；扁平快捷自选和市场/板块；BTC→SNDK→ETH→BTC 的 16 次周期切换；连续 OHLCV；日线历史 OI 对齐；点外部关闭面板；一屏四副图；十字中心移动与外围拖图；完整副图排序；数据显示模式状态清理；MA 参数取消/保存及输出开关；历史横拖、双指缩放、手动 Y 与恢复自动；最新端回弹、历史区自由拖动及重进；SNDK/SKHY/MU 行情；12 风格共用几何和横屏；正式收藏的前后台会话。

两次分类失败均有 XCTest `BannerNotification / NotificationShortLookView` 遮挡记录，其范围覆盖顶部“…”按钮。第二次已成功创建第一个文件夹，下一次点击又被新通知覆盖。测试辅助函数现在在分类点击前识别并向上收起系统横幅，不打开通知、不更改系统通知配置、不重试应用业务动作。补测分类用例通过（48.498 秒）。仅测试文件变化，App 二进制哈希不变，见 `physical-r3-delta.json`；原始失败、录像保留在本机 xcresult，通知相关原始附件不公开导出为验收图片。

真实 OHLCV 采样在约 5.17 秒内取得 5 份不同值，采样本身约每秒一次，不能据此声称测得每个 WS 包或 250 ms 帧率。正式存档诊断：冷启动首条报价 1043 ms；前台行情/自选切页保持 session=1；后台超过宽限后恢复为 session=2，首条报价 261 ms。这些是本次网络和设备下的会话诊断，不是普遍延迟承诺。详见 `physical-live-samples.json`、`physical-user-quotes.json`。

本轮未发现需修改 App 产品代码的故障。此次只能确认这台 16 Pro；17 系列仍只有模拟器结果。A16 模拟器之前的偶发行排序失败不能由另一台手机通过而抹去。功能性的历史拖动/捏合/手动 Y 已新增本项目真机证据，但原版 AICoin 精确手势曲线、最老历史边界遍历，以及自动配色在不同环境亮度下的实际体验仍未完成。
