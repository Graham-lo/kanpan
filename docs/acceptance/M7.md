## 2. 为什么不是改渲染器、也不是再覆写一遍 touches

两条绕不过去的现实：

**一、`touches*` 已经被占了。** M4 的 `ChartView+Gesture.swift` 在 extension 里覆写了
`touchesBegan/Moved/Ended/Cancelled` 四个方法。Swift 不允许在第二个 extension 里再覆写
同一个方法，而 `ChartView.swift` 是禁区不能改。所以画线这层走
**`DrawingOverlayView`**：一个盖满图区的透明子视图，触摸先到它手上，它判断这一下是不是
画线动作——**不是的就原样转发回 `ChartView.touchesBegan/Moved/Ended`**。于是拖图、捏合、
甩、长按十字线、双击复位全都照常（A7.8 就是这么成立的，单测两条钉着）。

**二、选中态没地方存。** `ChartState` 是纯值类型、没有 `selected` / `pending` 字段，
渲染器也是禁区。真要画琥珀色高亮和两个手柄，只能改这两处之一。所以同一个覆盖层顺手
把「当前选中的那条 + 两个手柄 + 半截线的琥珀点 + 跟手的虚线预览 + 读数胶囊」画掉，
`draw(_:)` 里裁到图区矩形内。代价是覆盖层在 `crossLayer` 之上，十字线和选中线同时
出现时选中线压着十字线——这是本轮唯一的叠放顺序差异，原型里这两者不会同时出现。

覆盖层的重绘靠一条**私有 `CADisplayLink`**，只在「有触摸被画线层接管 /
`gesture.touches` 非空 / `animation != nil`」三种情况下转，手一松就停——A3.12 的
「静止 CPU < 1%」不受影响。

## 5. 原型 / 任务书打架的地方

规矩是「原型即规格，冲突以原型为准并说明」。这一章分歧多，十二处逐条记，**每条都已经
定了并落地**：

**① 画线态下还能不能拖图：能。这条不取原型。**
原型 `chart.js` 的 `pointerdown` 里第一句就是 `if (this.drawMode) { mode = 'draw'; return }`
——进了画线态，拖图和缩放整个停掉。但任务书 A7.8 和 §10.8 都写死了「画线态下单指拖图、
双指缩放照常，只有「点」才是落笔」。**取任务书。** 原因是触摸屏和鼠标不是一回事：网页上
有滚轮可以缩放，手机上要是画线时不能拖图，用户想把线画到屏幕外的位置就完全没辙。
实现就是那条 `按下到抬起 < 200ms 且位移 < 4pt` 的判据（`drawTapMs = 200`，位移直接复用
M4 的 `Chart.panSlopPt = 4`，两处正好是同一个数）。落笔那一下还要把 M4 的轻点 / 双击分支
掐掉（`gesture.mode = nil; gesture.lastTapMs = 0`），否则「点两下画趋势线」会被当成双击复位。

**② 趋势线延不延伸到图边：不延伸，取原型。**
A7.2 写「线两端延伸到图边」，原型 `drawDrawings` 只画 `x1,y1 → x2,y2` 这一段，而且
`hitDraw` 的命中用的是 `distSeg`（线**段**距离，不是直线距离）。**取原型。** 两个理由：
一是延伸之后命中要跟着改成直线距离，M1 已经交付的 `distSeg` 和它的单测全得推翻；
二是渲染器是禁区，改延伸必须动 `ChartRenderer.swift`，会撞 A3.11 的 176 张基线。
真要延伸，是一个独立的小改动，写在最后一节。

**③ 水平线的价格标签：画在图内右侧，不是右轴胶囊。取原型。**
A7.3 要「右轴出价格胶囊」，原型是在 `(plotW-4, y-3)` 右对齐画一个 `fmtNum`，贴着图区
右边缘的**里侧**。**取原型。** 右轴是渲染器画的（禁区），而且右轴上已经有最新价胶囊，
再叠一个画线胶囊两者会打架。原型这个位置离右轴只差几个点，读数效果是一样的。

**④ 落点吸不吸价格：吸。这条不取原型。**
原型的 `point()` 只把时间吸到根，价格一直跟着手指。A7.2 和 §10.8 都明写「磁吸开时点吸到
最近 K 线的 OHLC」。**取任务书**，而且 M4 的十字线磁吸（`nearestOHLC`）已经是这么做的，
同一个磁吸开关下两处行为必须一致，否则用户会觉得开关坏了。

**⑤ 手柄画 r=5、命中半径仍是 12pt。**
§10.8 写「手柄直径 22pt」，原型 `handle()` 画的是 `r=5` 的圆（直径 10px）。**画取原型、
命中取任务书**：视觉上 r=5 的小圆点干净不挡线，命中半径用 M1 的 `Chart.hitHandlePt = 12`
（等效 24pt 的触摸靶，比 22pt 还宽松一点）。也就是说「22pt」这个数落在**可点区**上，
不落在**画出来的圆**上——这是唯一说得通的读法，画一个 22pt 的实心圆会把线头全糊住。

**⑥ 半截趋势线的预览：单指移动就实时跟随，落点在抬手那一刻。**
§10.8 既要求「只有「点」才是落笔」，又要求「第一点落下后手指移动时预览线实时跟随」。
触摸屏上这两条只有这样才能同时成立：**第一点之后**，单指按下即接管为「瞄准」，移动时
预览跟手，抬手落点（双指仍然是捏合）。第一点本身严格按 ① 的 200ms/4pt 判据。
也就是说 ① 的「只有点才是落笔」我按**第一点**执行，第二点让位给「预览实时跟随」。

**⑦ 画完自动松开工具：取原型（任务书没写）。**
原型 `placePoint` 里画完一条就 `this.drawMode = null`，底栏那个按钮跟着弹起来。任务书没提
这件事。**照抄原型**：连着画三条就点三次工具，比「画完还举着笔、下一次误触就多一条线」安全。

**⑧ 拖动时不吸附。取原型。**
原型 `pointermove` 拖端点时不走 `point()` 的吸附。**取原型**：落笔时吸是帮你对齐，
拖动时吸会让你永远微调不了那最后两个像素——拖动就是用来精调的。

**⑨ 撤销 / 重做放提示条右端，不进底栏。**
A7.1 的底栏钉死四项（趋势线 / 水平线 / 删除 / 完成），原型的 drawbar 也正好这四个。
但 A7.6 要能撤销。**底栏取原型的四项**，撤销 / 重做两个箭头放在 §10.8 那条提示条的
右端——提示条本来就只有一行字，右边空着。

**⑩ 提示文案：取任务书的常驻两态，不取原型的瞬时 toast。**
原型是弹一下就消失的 toast（「点两下落两个端点」/「点一下放一条水平线」），§10.8 要的是
「点两下画一条趋势线」→ 落下第一点后改口「再点一下」的**两态提示**。**取任务书**：
toast 飘走之后第二点该怎么落就没人告诉你了。水平线那句任务书没写，我按同样的口气补了
「点一下画一条水平线」。

**⑪ `DrawStore` 放在 KanpanCore，不是 §4.2 写的 `KanpanData/Store`。**
`KanpanData/` 这一轮是禁区。画线存的是纯值（时间 + 价格），不碰网络层任何东西，放 Core
反而能被 `make core-test` 直接盖住磁盘往返。位置（`Application Support/kanpan/draws.json`）
和 §4.2 的表一致。以后要挪到 `KanpanData/Store` 是纯搬文件。

**⑫ 覆盖层压着十字线。**
见第 2 节：选中态必须有人画，而渲染器是禁区。原型里十字线和选中线不会同时出现，
所以谈不上冲突；本实现里两者同时出现时选中线在上。

## 6. 你要验的

真机上按第 4 节那八行走一遍。第 3 节那 41 条（core 19 + 命中 15 复核、chart 22）
每次 `make core-test` / `make chart-test` 全跑，不需要你逐条点。第 5 节十二处分歧
都已按上面定死并落地，不同意哪条直接说，我改回去——尤其是 ②（趋势线不延伸到图边）
和 ③（水平线标签不在右轴），这两条是为了不动渲染器才取的原型，你要是想要任务书那个
