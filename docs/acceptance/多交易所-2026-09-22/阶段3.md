# 多交易所 阶段 3：接入 Coinbase 现货（客户端 + kanpan-api）

日期：2026-09-23。提交：`daaa3b0`（接入）、`e5beef2`（部署时发现的复盘 worker 崩溃修复）。

## 改动

客户端（`KanpanNetwork/Coinbase/`，交易所专属代码只在这个目录，`check-venue-isolation.sh` 守着）：

- `CoinbaseProvider`：REST K 线每页 350 根并行翻页；秒 → 毫秒、字符串 → 数值、降序翻成升序。
  原生 9 档周期，`3m←1m`、`12h←6h`、`1w / 1M / 1y←1d` 由上层聚（能力位声明）。
- `CoinbaseWS`：`heartbeats` + `market_trades` / `ticker`，5m 另订 `candles`；看门狗与币安同样分层
  （连心跳都没有 → 重连；连上后迟迟没有第一帧行情 → 重连；第一帧到过之后行情静默算合法）。
- `CoinbaseEndpoints`：直连 `api.coinbase.com` / `advanced-trade-ws.coinbase.com`；网关走 kanpan-api
  的 `/v1/market/raw/*?source=coinbase` 与 `/v1/market/stream?source=coinbase`。
- `CoinbaseRateLimiter`：保守 10 次/秒。`CoinbaseDTO`：只收美元计价、在线、现货、非只读的币对，类型标 COIN。
- `VenueRegistry` 加 coinbase 一行；搜索时代号去分隔符再比，`BTC-USD` / `BTC/USD` / `btcusd` 都能搜到。

服务端（`Backend/kanpan-api/src/venues/`）：

- `coinbase.rs`：REST 原样透传，只放 `products`、`products/<id>`、`products/<id>/candles`、
  `products/<id>/ticker` 四条路径与已知查询参数，品种表缓存 15s；推送 hub——所有手机共享一路上游，
  按引用计数增删订阅，上游断 / 沉默自动重连。
- `okx.rs`：原 `market_meta.rs` 里的持仓量替身挪过来。挂在 `/v1/market/` 下，不占 Caddy 归 Python 网关的 `/market/`。
- 复盘：`review_market` 取 Coinbase K 线（8h / 3d 服务端聚）；`review_worker` 删掉 okx 分支，逐笔按
  记录自己的交易所取；白名单只收 `binance | coinbase`。
- 提醒：为 `coinbase/spot` 单开一条 `market_trades` 订阅，服务端拼一分钟 K 线评估；深链带交易所前缀
  （`hkline://drawing/coinbase/spot/BTC-USD/<id>`），通知标题写 `BTC/USD`。

## 假设与边界

- Coinbase 只接现货（美元计价）。没有持仓量、资金费率、结算、主动买卖统计——这些由能力位关掉，界面写「—」（阶段 4）。
- 透传只做公开行情，不带任何鉴权头；路径与参数白名单之外一律 404 / 400，不当通用代理。
- 服务端 `/v1/capabilities` 不参与：客户端交易所与能力全部在本地 `VenueRegistry` 定死（见阶段 1 收尾）。

**部署后发现的既有崩溃**：`kanpan-worker` 在 17:18 后反复 panic（`NaiveDateTime` 溢出，
`sqlx datetime.rs:56`）。查下来不是这次改动引入：`provider_budgets.blocked_until` 列默认 `'-infinity'`，
16:54 那次复盘部署（`backup-p37-review-20260923-165453`）起每次取预算都把它解成 chrono 时间而溢出，
17:07、17:12、17:18 各崩一次，由 systemd 拉起后再犯，事务回滚导致这张表一直是空的。
修复 `e5beef2`：SQL 里 `greatest(blocked_until,'epoch')` 再读，语义不变。先推 `main`，再按同一流程
部署（同一份备份目录里已有部署前的旧二进制），`cargo build --release` 约 155s，17:25:23 两服务重启。

之后另一个窗口 17:39:59 部署了 P3.8（`backup-p38-import-20260923-173503`），它是从包含上述两次提交的 `main` 打的包。
