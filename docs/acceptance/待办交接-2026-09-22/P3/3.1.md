# P3.1 验收报告：提醒补齐三种（价格 / 复盘到点 / 自选五分钟波动）

规格：`docs/待办交接-Codex-2026-09-22.md` §3.1。提交：`P3.1 提醒补齐三种：随手价格提醒、复盘到点提醒、自选五分钟波动`（见 `git log --grep 'P3.1'`）。

## 做了什么

### 纯价格提醒 `.price`
- 提醒总表（`Kanpan/Kanpan/Alerts/AlertListPage.swift`）的面板页眉右上角加了「新建」。页眉的动作位是 `PanelChrome.swift` 新增的 `PanelSheetAction`，别的面板以后也能用。
- 表单 `Alerts/PriceAlertForm.swift` 只有三样东西：
  - 品种，默认当前品种。
  - 价格，用手动输入框、等宽数字，不用步进器。
  - 一行小字「当前 xxx · 高于/低于」，方向按现价自动判定。
- `AlertEvaluator` 放开了 `.price`：一条水平线沿用画线提醒的「穿越即响」判定。服务端 `alerts.rs` 的评估器也认 `kind='price'`。
- 同步对象和画线提醒是同一套（`alerts` 集合），白名单早就有 `"price"`。

### 复盘到点 `.reviewDue`
- 记一笔时填的「到点再看」由 `Alerts/ReviewDueAlerts.swift` 折成一条 `.reviewDue` 提醒。它会进总表、进同步。
- 服务端评估器每轮刷新时，把 `due_at<=now` 的那些置为 fired 并推送，深链是 `hkline://review/<id>`。本机的日历通知保留，作为双保险。
- 到点响过之后，这条提醒在总表里留一天，然后自动清掉。点它会直接定位到那条复盘记录。
- `Alert.swift` 里那句「本轮走本地排程」的注释已经改掉。
- 服务端迁移 `0018_alert_due.sql`：`alert_watches` 加了两列可空列 `due_at` 和 `review_id`。

### 自选五分钟波动
- 提醒总表顶部新增：
  - 「自选波动提醒」开关，默认关闭。
  - 「五分钟涨跌超过 [1.5] %」，手动输入，范围 0.1–50。
  - 两项都是同步设置（`settings/chart` 里的 `watchMoveAlert` / `watchMoveThreshold`）。客户端的 `PrefsFieldPlan` 和服务端的 `sync_validation.rs`、`contract/settings-fields.json` 一起对齐，`make sync-contract` 跑下来没有差异。
- 判定只有一种，客户端 `KanpanCore/.../WatchMove.swift` 和服务端 `watch_move.rs` 逐字对应：
  - 五分钟涨跌 = 现价 ÷ 五分钟前那根 1m K 线的收盘价 − 1。两端用的是同一个上游（币安 1m K 线流）。
  - 有缺口时这一口不判，既不响，也不把状态记成「已回到阈值内」。
  - 同品种、同方向、同一个对齐的五分钟窗口只响一次；要先退回阈值以内才会重新上膛。
- 前台响的时候：通知 + 震动 + 一条「BTC 五分钟涨 2.00% · 查看」浮条，点「查看」直接跳到该品种。
- 后台由服务端推送。

## 判断
- 波动的「五分钟」按对齐的五分钟窗口去重，不按「上次响后五分钟」去重。这样两端在不共享状态的情况下各自判定，结果也一致，同一个窗口里前台和后台最多各响一次。
- 价格提醒不单独做一个「方向」选项：方向按现价自动判定，用户只填一个价。
- 到点提醒响过之后在总表里留一天再清，这样用户点通知进来时还能看到它。
- 用 UI 用例抓到过一个问题：启动时没有把自选交给波动监视器，没登录的人开了开关也永远不响。已经修掉，`boot()` 把自选同时交给报价簿和监视器。
