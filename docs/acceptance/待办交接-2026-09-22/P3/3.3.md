# P3.3 验收：锁屏实时活动（客户端）

规格见 `docs/待办交接-Codex-2026-09-22.md` §3.3。服务端那一半早已上线：心跳 60s、stale 150s、八小时收场。这一节只改客户端，**不需要部署**。

## 做了什么
- **活动的数据格式**：`KanpanCore/Sources/KanpanCore/Alerts/AlertActivity.swift`。
  - `AlertActivityState` 和服务端 `live_activity.rs` 推的 content-state 字段一一对应（price / change / line / distance / state / firedAt / updatedAt）。
  - 距离的算法也和服务端一致：`(现价 − 线价) / 线价`。
  - `AlertActivityAttributes` 包含品种、同步 id、线种、小数位、红涨绿跌。
- **控制器**：`Kanpan/Kanpan/Alerts/AlertActivityController.swift`。
  - 一台设备只挂一块活动。盯另一条提醒时，先收掉手上那块；再点同一条就是不盯了。
  - app 在前台时，用报价簿和图上逐笔的价自己更新活动，最多五秒一拍，**不依赖 APNs 密钥**。
  - `staleDate` = 150s，到点后系统标成过期，锁屏写「价格已停更」。
  - 推送 token 交给 `POST /v1/devices/push-token`，参数 `kind=liveActivity`，带 `activityId` 和 `alertId`（`alertId` 就是同步 id `binance/usd_m/<S>/<id>`）。
  - 活动收起时调 `POST /v1/devices/live-activity/end`。
  - 以下情况会跟着收：提醒被删、被暂停、换账号。提醒响了则最后写一拍「已触发」再收。
  - app 被杀后重开，会把锁屏上还挂着的那块接回来继续更新。
- **锁屏和灵动岛的界面**：`Kanpan/KanpanWidget/AlertLiveActivity.swift`，挂在现有小组件扩展里。显示品种、价格、24h 涨跌、「离提醒价 x%」；已触发时写「已触发 价」；过期时写「价格已停更」。
- **入口**：提醒总表里每条生效中的提醒，行尾多一颗「盯一个」按钮。点了变成实心的「盯着」，再点一次取消。
- `Info.plist` 加了 `NSSupportsLiveActivities`。账号桥加了 `submitActivityToken` / `endActivity`，只在登录时上传。

## 测试
- `make core-test` 全绿，含新的 `AlertActivityStateTests`：
  - 距离与涨跌的文字
  - 空值写「--」
  - 服务端推送 JSON 的解码
  - 编解码往返
- 模拟器 p3（iOS 26.5）上跑 `AlertsFlowUITests.testWatchingOneAlertPutsItOnTheLockScreen`，**通过**，用时 150 秒。流程如下：
  1. 在总表里新建一条 BTC 12345 的价格提醒，点「盯一个」，按钮变成「盯着」（`3.3/01-提醒行盯一个.png`）。
  2. 锁屏，锁屏上出现一块活动：BTC、现价 86601.0、+1.08%、离提醒价 +601.51%（`3.3/02-锁屏实时活动.jpg`）。第一次锁屏时，系统会弹出它自己的「允许 Hkline 的实时活动？」。
  3. 回 app 跟价约 14 秒后再锁屏，数字变了：`+1.77% / 离提醒价 +605.26%` → `+1.87% / 离提醒价 +605.99%`（`3.3/03-锁屏价格更新.jpg`，用例日志里有 `P3.3 锁屏价` 这一行）。
  4. 回 app，左划删掉这条提醒，再锁屏，那块活动已经收起（`3.3/04-删提醒后收起.jpg`）。
- `xcodebuild build-for-testing`（模拟器）通过。

## 判断
- 「离提醒价」的正负按服务端既有的定义：现价高于线为正。客户端和服务端推的必须是同一个数，否则前台和后台两条路会在锁屏上互相改写。
- 活动的界面不加任何按钮。它只是用来看的，操作都在 app 里的提醒总表做。
