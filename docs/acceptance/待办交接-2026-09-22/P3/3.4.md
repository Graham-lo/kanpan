# P3.4 验收：Handoff

规格见 `docs/待办交接-Codex-2026-09-22.md` §3.4。

## 做了什么
- **`ChartHandoff`**（`Kanpan/Kanpan/Main/DeepLink.swift`，和深链解析在同一个模块）
  - activity 类型为 `com.mdd.kanpan.chart`。
  - userInfo 只有 `symbol` 和 `interval` 两个字符串。
  - 接力时把 userInfo 拼成 `hkline://symbol/<S>?interval=<i>`，再交给 `DeepLink.parse` 按同一套规则认。
  - 认不出来就什么都不做，品种名的大小写和字符约束与深链一致。
- **行情页登记**：`MainScreen` 在停在行情页时挂 `.userActivity`，内容是当前品种和周期，`isEligibleForHandoff = true`。离开行情页就不再登记。
- **接力入口**：`KanpanApp` 加 `.onContinueUserActivity`，收到后交给 `DeepLinkRouter`。之后的路径和通知点击、桌面快捷入口、`.onOpenURL` 完全相同，没有另开跳转。
- **`Info.plist`**：加 `NSUserActivityTypes`。

## 测试
两台模拟器之间做不了 Handoff：模拟器没有 iCloud 设备间的接力通道，同一个 Apple ID 的两台模拟器也不会互相出现在 Dock 或切换器里。按规格的备选方案，改用单测覆盖「NSUserActivity 序列化 → 深链」这一段。

- `make deeplink-test`：14 条全部通过，其中新增 `ChartHandoffTests` 3 条。
  - 品种加周期原样接力。`1M` 和 `1m` 的大小写不丢，`1000PEPEUSDT` 这种以数字开头的品种也能接。
  - 把 userInfo 按属性列表编解一次，模拟系统接力时的传输形态，之后仍然解析出同一条 `.symbol`。
  - 缺品种、品种带斜杠、类型不对时一律返回 nil；只有品种没有周期时，只打开品种。
- `xcodebuild build-for-testing`（模拟器）通过。
- 2026-09-23 拆分后在 origin/main `30bf1b4` 上重放复验：`make deeplink-test` 14 条（2 组）全过；`make build DEVICE='iPhone 16 Pro'` 成功（exit 0）。
- 本项只动深链模块、`KanpanApp`、`MainScreen` 一处修饰符和 `Info.plist`，不碰分享；`ShareFlowUITests` 随 3.5「回给他」一起跑（那一项才改分享流程）。

## 判断
- userInfo 里不放皮肤、指标、画线这些本机状态。接力的那台设备按它自己的布局打开同一张图，和「发给朋友」的规则一致。
- 没有另写一条跳转逻辑。Handoff 只是深链的又一个来源，这样同一个「打开 BTC 的 4 小时图」在通知、桌面图标、接力三个入口的行为完全一样。
