# P1 返工 2 · 小额盘口档位可见

基线：origin/main `90a6e80`；工作树 `/Users/mdd/zhk/kanpan-p2`（分支 `p2-fixes`）。返工 1 为 `47d3705`。

问题：返工 1 的十行几何是对的，但柱长按「数量 / 十档最大数量」线性缩放，碰上一档大单时其余档位不足 1pt，肉眼看像只有一两行。

## 改动（只含三份文件 + 本报告）

- `KanpanChart/Sources/KanpanChart/ChartRenderer+Depth.swift`：柱长改为 `min(64, max(2, 64 × sqrt(数量 / 十档最大数量)))`。开方压缩大单与小单的差距，2pt 下限保证极小挂单也看得见。行高 6pt、间隔 1pt、不透明度 0.55、上卖五下买五、跟随涨跌色、整架夹在主图区内，这些都没变。零数量、非法价量在 `OrderBook.init` 里就被滤掉了，缺档仍然留空，不会被 2pt 下限画成假挂单。
- `KanpanChart/Tests/KanpanChartTests/ExternalChartTests.swift`：密集十档回归改为断言开方比例（`64·√(2/10)`、`64·√(6/10)`），极小挂单正好 2pt，最大 64pt，全部 ≥2pt；另加一条：零数量档不出行。颜色、行距、夹边的原断言保留。
- `Kanpan/KanpanUITests/ChartFoundationUITests.swift`：新增 `revealChartControl(_:)`，负责在图表面板里滚动找控件；新增 `testDepthLadderVisibleAtBothIntervals`，用真实 BTC 行情打开「盘口」，分别在 1h 和 1m 下断言探针 `renderedDepthRows == 10`，截图附到结果包里，关掉后绘制归零。时间上限 420 秒：第一次跑时本机负载约 150，滚动找「盘口」就花了约 110 秒，被 180 秒上限压线杀掉，用例逻辑本身已经走到两张截图。放宽后重跑用了 188.6 秒，通过。
