### 4.5 跨设备并发与同步冲突回归 —— 完成，并修了一个产品 bug（`8251f5b`）

- **做了什么**：新用例 `AccountPreferenceSyncUITests.testConcurrentEditsOnTwoDevicesConvergeToTheNewest`。
  - 两台「设备」登录同一个测试账号，一台扮手机、一台扮平板（`KANPAN_TEST_DEVICE_KIND`）。
    **偏差**：交接书写两台模拟器；机器纪律是一个窗口同一时刻只开一台，所以在同一台 iPhone 16 Pro 上用两份独立档案（`KANPAN_PERSISTENCE_PROFILE`，各自的设备 id、偏好、账号存档与同步队列）轮流启动来扮两台。「同时改」是用各自暂停自动同步、改完先不推来造出交错的时间戳，效果等同于两台并发离线编辑。
  - 两台同时改设置（皮肤 / 深浅）和自选，都冷启动之后看是否收敛到较新的那份。
  - 收敛后 A 再改一次，B 能收到，证明队列不堵。
- **复现到的 bug**：
  - 已登录的设备每次冷启动，先装访客档案，再 `claimGuest` 认领它，并把访客那份整份当成「导入批次」记进同步队列。
  - 接下来脏标识那一步，会把这个人自己的全部非默认设置以当下时间重记一遍。
  - 于是最后冷启动的那台，总能盖掉别的设备更晚的改动。
- **修法**：`PersonalSyncCodec.guestImport` 只导入访客新带进来的东西。
  - 设置与画线偏好只在确实「采用访客那份」时导入。
  - 其它集合只导入访客有、账号原来没有的对象。
  - 调用点在 `AppAccountBridge.prepare` 的认领段。
- **怎么验的**：
  - SwiftPM 单测 `GuestImportTests` 三条（`make account-codec-test`）：
    - 冷启动不再生出操作；
    - 反例证明断言咬得住；
    - 首次登录照旧导入访客带来的设置与自选。
  - UI 用例在 rerun5 通过，用时 358 s。
  - 截图 `P4/4.5/`：
    - B 本地改完、还没推；
    - A、B 都收敛到同一份：皮肤取 B 较新的「经典」，深浅取 A 较新的「深色」（虽然 B 后推），自选 {SOL, DOGE}、ETH 已删；
    - 之后 B 仍能收到新改动。
- **只覆盖到的**：画线的并发改在同一条用例里没有单独做。画线走同一个同步队列、同一套 LWW 字段合并，服务端 `tests/accounts.rs` 覆盖了两人同 id 互不影响。

  - 那条 stash 仍在列表里，原封没动；别的工作树没受影响。
  - 此后推送一律「先提交，再 fetch / rebase / push」，不再用 stash。
- **机器资源**：全程只用 iPhone 16 Pro 一台模拟器，重活都经 `machine-guard`，同一时刻只跑一个。
