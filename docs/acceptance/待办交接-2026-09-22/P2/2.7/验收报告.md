# P2.7 验收报告：提示统一成一条 `say`，所有破坏性操作可撤销

规格：`docs/待办交接-Codex-2026-09-22.md` §P2 第 2.7 行。要求：只保留带撤销的 `say`，`PanelToast` 改成转发；删自选、删记录、移分组、恢复默认、清缓存都要能撤销。

## 做法
- 新增 `Kanpan/Kanpan/Main/ToastCenter.swift`，全 app 只剩这一条提示：
  - 它画在一扇独立的透明 `UIWindow` 里，层级 `.alert + 1`。所以半屏面板、复盘本、提醒总表这些 sheet 或 fullScreenCover 盖着的时候，提示和「撤销」按钮仍然看得见、点得到。原来需要 `PanelToast` 就是因为宿主那条提示会被这些层盖住。
  - 这扇窗只在「带动作的提示条」那一块接手势，其余地方全部穿透。它不抢 key window，键盘和读屏焦点都留在主窗口。
  - 规则沿用原来的 `say`：同一时刻只有一句，新的顶掉旧的。不带动作停 1.6 秒，带「撤销」停 5 秒。
- `MainScreen.say` 改成转发给 `ToastCenter`。`PanelToast`、`PanelToastLayer` 以及设置、图表、周期条三处的 `.panelToast(store)` 都删掉了。
  - 面板里 store 发出的提示（`onStoreNotice`）改为一律转发，面板开着时也一样。
  - 这相当于规格里说的「PanelToast 改成转发」。区别是转发放在 store 这一层，不再额外留一个空壳视图。
- 五类破坏性操作的撤销：

| 操作 | 位置 | 撤销方式 |
|---|---|---|
| 删自选 | 自选页（原有）、板块品种列表 `SectorSymbolList.unfavorite`（新增） | `restoreFavorites` 按原分组、原位置放回 |
| 删记录（作废复盘记录） | `ReviewFeature.voidRecord` → `holdVoid` | 作废操作在撤销窗口内**扣在队列里不发**，窗口过了才同步到服务端。撤销时直接从队列拿掉，服务端从头到尾不知道 |
| 移分组 | `FavoritesView.assign(_:to:)`、`SectorSymbolList.move` | 移动前给每只品种拍一张快照（原分组），撤销时逐只放回 |
| 恢复默认 | `SettingsPanel.resetAll`（原来已有撤销） | 保持不变，提示改走同一条 |
| 清缓存 | `PrefsStore.clearCacheLater()` | 延迟提交：先提示「已清缓存」，5 秒窗口过了才真的清。撤销时取消这个待办任务，缓存原样保留 |

## 测试
- UI（自克隆模拟器 p2，iPhone 17 Pro，iOS 26.5）：`FavoritesUndoUITests` 三条全部通过，见 `logs/ui-test.log`。
  - `testRemovingAFavoriteOffersUndoAndPutsTheRowBack`：原有用例，现在走 ToastCenter。
  - `testClearingTheCacheCanBeUndone`（新增）：在设置面板**开着**的情况下点「撤销」。这证明提示压在面板之上，而且点得到。
  - `testRestoringDefaultsCanBeUndone`（新增）。
- 复盘（xcodebuild，模拟器 p2）：`ReviewFeatureSyncTests` 16 条全部通过，见 `logs/review-test.log`。新增两条：
  - `testVoidingARecordCanBeUndoneBeforeItIsSent`：撤销之后服务端一个 `/void` 请求都没收到，记录还在。
  - `testAVoidIsSentOnceTheUndoWindowPasses`：窗口过了之后，`/void` 恰好发出一次。
- 设置包：`swift test` 全包 131 条全部通过，见 `logs/settings-test.log`。其中新增「清缓存」一组两条：五秒内撤销时缓存原样还在；不撤销时窗口一过就真的清掉。
- `xcodebuild build`（generic iOS Simulator）通过。

## 判断
- 撤销窗口统一定为 5 秒，和提示停留时间一致，提示消失的那一刻就是撤销机会没了的那一刻。
- 作废记录没有用「先发出去，撤销时再发一条恢复」的办法，因为服务端没有「取消作废」接口。扣在队列里不发最干净，而且不用改服务端。
- 延迟窗口里如果 app 被杀，作废操作仍然留在本地队列里，下次同步照常发出，不会丢。清缓存的待办任务则会丢失，效果等于用户撤销了，属于安全的一侧。
