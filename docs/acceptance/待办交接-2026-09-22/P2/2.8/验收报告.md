# P2.8 验收报告：最新价胶囊按涨跌闪 150ms，顶栏大字逐位滚动，「减少动效」下全关

规格：`docs/待办交接-Codex-2026-09-22.md` §P2 第 2.8 行。

## 做法
- **胶囊闪一下**：
  - `ChartView.adopt` 每收到一次新状态就调 `flashIfTicked`。只有「同一只、同一周期，末根收盘价动了一口」才算数：要么末根被改写，要么刚开出新的一根。换品种、换周期、整段历史被换掉，都不闪。
  - 算数时，`ChartRenderer.priceFlash` 置成这一口的方向，只重画 live 层，150ms 后清掉再画一次。
  - 连续跳价时，新的一口会取消上一口的收尾任务，重新计时。
  - 闪的时候：胶囊底色换成这一口的方向色，再叠一层 32% 白提亮。涨的一口亮红、跌的一口亮绿，哪怕这根 K 线整体是反方向的。看盘沿用红涨绿跌。
- **顶栏大字**：`TopBar.PriceRow` 的最新价用 `.contentTransition(.numericText(value:))` 加 `.snappy(0.22)`，只有变了的那几位滚动。
- **减少动效**：
  - 胶囊：`UIAccessibility.isReduceMotionEnabled` 为真时直接不闪。
  - 顶栏：读 `accessibilityReduceMotion`，打开时用 `.identity`，不加动画，直接换字。
- `priceFlash` 不属于 `ChartState`，所以不参与 `sameFrame` 的比较，也不会被存下来。

## 证据（模拟器 p2，iPhone 17 Pro，iOS 26.5，Debug，BTCUSDT 1h 实盘推送）
录屏用 `simctl io recordVideo`，用 AVAssetImageGenerator 按 33ms 抽帧，再裁出胶囊区和顶栏价格区。

**正常情况**
- `recording-normal.mp4`：5.8 秒。
- `frames-capsule/`、`frames-price/`：取其中 0.99–3.17 秒这 2 秒多的 67 帧。
- `capsule-color-timeline-normal.txt`：逐帧统计胶囊区饱和像素的平均色。
  - 平时的底色是 (233,98,105)，这根 K 线是红的。
  - 1122–1221ms：(242,151,156)，涨一口，亮红，约 4 帧 ≈ 150ms。
  - 3002–3134ms：(136,210,158)，跌一口（86432.0 → 86431.9），亮绿，约 5 帧。
  - 4587–4653ms：又涨一口，亮红。
  - 每次闪完都回到原底色。
- `capsule-up-tick-flash.png`：涨一口，逐帧对照。
- `capsule-down-tick-flash.png`：跌一口，逐帧对照。
- `top-price-numeric-roll.png`：86,431.9 → 86,432.0，只有末两位在滚，其余位不动。

**减少动效**（`simctl spawn … defaults write com.apple.Accessibility ReduceMotionEnabled -bool true` 之后重启 app）
- `recording-reduce-motion.mp4`：4 秒里价格变了十几次。
- `capsule-color-timeline-reduce-motion.txt`：124 帧里胶囊底色始终是 (68,188,110)，没有一帧提亮。
- `reduce-motion-capsule.png`、`reduce-motion-top-price.png`：86,419.2 ⇄ 86,419.1 下一帧直接换字，没有滚动的中间帧。
- 验完已把模拟器的「减少动效」关回去。

**其他**
- `xcodebuild build`（模拟器 p2）通过。
- KanpanChart 包 `xcodebuild test`（模拟器 p2）140 条全部通过，见 `logs/chart-test.log`。

## 判断
- 「涨跌」按这一口相对上一口来判，不按这根 K 线的开收来判。规格要的是「跳价的方向」。
- 提亮层用固定 32% 白，三套皮肤都用同一套 AICoin 涨跌色（`kanpan-kline-colors-are-aicoin-only`），不需要按皮肤分别调。
