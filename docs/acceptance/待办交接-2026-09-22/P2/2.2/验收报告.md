# P2.2 验收报告：FrameProbe 接上 DEBUG 入口

规格见 `docs/待办交接-Codex-2026-09-22.md` §P2 第 2.2 行：
- 在 `ChartHost.swift` 的手势开始、结束处加 `#if DEBUG` 打点，Release 不进。
- `Tools/pull-diagnostics.sh` 要能捞到 JSON。

## 改动
- **手势开始的回调**
  - `KanpanChart/Sources/KanpanChart/ChartView.swift`：新增 `onInteractionBegan`，和已有的 `onInteractionEnded` 成对。
  - `KanpanChart/Sources/KanpanChart/ChartView+Gesture.swift`：第一根手指落下时（`gesture.touches` 还是空的时候）调一次。
- **DEBUG 打点**：`Kanpan/Kanpan/Main/ChartHost.swift` 里 `wire(_:)` 下的 `#if DEBUG` 分支。
  - 手势开始调 `ChartGestureFrames.began()`，它会 `FrameProbe.shared.start(label: "图表手势")`。
  - 抬手后再等 1.2 秒才 `stop()`，停下时自动存盘。这样甩出去之后的惯性滑行也算在同一段里。
  - 如果 1.2 秒内手指又落下，就接着同一段采集。
  - `#else` 分支和改之前一字不差，所以 Release 包里零调用。
- **根因修复：帧报告在模拟器上根本存不下来**
  - 第一轮接上以后，`pull-diagnostics.sh` 报「容器里没有 Diagnostics 目录」。
  - 加日志复现后看到：`stop()` 返回了报告，但建目录时报 `NSPOSIXErrorDomain Code=20 Not a directory`，见 `logs/root-cause-ENOTDIR.log`。
  - 机制是大小写冲突：
    - 诊断目录原来是大写的 `Application Support/Kanpan/Diagnostics`。
    - 账号、行情缓存、提醒存档用的都是小写的 `kanpan/`。
    - 宿主盘不分大小写，模拟器进程却按分大小写解析。小写的 `kanpan` 先建出来以后，`mkdir Kanpan` 会被宿主判成「已存在」，模拟器里按分大小写却找不到它，于是失败。
    - 用 `simctl spawn … mkdir` 也能独立复现：`Kanpan/…` 报 ENOENT，`kanpan/…` 能建成。
    - 所以在模拟器上，MetricKit payload 和帧报告一份都存不下来。
  - 修法：`Kanpan/Kanpan/Diagnostics/DiagnosticsStore.swift` 的 `defaultDirectory()` 统一改成小写的 `kanpan/Diagnostics`。
    - 分大小写的真机上，如果老的大写目录里已有东西，第一次用时整个搬过来。
    - `Tools/pull-diagnostics.sh` 改读新目录。新目录没有、老目录有时退回读老目录（真机下载下来的老容器）。

## 验证
- **模拟器 UI 用例**：在自克隆模拟器 p2（iPhone 17 Pro，iOS 26.5）上跑。
  - 用例是一次性的，跑完即删，没有提交。
  - 它在画布上连续横拖三次，每次 0.05 秒按下后拖开，拖完再停 4 秒。
  - 结果 passed，见 `logs/ui-oneoff.log`。
- **取件**：`Tools/pull-diagnostics.sh <UDID>` 捞到了帧报告，已拷成本目录的 `frames.json`，MetricKit 汇总在 `logs/diagnostics.json`。
  - 标签是「图表手势」，共 273 帧，实测 60Hz。
  - 三次拖动的间隔都不到 1.2 秒，所以合成了一段。
  - 表里的「判定 False」说的是这台模拟器的帧预算，不是本项的验收内容。本项只要求「采得到、捞得出」。
- **包测试**：`cd Kanpan/Diagnostics && swift test`，47 个用例全过。

## 判断
- 用户看不到这一项，它只在 DEBUG 包里给我们测帧用，所以不需要装真机。
- 诊断目录改名以后，真机上老目录里的 payload 会被搬过来，不会丢。
