# P2.4 验收报告：自选页切走再回来，差一行半的滚动零头

规格：`docs/待办交接-Codex-2026-09-22.md` §P2 第 2.4 行（审查 C-08）。要求从根因修，并用 UI 用例断言 frame：从自选切到图表再切回来，锚点行的 y 要和离开时一样。

## 根因
- C-08 原来的还原办法：记住「顶上露着的是哪一行」，回来时 `ScrollViewProxy.scrollTo(该行, anchor: .top)`。
- `scrollTo` 只能对到整行，离开时那一行被滚掉的半截零头就丢了，所以回来后整张表差出小半行到一行半。
- `.scrollPosition(id:)` 在 `List` 上根本不回写，已经实测排除（旧注释里有记录）。

## 改动（`Kanpan/Kanpan/Symbols/FavoritesView.swift`）
- `FavoritesRenderedRows.anchorOffset`：记录落脚行时，同时记下它的上沿离列表上沿多少 pt。
- `FavoritesEditSession.topOffset[分类]`：切走或切类时，连同 `topRow` 一起存起来。
- `FavoritesScrollerProbe`：挂在行内容背后的一个空 `UIView`，上窗时沿父视图找到 `List` 背后的 `UICollectionView`（弱引用）。
- 还原分两步：
  1. 先照旧 `scrollTo` 把行对上。
  2. 再由 `alignAnchorPixels` 量出锚点行现在的上沿，按差值直接推 `contentOffset` 补上零头。推的范围限制在表能滚到的两头之内，最多补两次。

## 测试
- `Kanpan/KanpanUITests/PresenterAndStateUITests.swift` → `FavoritesScrollAnchorUITests`：
  - 原用例抽成 `roundTrip(away:leave:)`，判据收紧为两条：顶上那一行是同一只；锚点行 y 的差 ≤ 1pt（原来容差是两行高）。
  - `testFavoritesKeepsTheScrollPositionAcrossTabs`：去「设置」转一圈再回来。
  - `testFavoritesRowKeepsItsPixelAcrossTheChartTab`（新增）：按验收原话，去「图表」转一圈再回来。
- 在自克隆模拟器 p2（iPhone 17 Pro，iOS 26.5）上两条都通过，见 `logs/ui-test.log`。

## 判断
- 像素偏移只在本次使用、同一台设备和同一字号下有效，只补「那一行里的零头」。落到哪一行仍然按品种代号决定，和原注释「存代号不存偏移量」的理由不冲突。
