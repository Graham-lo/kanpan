# P2.15 验收报告：上线 30 天以内的品种名字后面挂一枚「新」

规格：`docs/待办交接-Codex-2026-09-22.md` §P2 第 2.15 行。要求：
- 上线 ≤30 天的品种，在搜索结果和自选行的名字后面加一枚小「新」；
- 用皮肤强调色，字号同分类 chip；
- 不加别的。

## 做法
- **数据**：
  - `ExchangeInfoDTO.onboardDate` → `SymbolInfo.onboardDate`（毫秒，可空）。
  - `SymbolInfo.isNewListing(nowMs:)`：上线时间 ≤ 现在，且距今 ≤ 30 天。预告上线（还没到上线时间）和没有日期的都不算。
- **目录缓存**：
  - `SymbolCatalog.schema` 从 6 升到 7。旧缓存里没有这一列，沿用它的话，升级后一整天搜索和自选里一个「新」都不出。
  - 旧缓存仍然解码得开，这一列为 `nil`。
- **界面**：`Kanpan/Kanpan/Symbols/NewListingMark.swift`，只有一个「新」字。
  - 皮肤强调色。
  - `.scaled(12, .medium)`，和品种页「市场 / 板块」分类筛选同字，并随系统文字大小变化（P2.13）。
  - 不垫底色、不写日期、不给解释。规格写的是「不加别的」，按字面执行，旧稿里的浅底块去掉了。
  - 挂在两处：
    - 搜索页和品种页共用的 `SymbolRowView` 名字后面（搜索结果）；
    - `FavoritesView` 自选行的「BTC USDT」后面。
  - 读屏标签为「新上线」。

## 有意没覆盖的一处
- 「网关」线路下，行情和品种目录走 OKX，由 Python 网关的 `/market/v1/instruments` 转成币安格式下发（`Backend/kanpan-gateway/market_rest.py` 的 `exchange_info`）。转出来的数据里没有 `onboardDate`，所以选了「网关」的人看不到「新」。
- 出厂默认是直连（币安），不受影响。
- 要补上，得让网关把 OKX 的 `listTime` 映射成 `onboardDate`。按项目规矩（后端新功能一律写在 Rust 的 kanpan-api，不再往 Python 网关里补），且本轮的部署授权只覆盖 kanpan-api，这件事留给多交易所模块的品种身份（InstrumentID）阶段一起做。那时 OKX 目录由客户端或 Rust 侧直接解析，`listTime` 顺手带上。
- 截至本提交，InstrumentID（多交易所第一阶段）尚未合入 main，本项按现有 `SymbolInfo` 实现。
