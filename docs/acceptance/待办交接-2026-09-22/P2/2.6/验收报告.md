## 二、死锁试验（`tests/deadlock.rs`）

### 结论

后端的锁顺序约定确实被遵守了，不需要改 `src/`，也就不需要部署。

- 所有写 `sync_objects` 或 `alert_watches` 的路径，都在拿行锁之前先拿 `sync:{owner}`：`sync::push` 直接拿；`alerts::materialize` 只从 `push` 调用；`alerts::record_fired` 在调用 `apply_server` 之前拿。
- `share::send` 按 UUID 从小到大拿 `shares:{uuid}` 这两把锁。

### 跑法

用 `Backend/kanpan-api/ops/test.py` 的同一套流程：在 scorebook-backend compose 的 PG（55432 端口）里临时建库和非属主角色，跑完删掉，不碰 scorebook 的数据。为了省时间，复制了一份脚本到 `/tmp`，把 cargo 参数改成从命令行传入：

```sh
export PATH=~/.rustup/toolchains/1.95.0-aarch64-apple-darwin/bin:/usr/local/bin:$PATH
python3 /tmp/p2conc-test.py --test deadlock -- --test-threads=1 --nocapture
python3 /tmp/p2conc-test.py --lib -- --test-threads=1
```

### 三层证明

**第 1 层 反例**：不拿 advisory 锁，两边以相反顺序取同一对行锁，PostgreSQL 必须判 40P01，而且恰好一边是牺牲者、另一边提交成功。分享链路额外验证了一点：advisory 锁如果不排序（「自己先、对方后」），同样会 40P01。

**第 2 层 正例**：交错方式完全一样，只是两边都先拿约定的 advisory 锁。试验用 `pg_locks` 确认乙确实堵在 advisory 锁上之后，才让甲去拿第二把行锁。结果两边都提交，没有 40P01。

**第 3 层 真函数压测**：不手写 SQL，直接对真实入口并发打 50 轮。一组是 `POST /v1/sync/operations`（和线上 serve 用同样的池子，lock_timeout=5s）对 `alerts::record_fired`（和线上 worker 用同样的池子）；另一组是 A→B 和 B→A 同时 `POST /v1/shares`。

`logs/cargo-test-deadlock.log` 摘录：

```
running 4 tests
test friendship_inserts_deadlock_unless_share_locks_are_sorted ... ok
test mutual_shares_race_fifty_rounds_without_deadlock ... A→B × B→A：50 轮全部成功，用时 5.875560834s，无 40P01
ok
test push_and_record_fired_race_fifty_rounds_without_deadlock ... push × record_fired：50 轮全部成功，用时 3.388203958s，无 40P01
ok
test sync_row_locks_deadlock_without_the_gate_and_queue_behind_it ... ok

test result: ok. 4 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 208.47s
```

前两个用例里的 `one_deadlock_victim` 断言就是第 1 层反例：它们要求 40P01 必须出现，否则用例失败。所以用例通过，本身就证明这套试验抓得到死锁。

**第 3 层的灵敏度（变异试验）**：只用绿灯不能说明压测真的会撞上，所以临时把 `src` 改坏，跑两个压测用例，看完立即 `git checkout` 还原。本提交里没有任何 `src` 改动。日志在 `logs/cargo-test-deadlock-mutation.log`，日志里的行号是在 `deadlock.rs` 头注释加 3 行之前的。

- 注释掉 `record_fired` 里的 `crate::sync::lock`：`第 0 轮 record_fired 失败：ApiError(503, "temporarily_unavailable")`
- 把 `share::send` 的取锁顺序改成 `[who.user,other]`：`第 10 轮 A→B 失败（死锁或锁等待超时都会变成 503）`

也就是说，锁顺序约定哪天被改坏，这组试验会直接红灯。

`cargo test --lib`：157 个全部通过，见 `logs/cargo-test-lib.log`。
