# P2.17 「收盘价」画法 · 验收报告（2026-09-23）

## 改了什么

- `CandleKind` 增加 `line`（显示名「收盘价」），原始值 `line`。
- 主图画法：`kind == .line` 时只画一条收盘价折线，外加最新价胶囊和实时价格线（胶囊跟随「实时价格线」开关，出厂默认开）。
  折线直接复用 AICoin 窄缩放时的收盘线笔触：涨色，线宽 2 物理像素（`refs/aicoin/java/bk/a.java`）。
  所以任何缩放下样子都一样，蜡烛模式缩到最窄时也能和它无缝衔接。
- 价格轴自适应：`PriceScale.priceRange(..., closeOnly:)`。line 模式下可见区间只用收盘价撑，指标、画线、额外价位仍照常并入。
  这照的是 AICoin 收盘线路径不用高低价撑区间的做法（见 `REPORT-candle-axis.md`）。
- 极值标注：line 模式标的是可见区里最高、最低的收盘价，标记落在折线上，不会指向一个图上看不到的影线高点。
- 探针与诊断：line 模式下 `candleXs` 为空；DEBUG 诊断里加了 `candleKind` 字段，UI 用例靠它断言。
- 「图表」面板 `ChartPanel.kinds` 增加第三档「收盘价」，分段控件 id 为 `chart.candleKind.收盘价`。
- 使用手册 `docs/使用手册-2026-09-21.md`：
  - 画法写成三种（蜡烛 / 平均 K 线 / 收盘价），并说明各自行为。
  - 删掉了旧文案里并不存在的「平均 K 线是否用平滑价格」选项。
- 同步值域对账：
  - 客户端 `PrefsCodec` 已经按 `CandleKind(rawValue:)` 解码，新增了三种画法逐个往返的单测。
  - 服务端 `sync_validation.rs` 对 `candleKind` 只校验它是长度不超过 64 的字符串，本来就接受 `line`，所以只补了单测 `every_candle_kind_the_panel_offers_is_accepted`。
  - **服务端 src 未改，无需部署。**
  - `make sync-contract` 重生成后没有差异，因为字段名没变。

## 判断与取舍

1. **十字光标数据框、图例、VoiceOver 的开高低收、最新价胶囊**：仍读真实 OHLC，不改。这和平均 K 线的原则一致：换的只是画法，数值永远是真的。
2. **磁吸**：仍吸附真实 OHLC，和平均 K 线一致。`snapDrawPoint` 刚被另一窗口改过（90a6e80 迟滞），所以没有动它。
3. **横屏画线工作台**：按「用户选了什么就画什么」处理，line 模式在横屏里仍是折线。横屏本来只剥掉主图指标、副图和盘口，不碰画法，所以不用改代码。
4. **复盘图与分享图**：它们用的是同一份偏好和渲染器，自动跟随画法。
5. **阳线实心 / 空心**：在 line 模式下不起作用，但没有因此隐藏开关，免得切换画法时面板布局跳动。
6. **没有新增算法口径类选项**：线的颜色和线宽直接定为 AICoin 的那一套，不交给用户选。
