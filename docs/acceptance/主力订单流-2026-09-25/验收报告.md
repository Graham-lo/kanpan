# 主力订单流 · 并墙、屏内排名、细线 + 签、新四色、详情卡精简 — 验收报告（2026-09-25）

设备：iPhone 17 Pro Max 模拟器（iOS 26.5 SDK）。方案文档：`docs/主力订单流-方案-2026-09-24.md`「图上怎么画」一节最上面两段；
项目记忆：`.project-memory/PROJECT.md`「并墙 + 屏内排名 + 非加密簿深标定」一条。服务端（kanpan-api 的跟踪范围、3 天保留、簿深标定）另一个子代理在做，不在本报告。

## 做了什么

1. **去碎屑**：已结束、且活不过一根 K 线的单先扔，不参与切段与并墙；挂着的单不扔。
2. **并墙**：同侧、同类、价位桶相邻、时间连着的段并成一堵墙；墙要成块（所有段有共同在场的时刻）、最多 5 个桶。
3. **屏内排名**：落在这一屏主图里的墙按名义排，前 6 主、7–18 次、其余底噪；挂着的底噪升成次。
4. **非加密门槛按簿深标定**：T = round125(0.03 × D)，夹 [5 万, 200 万]；簿全到或起订 8 秒定一次，定前不评估。
5. **保留期**：手机端回填与内存 30 天 → 3 天。
6. **细线 + 签，垫在 K 线下面**（用户：「大单不许盖住 K 线」）：订单流先于蜡烛画；主 2 pt（挂着 2.5 pt）100%、次 1 pt 70%、底噪 1 pt 35%；
   墙只画代表价芯线、不铺范围底色，范围用段右端一枚 3 pt 宽的竖括号表达（见下「复验后收口」）；金额签只给主档（最多 6 枚），挂着的贴主图右缘（价格刻度列左侧）、已结束的在结束点右侧，撞了名义小的让；命中带 ≥ 8 pt。图例保留。
7. **新四色**（用户：「是颜色重合了把 K 线覆盖了」）：合约不再用蜡烛涨跌色，见下「颜色」。K 线颜色一律没动。
8. **详情卡精简**（用户：「详情卡不列交易所」）：标题「价位或区间 · 委托买/卖单 · 合约/现货」+ 右上「持续 X」+ 两行键值（总名义金额 / 总数量、开始时间 / 状态）。
9. **切品种不起订**（ETH 卡在「主力 …」180 秒）：根因与修复见下。

## 用户问的：「详情卡为什么只写了一个价」

所以真机上所有卡片都只写单价——是旧包，不是范围那条分支没走到。现在卡片价格跟着段的形态走：
单价位的段写一个价，跨桶的墙写范围，截图两张都有：

- `详情卡-区间-17ProMax.png`（经典深）：「84,200 – 84,500 · 委托卖单 · 合约」、右上「持续 1 小时 38 分」，总金额 75.48M USDT / 总数量 893.92 BTC，开始 09-25 03:52，状态「在场 · 已成交 21%」；

`Palette.orderFlow(bg:)`（KanpanPresentation），按图区底色亮度分深 / 浅两套，不随皮肤、不随红涨绿跌翻：

|---|---|---|
| 合约买 | #5A7DFF 蓝（228°） | #0A78C2 蔚蓝（204°） |
| 合约卖 | #E04BF0 品红（294°） | #8A149F 李紫（291°） |
| 现货买 | #CCE21E 黄绿（66°） | #76850A 橄榄（67°） |
| 现货卖 | #B89CFF 浅紫（256°） | #8566E8 紫（254°） |

- 蜡烛绿在 134°–165°、红在 356°–6°，与两者都差 ≥ 60° 的色相只有 66°–74° 与 225°–294° 两段，四色只能落在这两段里、靠明暗拉开。
  协调方建议过的橙（离红 18°）、#4C8DFF（离绿 53°）、黄（离绿 51°）都过不了「≥ 60°」这条，没采用。
- `SkinPaletteTests`「主力订单流四色：看得见、不和蜡烛撞色、彼此分得开」对六套皮肤种子守着：对图区底 ≥ 3:1；与涨、跌两色色相差都 ≥ 60°；
  同类买卖 ≥ 60°；四色两两 ≥ 25°，不足 45° 的对比度差 ≥ 1.4 倍。
- 透明度：主 100%、次 70%、底噪 35%、墙的范围括号 70%。金额签底是同一线色（85% 不透明），字色由 `orderFlowLabelInk` 在近黑 / 白里取对叠出来的颜色对比度高的那个，
  两个都不到 4.5:1 用纯黑；六套皮肤 × 四色 × 深浅两档都 ≥ 4.5:1（`OrderFlowChartTests` 颜色用例守着）。
- 图例「主力 ▬▬ 买 X · ▬▬ 卖 Y」的色样跟着换成新色。
- `BTCUSDT-1m-局部放大-17ProMax.png`：BTC 1 分钟大单密集处放大，蜡烛实体压在订单流线上面、看得清。
- `ETHUSDT-1m-局部放大-17ProMax.png`：ETH 1 分钟同样放大，蜡烛与均线都在订单流线上面，主档签「76.2M」贴在线上。

## ETH 卡在「主力 …」：根因与修复

复现：BTC 15m → ETH 1m（深链 `hkline://symbol/ETHUSDT?interval=1m`），ETH 180 秒一直是 `phase=loading`、0 条。

- 深链的处理是 `open(linkedSymbol:)` 换品种，紧接着 `pick(interval:)` 换周期，同一帧里对 `MarketModel.switchTo` 连调两次。
- 第二次（ETH 同品种换周期，不是冷切换）会先 `switchTask?.cancel()`，把第一次（冷切换）的任务在开跑之前取消掉（`guard !Task.isCancelled else { return }`），
  而第一次的任务里才有 `if cold { await refreshInfo() }`。第二次不是冷切换，不发 `refreshInfo`。
- 于是 ETH 的品种信息永远不查，`OrderFlowLink.noteInfo` 拿不到 ETH 的品种事实，行情流里「首帧已画｜品种事实 false」之后再没有「起订」。
  （顺带：这条路上新品种的小数位也停在占位值上，没有锁过的品种会用 2 位小数。）
- 修复（`Kanpan/Kanpan/Main/MarketModel.swift`）：冷切换记一笔 `infoOwed`；接手的切换 / `retryHistory` 看到欠着就还（`refreshInfo` + 冷启动口径传给行情流），
  `refreshInfo` 查到当前品种之后才销账。
- 同时起订不再只靠「首帧刚到」等几个一次性时机：`RoutedMarketFeed.forward` 每条转发的行情事件都问一次 `OrderFlowSlot.wantsStart`
  （开着、前台、没在跑、品种非空、首帧已画是这只、品种事实到了）。
- 取证中还发现：XCUITest 的 `app.open(URL)` 在 App 已在前台时偶尔由模拟器宿主强杀重启（SpringBoard「Termination requested by simulator host」），
  重启后冷启动 + 深链走的正是上面这条路，同样卡住；修复后冷启动这条也过（见下 `testSwitchSymbolRestartsOrderFlow`）。
- 验证：`testSwitchSymbolRestartsOrderFlow`（「4b. 切品种后要重新起订」）按 BTC 15m → ETH 1m → ETH 15m → SOL 1m 深链切，每一步 90 秒内要 `phase=ready`：
  BTC 15m 2 秒、ETH 1m 4 秒、ETH 15m 2 秒（这一步正好碰上模拟器宿主强杀重启，走的是冷启动 + 深链，日志先见 BTC 首帧、再见「品种信息 ETHUSDT：到了」→「起订」）、SOL 1m 4 秒，通过。
  修复前 ETH 1m 180 秒 0 条、ETH 15m（冷启动）93 秒 0 条。

## 复验后收口（协调方看截图后的两处）

1. **去掉跨桶墙的范围底色，改成竖括号。**
   - 原来：跨桶墙在范围上铺 10% 段色矩形。经典深 BTC 1 分钟那堵「84,200 – 84,500」铺满了几乎整个图区，读成一层紫雾。
   - 现在：墙只画代表价芯线。范围用段右端一枚竖括号表达（形如「]」）：
     - 宽 3 pt、笔画 1.5 pt，高 = 范围在屏上的高度（整段范围不在主图里就不画，见下「二次收口」）。
     - 颜色同段色，70% 透明度。
     - 右缘离金额签左缘 1 pt。挂着的墙签贴主图右缘，括号就在签左侧；已结束的墙签在结束点右侧 4 pt，括号正好落在结束点上（[结束点, 结束点 + 3]）。
     - 括号 x 按签的名义位置算。签被挤得上下挪位或不放时，括号不跟着动。
   - 只有主档、跨两桶以上、范围在屏上比线高的墙才有括号；被挤成细线的不画。
   - 命中：轻点括号（横向 ±4 pt，触摸放到 44 pt）选中这堵墙；范围里的空白不再算命中。选中后括号在十字线层上用 100% 重描。
   - 范围数字仍在详情卡里（`详情卡-区间-17ProMax.png`）。
   - 诊断 `orderFlowBands` 的 `spanTop / spanBottom` 换成 `bracketX / bracketTop / bracketBottom`（不画时为 null）。图例没动。
   - 截图 `BTCUSDT-1m-经典深-17ProMax.png`（新加）：紫色底没有了，只剩芯线 + 签。
   - **二次收口（协调方选 (a)）**：第一版照定义画，BTC 1 分钟一屏只有几百美元，墙的范围（300 美元级）比主图还高、两端横钩被裁在屏外；几堵挂着的墙签宽相同、括号 x 相同，叠成一根从主图顶到底的竖线，远看像十字线。现在的规则：
     - 括号的上下两端（含横钩）都在主图里才画；任一端出界整枚不画，不裁一截。这堵墙只剩芯线 + 签，详情卡照旧给区间。
     - 同一 x 上仍有两枚纵向重叠的（只可能是屏内的短括号），按排名先立的是名义大的，后一枚不画；不错开 x，签照旧紧贴。

   - 重拍 `BTCUSDT-1m-经典深-17ProMax.png`（06:04，1 分钟）：主图价 84,117 – 84,490。五堵跨桶主墙的范围出了这一屏（83,900–84,400、84,200–84,500、84,400–84,800、83,800–84,200、84,200–84,500），一枚括号都没画，主图上没有贯穿的竖线。

     `testCoinAnkBandsAndDetailCard` 在青苔浅、青苔深、经典深三套上都断言了三件事：画出来的括号上下沿都在 [0, 主图高] 里；同一 x 上不重叠；出屏的跨桶主墙一枚括号都没有。
2. **金额签底色 85%。**
   - 假设：「透明度 85%」按不透明度（alpha = 0.85）理解。本报告里「主 100%、次 70%」「括号 70%」用的都是这个口径。反过来读成「85% 透明」（alpha 0.15）的话，签字对底的 4.5:1 在任意 K 线背景上都保证不了。
   - 注意：这比上一轮的 80% 还不透明 5 个点，不是更透。
   - 实拍：`BTCUSDT-1m-经典深-17ProMax.png`（二次收口重拍）里 56.8M 签后面的阴线实体、`SNDKUSDT-15m-17ProMax.png` 里签后面的最右几根 K 线仍能隐约看出轮廓。
   - 字色 `orderFlowLabelInk`：对「段色 85% 叠在皮肤底色上」的实际签底算对比度，#141414 与白取高的。两者都不到 4.5:1 时退纯黑 #000000。
     新四色里有几种中间亮度的紫 / 洋红（如 #CF09E7），#141414 与白都只有 4.31–4.36，纯黑能过。
     单测覆盖六套皮肤 × 四色 × 深浅两档，全部 ≥ 4.5:1。
   - 签最多 6 枚（`orderFlowLabelMax`），只给主档。撞了照旧名义小的让，挪不开就不放。

## SNDK 簿深标定出的门槛

- 诊断 `SNDKUSDT-1m-诊断.json` / `SNDKUSDT-15m-诊断.json`：`orderFlowThresholds = {usdtPerp: 500000, step: 1}`，`orderFlowBands` 非空（复验时 1m 13 条、15m 18 条；上一轮 3 条 / 11 条；大单数从 17 涨到 107）。
- 500K = round125(0.03 × D)：SNDK 各本簿 ±1% 内的买卖名义合计 D 落在约 1,170 万–1,670 万美元之间（0.03 × D 在 35 万–50 万之间，最近的 1/2/5 × 10ⁿ 是 50 万），在 [5 万, 200 万] 之内；
  原来一律 200 万，SNDK 一条都出不来。
- `SNDKUSDT-参数表-17ProMax.png`：参数表里 U 本位永续一格的默认值就是 500000（右侧 500K 读法），没有「恢复默认」（没改过）；照原样保存不算改动。
- `SNDKUSDT-15m-17ProMax.png`（复验重拍）：六枚主档签（2.1M、1.4M、1.3M…1.2M）都挂在最新价附近，贴主图右缘排开，挤在一起的按名义小的让位上下挪；跨桶的 1.3M / 1.4M 几堵墙签左侧有 3 pt 竖括号；签底 85%，1.4M 签后面最右几根 K 线的实体和影线仍隐约可见。

- 被扔掉的短段不参与并墙，不当两堵墙之间的桥。墙最多 5 个桶：3 天历史会把相邻桶前后接力的段链成一片（真机 BTC 首版一堵 34 桶），用户要的「墙」是一个时刻同时站着的一排挂单。
- 范围写法的小数位按步长算（BTC 步长 100 写整数），价格加千分位，与顶栏、自选一致。
- 挂着的签贴主图右缘（刻度列左侧 4 pt），会盖住最新几根 K 线的一小块——用户定的位置就是「价格轴左侧」，签底是线色 85%，挪不开就不放。
- 签撞了：名义小的让，挪到撞上那枚的上方或下方、离自己的线 ≤ 32 pt，挪不开就不放（而不是缩小字号）。
- 同价叠着（被压细的小单和大单同价）一点，出名义大的那条。
- 状态文案：在场（被吃过的补「· 已成交 X%」）/ 已成交 X% / 已撤；「已成交」要的是比例，所以带百分比。
- 颜色没照协调方举的例子（橙、#4C8DFF、黄）：它们过不了「与蜡烛色相差 ≥ 60°」这条硬约束，硬约束优先。
- 卡片右上的时长放不下时退成短写，不截断标题——标题四段（价 · 方向 · 类）是这张卡的主信息。
- 「签底 85%」「括号 70%」的百分比一律按不透明度读（与线的 100% / 70% / 35% 同一口径），理由见「复验后收口」第 2 条。
- 「主图 plot 矩形」取主图窗格（y 从 0 到主图高，含顶上图例那一条），与金额签夹位用的是同一个矩形。
- 括号 x 按签的名义位置算，签被挤得挪位或不放时括号不动；括号只给跨桶主档，次档和底噪的墙只剩芯线，范围看详情卡。
- 深链的品种信息修复放在 App 里而不是只改测试：通知、桌面快捷入口点进来的冷启动走的就是这条路，是真实用户路径。
