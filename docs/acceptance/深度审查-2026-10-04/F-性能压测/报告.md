范围：渲染热路径（超 8 ms 帧与其热点函数）、行情吞吐与前后台补数、内存（10 分钟以上泡机 + leaks + 磁盘/内存预算）、

- 模拟器只用 **iPhone 16 Pro**（iOS 26.5 模拟器，60 Hz 显示）；所有起编译 / 跑测都经 `scripts/machine-guard.sh run` 排队，同一时刻一个编译。

  `DEBUG KANPAN_TEST_SUPPORT` 两个编译条件——所以 `#if DEBUG` 的诊断代码（如 `ChartView.dirtyReasons`、FrameProbe）在测试包里是活的，

## 二、判为非 bug 的项（及理由，附数字）

- **登录 / 退登 10 轮的 1–2 s 卡顿**：整套复跑（与 G 线走查、编译同时在跑）时两次量到「卡顿 > 100 ms 11 次、最坏 2,014 ms、有两轮 33.9 / 34.3 s」与
  「4 次、最坏 1,178 ms」；机器空下来后同一个包单跑：10 轮 27.0 / 26.9 / 26.7 / 26.8 / 26.8 / 26.7 / 26.8 / 26.9 / 27.0 / 27.0 s，**卡顿 > 100 ms 0 次**
  （09-28 基线约 26.9 s、1 次 113 ms）。判为机器争用，不是产品问题。
- **`testLayers` back=1500 一帧 7.35–7.96 ms**：贵在 30 条合成画线里的大块半透明填充（矩形 / 区间类整片铺满图区），真用户不会在同一屏铺 30 块大填充；
  逐层拆账见 `FScaleBenchTests`。
- **订单流在缩到最小间距时的大面积叠画**：只出现在合成的 2,400 单场景；真数据缩到最小间距时实测屏上带子数为 0，不叠画。
- **订单流竖括号 44 pt 触控宽盖住相邻空白**：按 HIG 最小触控目标设计（F-5 的用例落点已改，不改产品）。
- **分享收件箱、提醒顶满、交易分组、复盘记录**：收件箱有上限、提醒客户端封顶 200 条；交易分组约 1 µs / 条；`ReviewBook` 1,000 条记录 0.096 s——都量过，够快，不改。
- **服务端提醒评估线性扫表**：见上文，单帧 3.47 µs、一分钟真实流量 249.7 ms，约一个核的 0.4%，不建按品种索引。
- **整套复跑时 30×3、面板 ×50、画线进出、泡 5 分钟的卡顿比基线多**：忙时 30×3 最坏 1,056 ms、分析 ×50 七次、泡机最坏 494 ms；机器空下来单跑同一个包：
  30×3 0 次（78 s）、分析 ×50 0 次、图表设置 ×50 0 次、画线进出只剩第 0 轮进横屏 127 ms（基线 321 / 392 ms）、泡 5 分钟 1 次 / 113 ms——全部回到基线或更好，判为机器争用。
- **后台 → 前台补数**：回前台一次 21–22 个请求、头 3–4 s 内发完，与冷启（22 个）相当，不随后台时长涨（后台 60 s 与 180 s 一样），0 失败——是一次有界重同步，不是风暴（详见第三节）。
- **冷启与长时内存**：冷启中位 685 ms（与 09-24 的 683 ms 持平）；12.5 分钟泡机占用 82–114 MB 来回、0 leaks、malloc 节点 +3.3%——没有爬升（详见第三节）。
