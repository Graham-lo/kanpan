### P1-1 一字板价格区间被撑到 −1…+1
- **位置**：`KanpanCore/Sources/KanpanCore/Geometry/PriceScale.swift:128`
- **现象**：可见窗口全同价时（停牌、小币十字星），蜡烛压成正中一条线，价格轴出现负价；高低价里混进 inf 时，整屏退成兜底的 0…1。
- **根因**：退化补边用绝对值 ±1，和价格量级无关；坏数也进了区间。
- **修法**：
  - 补边改成 ±0.1% × |价格|，价格为 0 时才退回 ±1。
  - 高低价、画线价、外部价里的非有限值不进区间。
- **用例**：`PriceScaleTests`
  - 「一字板留白按价格比例：小币不进负价、大币不被撑开」（参数化）
  - 「一字板价格为 0 仍有厚度」
  - 「高低价里的坏数不进区间」
- **提交**：`3588be36`

### P1-2 叠加对比：基准根缺数据时整条对比线消失
- **位置**：
  - `KanpanChart/Sources/KanpanChart/CompareSeries.swift:30`（`baseIndex(from:through:)`）
  - `ChartRenderer+Compare.swift:48`（`compareLines`）、`:65`（`compareAnchor`）
  - `ChartView.swift` 诊断里的 `compareReady`
- **现象**：比价品种在视野左缘那根上没数据（还没上市、停牌、数据没到）时，整条对比线连同它对价格区间的贡献一起消失，往回拖一点又出现。
- **根因**：所有对比线共用主序列左缘这一根当 0% 基准，没有退路。
- **修法**：
  - 每条线在视野内从左缘往右，找自己第一根开盘价有限且大于 0 的那根当基准，和 TradingView 对比模式同口径。
  - 画线、图例、价格区间、诊断计数共用 `compareAnchor` 这一个答案。
- **用例**：`CompareChartTests.compareLineStartsAtFirstAvailableBar`，以及按新口径改写的基准缺价用例。
- **提交**：`40ca8981`

### P3-1 十字线停在末根，末根在跳时读数不刷新
- **位置**：`KanpanChart/Sources/KanpanChart/ChartView.swift:659`（`crossReadsLastBar`），在 `changed(from:to:)` 里调用。
- **现象**：手指按着最后一根不动时，蜡烛在长，读数框和图例停在按下那一刻的价。
- **根因**：只有前后某一方没有十字线时才脏十字线层。
- **修法**：十字线「读末根」时，末根一跳也脏十字线层。读末根有三种情况：
  - 十字线就在末根上；
  - 开着「至今涨幅」；
  - 末根在屏里，参与价格区间：区间一变，横线与右轴读数都得跟着挪。

  往回翻到末根不在屏里、又没开「至今涨幅」时，照旧不脏。
- **用例**：
  - `ChartViewDirtyTests.lastBarTickRefreshesCrosshair`，参数为 onLast / visible / sinceChange
  - 改写后的「往回翻到末根不在屏里时不必重画」
- **提交**：`89983d5e`

### P3-2 十字线跳到第二根手指底下
- **位置**：`KanpanChart/Sources/KanpanChart/ChartView+Gesture.swift:69`（`GestureState.owner`），以及 touchesMoved / Ended 与长按进十字线的三处。
- **现象**：长按出十字线后第二根手指碰屏，先抬起第一根时，十字线跳到第二根手指底下，还带着原来的抓取偏移，之后一路跟着它走。
- **根因**：十字线不记得归哪根 UITouch，`touches.first` 换了人也照用。
- **修法**：
  - 进十字线模式时记下主人手指，移动只认它。
  - 主人抬起，这一轮十字线就放下；剩下的手指不接班。
- **用例**：`ChartGestureTests`「十字线只归拎起它的那根手指：它抬起后剩下的手指不接班、十字线不跳」
- **提交**：`cbcbbc50`

### P3-3 周 / 月 / 长视野时间轴不按日历对齐，九年视野标签互压
- **位置**：
  - `KanpanCore/Sources/KanpanCore/Geometry/Ticks.swift:20`（阶梯）、`:29`（`calendarMonths`）、`:55`（周一锚）、`timeTicks`
  - `Format/Format.swift:115`（`fmtTick`）
  - `KanpanChart/Sources/KanpanChart/ChartRenderer.swift:610`（`timeAxisLabels`）
- **现象**：
  - 周线刻度全落在周四，指在两根 K 线之间。
  - 月刻度标成「03-17」这种逐年漂移的日子。
  - 月线缩到最密时，九年历史的标签挤成一团。
- **根因**：
  - 刻度只有「epoch 秒数整倍数」一种对齐，而 1970-01-01 是周四。
  - 步长阶梯封顶一年。
  - 绘制时不防叠。
- **修法**：
  - 周 / 两周档锚到周一零点（按所选时区）。
  - 月及以上按日历月推进，刻度落在 1 号：季在 1/4/7/10 月，半年在 1/7 月，年在 1 月 1 号。
  - 阶梯补 2 / 5 / 10 年。
  - 标签：月档写年-月，年档只写年。
  - 画标签时，贴边的、和左邻挨得不到 4 点的跳过。
- **用例**：
  - `TickTests`：阶梯表、周线刻度在周一零点、月 / 长视野落在 1 号且不挤、跨闰年与年末不漂
  - `FormatTests`：月 / 年档文案，以及与原型对照表的唯一有意分歧（年档）
  - `AxisWidthTests`：月线整段历史在窄图里只写年且互不相压、各档缩放互不相压、周线刻度写周一那天
- **提交**：`63994ab2`

### P3-4 ＋ 待核实·成交量 NaN
- **位置**：`KanpanChart/Sources/KanpanChart/ChartRenderer+Sub.swift:172`（`subVol`）
- **现象**：
  - 每帧逐根重复求 `outputVisible`、零线和柱色。
  - 坏量（NaN / ±inf）时，逐根算出 NaN 矩形交给 CoreGraphics；+inf 那根能画出一整列。
- **根因**：
  - 循环不变量写在了 `where` 里。
  - 量柱没有像量轴区间（`extent`）那样剔掉坏数。
- **修法**：
  - 循环不变量提到循环外。
  - 坏量那根直接跳过，和量轴区间同一口径。
  - 解析层（REST / WS / 缓存解码）已核过，本来就安全，不用改。
- **用例**：新增 `VolumeBarTests.nonFiniteVolumeDrawsNoBar`。逐像素断言 NaN / +inf / −inf 三种情况下：
  - 量柱那一列和「量 = 0」时一样；
  - 主图顶行也不受影响；
  - 正常量会画出柱子（对照组）。
- **提交**：`953c8766`

### 待核实 3 · 计算型画线的帧开销（6000 根实测后做了缓存）
- **位置**：
  - `KanpanCore/Sources/KanpanCore/Drawing/DrawVolume.swift:118`、`:152`、`:264`（`ComputedMemo`）
  - `DrawGeometry.swift` 的 `.anchoredVWAP` 分支：二分找屏内起点，出右沿即停
- **现象**：锚定 VWAP / 成交量分布每帧整段重扫。
- **根因**：计算结果没有缓存，VWAP 每帧把全部历史换算成像素。
- **修法**：
  - 结果按「序列戳 `series.revision` ＋ 种类 ＋ 锚点」缓存，nil 也缓存。上限 64 条，满了整体清空。
  - `BarSeries` 任何一列改动都会经 `didSet` 调 `stampAll()` 刷新戳，所以不会读到旧结果。
  - VWAP 只换算屏内那一段。读数尖用最后一个有限值。
- **实测**：`StressExtremeBenchTests`，n = 6000，iPhone 16 Pro 模拟器。

  | 场景 | 修前 | 修后 |
  |---|---|---|
  | 6 把计算型画线 | 13.19 ms（p90 14.15） | 6.31 ms（p90 8.94） |
  | 6 把且藏起 | 5.31 ms | 4.33 ms |
  | 30 把计算型画线 | 43.99 ms（p90 45.69） | 7.65 ms（p90 7.88） |

- **用例**：`DrawVolumeTests`
  - 「计算结果按序列戳缓存：同一条序列只算一次，序列一改就重算，nil 也记住」
  - 「VWAP 只换算屏内那一段：和逐根全扫出来的线段、读数一模一样」（3000 根带 NaN 断档，6 种平移）
- **提交**：`9b94cba3`

### 自查 · 画线拖到一半被删掉的残留
- **位置**：`KanpanChart/Sources/KanpanChart/ChartView+Drawing.swift:208`（`reprojectDrawings`）、`:954` 起（`drawingTouchesEnded`）
- **现象**：拖线途中这条线被别处删掉（另一台设备同步删、另一根手指点删除 / 清空）后：
  - 读数胶囊一直挂在图上；

  - 抬手分支先认「在拖」再找线，找不到就收干净返回。
- **用例**：`ChartDrawingPreviewResidueTests.deleteMidDragDropsTheDrag`

### 自查 · 指标三处（iOS 与手机网页同改）
- **位置**：
  - `KanpanCore/Sources/KanpanCore/Indicator/IndicatorEngine.swift:819` 起（`SARState`，反转分支约 `:863`、`:869`）
  - `:643`（`startsAnchorPeriod`）
  - `:677`（VWAP 坏量）
  - 网页 `Web/src/m/indicator/engine.ts`
- **现象与根因**：
  - **SAR**：反转那一根直接写上一段的旧极值，没把当根最高 / 最低算进去。大振幅 K 线上，点会画进影线里。
  - **锚定 VWAP / CVD**：日线以上一律按自然月归零，于是月线上每根都是新周期，VWAP 恒等于典型价、CVD 只剩单根净额。
  - **VWAP**：一根坏量（NaN / 负数）就让后面整段变成 NaN。
- **修法**：
  - **SAR**：翻空时 `sar = max(旧极值, 当根高)`，翻多时 `sar = min(旧极值, 当根低)`。
  - **锚定周期的准确口径**：
    - 步长 < 1 天：按 UTC 日归零；
    - 1 天 ≤ 步长 < 7 天：按 UTC 自然月归零；
    - 7 天 ≤ 步长 < 365 天（周线、月线）：按 UTC 自然年归零；
    - 年线：不归零。

    提交说明里写的「日到周→月、月→年」是简写，以这里为准。
  - **VWAP**：坏量那根只空这一根，不进累计，后面照常累计。
- **用例**：
  - `IndicatorEdgeTests`：
    - 「翻转那一根的点落在这根 K 线之外」
    - 「随机序列：每一根的点都在这根之外」
    - 「周线、月线按自然年归零，年线不归零」
    - 「月线上的 VWAP / CVD 真的在累计」
    - 「VWAP 碰上一根量不是有限数……」
  - 网页 `Web/tests/m-indicator.test.ts` 同步用例
- **交叉验证夹具**：算法改了以后，`Web/tests/m-indicator-xcheck.test.ts` 里 h1 / d1 / tiny / mo1 / w1gap / nan 六个场景的摘要失配（D 线跑 web-test 时报出）。处理方式：
  - 新增 Swift 侧 `KanpanCore/Tests/KanpanCoreTests/IndicatorCrossCheckTests.swift`：移植同一个 LCG 生成器、9 个场景和 FNV-1a 摘要，与网页表逐格比对。
  - 先确认 Swift 算出的摘要与 TS 逐位一致，再把两张表的 8 格同时更新：h1 / d1 / tiny 的 SAR；mo1 / w1gap 的 CVD 与 VWAP；nan 的 VWAP。
  - 以后任一端单改算法，两边的测试都会红。
- **提交**：`95e6e767`
