# 数据 / 同步 / 提醒 / 画线 / 账号 / 复盘本地层压测审查报告（2026-09-26）

范围：`KanpanData` 里的非行情部分（偏好编解码、同步队列、画线存档、提醒存档与判定、自选、复盘本地存档、换号、收件箱本地侧）、`KanpanAccount`、`KanpanReview` 的本地部分、`Kanpan/Kanpan` 里 `Settings/`、`Alerts/`、`Symbols/`、`Account/` 的逻辑层。

全部离线、进程内完成：桩传输、临时目录、固定种子的随机数。**没有连线上 VPS，没有用任何账号密码。** 重活一律经 `make` 目标或 `scripts/machine-guard.sh run`，同一时刻只有一个编译，模拟器只用 iPhone 17 Pro Max（16 Pro 当时由别的窗口在用）。

压测判据一律是**结构性的**：请求数、落盘次数、记录条数、逐位相等、与旧实现对拍，不写墙钟断言；表里的毫秒数是同一条用例在修前 / 修后各跑一遍的实测，只作说明（除注明 Release 外均为 Debug、M4）。

## 一、结论

- 共发现并修掉 **19 个**问题（另有 1 个是压测用例自身占主线程，一并修了），另补 2 组只加用例、实测无问题的压测（同步结账、画线三千条）；偏好编解码、自选、访客复盘并入的压测跟各自的修复一起提交。
- 高：换号缝里的数据串号（A 的操作带 B 的令牌推进 B 的云端、B 的对象写进 A 的档案）、旧会话的结论清掉新会话、复盘同步一轮落盘几千次。
- 回归（全部在 iPhone 17 Pro Max 模拟器 / 本机，串行跑）：`make account-test` 143 条全绿；`make data-test` 258 条全绿；`make app-logic-test` 625 条 + 冒烟 4 条全绿；`make review-test` 全绿；`KanpanTests/DrawStressTests` 4 条全绿；Symbols + AccountCodec 两组 230 条全绿。
- `make app-logic-test` 的前置守卫 `venue-isolation` 当时是红的，拦下它的是别的窗口在 `Main/MarketModel.swift`、`Feed/MarketFeed.swift`、`OrderFlow/OrderFlowFeed.swift` 注释里写了交易所名，不在本范围，用 `make -o venue-isolation` 跳过守卫跑的测试本身（见第四节）。
- 服务端、行情线：**没有需要转交的根因**。

严重度：**高** = 一次普通操作就能丢数据 / 串号 / 长时间卡主线程；**中** = 大数据量时明显卡顿、局部功能长时间不可用；**低** = 边角输入或浪费资源。
