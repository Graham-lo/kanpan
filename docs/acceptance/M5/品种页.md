## 5. 原型与任务书不一致的地方（一律以原型为准，逐条记账）

1. **中间那一组的含义。** 原型第二组叫「原型带了数据的」，是内嵌快照的产物；任务书要的是
   「最近打开」。取任务书语义、取原型的版式与位置，标题写「最近」。原型里没有「最近」这个概念。
2. **搜索排序。** 原型是纯 `includes` 子串过滤，命中集合不排序、不高亮。任务书 §10.5 与 A5.7
   要求「base 前缀优先」「匹配片段高亮」。做法：**命中集合与原型逐字一致**（base 或 symbol 含即命中），
   只在这个集合内部加四档排名和高亮——是叠加，不是改口径。
3. **行内第二行小字。** 原型放的是「内嵌了哪些周期」（`1m · 5m · 1h`）或「原型无快照」，是原型特有。
   真 app 里放合约全称 `BTCUSDT 永续`，和顶栏那颗按钮对上。
4. **价格小数位。** 原型 `symRow()` 用 catalog 行里的 `p`（= `pricePrecision`）。
   `KanpanCore.SymbolInfo` 另有一个 `priceDecimals`，是从 `tickSize` 推的。两者会打架：
   BTCUSDT `pricePrecision = 2` 而 `tickSize = 0.10` 只推得出 1 位。按原型取 `pricePrecision`，
   显示 `76800.00`（也和币安网页版一致）。
5. **「全部」分区的排序。** 原型不排序，直接按 catalog 原序 `slice(0, 120)`。任务书 §9.3 / A5.7
   要求按 24h 成交额降序——这一条**取任务书**，因为原型的 catalog 是静态内嵌表、根本没有全量成交额，
   不是有意为之的设计。同额或缺行情的按 catalog 原序兜底，排序稳定。
6. **「全部」剔除谁。** 原型剔的是「有内嵌快照的」（`!have.has(sym)`），真 app 里对应
   「已经在自选 / 最近露过脸的」。规则同构，集合不同。
7. **「还有 N 个」的算法。** 原型算的是 `D.catalog.length - have.size - 120`，用的是整表长度；
   这里算的是本组实际剩余（`pool.count - 120`）。文案一字不改：`还有 N 个，搜名字更快。`
8. **点一行的行为。** 原型对没有快照的品种弹 toast 拒绝进入，并且会把周期回退到快照里有的那档——
   纯属原型的数据限制。真 app 一律可进，去掉这段。
9. **半透明行。** 原型给无快照的行 `opacity: .5`。真 app 没有「无快照」这回事，不复刻。
10. **自选存档。** 原型是 `localStorage` 的 `kanpan.v3`、字段 `watch`、纯数组。这里是
    `UserDefaults` 的 `kanpan.symbols.v1`、`{favorites, recents}`。加自选**push 到末尾**这个口径
    照抄原型（移除再加回来是排到末尾，不回原位）。任务书 §4.4 说自选走「JSON + Codable 放
    Application Support」——两份列表不到 1 KB，先落 UserDefaults（它本身就是 Application Support
    下的 plist），换实现只要换掉 `SymbolPrefsStorage`。
11. **左滑删除与拖排序。** 原型是网页，只有一个星星按钮，没有左滑、没有拖动。任务书 §10.5 明确要
    「可拖排序、左滑删除」，按任务书补；星星按钮保留，三条路都通向同一份 `SymbolPrefs`。
