## 2. 手势层为什么不用 UIGestureRecognizer

原型是 `pointerdown / pointermove / pointerup` 三个回调一把梭（`chart.js:1173` 的 `_bind`）。
`UIGestureRecognizer` 那套有自己的 slop、长按时长和互斥策略，跟原型对不上；G10 要的
「捏合中途抬一根手指变拖动**不跳**」在两个 recognizer 之间转交时也很难做到无缝。
所以 `ChartView` 直接覆写 `touchesBegan/Moved/Ended/Cancelled`，状态机全在
`KanpanChart/Sources/KanpanChart/ChartView+Gesture.swift`，一次手势的全部现场存在
`GestureState` 里，抬手 `reset()`。

## 5. 原型 / 任务书打架的地方

规矩是「原型即规格，冲突以原型为准并说明」。这一章有六处，逐条记：

**① 长按时长：320ms，不是任务书写的 450ms。**
原型 `chart.js:1228` 是 `setTimeout(..., 320)`。450 按下去明显有「等一下」的滞涩感，
而且和 iOS 自己的长按（500ms）撞车，用户会以为没响应。**取原型的 320。**

**② G7「时间轴拖」原型根本没有。**
原型只绑了价格轴的竖拖，底部时间轴不响应手势。任务书 §13 G7 明确要，所以这是**新增**：
`PriceAnchor.spanFactor(dx:) = exp(-dx/220)`，以按下点为锚缩放（`ViewMath.zoom`），
手感常数 220 沿用价格轴那条，两个轴拖起来力度一致。

**③ G6「按下点价格不动」原型也没有。**
原型拖价格轴只改 `zoom`，按下点会跟着滑。任务书要「按下点价格不动」，于是加了
`PriceAnchor.shift`：拿 `zoom` 变化后的区间，解出让按下点价格落回原 y 的 `shift`。
解法是自适应外扩括号 + 60 步二分——不是闭式，因为 `priceRange` 里还掺着叠加指标和
画线的取值，写不出解析式。对数模式下要特别挡一道：区间下沿一旦跌破 0，`log(max(1e-12,p))`
把曲线压平，`yOf` 不再单调、二分会收敛到离谱的值，所以先用 `usable()` 判合法再解。

**④ G4「y 吸最近的开高低收」原型也没有。**
原型的 `magnet` 只管 x（竖线吸根中心），横线一直跟着手指。任务书 G4 明确写了
「磁吸开时 x 吸 K 线中心、y 吸最近的开高低收」，这是纯叠加，照做（`nearestOHLC`）。

**⑤ 甩的速度取样用 M1 的 `VelocityTracker`，不是原型的两点法。**
原型 `flick` 拿最后两个 `pointermove` 算速度。那是 60Hz 网页的做法；120Hz 下两点间隔
只有 8ms，一次抖动就能把速度翻倍，甩出来忽长忽短。这里改用任务书 §7 规定的 100ms
滑动窗口（M1 就实现好了）。G15 的口径是「一样或更好」，这条是**更好**的那一侧。

**⑥ 回弹时长：240ms，不是任务书写的 200ms。**
原型 `chart.js:1370` 是 `/ 240`，缓动 `1 - (1-k)^3`（三次方 ease-out）。`Settle` 原样照抄，
连 `< 1ms 就不animate` 的死区也一样。**取原型的 240。**
