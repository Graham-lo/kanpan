**C-2 现象：**
- 手机自选或提醒里只要有一只 Coinbase 现货，网关线路的整条推送连接握手就被拒，然后永远重连；
- 快速换品种时被网关以 `control rate exceeded` 掐断；
- 订阅被拒后照样每 30 秒重连一轮。

**C-2 修法：**
- `validStream` 按 `stream_hub.py` 的 STREAM 正则（含非 ASCII 品种段）与币安流名形状过闸；
- 每条连接一个控制消息令牌桶（`stream.ts:191`）：网关 3/s、突发 12，直连 4/s、突发 4；
- `pending` 按 id 对账（`:206`–`:217`），error 回执把那批流记成被拒、不再重发，换线路清空；
- 回执不算首帧；首帧看门狗只在还有订阅时才计时；每帧只解析一次。

**C-6 现象：**
- 换令牌的请求还在路上时退登、再登另一个账号，旧账号换回来的令牌会盖掉新账号的会话，或者旧账号被拒后把新账号清成未登录；
- 别的标签页主动退登后，这一页报「登录已失效」。

**C-7 现象：**
- 第一次同步合并途中换账号：上一个人的云端数据被合并进下一个人的页面，下一个人自己的第一次合并被跳过，旧账本剩下的请求拿新账号的令牌发出去；
- 途中退登后，同一账号再登录就永远不再同步，还留着一个 15 秒的轮询定时器。

**C-7 修法：**
- `authed` 加 `asUser`（`client.ts:224`、`:227`）：会话已经换人就不发，回 401 `session_changed`，属于非永久错，不会隔离操作；
- 每个账本用 `transportFor(userId)`；
- `firstSync` 与 `lead` 在 await 之后核对 `gen`；
- 领头锁的回调看到信号已取消就直接返回、放锁。

**C-9 修法：**
- 新增 `market/tail.ts`：`tailNeed`、`tailFrom`、`TailResync`。
- `pages/chart.ts` 在两个时机对每格补一次尾巴（`resyncTail`）：掉线后重连上，或标签页藏够 30 秒后回来。
- 只取缺的那几根，逐根 `updateBar`，视口与往前翻过的历史都不动。取数期间这一格的推送照 `loadCell` 的做法先攒进 PushBuffer，取到后再按顺序补上。
- 超过 500 根改为整段重取；没取到就冷却后再补，最多三次。

## 二、判为非 bug 的项（及理由）

- **设置字段三方对账**（PC / 手机网页 `sync/codec.ts`、iOS `PrefsCodec`、服务端 `sync_validation.rs`）：差集为空，指标布局与 `orderFlowOverrides` 都在三方白名单里。服务端多出的 4 个只写键（`styleID`、`compactValues`、`routePolicy`、`drawToolGroup`）是有文档的旧键，用来接住老客户端，不会让新客户端的操作被拒。
- **同步队列幂等**：服务端按单条操作的 id 与内容摘要去重（`sync.rs` push 循环里的 `digest`），不认请求级的 key。客户端一条操作暂存后内容不再改，所以重发的同一条摘要一致，不会撞 `idempotency_mismatch`。
- **新者胜**：服务端 `merge()` 按字段时间戳合并；客户端 `acknowledge` 按服务端回执落地。
- **未知字段堵队列**：遇到永久错（400 / 422 / `invalid_operation`），`engine.ts` 用 `suspects` 二分，最后只隔离出错的那一条，其余照常推上去。
- **离线队列上限**：iOS `SyncStore.stage` 也不设上限；设上限就得丢用户的改动。localStorage 写满时队列留在内存里，不丢。
- **换账号清队列**：账本按 userId 分开存（`sync/keys.ts`），换账号只是切到另一本账，旧账本留着等原主人回来续推。这次 C-7 补上的是「旧一轮请求不能替新账号发」。
- **推送「醒来的旧连接」**：web 的 `stream.ts` 与订单流 `feed.ts` 都按连接对象判断当前与否，旧连接的事件进不了当前连接的状态。没有 iOS C-1 那种共享看门狗被旧轮收掉的问题。
- **200 路 / 每秒 10 条**：`PER_CONN = {direct:200, gateway:64}`、`TOTAL = {direct:1000, gateway:160}`，控制消息走 C-2 的令牌桶。
- **藏起只留核心流**：`stream.ts:134`；可见性变化有 1.5 秒防抖；藏着时断线，重连至少隔 10 秒。
- **首帧 K 线与推送对齐**：`loadCell` 取数期间把推送攒进 `chart/pushBuffer.ts`，取到后用 `alignPushes` 把开盘时间 ≥ 最后一根的按顺序补上（`tests/push-buffer.test.ts`）。
- **手机网页重连补缺**：`m/chart/index.ts` 的 `resyncOnOpen` 会调 `resync()` 与 `compareFeed.resync()`，本来就有。
- **手机默认走网关**：这是既定设计，不是故障。
- **周期名**：网页用到的所有周期都匹配网关 hub 的 kline 正则。
- **相对地址的本地冷却键**：前后一致。
- **订单流聚合 / 门槛同步 / 回填去重**：三家的簿在 `feed.ts` 里聚合计算。门槛走设置字段 `orderFlowOverrides` 跨端同步。`model.ts:408` 的 `mergeHistory` 按交易所 + 方向 + 价位桶 + 时间重叠逐条认领，回填与实时不会出现重复的条。
