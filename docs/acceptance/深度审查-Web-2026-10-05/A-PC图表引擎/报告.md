## 判为非 bug 的项

| 项 | 理由 |
|---|---|
| 往前翻页用 endTime 取历史，是否会漏根或重根 | `loadMore` 以第一根的 t 作 endTime 取历史，`chart.ts:396 prependData` 只收 `t < 第一根` 的根，边界那根不会重复；币安 endTime 含端点，所以不漏。新增的 A2 用例也覆盖了拼接 |
| 取数期间的推送 / 旧推送并进图 | loadCell 期间推送进缓冲 `pushes`，取到之后按顺序补；换品种 / 周期时缓冲作废。迟到行情拒旧由 C 线（6a12909c）处理 |
| 时间轴对齐 / 上海时间 | 刻度与底栏时钟都走 `sh()`（+8h），日线切换点是上海 8 点（UTC 0 点），与 09-28 的约定一致 |
| 自定义周期最后一桶不满 | 设计如此：最后一桶就是当前未收线的那根，与 TradingView 一致 |
| 本机存档读回（hydrate） | `app/store.ts:240 hydrate` 对每个字段做类型 / 白名单过滤，坏值回落默认；画线存档逐条校验 id / type / pts 有限（`store.ts:179-185`），坏条目丢弃并标 damaged，不会把整份读坏 |
| `pages/chartLayout.ts` 多图布局 | 区域宽度经 `app/sizes.ts clampSize` 夹在各区域最小 / 最大值与剩余空间之间；多图轨道比例走 `fitTracks` / `dragTracks`，有 `TRACK_MIN_W/H` 下限；网格列用 `minmax(0, …fr)` 不会被内容撑破。读完未发现问题 |
| PC 没有对比叠加 | PC 版本来就没有这个功能，不算缺失 |
| 数额格式 1000K | B 线 6a9df553（fmtCompact）、6fd13ed1（订单流 amt）已修 |
| loadCell 先 setDrawings 再取 K 线 | 有意为之：线先出，K 线到了再按时间落位，空图期间画线不丢 |
| 主图负价格 | 币安不会出现负价。即便如此 A4 也按有限值、按绝对值处理了 |
| VPVR 每帧重算 | 只在 dirty 帧算，复杂度为可见根数 × 每根跨的行数；满载量法里平移 / 缩放主线程占用已降到 2–3%，不是瓶颈，不值得加缓存层 |
| canvas 尺寸是小数 | `chart.ts:601 resize` 后备缓冲按 `Math.round(尺寸 × DPR)` 取整，CSS 尺寸保留小数，setTransform 按 DPR 缩放，不糊 |
| PC 锚定 VWAP 用 floor，手机网页用 ceil | PC 照 TradingView（锚点所在的那一根算进去）。手机端照 iOS `firstBarAtOrAfter`。两端各照各的参照。手机 `computeVWAPTrail` 在锚点早于已载数据时从第 0 根起算、起点取 ceil，D 线对照 iOS `KanpanCore/Drawing/DrawVolume.swift computeVWAPTrail` 确认 iOS 原文就是这样写的，手机网页照 iOS 复刻、保持不变，列入 D 线报告的非 bug 项 |
