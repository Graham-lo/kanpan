# 深度审查 Web · D 线：手机网页图表引擎与指标（2026-10-05）

范围：
- `Web/src/m/chart/`：状态、几何、渲染、手势、画线、订单流、对比、生命周期。
- `Web/src/m/indicator/`。
- 测试：`Web/tests/m-chart-*.test.ts`、`Web/tests/m-indicator*.test.ts`。
- 压测工具：`Web/scripts/m-chart-perf.mjs`、`Web/src/m/chart/bench.*`。

手机网页引擎是 iOS KanpanChart / KanpanCore 的 TS 复刻，所以本线的头一件事是对账：iOS 10-04 B 线（图表引擎）的每一个提交，逐一核对手机网页有没有同样的病。

做法：
1. 先只读，顺着手势、渲染、切换、生命周期走一遍状态机，列出清单。
2. 每条用 vitest 复现（DOM 交互用假 DOM + Pointer Events 驱动真 ChartView）。
3. 从根因修，小步提交到 main。每条回归用例都在修前代码上确认是红的，再恢复修法。
4. 三端指标（PC `src/chart/calc.ts`、iOS、手机网页）逐根对拍，以 iOS 为准。

修复表「根因」列的行号是修后的位置。

## 判为非 bug 的项

| 项 | 理由 |
|---|---|
| 分隔线拖动的副图高度是否抬手即落盘 | 代码审读 `m/chart/index.ts:957–971`：拖动中只改视图，`pointerup` 时 emit 一次 `subScale`，页面即刻 `save()`，不靠定时器；`pointercancel` 退回拖前高度、不落盘 |
| DPR 3 与换屏 | 按 matchMedia 监听分辨率变化重量尺寸（上限 4），画布按设备真实倍率画（91967bf6） |
| 文字宽度缓存 | 只缓存系统字体的宽度，按字体 + 文本做键，不随皮肤 / 字号串值 |
| 换品种 / 换周期的旧数据 | 以下各路都有守卫，复核无残留：CompareFeed 的 generation 守卫、DepthFeed 重启先发 null、OrderFlowSource 换品种置 null、ExternalFeed 的 sym / iv 守卫 |
| 生命周期 | destroy 时 ChartBeat 与 rAF 都会取消，画线控制器也会摘下（f660e2c8） |
| 收盘倒计时 | 选项默认关，界面不展示，符合 10-03 规矩 |
| 指标布局按周期分组 | 引擎里已没有按周期分组的布局，整份跟人走（10-03） |
| SRSI 与 PC 差约 1e-14 | 浮点累加顺序不同产生的噪声，远低于显示精度；手机目录里 SRSI 已下线 |
| PC 的 CVD 与手机 CVD 不同 | PC 的 CVD 是 PC 独有的三家交易所聚合指标，与手机 / iOS 的单序列 CVD 不是同一个指标 |
| PC 独有的 OBV / CCI / WR / 一目均衡 / 成交量分布 | iOS 与手机都没有对应指标，无从三端对账 |
| 手机锚定 VWAP 的起点（A 线来信提的两点） | 锚点早于已载数据时从第 0 根累计，起点用 ceil（`firstBarAtOrAfter`），与 iOS DrawVolume.swift 逐行一致，手机照 iOS 复刻。PC 取 floor / null 是 A 线按 TradingView 定的 PC 口径 |
| 每帧分配 | 逐项看过，都不是每帧分配：probe 只在测试里用；订单流分组有缓存；`displayed` 有缓存；深度簿行数很少。`fireOrderFlowFocus` 的 JSON 比较只在十字线 / 选中订单流时走，对象很小，压测十字线段 p95 2.0 ms |
| PC `util/format.ts` 单位进位 | B 线已修（6a9df553） |
