## A0.3　空壳 app 装上并启动到首屏 ✅

首屏是 `Kanpan/Kanpan/LaunchScreen.swift`：纯色底 + 「看盘」两字，颜色直接取自 `KanpanCore` 的 `Palette.lightSeed` / `darkSeed`（浅 `#FFFFFF` / `#12163A`，深 `#0F1230` / `#EDEEF8`）——顺带证明 app target 确实链上了 Core。

八台 × 浅深两色 = 16 张：`shots/M0-<机型>-light.png`、`shots/M0-<机型>-dark.png`。
运行日志 [`logs/M0-screenshots.log`](logs/M0-screenshots.log)，退出码 0。

工程结构：根目录 `Kanpan.xcworkspace` → `Kanpan/Kanpan.xcodeproj`，本地包 `KanpanCore` 经 `XCLocalSwiftPackageReference` 引入。关键构建设置：`IPHONEOS_DEPLOYMENT_TARGET = 17.0`、`SWIFT_VERSION = 6.0`、`SWIFT_STRICT_CONCURRENCY = complete`、`TARGETED_DEVICE_FAMILY = 1,2`、`PRODUCT_BUNDLE_IDENTIFIER = com.mdd.kanpan`。

## A0.4　Core 在纯 CLT 环境可测 ✅

```
DEVELOPER_DIR=/Library/Developer/CommandLineTools make core-test
```

→ [`logs/M0-core-test-clt.log`](logs/M0-core-test-clt.log)，退出码 0，`Test run with 150 tests in 18 suites passed`。

`KanpanCore` 不 import UIKit，因此不经 `xcodebuild`、裸 SwiftPM 即可跑。CLT 单独发行时 SwiftPM 不会把 swift-testing 的框架路径加进来，`Makefile` 里在 `DEVELOPER_DIR` 指向 CLT 时补了 `Testing.framework` 的 `-F` 与 `lib_TestingInterop.dylib` 的两条 `-rpath`。

## 一个环境坑，记在这儿

`xcrun simctl bootstatus -b` 返回只代表内核起来了，SpringBoard 与显示表面可能仍未就绪；此时 `simctl io screenshot` 报 `NSPOSIXErrorDomain code=60 (Timeout waiting for screen surfaces)`，`install` / `launch` 报 `SimError code=405 (Unable to lookup in current state)`。`Tools/snap.sh` 因此对 install / launch / screenshot 统一加了重试（2 秒一次，最多 30 次）。
