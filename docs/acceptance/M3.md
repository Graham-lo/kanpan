## 取证是怎么出的

绘制要 UIKit，只能在模拟器里跑，所以取证器就是测试 target 里的三个套件（`M3 取证渲染` /
`A3.2 几何量化` / `A3.3 颜色取样`）。落盘开关是 `M3/.render` 标记文件——脚本建、跑完删；
没有它 `make chart-test` 照样跑断言，但一个字节都不落盘。入口：

```bash
make evidence          # 出全套证据到 docs/acceptance/M3/
make fixtures          # 原型改了才需要：重新导一次定版 fixture
```

对照物按 §12.1 只有一个，就是定版原型。`Tools/export-chart-fixtures.mjs` 在 Node 的假 DOM 下
**原样跑 `prototype/src/` 的 chart.js / styles.js / data.js**，不重写任何公式，问出三份黄金值：
`snapshot.json`（BTCUSDT 1h 1000 根 + OI 500 点）、`geometry.json`、`colors.json`。零第三方依赖、不联网。
所以每次出图逐字节可复现。

## 与任务书 / Core 不一致的地方（一律以原型为准）

### ① 层数：原型 2 层，任务书 3 层 —— 按任务书做了 3 层

原型 `chart.js` 只有两块 canvas（`base` + `over`），最新价是画进 `base` 的。任务书 §5.7 要三层。
这里**按任务书**拆成 `plotLayer` / `liveLayer` / `crossLayer`，因为 M7 的实时跳动要的就是「只重画
最新价那一层」。三层合成的结果有单测兜底：和单张 `ChartRenderer.draw()` 逐像素比，通道差超过 2/255 的像素占比 < 2%。

### ② 「spacing 0.4 时一屏 ≈ 2000 根」不可达

`Chart.minBarSpacing = 0.4`（原型定死），iPhone 16 Pro 的 `plotW = 344pt` → 一屏容量 860 根，
实测 811 根；iPad mini `plotW ≈ 686pt` → 1715 根。而且定版快照本身只有 1000 根。
要凑到 2000 根得把 `minBarSpacing` 降到 0.17 左右，或者改成横屏 iPad——两者都是改规格，没动。
**补了一张 iPad mini 的 thin 图**，并把每张的 `barsOnScreen` 写进清单，实际能到多少一目了然。
这条要么改任务书的数字，要么改 `minBarSpacing`，**等你定**。

### ③ A3.2 的机型尺寸：393×852 是 iPhone 15，不是 16 Pro

任务书 A3.2 写「iPhone 16 Pro」。原型 `app.js` 里 `pro` = **402×874**，393×852 是 `std`（iPhone 15）。
按原型取 402×874@3x，fixture 全部重导。

### ④ §12.2 的工具名与实现位置对不上

表里写的是 `KanpanSnapshotTests` 和 `scratchpad/export-fixtures.py`（无头浏览器）。实际落在
`KanpanChartTests` 的三个套件 + `Tools/export-chart-fixtures.mjs`——用 Node 假 DOM 跑原型的
chart.js，不引无头浏览器，符合零第三方依赖。名字对不上，做的事一样。

### ⑤ 「颜色一律精确匹配十六进制」对亚设备像素影线在几何上不成立

靛 / 密 / 骨的影线宽 0.5px、砖 0.5px、纸 0.8px、描 0.9px——这些风格的影线**不满一个设备像素**，
那个像素本身就是底色与影线色按覆盖率合成出来的，不可能等于纯影线色。
处理方式是**按 CoreGraphics 的合成规则算出期望值再比，而不是放宽容差**。154 点里 143 点精确相等，
剩下 11 点仍有 1/255 的单通道舍入差，表里逐点记了 `coverage` / `expected` / `actual` / `delta`。
最差的一例：`light / paper / wick`，期望 `#3CB093`、实得 `#3CAF92`。

### ⑥ 取证固定用 UTC（有意偏离）

原型跟随设备时区。取证要跨机器逐字节可复现，所以固定 UTC。十字线那两张的清单字段里标了。

### ⑦ 最新价的 z 序变了（①的副作用）

原型里最新价画在副图 / 时间轴 / 图例**之前**，会被它们盖住；独立成 `liveLayer` 后跑到最上面。
只在最新价正好落到主图图例带（y ≈ 主图顶 + 11pt）时看得出来，A3.1 并排比对可能撞上。

### ⑧ `liveLayer` 目前不会单独变脏

最新价读的是 `series.close.last`，ticker 一变蜡烛也跟着变，所以脏位永远是 `[.plot, .live]`。
要真正只刷最新价，得等 M4/M7 把 `ticker` 提成 `ChartState` 的独立字段；`setNeedsRedraw(.live)`
的入口已经留好了。当前不影响正确性，只是省不下那点重画。

### ⑨ 沿用 M1 已记的两条

- **长按阈值**：原型 `320ms`，任务书 §7 的表写 450ms——以原型为准，`Constants.longPressMs = 320`，
  M1.md 已记。
- **`decimals` ≡ `pricePrecision`**：原型快照里的 `meta.p`（BTCUSDT 是 2）等于 `exchangeInfo` 的
  `pricePrecision`，**不是**按 `tickSize` 推出来的 `priceDecimals`（那个是 1）。

### ⑩ 两处 Core 侧的口径，M3 绘制时确认过

- **KDJ 不锁 0–100**：原型 `drawSub` 只给 RSI / StochRSI 锁纵轴，KDJ 走自适应——J 线常年冲出
  0–100，锁了就看不见。参考线 RSI 是 30/70，KDJ 与 StochRSI 是 20/80。
- **VOL 染色**：原型 `app.js` 里 `volUp = up + '66'`、`volDn = dn + '66'`，即涨跌色加 40% 透明度，
  不是另一套颜色。
- **时间戳取 `series.time(at:)`**，不是 `t0 + i*step`——补历史后 `t0` 会变，后者会漂。

## 顺带修掉的：`make strict`（A2.13）

`make strict` 之前是坏的。原因是给 xcodebuild 传的 `SWIFT_TREAT_WARNINGS_AS_ERRORS=YES` 是
**命令行级构建设置**，会一路盖到 SwiftPM 依赖 `KanpanCore` 头上，和 Xcode 给包依赖自动加的
`-suppress-warnings` 撞车：

```
error: Conflicting options '-warnings-as-errors' and '-suppress-warnings' (in target 'KanpanCore')
```

改法是收窄到包内自己的两个 target：`KanpanChart/Package.swift` 里按 `KANPAN_STRICT` 环境变量
挂 `.treatAllWarnings(as: .error)`，`make strict` 置这个变量并用独立的 `.xcbuild-strict`
派生目录（免得和普通构建互相污染缓存）。

验证过它**确实会拦**：塞一个故意的未使用变量进去，`make chart-build` 通过并报 1 条 warning，
`make strict` 直接 `error:` + `** BUILD FAILED **`，探针随后删除。
