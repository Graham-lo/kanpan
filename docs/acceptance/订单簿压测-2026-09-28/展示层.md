# 订单簿 / 主力订单流 · 展示层压测与审查（2026-09-28）

**范围**
- 图上画带：`ChartRenderer+OrderFlow.swift`、`OrderFlowGroup.swift`
- 盘口梯：`ChartRenderer+Depth.swift`
- 详情卡：`OrderFlowDetailCard.swift`
- 参数表：`OrderFlowEditor.swift`

数据层另见同目录的 `数据层.md`。

**环境**
- 基准：Release 配置（`make chart-test-release`，开 `ENABLE_TESTABILITY`），机器空闲时跑。
- 真跑：Debug 包，iPhone 16 Pro 模拟器（iOS 26.5），走币安直连。
- 机器：M4，10 核 / 16 GB。

## 结论（先看这里）

1. **性能：拖动时的主要问题已修掉，但整帧 4 ms 只有可视 30 根时达标。**
   - **原来**：每一帧都把整份快照重新切段、并墙、建组、排序。1m 密度 2 万单、可视 300 根时，拖图一帧 p50 68.5 ms、p95 124 ms。
   - **现在**：视野无关的那一半交给 `OrderFlowWallCache` 缓存，拖图和捏合都不再重算。同一场景拖图一帧降到 p50 10.3 ms、p95 10.9 ms，其中 K 线本身已经占了 6.1 ms。
   - **订单流带来的增量**：
     - 静止时 ≤ 2.7 ms，1d 密度下 ≤ 0.3 ms，达标；
     - 1d 拖动时 ≤ 1.1 ms，达标；
     - 1m 拖动时 3.6–4.3 ms，卡在 4 ms 边上。剩下的主要是 500 多条带的像素填充（约 2.4 ms），只有换一种画法才能降（见 D1）。
   - **整帧**：可视 300 根和 1500 根时，不画订单流的底座就已经 5.8–6.3 ms，本身已超过 4 ms。这部分是 K 线、均线和副图的开销，不在本范围。
2. **展示 bug：修了 5 处。** 全部能复现，都已补回归并跑绿：
   - 屏外的墙占了排名；
   - 签压盘口梯；
   - 签压图例；
   - 详情卡把成交比例截掉；
   - 万亿金额没有 T 档。
3. **真跑情况**：BTC / ETH / SOL / DOGE 四只 × 1m、15m 两个周期，四套皮肤，缩放、平移、十字线，快切 20 次，切周期 10 次，进后台再回来。修复后的自检结果是「问题 0 · 签压盘口梯 0 · 残留 0」，回前台 1.2 秒恢复。
4. **参数表**：修了 2 处，框里打多余小数点不回显、粘贴科学计数法会变形。粘中文单位、全角数字、「1..5」和「2e1」都能正确换算，保存后立即生效。同步字段与服务端白名单逐项一致。
5. **范围外发现（交数据层，未改）**：app 回前台后，图上的单子从约 1.17 万降到 5000，原因是 `OrderFlowModel.bufferCapacity` 和 `journalMaxOrders` 都是 5000。更早的墙要等历史回填才会回来。

## 第三轮（2026-09-29）· 金额签躲 K 线、线不进图例

## 第四轮（2026-09-29）· 已结束的签沿自己的线滑（`047a2c99`）

第三轮的展示残留：默认密度下已结束的签在「哪儿都是蜡烛」时仍会盖住一小块（取五处里盖得最少的那处）。用户说「你看看残留的根因在哪里，一并设计修复好」。

### 根因

五处备选（结束点右侧居中 / 上 / 下、左侧上 / 下）全都钉在结束点那一根附近，横向让也只往右让。可是结束点就是价格穿过墙的地方——那儿的蜡烛密度最高、价位又正好在签的高度上，五处都压着是常态，不是巧合。真正空的地方在签自己那条线的左边：线走过的这一段价格只在一侧（墙挂着时价格没穿过它），线的另一侧多半没有蜡烛。

### 改法（`ChartRenderer+OrderFlow.swift`）

五处里没有不用挪、也不压蜡烛的时候，先**沿自己那条线往左滑**：签整枚在线上、下限是线的起点（`floor`），滑到第一处上下方都清的位置；和「右侧居中往右让」比谁挪得少就用谁。两边都让不出去（左边滑到线头、右边出了主图）才退回原来的兜底（五处里盖蜡烛面积最少的那处）。挂着的签规则不变（`floor` 是 0，让出主图左缘就不放）。括号照旧跟着签走。

### 用例（KanpanChart Release 210 过，`endedLabelSlidesAlongItsOwnLine` 新增）

- 结束点周围三根高蜡烛把五处都压着、右侧也让不出 → 签沿线往左滑到线上第一处清的位置，整枚在线的范围里、不压任何一根。
- 线头之前都压着 → 退回兜底，签仍在五处之一。
- 原有 `endedLabelDodgesCandles`、`labels`、`liveLabelSitsAboveLine` 的断言改为「五处之一、往右让过去的、或沿线滑过去的」（`endedLabelAtAllowedSpot`）。

性能：每枚已结束的签多一次沿线扫描，只查线上那几根（二分找起点、逐根探），和第三轮的躲 K 线一起仍在 0.1 ms 内，1m·v300 拖动帧的数字没有变化。
