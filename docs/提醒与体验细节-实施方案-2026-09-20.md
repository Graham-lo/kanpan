# 提醒模块与体验细节 · 实施方案（2026-09-20）

用户 2026-09-20 批准的一批「替他着想」的细节，除「行情陈旧提示」一条被否掉外全部落地。
本文是主窗口给各 Opus 子代理的统一契约；子代理动手前先读 `AGENTS.md`、`.project-memory/PROJECT.md`、
`README.md`，再读本文自己那一节。**契约（JSON 字段名、端点、URL 形态、模块边界）以本文为准，
不要各自另起名字。** 用户当前指示优先于本文。

## 0. 总原则（来自用户与项目既有约定）

- 提醒是**独立模块**，画线到价只是它的第一种提醒方式；数据模型与入口都要给「价格提醒、复盘待办到点、
  以后的别的方式」留位置，不能把提醒逻辑写死在画线里。
- 画完一条线之后**主动弹一个小确认**问要不要加提醒（用户点名要的，因为有时候他只是单纯画线）。
  弹窗要小、选项只有「加入提醒 / 只画线」，不要变成设置表。
- 界面文案一律中文；不出现任何状态 / 维护字段（「已连接」「更新于」「停在 3 分钟前」都不要）；
  不堆解释文案；元素尺寸克制；K 线画布上不浮任何控件（确认卡放在图外的工具栏行）。
- 同一动作只留一个入口。
- 一个功能收拢成一个模块，不散落在图表、宿主页、偏好仓库、账号桥各处。
- 跨端功能端到端做完：客户端、`Backend/kanpan-api`（Rust）、协议与字段白名单是同一个功能的三部分。
  加同步集合 / 字段走 `AGENTS.md` 里「加 / 删一个同步字段」那条路（`PrefsFieldPlan` → `make sync-contract` →
  `sync.rs` 白名单 + `sync_validation.rs` 值规则 → 两边测试对账）。
- 验证：只跑受影响的一两条用例；模拟器用于子代理自查；真机由主窗口最后统一 `make install-release`。
  几个子代理并行时各用自己的 `-derivedDataPath /tmp/kanpan-dd-<你的代号>`，不要共用。
- **子代理不提交 git**，改完自查通过后把改动文件清单和验证结果报回来，主窗口验收后统一提交。
  只动自己那一节列出的范围；必须碰共享文件（`MainScreen.swift`、`ChartHost.swift`、`KanpanApp.swift`、
  `project.pbxproj`、`Info.plist` / target 设置）时编辑前重新读一遍最新内容、改动尽量小且局部。

## 1. 深链路由（所有入口共用，先落地）

`Kanpan/Kanpan/Main/DeepLink.swift`。URL scheme `hkline://`（在 target 的 Info 里登记 `CFBundleURLTypes`），
以后通用链接（`https://kanpan.107-174-172-10.sslip.io/s/<id>`）也解析到同一个枚举。

```swift
enum DeepLink: Equatable {
  case symbol(String, interval: String?)          // hkline://symbol/BTCUSDT?interval=1h
  case drawing(symbol: String, drawingID: String)  // hkline://drawing/BTCUSDT/<drawingID>
  case alerts                                      // hkline://alerts       （提醒列表）
  case search                                      // hkline://search
  case share(id: String)                           // hkline://share/<id>   与 https://…/s/<id>
  static func parse(_ url: URL) -> DeepLink?
}
@MainActor final class DeepLinkRouter { static let shared; func open(_ link: DeepLink) }
```

`MainScreen` 订阅路由：`.symbol` 切到图表页并换品种（有 interval 就换周期）；`.drawing` 打开该品种并选中那条线
（线不存在就只开品种）；`.alerts` 打开提醒列表；`.search` 打开搜索页；`.share` 交给共享模块（第 8 节）。
`KanpanApp` 用 `.onOpenURL` 喂给路由。桌面快捷入口、通知点击、共享链接全部经这一个口进来。

## 2. 提醒模块（Alerts）

### 2.1 客户端结构

- 纯逻辑：`KanpanCore/Sources/KanpanCore/Alerts/`（`Alert` 模型、`AlertGeometry`、`AlertEvaluator`），单测在 KanpanCore。
- app 模块：`Kanpan/Kanpan/Alerts/`（`AlertStore`、`AlertWatcher`、`AlertPrompt`（画完后的确认卡）、
  `AlertListPage`、`AlertNotifications`（本地通知 + 推送 token 注册 + 通知点击 → 深链）），
  测试壳 `Kanpan/Alerts/`（照 `Kanpan/Sector/` 的符号链接做法，加 `make alerts-test`）。
- 图表只暴露两样：`ChartHost` 在一条画线**提交**时发出 `drawingCommitted(Drawing, symbol)`；
  `KanpanChart` 接受一个 `alertedDrawingIDs: Set<String>` 用来在线的右端画一枚小铃铛记号。
  提醒的其它逻辑不进 `KanpanChart`、不进 `DrawingController`。

### 2.2 数据模型（客户端与服务端同一份字段名）

同步集合名 `alerts`，对象 id = `binance/usd_m/<SYMBOL>/<alertID>`（和 `drawings` 同一套 id 形态）。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `kind` | `"drawing"` \| `"price"` \| `"reviewDue"` | 本轮实现 `drawing` 与 `reviewDue`；`price` 只进模型与白名单 |
| `symbol` | string | 如 `BTCUSDT` |
| `market` | string | `binance/usd_m` |
| `drawingID` | string? | `kind == drawing` 时必填，对应 `drawings` 集合里那条线 |
| `lines` | `[{points:[{t,p}], extendLeft:bool, extendRight:bool}]` | 客户端把任意画线**摊平成若干条价格折线**；服务端只做时间上的线性插值 / 外推，不需要认识画线种类 |
| `condition` | `"touch"` | 触碰或穿过：某根 1m K 线的 `[low, high]` 含线在该时刻的价 |
| `armedAt` | ms | 从这一刻之后开盘的 K 线才算，避免创建当下已经贴着线就触发 |
| `once` | bool | 本轮固定 `true`：触发一次后状态变 `fired`，列表里可「再次提醒」重新武装 |
| `status` | `"active"` \| `"fired"` \| `"paused"` | |
| `firedAt` / `firedPrice` | ms? / number? | 触发时记录 |
| `dueAt` | ms? | `reviewDue` 用：到这个时刻本地通知 |
| `reviewID` | string? | `reviewDue` 用 |
| `title` | string | 通知标题，客户端生成（如「BTC 触到你画的趋势线」） |
| `created` | ms | |

`AlertGeometry.lines(for: Drawing) -> [AlertLine]?`：返回 nil 的画线种类不弹确认。本轮支持
`hline, hray, trend, ray, extended, arrowLine, crossLine（只取水平那条）, channel（两条边）,
rectangle（上下两条边）, fibonacci（每一级一条）`。`extendLeft/Right` 按该工具在图上的实际延伸规则给。

### 2.3 交互

- **画完即问**：`DrawingController` 提交一条线（竖屏或横屏画线工作台都算）后，若 `AlertGeometry` 认得它，
  在**图外**的那一行（竖屏是周期条下 / 底栏上的工具行，横屏是横屏工具栏那一行）出现一张小卡：
  一句话「价格穿过或触到这条线时提醒我」+ 「加入提醒」「只画线」。约 6 秒无操作等于「只画线」，卡收起。
  不要遮住画布，不要用系统 alert。
- **线上的记号**：有活动提醒的线，右端画一枚很小的铃铛（皮肤墨色，克制）。
- **管理入口**：设置面板加一行「提醒」→ `AlertListPage`：每行 = 品种徽章 + 品种 + 线的种类名 + 当前状态
  （活动 / 已在 09-20 14:32 触发 63,120）。滑动删除；点行 → `DeepLink.drawing`；已触发的行有「再次提醒」。
  用户删掉一条画线时，它挂着的提醒一起删；提醒删了线不动。
- **前台触发**：`AlertWatcher` 在 app 前台时用现有行情流（1m K 线 / 最新价）本地评估活动提醒，触发即
  `UIImpactFeedbackGenerator(.rigid)` 震一下 + 一条短暂的顶部 toast（同通知文案），并把 `status=fired`
  写回同步。服务端看到 `fired` 就不再推。
- **通知**：文案中文，标题如「BTC 触到你画的趋势线」，正文「现价 63,120」。点通知 → `DeepLink.drawing`。
  app 在前台时不再弹系统横幅（`willPresent` 里对提醒类通知返回空）。
- **权限时机**：第一次点「加入提醒」时才请求通知权限；被拒了提醒照样创建，列表顶部一行「去系统设置打开通知」。
- **复盘待办到点**（`kind == reviewDue`）：待办若有到期时间就在本地排一条 `UNCalendarNotificationTrigger`；
  若现有复盘待办没有到期时间字段，在待办编辑处加一个可选的「到点提醒我」时间（默认空）。
  点通知 → 打开那条复盘记录。全部走本地通知，不经服务端。

### 2.4 服务端（`Backend/kanpan-api`，Rust）

- `sync.rs`：`COLLECTIONS` 加 `alerts`；`sync_validation.rs` 加 `alerts` 的字段值规则（表 2.2）。
  `contract/settings-fields.json` 若需带上集合名由 `make sync-contract` 生成，不手改。
- 新模块 `src/alerts.rs`（评估）+ `src/apns.rs`（推送）+ 迁移 `0014_alerts.sql`（活动提醒物化表 +
  `device_push_tokens`）。物化表从 `alerts` 同步对象刷新（写入同步时顺手 upsert），字段：
  user_id, alert_id, symbol, lines(jsonb), armed_at, status。
- 评估器跑在 `kanpan-worker`：对所有 `status=active` 的 `drawing` 提醒按品种去重，
  订阅 `wss://fstream.binance.com/stream?streams=<symbol>@kline_1m/...`（先在 VPS 上实测这条 WS 通不通、
  `combined stream` 上限 200 条 / 连接，够用）。每来一帧：对该品种每条活动提醒，取 K 线开盘时间
  `t ≥ armedAt` 的那根，算每条折线在 `t` 处的价（点之间线性插值，超出端点按 extend 标志外推，不延伸
  的一侧超出即不评估），`low ≤ price ≤ high` 即触发。触发：把物化表置 `fired`，并**以服务端身份往
  该用户的同步日志写一条 `alerts` 集合的 op**（`status=fired, firedAt, firedPrice`），客户端下次拉取
  自然收到；然后推送。
- 推送：APNs HTTP/2 token 认证（`.p8`，ES256 JWT，55 分钟轮换）。配置全部走 `/etc/kanpan-api/service.env`：
  `KANPAN_APNS_KEY_PATH`、`KANPAN_APNS_KEY_ID`、`KANPAN_APNS_TEAM_ID=27Y32PT2HZ`、`KANPAN_APNS_TOPIC=com.mdd.kanpan`、
  `KANPAN_APNS_ENV=production|sandbox`。**密钥缺失时服务照常起、评估照常跑、状态照常回写，只是不推**，
  日志一行 warn，不要 panic。payload：`aps.alert.title/body`、`aps.sound=default`、`aps.thread-id=alerts`、
  自定义 `link: "hkline://drawing/BTCUSDT/<drawingID>"`。410 / `BadDeviceToken` 时删掉那枚 token。
- 端点 `POST /v1/devices/push-token`（带会话）：`{"token":"<hex>","kind":"alerts"|"liveActivity"|"widget",
  "environment":"production"|"sandbox","activityID":string?}`。token 挂在现有设备记录上，同一设备同 kind 覆盖。
- 部署：备份 → 迁移 → `systemctl restart kanpan-api kanpan-worker` → 只读验证 `/health` 与 worker 日志。

## 3. 搜索与入口

- **拼音 / 中文搜品种**：搜索框继续锁 ASCII 键盘（用户定过），所以中文能力用**拼音**承接：
  「bitebi」「btb」→ 比特币 → BTC，「tesila」「tsl」→ 特斯拉 → TSLA。别名表 `SymbolAliases`
  （加密主流币的中文名 + 常用简称：比特币 / 大饼、以太坊 / 以太、索拉纳、狗狗币、瑞波、币安币、艾达、波卡、
  莱特、链接、阿童木、Sui、Aptos 等至少前 60 名；美股中文名直接复用 `SectorCatalog.chineseName`）。
  拼音用 `CFStringTransform(kCFStringTransformMandarinLatin + StripDiacritics)` 在运行时从中文名生成全拼与首字母，
  不引第三方库。用户从剪贴板贴进来中文也要能命中。排序仍按现有规则（最匹配 → 24h 成交额）。
- **剪贴板识别**：搜索页出现时，若 `UIPasteboard.general.hasStrings` 且 `changeCount` 与上次不同，
  先 `detectPatterns` 再读内容，能解析成合约代号（`SOLUSDT` / `$SOL` / `sol` / 中文名）就在列表最上面给
  一行「打开 SOL」。同一段剪贴板只提示一次。
- **桌面快捷入口**：`UIApplication.shared.shortcutItems` = 最近看过的 3 个品种 + 「搜索」，
  在 `recents` 变化时刷新；点击走 `DeepLink`。
- **默认自选**：首次启动、没有自选也没有账号时，种一份默认自选：BTC、ETH、SOL 加当天 24h 成交额前 5
  的币（去掉重复、非币合约不进）。种过一次记一个本机标记，用户删了不再回来；游客数据并入账号的
  既有逻辑照旧。

## 4. 图与自选的顺手事

- **长按自选行预览**：自选页与板块品种列表（它照抄自选页）的行加 `.contextMenu` 带预览：
  一张紧凑卡（徽章 + 品种 + 最新价 + 涨跌药丸 + 最近 60 根 1h 的迷你 K 线 + 四格数据），
  菜单项：打开、移到分类、取消自选。预览走现有快照 / feed，不另开网络请求路径。
- **分享图片**：图表设置面板「这张图」一节加「分享图片」：离屏渲染当前图（含画线与指标，皮肤同款底色）
  + 顶部一条品种 / 周期 / 价格与涨跌 + 右下角小小的 `Hkline` 字标，2x，`ShareLink` / `UIActivityViewController`。
  不加任何时间戳、线路、版本之类的字。
- **记一笔自动附截图**：从图表「记一笔」时自动用同一套离屏渲染截一张附在记录上（复盘数据模型若已有截图
  字段就用它，没有就加，存进该账号目录；服务端若已有附件上传就接，没有就补 `multipart` 端点）。
- **费率结算倒计时**：`HeaderStats` 的「费率」格值下加一行小字「距结算 1h 12m」，数据来自
  `MarkPriceTick.nextFundingTime`，每分钟刷新，结算后自动切到下一期；不到 1 分钟显示「即将结算」。

## 10. 从 GPT 功能规划（2026-09-20）里采纳的项（第四、五波）

用户 2026-09-20 给了一份 GPT 写的「纯看盘产品功能规划」，主窗口逐项对照现状后采纳如下，不重复已在做的：

| 采纳 | 规划里的名字 | 落地方式 | 波次 |
| --- | --- | --- | --- |
| ✅ 并入第 1 波 | 连续扫图 | 从自选分类 / 板块品种列表进图表时冻结那份名单；在**图外的顶栏价格区**左右横滑切上一只 / 下一只（画布上不加手势、不加控件）；周期 / 根宽 / 指标本来就跟人走，不动；正看历史时尽量停在同一时间附近（复用 `switchInterval` 的 `anchorRight` 思路）；名单序号不上屏 | 1（代理 S） |
| ✅ 并入第 1 波 | 临近关键位置筛选 | 不另立「关注线」概念：**加了提醒的线就是关注线**。自选页排序弹层加一档「离提醒线最近」，行的副文案显示当前距离（百分比）；只回答远近，不回答方向 | 1（代理 C 顺手做） |
| ➡ 另一窗口 | 锚定均价 | 用户 2026-09-20 说明这项已由另一个 Claude 窗口在做，本文各代理**不要碰**；`AlertGeometry` 对不认识的画线种类返回 nil 即可 | — |

### 10.1 代理 S 的规格（连续扫图 + 看细节）

- **连续扫图**：`MainScreen.chartOrigin` 已经记着「从哪一层进来的」。进图表时把来源列表**当时的顺序**冻结成
  一份 `ScanList`（品种数组 + 当前下标），来源只认自选分类页的某个分类、板块品种列表；顶栏放大镜搜索进来的
  不冻结名单（没有「下一只」）。切换手势：**顶栏价格区（`TopBar` 的价格 / 涨跌 / 四格那块）左右横滑**，
  向左 = 下一只，向右 = 上一只，到头不循环、末端给一下轻触感。画布与周期条不加手势。切换保持周期 / 根宽 /
  指标（本来跟人走）；正在看历史时按 `switchInterval(anchorRight:)` 同一思路停在同一时间附近，看最新时贴最新。
  底栏切到别的页时名单清掉（和 `chartOrigin` 同生命周期）。不显示「3/12」之类序号。
- **看细节**：十字线选中一根 K 线（`CrosshairReadout` 有选中根的时间）且当前周期不是最小档时，
  周期条右端出现一颗「看细节」小按钮（图外，周期条那一行；无选中时不出现）。点它进**下一档**周期
  （14 档序列里的下一个更小档）并把视野铺成刚好覆盖那根大 K 线的时间区间（左右各留半根的空隙）。
  同时把切之前的（周期, 视野）压进一个按品种的小栈；用户随后通过周期条切回那个大周期时，从栈里恢复那份
  视野而不是跳回最新；栈只在「看历史」时记，看最新时不记；换品种清栈。
