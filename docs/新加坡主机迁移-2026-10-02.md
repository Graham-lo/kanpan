# 服务端迁到新加坡（2026-10-02）

## 为什么

美国主机（`orderflow-vps`，107.174.172.10）被币安 451，到国内的链路又慢，手机上用着卡。用户买了腾讯云新加坡
CVM（`ins-kf1imlt2`，ap-singapore，`SA2.MEDIUM8`：2 vCPU / 7.7 GB / 79 GB，Ubuntu 22.04，无限流量，`43.160.232.253`），
原话「我只想利用它的网络」→「其实这配置是不是完全可以部署啊，你根据三台机器配置给出最合理的部署方式」。

## 卡在用户手上的一件事：安全组没放 443

从美国往新加坡 443 发 SYN，`tcpdump` 在新加坡网卡上一个都看不到；22 / 80 都通、ufw 已放 443、Caddy 在听 443——
只能是腾讯的**安全组**没放行入站 TCP 443。控制台 → 云服务器 → 实例 `ins-kf1imlt2` → 安全组 → 入站规则 → 加 `TCP 443 来源 0.0.0.0/0`。

放行之前手机 / 网页都到不了新加坡，所以**正式切换没做**：美国的 api / worker / 网关仍然是线上，两边数据会分叉，
切换时要重新从美国取最终转储。

## 正式切换（443 放行后在 Mac 上跑一次）

```
bash Backend/kanpan-api/ops/cutover-sg.sh
```

它按顺序做：从美国验 443 通 → 美国停 api / worker、落最终瘦转储 → 经 Mac 运到新加坡 → 新加坡重建 public schema、
`pg_restore`、`install.py`、起服务、查健康与账号数 → 美国 Caddy 把旧主机名改成过渡代理（接口反代、`/web` `/ui` 308）→
美国禁用 api / worker / 网关 / timer → 从美国与 Mac 探旧新两个主机名。第 3 步前出错 `ssh orderflow-vps systemctl start kanpan-api kanpan-worker` 即回滚。

切完再：`make install-release`（手机在身边时）、`make web-deploy`（已部署，不用重做）、Surge 手机端也给新加坡加 DIRECT。
