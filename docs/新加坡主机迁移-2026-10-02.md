# 服务端迁到新加坡（2026-10-02）

## 为什么

美国主机（`orderflow-vps`，107.174.172.10）被币安 451，到国内的链路又慢，手机上用着卡。用户买了腾讯云新加坡
CVM（`ins-kf1imlt2`，ap-singapore，`SA2.MEDIUM8`：2 vCPU / 7.7 GB / 79 GB，Ubuntu 22.04，无限流量，`43.160.232.253`），
原话「我只想利用它的网络」→「其实这配置是不是完全可以部署啊，你根据三台机器配置给出最合理的部署方式」。

## 定稿的三台分工

| 机器 | 角色 |

| 新加坡 `kanpan-sg`（`kanpan.43-160-232-253.sslip.io`） | **唯一公开主机**：Caddy、kanpan-api、kanpan-worker、Postgres（docker `kanpan-postgres`）、kanpan-gateway + stream-hub、网页版 `/web/` `/web/m/` |
| 美国主 `orderflow-vps`（`kanpan.107-174-172-10.sslip.io`） | 编译机（Rust 在这里编，二进制运去新加坡）+ 温备（Postgres 留着）+ 旧主机名的过渡代理 |
| 美国备 `96.44.162.222:33333`（`kanpan.96-44-162-222.sslip.io:8443`） | 行情网关备用 + 第二份离机备份 |

`KANPAN_PASSWORD_PEPPER` / `KANPAN_ENCRYPTION_KEY` 原样从美国拷过去，**绝不重生成**（换一把谁都登不回来，且一个错不报）。

## 安全组 443 与正式切换（22:45–22:49 完成）

一开始从美国往新加坡 443 发 SYN，`tcpdump` 在新加坡网卡上一个都看不到（22 / 80 通、ufw 已放、Caddy 在听）——是腾讯**安全组**
没放入站 TCP 443。用户 22:4x 在控制台放行后，Mac（Surge 直连）与美国到新加坡 `/chart-gateway/health` `/v1/market/meta` `/web/` 都 200、
WS 101、证书 CN 对、到 12-31。

随后跑 `bash Backend/kanpan-api/ops/cutover-sg.sh` 完成正式切换：美国停 api / worker → 最终瘦转储（8,464,927 B）经 Mac 运到新加坡 →
新加坡重建 public schema、`pg_restore`、`install.py`、起服务 → **users=128 sync_ops=17627 alerts=35 notes=38** → 美国 Caddy 把
`kanpan.107-174-172-10.sslip.io` 改成过渡代理（接口反代新加坡、`/web/*` `/ui/*` 308）→ 美国禁用 api / worker / 网关 / stream-hub /
备份与推送 timer（Postgres 容器留着当温备，最终转储也留在美国 `/tmp/kanpan-final-20261002-144725.dump`）。

切完按真正的公网地址对**新、旧两个主机名**各跑一遍冒烟：注册 201 → 登录 → me / devices → 同步推 / 拉 / bootstrap → refresh → 注销 →
删号 → 删后登录 401 全对；`/v1/market/*` 200、`/privacy` 200、旧主机名的 `/web/` `/web/m/` 308 到新加坡、两条 WS 都 101 且在推数据。
新加坡 worker 起来 4 分钟就把被排除的行情表填回来了（orders 2998 / live 2477 / features 49714 / heat 12093），内存用 0.8 GB、负载 1。

第一次跑脚本踩了两个坑，脚本已改、记在这里：远端恢复脚本原来是 `ssh host bash -s <<EOF` 从 stdin 喂，中间 `docker exec -i` 把后半段
脚本吞掉了，bash 读到 EOF 当作正常结束——库建空、服务没起、脚本还往下走；现在远端脚本先落成文件再执行，`docker exec` 不带 `-i`。
美国的 Caddyfile 是 `admin off`，`systemctl reload caddy` 要走 2019 管理口必败，改成 `restart`。
