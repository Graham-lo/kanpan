> **2026-09-18 标注**：方案本身仍待用户确认、仍未动代码，但「现状：耦合在哪」那张表的路径已经变了——币安线协议、线路策略与网关竞速在 2026-09-17 抽成了独立的 `KanpanNetwork` 包（`KanpanNetwork/Sources/KanpanNetwork/{Binance,Route,Transport}/`），不再在 `KanpanData/Binance/` 下；`FavoritesQuickPicker.swift` 已删除。接手前按当前源码重新核对一遍耦合点。

回答三个问题：
1. Coinbase 现货怎么接？
2. 现在那套「网关／线路」逻辑能不能从行情层抽出来？
3. 以后要接别的交易所、别的品种、券商，能不能做成通用的？

一句话结论：**能，但要先把「品种身份」和「行情提供者」这两层从币安里拆出来，再接 Coinbase；直接在现有代码上硬塞第三个 `MarketSource` 会把耦合翻倍。** 拆完以后，接一个新交易所 = 写一个 Provider 适配器 + 网关加一条通道，其他层（缓存、自选、画线、复盘、账号同步）不用再改。

## 一、现状：耦合在哪

客户端从头到尾只会讲**币安 USDT 本位永续**这一种「语言」，OKX 不是第二种语言，而是网关在服务端把 OKX 伪装成币安：

| 耦合点 | 位置 | 说明 |
|---|---|---|
| 线协议 | `KanpanData/Binance/{Endpoints,RESTClient,WSClient,DTO}.swift` | `BinanceHosts / BinanceREST / BinanceWS / KlineRow / Ticker24hDTO` 是具体类型，被 `MarketFeed`、`RoutedMarketFeed`、`QuoteBook`、`MarketModel`、`SymbolCatalog`、`OISource`、`ReviewChartBridge` 直接持有 |
| OKX 是伪装 | `Backend/kanpan-gateway/market_rest.py`、`okx_hub.py` | 网关把 OKX K 线／ticker 翻成币安数组和 `24hrTicker` 帧；`/market/v1/*?source=` 只认 `binance\|okx` |
| 线路 = 交易所 | `KanpanData/Feed/MarketRoutePolicy.swift`（另一窗口在改） | `policy.source`：网关⇒OKX，直连⇒币安。「走哪条路」和「看哪家所」被绑成一件事 |
| 品种身份是裸字符串 | `SymbolInfo.id = symbol`，`SymbolPrefs`（`kanpan.symbols.v1`），`DrawStore`，`SeriesStore/Paths`，`QuoteBook.raw[String]` | `"BTCUSDT"` 到处当主键，没有「哪家所、哪个市场」 |
| 只有同步层是对的 | `Kanpan/Account/PersonalSyncCodec.swift:74-94`、`AppAccountBridge.swift:288` | 对象 id 已经是 `binance/usd_m/BTCUSDT`，有 `venue/market` 字段——**这就是全局该用的身份格式** |
| 后端白名单 | `Backend/kanpan-api/src/review_domain.rs:5`、`search.rs:86` | `venue` 只认 `binance\|okx`，且归一成 `binance` |
| 币安专属功能 | `OISource`、`Interval.oiPeriod`、`MainScreen.swift:712 oiSupported`、`MarketModel.swift:330` | 持仓量只有币安永续有；现在靠 `source == .binance` 分支硬判 |
| UI 假设 USDT 后缀 | `FavoritesView.swift:789`、`FavoritesQuickPicker.swift:42`、`FavoriteCategory.swift:8`、`TopBar.swift:29`、`ReviewModels.shortSymbol`、`MarketModel.placeholder` | 币名 = 去掉 USDT；Coinbase 是 `BTC-USD`，这些都会算错 |
| 分类器 | `KanpanCore/Model/SymbolClassification.swift` | 按币安 `underlyingType` 分「加密／美股／港股」，别家没有这个字段 |

好消息：`MarketFeed` 内部已经有几个正确的缝——`HTTPTransport`、`WSSocketFactory`、`FeedEvent` 流、`Interval.source`（1y 从 1M 聚合）、`Aggregator`、`FeedComposer`。方案就是把这些缝往外推一层。

## 二、Coinbase 现货的事实（2026-09-17 核实）

| 项 | 事实 | 来源 |
|---|---|---|
| 产品 | 现货，id 形如 `BTC-USD`，计价 **USD**（不是 USDT）；无持仓量、无资金费、无标记价 | Advanced Trade 文档 |
| REST K 线 | `GET /api/v3/brokerage/market/products/{id}/candles`，公开无需签名；`start/end` 为 Unix **秒**；`granularity` 枚举 `ONE_MINUTE, FIVE_MINUTE, FIFTEEN_MINUTE, THIRTY_MINUTE, ONE_HOUR, TWO_HOUR, FOUR_HOUR, SIX_HOUR, ONE_DAY`；**每页最多 350 根**；每根 `{start, open, high, low, close, volume}` 全是字符串 | [Get Public Product Candles](https://docs.cdp.coinbase.com/api-reference/advanced-trade-api/rest-api/public/get-public-product-candles) |
| 缺的周期 | 3m、12h、1w、1M、1y 没有原生 → 3m 由 1m 聚、12h 由 6h 聚、1w/1M 由 1d 聚、1y 由 1M 聚（现有 `Aggregator.bucket` 直接可用） | 推论 |
| WebSocket | 公开 `wss://advanced-trade-ws.coinbase.com`，无需鉴权；频道：`candles`（**只有 5 分钟桶**，每秒推）、`ticker`（每笔成交）、`ticker_batch`（5 秒一批）、`market_trades`（250ms 一批）、`level2`、`heartbeats`、`status` | [WebSocket Channels](https://docs.cdp.coinbase.com/coinbase-app/advanced-trade-apis/websocket/websocket-channels) |
| 实时末根 | 1m/15m/1h 等的末根不能靠 `candles` 频道，要用 `market_trades`（有成交量）在客户端拼末根，REST 定期校正——`MarketFeed` 已有 `reconcileMs` 和 `.trade` 分支，机制现成 | 推论 |
| 自选报价 | `ticker_batch`（5 秒）给自选页，`ticker` 给当前品种 | 文档 |
| 限速 | Advanced Trade 公开 REST 的具体数字**未核实**（页面 404）；同厂 Exchange API 公开端点为 10 次/秒/IP、突发 15，WS 8 次/秒/IP、客户端消息 100/秒。按 10 人规模，即便按这个保守值也够 | [Exchange rate limits](https://docs.cdp.coinbase.com/exchange/introduction/rate-limits-overview.md) |
| 可达性 | 国内手机能不能直连 Coinbase **未核实**；美国 VPS 网关肯定能（Coinbase 不封美国 IP，和币安 451 相反） | 待真机验证 |

## 三、目标架构

### 3.1 三个正交的概念

现在混成一团的东西要拆成三件事，各自独立选择：

```
品种身份 Instrument   = venue / market / symbol      看什么   binance/usd_m/BTCUSDT   coinbase/spot/BTC-USD
行情提供者 Provider    = 谁会讲这家所的线协议          怎么解   BinanceProvider   CoinbaseProvider
线路 Route             = 直连 / 网关                    走哪条路 与交易所无关，每家所都有直连和网关两条
```

- **OKX 的定位**：它不是一个「品种」，而是币安永续这个品种在网关线路上的**服务端替身**。保持现状（服务端翻译成币安线协议），不要在客户端再写一个 OKX Provider。这样「线路」记忆里的规则不变：直连=币安直连不兜底；网关=网关（内部用 OKX）。
- **Coinbase 是新品种，不是币安的替身**：`coinbase/spot/BTC-USD` 和 `binance/usd_m/BTCUSDT` 是两个条目，可以同时在自选里，永远不混。

### 3.2 品种身份：`InstrumentID`

```swift
public struct InstrumentID: Hashable, Codable, Sendable {
  public var venue: String    // "binance" | "coinbase"
  public var market: String   // "usd_m" | "spot"
  public var symbol: String   // "BTCUSDT" | "BTC-USD"
  public var key: String { "\(venue)/\(market)/\(symbol)" }   // 与账号同步的 id 一模一样
}
```

- `SymbolInfo.id` 改成 `InstrumentID`；`base/quote` 由 Provider 填（Coinbase 给 `base_currency_id/quote_currency_id`，不再靠去后缀猜）。
- 所有以 symbol 为键的存储改用 `key`：自选（`kanpan.symbols.v2`，读旧 v1 时裸符号一律映射到 `binance/usd_m/`）、`DrawStore`、`SeriesStore`（目录 `series/<venue>/<market>/`，代替现在的 `sources/okx`）、`QuoteBook.raw`、`opens.json`、`quotes.json`。
- `ReviewRange` 已经有 `venue/market` 字段，只需停止把 venue 归一成 binance。
- 账号同步：客户端 id 格式已经对了；服务端把 `review_domain.rs:5`、`search.rs:86` 的白名单改成 `binance | coinbase`（OKX 从 venue 中去掉，它从来不是用户可见的 venue），迁移不需要改表结构（`venue/market/symbol` 三列已存在）。

### 3.3 行情提供者：`MarketProvider` 协议

放在 `KanpanData/Provider/`，处于 `MarketFeed` 之下、`HTTPTransport/WSSocket` 之上。`MarketFeed` 只跟协议说话，返回值全是 `KanpanCore` 里已有的 `Bar / BarSeries / Ticker / SymbolInfo`：

```swift
public protocol MarketProvider: Sendable {
  var venue: String { get }
  var market: String { get }
  var capabilities: ProviderCapabilities { get }

  func instruments() async throws -> [SymbolInfo]                // 品种表
  func klines(_ id: InstrumentID, interval: Interval, limit: Int,
              start: Int64?, end: Int64?) async throws -> [Bar]   // 一页 K 线，interval 必须在 nativeIntervals 内
  func ticker(_ id: InstrumentID) async throws -> Ticker
  func tickers(_ ids: [InstrumentID]) async throws -> [Ticker]
  func stream(_ subs: StreamSubscription) -> AsyncStream<ProviderEvent>  // .kline/.trade/.ticker/.status/.connected
  func openInterest(...) async throws -> [OIPoint]               // 默认实现抛 unsupported
}

public struct ProviderCapabilities: Sendable {
  var nativeIntervals: Set<Interval>      // 币安全 13 档；Coinbase 9 档
  var maxPage: Int                        // 币安 1500；Coinbase 350
  var liveKlineIntervals: Set<Interval>   // 币安全档；Coinbase 只有 5m
  var hasOpenInterest: Bool               // 币安 true；Coinbase false
  var hasMarkPrice: Bool
  var quoteAssets: Set<String>            // ["USDT"] / ["USD","USDC"]
}
```

改动落点：
- `Interval.source`（现在只有 1y→1M）改成 `Interval.source(in caps)`：不在 `nativeIntervals` 里的周期，退到最近的能整除的原生周期，`MarketFeed` 里已有的 `sourceComposer + Aggregator.bucket` 路径原样复用（`MarketFeed.swift:612-616、664-671`）。
- 实时末根：`liveKlineIntervals` 不含当前周期时，`MarketFeed` 走 `.trade` 分支拼末根（`FeedComposer` 已支持 tick 合并），并按 `reconcileMs` 用 REST 校正。
- `OISource`、`oiSupported` 等改成读 `capabilities.hasOpenInterest`，删掉 `source == .binance` 分支。
- `BinanceProvider` = 现在的 `BinanceREST + BinanceWS + DTO` 原样包一层；测试里 92 处对具体类型的引用先不动，行为零变化。
- `CoinbaseProvider` = 新写：REST 候选解析（秒→毫秒、字符串→Double、按 `start` 升序）、分页（350/页，深度目标 1800 根 ≈ 6 页）、WS（`market_trades`+`ticker`/`ticker_batch`，5m 时另订 `candles`），`instruments()` 用 `GET /api/v3/brokerage/market/products`，只保留 `USD` 计价、`status == online`。

### 3.4 线路与交易所正交

- `MarketRoutePolicy` 只剩 `.direct / .gateway`，去掉 `var source`。每个 Provider 拿到的是「一个 `HTTPTransport` + 一个 `WSSocketFactory`」，由 `RouteResolver(policy, venue)` 决定它们指向直连域名还是网关：
  - 币安 + 直连 → `fapi.binance.com` / `fstream.binance.com`；币安 + 网关 → `/market/v1/*?source=okx` + `/market/okx/stream`（**现状不变**）
  - Coinbase + 直连 → `api.coinbase.com` / `advanced-trade-ws.coinbase.com`；Coinbase + 网关 → `/market/v1/*?source=coinbase` + `/market/coinbase/stream`
- `RoutedMarketFeed` 现在的 `primary/backup` 两套 REST 结构，简化为「一个 Provider 实例 + 换线路时重建 transport」。这块**等另一窗口的线路重构落地后再动**。
- 设置里「行情线路」保持一个全局开关，对所有交易所生效。

### 3.5 网关通用化（Python，线上服务，动前备份、先动备用节点）

`market_rest.py` 从「币安 + OKX 伪装」变成「按 venue 分发的通用代理」：

```
/market/v1/klines?source=okx        → 现有 OKX→币安翻译，保持不动
/market/v1/klines?source=coinbase   → 新增：透传 Coinbase Advanced Trade 公开接口，响应**原样**（不翻译成币安格式）
/market/coinbase/stream             → 新增 coinbase_hub.py：一条上游 WS 共享给所有手机，帧原样转发
```

为什么 Coinbase 不像 OKX 那样翻成币安格式：OKX 翻译是因为它要冒充同一个品种；Coinbase 是独立品种，客户端反正要有 `CoinbaseProvider`（为了直连），网关只透传、不翻译，逻辑只写一份。以后接第四家也是同样两步：客户端一个 Provider，网关一条透传通道。

### 3.6 UI 层需要跟着变的地方（不重设计，只是身份变宽）

- 自选页：分类由 `SymbolClassifier` 改为「venue+market 优先」：`coinbase/spot` 归入「Coinbase 现货」组（或并入「加密」组但徽章带所标——**要你拍板**，见第五节）。
- 顶栏／品种名：显示用 `SymbolInfo.display`（`BTC/USD`），去掉四处 USDT 后缀假设。
- 品种搜索：`SymbolCatalog` 改为每个 venue 一份缓存，搜索结果带所标。
- 周期条：`Interval.oiPeriod` 只对 `hasOpenInterest` 的品种展示 OI 副图；Coinbase 品种切到 OI 时副图隐藏，不报错。
- 品种记号（57 个手绘记号）：按 base 币复用，`BTC` 在两家所用同一个记号。

## 六、未核实项
