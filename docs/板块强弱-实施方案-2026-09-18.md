# 板块强弱：实施方案（2026-09-18）

研究来源：[板块强弱与二阶变化-算法研究-2026-09-18.md](板块强弱与二阶变化-算法研究-2026-09-18.md)。
本方案是它的裁剪版：**保留时间窗口、广度、前沿成员三样真正有增量的东西，砍掉加速度、
状态机、小时历史。** 分两版，甲版不依赖服务端，乙版在甲版之上加 5 日 / 20 日。

代码归属：Claude 窗口（Opus 子代理写，主窗口验收、装真机、push）。Codex 不参与。

## 0. 现状裁决：单日算法哪里对、哪里要修

现有 24h 算法（[SectorAggregate.swift](../KanpanCore/Sources/KanpanCore/Sector/SectorAggregate.swift)、
[SectorSelection.swift](../KanpanCore/Sources/KanpanCore/Sector/SectorSelection.swift)、
[SectorFeed.swift](../Kanpan/Kanpan/Sector/SectorFeed.swift)）：

| 项目 | 现状 | 裁决 |
| --- | --- | --- |
| 主数字 = 币安 ticker 的滚动 24h 涨跌幅 | 对 | 保留。「今天谁在动」就该看这个 |
| 默认口径 = 中位数 | 对 | 保留为**唯一**口径。均值 / 成交额加权 / 市值加权都不给用户选：均值被单只极值劫持，成交额加权给已经涨完的币双倍权重，市值加权让 `l1` 变成 BTC 一只币。用户不选口径（kanpan-sector-page-no-basis-picker） |
| 没行情的成员跳过、不计零 | 对 | 保留 |
| 强端 / 弱端按名次上色，不按正负 | 对 | 保留 |
| 面积分母 = 上场那几颗的最大绝对值 | **半对** | 分母改成**全场**最大绝对值 + 20% 迟滞。仍取最大值而不取分位数：定稿原型里「最大的那颗球 = 幅度最大的板块」是用户认可的读法，分位数会把领涨端前一两颗截成一样大（2026-09-18 与 kanpan-a2 对过后定） |
| 1 个成员的板块（`desci`）和 88 个成员的 `l1` 同台排名 | **错** | 一只币的涨跌不是板块强弱。有行情成员 < 3 的板块不进球场，留在「全部板块」 |
| 同一 base 多张合约，每 10 秒按成交额挑一张 | **不稳** | USDT/USDC 两张的涨幅不同，来回切会让球抖。改成固定优先级 USDT > USDC > 其它 |
| `setCatalog` 只比数量不比内容 | **bug** | 改成比内容（symbol 集合哈希） |
| 球上看不出「整体涨」还是「一只在爆」 | **缺** | 甲版补广度与前沿成员，进列表不上球 |

板块成员数分布：1 / 5 / 5 / 5 / 6 / 7 / 8 / 8 / 8 / 9 / 10 / … / 78 / 88。小板块（5–10 个）本来就是
主题性更强的一组，中位数方差大是它们的天性，不做收缩；只把 < 3 的挡在球场外。

## 甲版：单日（24h 截面，纯客户端）

### 甲.1 算法

记市场池 `G` = 该市场（加密 / 美股）所有**有行情**、按 base 去重的品种。对每个品种：

```
r_i = ln(1 + pct_i / 100)           // 24h 对数收益
b   = mean_{i∈G} r_i                // 池基准：等权均值
e_i = r_i − b                       // 相对收益
```

板块 `s` 的有效成员集合 `S_s` = 目录成员 ∩ 有行情。`n_s = |S_s|`。

| 字段 | 定义 | 备注 |
| --- | --- | --- |
| `pct` | 成员 24h 涨跌幅的中位数，百分数 | 三档口径删掉，`SectorBasis` 枚举与 mean / volumeWeighted 路径一并删；中位数口径与测试不变 |
| `memberCount` | `n_s` | 已有 |
| `staticCount` | 目录里的成员数 | 新增。「全部板块」要能写 `15/18` 而不是只写有行情的 |
| `breadth` | `#{i∈S_s : e_i > 0} / n_s` | 相对广度。平盘不算上涨 |
| `upCount` | `#{i∈S_s : pct_i > 0}` | 绝对上涨家数 |
| `frontier` | `{ i∈S_s : e_i > 0 且 e_i 在 G 内分位 ≥ 90 }` 按 `e_i` 降序 | 前沿成员。分位用 `(n−1)p` 线性插值 |
| `jackknife` | `[min_j med(S_s∖j), max_j med(S_s∖j)]`，百分数 | 删一区间。`n_s ≤ 2` 时缺失 |
| `eligible` | `n_s ≥ 3 && !isFallback` | 进不进球场 |

极端例：五个成员 `−2, −1, 0, +1, +300`。`pct`（中位）= 0，`breadth` 取决于池基准，
`frontier = [那只 +300]`，`jackknife` = `[−0.5, +0.5]`。结论「整体没动、一只在爆」直接可读。

### 甲.2 选取与面积

`SectorSelector.select` 改动：

1. 排序前先按 `eligible` 过滤（原来只滤 `isFallback`）。
2. 面积分母 `maxAbsPct` 改名 `scalePct`：取**全场**（不是上场那几颗）`|pct|` 的最大值，
   下限 0.01。不用分位数——领涨端要一颗一个大小。迟滞：调用方保留上一次的 `scalePct`，新值与旧值相差不到 20% 就沿用旧值。
   超过分母的球面积截到 1，数字照真值显示。
3. 排序稳定：`pct` 相同按 `id` 排，避免并列时随机换位。

`proto2/app.js` 逐行等价的约定到此为止，`SectorTests` 里对应归一与过滤的用例改预期，
其它用例不动。

### 甲.3 取数层

[SectorFeed.swift](../Kanpan/Kanpan/Sector/SectorFeed.swift)：

- 合并计价对：固定优先级 `USDT > USDC > FDUSD > 其它`，同优先级才看成交额。
- `setCatalog`：比 symbol 集合的哈希，不比数量。

### 甲.4 界面

球场**一个像素不动**（名字 + 数字、色相、陪衬）。

- **品种列表**（点球进入）头部加一行小字：`中位数 +4.64% · 15/18 跑赢`。
  前沿成员的行右侧一枚小记号「领涨」，字号跟成交额那行一样，不做徽章。
- **全部板块**每行副文案：`18 个品种 · 15/18 跑赢 · 成交额 1.2B`。
  `n_s < 3` 的板块照常列出，副文案 `1 个品种`，不写解释。
- 「中位数 / 均值 / 成交额加权」那行 chip **整行删掉**，`sector.basis` 存储一并删。甲版页面头部没有任何模式切换。

不出现任何「覆盖率 / 数据状态」字样（kanpan-no-engineering-status-fields）。

### 甲.5 测试

`KanpanCoreTests/SectorTests.swift` 新增：

| 用例 | 断言 |
| --- | --- |
| 单点极值 | `pct` 不变、`frontier` 只含那一只、`jackknife` 窄 |
| 全部相同 | `breadth` 全 0（e_i 全 0 不算上涨）、`frontier` 空 |
| 1–2 个成员 | `eligible == false`、`jackknife == nil` |
| 缺成员 | `memberCount < staticCount`，不出现零收益 |
| 价格统一乘常数 | 全部字段不变 |
| 分位插值 | 手算的 `(n−1)p` 值 |
| 全场最大值分母 + 迟滞 | 分母看全场不看上场；差不到 20% 不动 |
| < 3 成员不进球场 | `select` 结果不含它，`total` 不计它 |
| 计价对优先级 | USDT 成交额更小也选 USDT |
| 口径 | `SectorBasis` 已不存在；`stats()` 没有 basis 参数 |

UI：跑 `sector` 相关的那一两条真机用例，视觉在模拟器三套皮肤各看一眼球场、列表、全部板块。

## 乙版：进阶（+ 5 日 / 20 日，日线服务端）

### 乙.1 为什么是日线不是小时线

5 日 / 20 日相对表现只需要「现价」和「N 天前的收盘」。现价手机已经有（ticker），
N 天前收盘拿日线一天一趟就够。小时线是研究里为加速度和小时级确认准备的，那两样不做。

| | 研究原方案（1h） | 本方案（1d） |
| --- | --- | --- |
| 币安请求 | 707 / 小时 | 707 / 日，权重 707 |
| 冷启动 | 12 分钟，完整状态等 22 天 | 12 分钟，**当天就有 5 日和 20 日** |
| 服务端存储 | 一年 600 MB | 一年约 13 MB |
| 服务端计算 | 小时重算 + 滤波 + 状态机 | 无。服务端只存收盘价 |

### 乙.2 服务端（`Backend/kanpan-api`，Rust）

**表** `daily_close`：

```
symbol TEXT, day DATE (UTC), close DOUBLE, quote_volume DOUBLE,
PRIMARY KEY (symbol, day)
```

**每日任务**（照 `market_meta::spawn_refresh` 的写法，00:10 UTC 起跑，启动时若当天没跑过也跑）：

1. `www.binance.com/fapi/v1/exchangeInfo` 取 `contractType == PERPETUAL && status == TRADING`
   的合约。**主机必须是 `www.binance.com`**：两台美国 VPS 上 `fapi.binance.com` 回 451
   （`market_meta.rs:24`）。顺手把 `import_public_history.rs:113` 的域名改掉。
2. 每个合约 `klines?interval=1d&limit=22`，全局 1 请求 / 秒，429 退避。
3. 丢掉最后一根（当天未完成），其余按 `(symbol, day)` 幂等写入。
4. 一年以上的行清掉；不在 `exchangeInfo` 里的合约保留 30 天后清。

**接口** `GET /v1/market/sector-history`，无认证、无 owner，和 `/v1/market/meta` 同一类：

```json
{
  "asof": "2026-09-18",
  "symbols": {
    "BTCUSDT": { "c5": 61234.5, "c20": 58900.1 },
    ...
  }
}
```

`c5` = 距 `asof` 5 个完整 UTC 日之前那天的收盘（即 5 日窗口的起点），`c20` 同理。
历史不够的品种该字段缺省，不填 0。全表约 707 × 40 B ≈ 30 KB，服务端内存缓存，
`Cache-Control: max-age=3600`。

Caddy 加一条 `/v1/market/sector-history` 转发（现有 `/v1/market/*` 已覆盖则不用）。

**部署**：先备用节点，只读验证接口返回、日志无 429，再主节点（kanpan-gateway-is-production）。

### 乙.3 手机端

`SectorHistoryFeed`（新文件，`Kanpan/Kanpan/Sector/`）：

- 页面可见时取一次 `/v1/market/sector-history`，落盘缓存；每小时看一次 `asof` 有没有变。
- 主机列表照 [MarketStats.swift](../Kanpan/Kanpan/Main/MarketStats.swift) 的 `hosts` 走。
- 失败静默，5 日 / 20 日 chip 就不出现——**不弹窗、不解释、不灰掉**。

`SectorAggregator.stats` 抽成「给定每个成员一个收益向量，算中位数 / 广度 / 前沿 / 删一」，
24h 传 `pct`，5 日传 `100·(last/c5 − 1)`，20 日同理。三个窗口**各自**取有历史的成员交集：
`S_s^W` = 目录成员 ∩ 有行情 ∩ 有 `cW`。`eligible` 再加一条：`|S_s^W| ≥ 0.8·n_s`，
历史覆盖不足 80% 的板块在那个窗口不进球场。

池基准 `b` 也按窗口各算一次（用同一批有 `cW` 的品种）。

### 乙.4 界面

- 页面头部只有两颗 chip：**`今日` / `5 日`**，`AppStorage("sector.window")`。没有第三个模式，
  没有口径菜单。20 日不做模式，只在品种列表头部那行小字里当一个数字出现。
- 球上的数字、面积、名次跟当前窗口；**球的画法不变**。
- 品种列表头部：`5 日 +8.3% · 20 日 +12.1% · 15/18 跑赢`（当前窗口的广度）；
  排序选项仍是「涨跌幅 / 成交额」两颗，涨跌幅跟当前窗口。
- 全部板块：主数字跟当前窗口，副文案同甲版。
- 服务端没有历史（首日、接口不通）时，`5 日` 那颗 chip 不出现，页面退回甲版的样子。

「5 日」= 5 个完整 UTC 日 + 当天已过的小时，不是精确 120 小时；美股合约的窗口里含周末，
研究已指出，本版接受。

### 乙.5 测试

- Rust：`daily_close` 幂等写入、丢当天未完成一根、`c5/c20` 的日期算法（含月末、闰年）、
  历史不足时字段缺省。
- Swift：收益向量抽象后 24h 用例全部照旧通过；5 日窗口覆盖不足 80% 不进球场；
  `asof` 未变不重算；接口失败 chip 不出现。
- 真机：三套皮肤 × 三个窗口看球场；品种列表与全部板块的文案。

## 顺序

1. **甲版**客户端（含面积分母、< 3 成员过滤、计价对优先级、`setCatalog` 修复）——
   不依赖任何服务端，做完即推、装真机。
2. **乙.2** 服务端采集器与接口——和甲版并行写，写完先在备用节点跑起来攒数据。
3. **乙.3 / 乙.4** 手机端接历史——等 1、2 都落地。

不做的：加速度、「持续领涨」状态机、小时级走弱预警、OI、成交额放大。
研究第三期若要验证加速度，日线表攒到的数据够做离线对照，到时候再说。
