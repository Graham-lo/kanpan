# 美元指数（DXY）行情协议（2026-10-05）

> 写给做 iOS / 网页客户端的人：照这份就能做出 `macro` 这家「交易所」的提供者，不用读服务端代码。
> 服务端代码在 `Backend/kanpan-api/src/venues/macro_index/`（`mod.rs` 答 REST、`stream.rs` 推送、
> `collector.rs` 采集与入库、`bars.rs` 周期聚合、`calendar.rs` 交易时间、`cnbc.rs` 上游）。
> 下面所有 JSON 都是 2026-10-05 19:1x（北京时间，周一欧洲盘）从线上 `kanpan-sg` 抓的原文。

## 1. 身份

| 字段 | 值 |
| --- | --- |
| `venue` | `macro` |
| `market` | `index` |
| `symbol` | `DXY` |
| 键 `InstrumentID.key` | `macro/index/DXY` |
| 显示名 | 美元指数 |
| 价格精度 | 3 位小数（`tickSize` 0.001） |
| 成交量 | 没有：K 线、行情里的量 / 额 / 笔数一律 `"0"` / `0`，客户端别画成交量副图 |

只有这一只。搜索没有服务端目录可挂，关键字写在品种表的 `keywords` 里：
`美元指数`、`DXY`、`USD`、`美元`、`美指`。客户端搜索命中这几个词（不分大小写）就给出这一只。

## 2. 主机与路径

两条线路是同一台：`https://kanpan.43-160-232-253.sslip.io`（直连、网关都走它，没有直连交易所这一说）。

| 用途 | 路径 |
| --- | --- |
| 品种表 | `GET /v1/market/raw/instruments?source=macro` |
| K 线 | `GET /v1/market/raw/klines?source=macro&symbol=DXY&interval=<14 档>[&limit][&startTime][&endTime]` |
| 24h 行情 | `GET /v1/market/raw/ticker/24hr?source=macro[&symbol=DXY]` |
| 推送 | `WSS /v1/market/stream?source=macro[&streams=dxy@ticker/dxy@kline_1m/…]` |

所有 REST 答复都带 `Cache-Control: no-store`。错误一律 `{"error":"<码>"}`：

| HTTP | 码 | 什么时候 |
| --- | --- | --- |
| 400 | `invalid_symbol` | `symbol` 不是 `DXY`（大小写都认）；K 线必须带 `symbol` |
| 400 | `invalid_interval` | 不在 14 档里（`1m` 是分钟、`1M` 是月，区分大小写） |
| 400 | `invalid_limit` | `limit` 不是正整数 |
| 400 | `invalid_time` | `startTime` / `endTime` 不是非负整数，或 `startTime > endTime` |
| 404 | `unsupported_path` | `raw/` 后面不是上面三条 |
| 503 | `not_ready` | 这台主机没起采集（只答持仓量的备用主机）或库连不上；客户端按网络错误退避重试 |

## 3. 品种表

```json
{"symbols":[{"baseAsset":"DXY","displayName":"美元指数","filters":[{"filterType":"PRICE_FILTER","tickSize":"0.001"}],"key":"macro/index/DXY","keywords":["美元指数","DXY","USD","美元","美指"],"market":"index","pricePrecision":3,"quoteAsset":"USD","status":"TRADING","symbol":"DXY","tickSize":"0.001","underlyingType":"INDEX","venue":"macro"}]}
```

`underlyingType` 是 `INDEX`（不是 `COIN`）：徽章、分类按它走「指数」那一类；市值、持仓量、费率、估值一律没有。

## 4. K 线

答复是币安 `/fapi/v1/klines` 的数组形状，开盘时刻升序：
`[openTime, open, high, low, close, volume, closeTime, quoteVolume, trades, takerBase, takerQuote, ignore]`。

```json
[[1791198660000,"102.217","102.218","102.207","102.212","0",1791198719999,"0",0,"0","0","0"],
 [1791198720000,"102.244","102.251","102.244","102.251","0",1791198779999,"0",0,"0","0","0"]]
```

- 参数语义照币安：`limit` 缺省 500、最大 1500；`startTime` / `endTime` 按开盘时刻、含端点；
  只给 `startTime` 时从它往后数 `limit` 根，否则取截止 `endTime`（缺省现在）的最后 `limit` 根。
  往前翻页：`endTime = 最早那根的 openTime - 1`。
- `closeTime` = 下一根的开盘时刻 - 1 毫秒（日线 `…T23:59:59.999Z`）。
- 最后一根是正在走的那一根（休市时就是休市前最后一根）。
- **休市段没有 K 线**：每天 17:00–18:00 ET 那一小时、周五 17:00 到周日 18:00 ET，K 线直接缺，
  不补平盘线（和 TradingView 的 DXY 一样）。上游偶尔也缺几分钟（没有报价的分钟），同样不补。

### 14 档从哪儿来

| 周期 | 源（库里存的档） | 对齐 |
| --- | --- | --- |
| 1m 3m | 1m | 从 1970-01-01 00:00 UTC 起按步长切（同币安） |
| 5m 15m 30m | 5m | 同上（CNBC 没有 15 分钟原生 K 线，15m 由 5m 聚） |
| 1h 2h 4h 6h 12h | 1h | 同上 |
| 1d | 1d | **ICE 交易日**：美东前一天 18:00 → 当天 17:00；标签是交易日那天的 00:00 UTC |
| 1w 1M 1y | 1d | 按交易日的日期聚：周一 / 月初 / 年初 00:00 UTC |

日线标签举例：2026-10-05（周一）这个交易日从 2026-10-04 18:00 ET（22:00 UTC）开盘，
它的日线 `openTime` 是 `1791158400000`（2026-10-05 00:00 UTC），`closeTime` 是 `…05T23:59:59.999Z`。
所以客户端按「上海时间 8 点换日」的规矩画日线分隔，和这里的标签正好对上。

### 历史深度（线上实际）

| 档 | 最早 | 说明 |
| --- | --- | --- |
| 1m | 约 30 天（2026-09-06 起） | CNBC 1 分钟只给一个月左右 |
| 5m（→15m、30m） | 约 64 天（2026-08-02 起） | |
| 1h（→2h…12h） | 约 100 天（2026-06-28 起） | |
| 1d（→1w、1M、1y） | 10 年（2016-09-27 起） | |

库表永久保留，往后只会越攒越长。往前翻到头时答空数组 `[]`，客户端照币安「没有更早」处理。

## 5. 24h 行情（`ticker/24hr`）

不带 `symbol` 答数组（一个元素），带 `symbol=DXY` 答对象：

```json
{"closeTime":1791198990000,"highPrice":"102.534","lastPrice":"102.262","lowPrice":"101.855","marketState":"open","openPrice":"101.917","openTime":1791151200000,"prevClosePrice":"101.932","priceChange":"0.330","priceChangePercent":"0.324","priceSource":"official","quoteVolume":"0","symbol":"DXY","volume":"0"}
```

| 字段 | 含义 |
| --- | --- |
| `lastPrice` | 最新价 |
| `prevClosePrice` | **上一个交易日的官方收盘**（CNBC `.DXY` 的 `previous_day_closing`；拿不到时退用库里上一根日线的收） |
| `priceChange` / `priceChangePercent` | `lastPrice - prevClosePrice`、它除以 `prevClosePrice` 的百分数（三位小数，同币安的口径是百分数不是小数）。**不是滚动 24 小时**。没有昨收时两个都是 `null` |
| `openPrice` / `highPrice` / `lowPrice` | 本交易日（18:00 ET 起）的开高低 |
| `openTime` | 本交易日开盘时刻（上例 = 2026-10-04 22:00 UTC） |
| `closeTime` | 最新价的时刻 |
| `marketState` | `open` / `closed`，见第 7 节 |
| `priceSource` | `official`（CNBC 的 ICE 官方 `.DXY`）/ `synthetic`（官方断了时用六个汇率按 ICE 公式算的，见第 8 节） |
| `volume` / `quoteVolume` | 恒为 `"0"` |

顶栏六格：持仓 / 额 / 市值 / 费率 / 结算 / 估值都没有，写「—」或整格不摆（能力位全 false）。

## 6. 推送

`wss://kanpan.43-160-232-253.sslip.io/v1/market/stream?source=macro&streams=dxy@ticker/dxy@kline_1m`

帧是币安组合流的形状 `{"stream":…,"data":…}`。流名：`dxy@ticker`、`dxy@kline_<14 档之一>`
（代号大小写都认，周期区分大小写）。一个连接最多 32 条流，全服务最多 64 个连接（超了回一帧
`{"error":{"code":…,"msg":"Too many connections"},"id":null}` 后关闭）。

**连上（或 SUBSCRIBE）立刻收到当前快照**，之后只在值变化时推（采价 5 秒一次，没变不推）：

```json
{"data":{"C":1791198967000,"E":1791198972794,"O":1791151200000,"P":"0.319","c":"102.257","e":"24hrTicker","h":"102.534","l":"101.855","marketState":"open","o":"101.917","p":"0.325","prevClosePrice":"101.932","priceSource":"official","q":"0","s":"DXY","v":"0"},"stream":"dxy@ticker"}
{"data":{"E":1791198972794,"e":"kline","k":{"B":"0","L":-1,"Q":"0","T":1791199019999,"V":"0","c":"102.257","f":-1,"h":"102.257","i":"1m","l":"102.257","n":0,"o":"102.257","q":"0","s":"DXY","t":1791198960000,"v":"0","x":false},"s":"DXY"},"stream":"dxy@kline_1m"}
{"data":{"E":1791198972794,"e":"heartbeat","marketState":"open"},"stream":"heartbeat"}
```

- ticker 帧字段同币安 `24hrTicker`（`c` 最新、`o/h/l` 本交易日、`p/P` 涨跌额 / 涨跌幅、`O` 交易日开盘时刻、
  `C` 最新价时刻），另加 `prevClosePrice`、`marketState`、`priceSource`。
- kline 帧同币安：`t/T` 开收时刻、`x` 是否已收。**末根换了**（新的一分钟、新的交易日……）先补发上一根
  `x:true`，再发新的一根 `x:false`。
- **心跳**：每 15 秒一帧 `stream:"heartbeat"`。休市时没有行情帧，客户端的看门狗要认它
  （收到心跳就算连接活着；不认识的 `stream` 不要当错误）。`marketState` 变了也会立刻反映在下一帧 ticker / 心跳里。
- 控制报文照币安：`{"method":"SUBSCRIBE"|"UNSUBSCRIBE"|"LIST_SUBSCRIPTIONS","params":[…],"id":n}`，
  回 `{"result":null,"id":n}`（`LIST_SUBSCRIPTIONS` 回流名数组）；认不出的回 `{"error":{"code":2,"msg":…},"id":n}`。
  实测：`SUBSCRIBE ["dxy@kline_15m"]` 193 ms 后收到 `{"id":7,"result":null}` 紧跟一帧 15m 快照。
- 慢连接不会积压：服务端只留最新版本，跟不上就跳到最新。
- 能力位：14 档都有末根推送（`liveKlineIntervals` = 全部），不需要逐笔拼末根，也不需要定时 REST 对表；
  断线重连后照常 REST 补末页即可。

## 7. 交易时间与 `marketState`

ICE 美元指数期货的时间：**美东周日 18:00 开盘 → 周五 17:00 收盘，周一到周四每天 17:00–18:00 休一小时**。
夏令时自动跟着美东走（夏令时 18:00 ET = 22:00 UTC = 北京 06:00；冬令时 23:00 UTC = 北京 07:00）。

`marketState = "open"` 要同时满足：

1. 现在落在上面的开盘时间里；
2. 最新价不超过 10 分钟（节假日 ICE 不开但日历上算开盘，上游不出价 10 分钟后自动变 `closed`；
   上游断了 10 分钟也一样）。

客户端：`closed` 时价格文字变灰（照「行情停住时价格变灰」的既有规矩），不加额外文案；K 线、行情照常显示最后的值。

## 8. 数据来源与校准

- 上游是 CNBC 的公开报价（`quote.cnbc.com` 报价 + `ts-api.cnbc.com` K 线），从新加坡这台机器拉。
  原定的 Yahoo Finance 在 `kanpan-sg` 上一律 429（限流），按规格的备用条款改用 CNBC；
  客户端不直连任何上游，只连 `kanpan-api`。
- 报价每 5 秒一次，一次同时拿官方 `.DXY` 和六个汇率（EUR=、JPY=、GBP=、CAD=、SEK=、CHF=）。
- **官方优先**：官方价不超过 2 分钟就用官方（`priceSource:"official"`）。
- **合成兜底**：官方断了、汇率还新鲜（不超过 3 分钟）时，用 ICE 公式
  `50.14348112 × EURUSD^-0.576 × USDJPY^0.136 × GBPUSD^-0.119 × USDCAD^0.091 × USDSEK^0.042 × USDCHF^0.036`
  算合成价，再乘校准系数（官方 ÷ 合成，两者都在时持续更新；单次偏离超过 5% 的观测不收）
  （`priceSource:"synthetic"`）。
- 实测偏差：2026-10-05 19:17（北京）官方 102.249、未校准合成 102.2517，差 0.0027 点（0.0026%）；
  抓取样本时（05:44 ET）官方 102.185、合成 102.19909，差 0.014%。校准后的合成价与官方基本重合。
- 1 分钟 K 线：报价逐笔拼当前这一分钟；每分钟拉一次 CNBC 官方 1 分钟 K 线，**官方的一根盖掉拼出来的**
  （库里 `source` 1 = 官方、0 = 拼的 / 聚的；官方行只能被官方改）。5m / 1h / 1d 同理：
  最近的由 1 分钟聚出来，回填循环每 30 分钟拿官方的盖一遍。
