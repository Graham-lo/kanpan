# TestFlight 上传台账

这个文件记录每一次 `make upload` **真正成功**的上传。由 `make upload` 在 `xcrun altool --upload-app`
成功之后自动追加，**不要手写、不要改格式、不要删行、不要排序**。

**谁在读它：清理 `DerivedData-archive/` 的人。** 归档里的 dSYM 是那个构建号的崩溃日志唯一能用的
符号表——重编一遍出来的二进制 UUID 对不上，补不回来，而 `DerivedData-archive/` 被 `.gitignore`
挡在仓库外，本机独一份、没有备份。一个 TestFlight 构建有 90 天有效期，这期间测试者还装着它、
崩溃日志还会回来，所以 `Kanpan-<构建号>.xcarchive` 必须留到下表「dSYM 保留到」那一列的日期之后
才能删。本机没有任何别的痕迹能事后推断某份归档是哪天传上去的（`~/Library/Logs/ContentDelivery*`
和 `~/.itmstransporter` 都不存在），这份台账就是 90 天的唯一起算依据——所以它进 git，跟着仓库走，
push 上去有备份。

**写入规则（这个工作树常有几个窗口同时往 main 提交，靠这几条扛合并）：**

- 严格只追加：新记录一律加在**文件最末**，行尾留换行。
- 已有的行一个字都不改；上面这段抬头和下面的表头写好之后不再动。
- 不做任何需要改写的汇总行（「累计上传 N 次」「最近一次上传」之类）。
- 不倒序、不把新记录插在前面——那样每次提交都落在同一处，两个窗口各传一版就必冲突。

**字段（把一行去掉首尾的 `|` 再按 `|` 切分，逐段 trim；位置固定，给机器解析用）：**

1. 上传时间，`YYYY-MM-DD HH:MM`，开头就是日期
2. 版本号（MARKETING_VERSION）
3. **构建号**（CURRENT_PROJECT_VERSION），单独一个字段，不和版本号粘在一起，
   直接对应 `DerivedData-archive/Kanpan-<构建号>.xcarchive`
4. 归档路径
5. ipa 文件名
6. dSYM 保留到（上传日 + 90 天）

构建号那格写成 `dev` 的是没传 `BUILD=` 的本地包：它没有唯一构建号，App Store Connect 不收，
正常不该出现在这里。真出现了说明有人拿 dev 包试过上传，那条记录不作数，也别按它算 90 天。
